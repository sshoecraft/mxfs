Verdict: UNSAFE as written. Facts that make it so: a PAUSED peer can resume after any finite HB scan (silence is not exclusion; only bounded self-fencing leases + P&A prove it); a survivor may already own recovery (manifest sealed / token) while the rebooter scans; a new ACTIVE identity makes survivors retire the pending recovery + purge the dead tuple's grants BEFORE own replay finishes (torn window); cross-slice LSNs are incomparable, so ungated own replay followed by token-gated foreign replays of the other 31 slices has no proven redo-ordering invariant; WE-AR: unknown REGISTRANTS (not just the holder) can write; READ KEYS "on every path" does not prove per-nexus registration (need READ FULL STATUS transport IDs); WITHDRAWN is reclaimable only if it is a proven terminal/quiesced stamp; crash points inside self-succession need restartable ledger transitions.

Required shape (= design doc §3 bootstrap, items 5+): (1) durable CAS bootstrap/recovery-owner token (whole-cluster); (2) fence + verify removal of EVERY old/unknown registrant (classify every READ FULL STATUS registrant against ledger/HB), mark predecessor FENCED only after verified P&A, ours REGISTERED only after per-nexus verification; (3) freeze/reconstruct all dead grants; (4) replay ALL slices — own predecessor slice INCLUDED — through the common sealed-manifest + recovery-ownership + token-gated foreign replay engine (claim into a GUARD/RECOVERING state or durable descriptor, never publish a plain ACTIVE successor first); (5) publish ACTIVE / allow old-grant purge only after a durable RECOVERY_COMPLETE record; P237 supersession only with a matching durable recovery-complete proof. HB liveness scan: advisory/refusal only (validate crc/state/identity/(node,epoch)/host/boot/key on both samples; window >= formal death timeout incl. stalls; bracket with PR generation checks). Do NOT clear CAW bits / DLM recovery metadata because a PR key was replaced.
