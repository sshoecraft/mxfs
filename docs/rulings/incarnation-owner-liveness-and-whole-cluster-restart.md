## Ruling — Hole 1 (owner liveness)
- Owner liveness keyed by exact tuple (owner_node, owner_epoch), never node_id. Table: exact tuple == my incarnation -> continue; exact tuple another live incarnation -> WAIT; same node_id different live epoch -> owner REVOKED, eligible for takeover; no exact tuple heartbeating after expiry -> eligible; two live epochs for one node_id -> invariant violation, fail-stop.
- Remove EVERY "owner_node alive => WAIT" branch (incl. reacquire path). SUPERSEDED = "my cached ownership is invalid; reclassify", not "prohibited from takeover".
- Same-node adoption = ordinary takeover CAW: owner=(R, epoch_new), owner_term = T+1; R never inherits epoch_old auth. Never compare random epochs numerically (equality only); add claim_gen/previous_epoch if lineage is wanted.
- Unfenced incarnation takeover is sound ONLY if the ladder is incarnation-fenced: takeover = one CAW from the observed image; every stage CAW carries owner tuple + term; no non-idempotent side effect after an unguarded lease check (idempotent replay / INTENT(term,step) / term-checked target / drain); stale async completions revalidate via CAW. If any unguarded non-idempotent step exists: fallback = fence the whole node_id PR key (sacrificing the live successor) then take over.
- Revocation interval: exact tuple's lease expired + no renewal through the abandon interval (covers skew + outstanding-command bound).
- Invariants: at most one live tenancy per node_id; ownership always a tuple; owner_term increments on every transfer; only exact tuple+term advances; steps safe 0/1/N times across term changes; a node alive under another epoch is NOT evidence the owner is alive.
- Tests (13): same node_id nonexistent epoch; same node_id live different epoch; loss during reacquire (the harness case); concurrent same-node adoptions (one CAW wins); old owner side effect then resumes after takeover; delayed completion under old term; crash after takeover CAW; crash after side effect before stage CAW; takeover at every stage; two slots same node_id -> fail-stop; forged 'future' epoch; slot loss/reclaim mid-recovery; whole-node PR fence while same-node successor active.

## Ruling — Hole 2 (unattended whole-cluster restart)
- REJECT low32=node_id/high32=boot-hash key. USE full 64-bit unpredictable PR key, one per host BOOT per LUN, same key on all paths; plus a CAW-protected on-disk registrant ledger: pr_key -> {cluster_uuid, stable_host_uuid, initiator_identity, full_boot_uuid(128b), key_generation, state}. Reserve key in ledger atomically, check against REPORT KEYS, regenerate on collision. Incompat feature bit; no mixed 32/64 semantics (also addresses D-PR-KEY-32BIT-NODE-ID-COLLISION-RISK-377).
- Self-replacement of own predecessor key allowed only when: same stable host identity; DIFFERENT authentic boot uuid (immutable per kernel boot); topology guarantees non-concurrency (no duplicate IQN/host uuid, no VM clone/snapshot resume — refuse on any duplicate-identity/session-reinstatement evidence); all I_T nexuses covered; target PR semantics validated (REGISTER AND IGNORE EXISTING KEY, P&A, PTPL); verify afterwards with READ FULL STATUS. Same-boot predecessor stays refused (current rule).
- 'heartbeat-dead + holder absent' is NOT a fence (paused host may resume). Foreign host: HB expiry authorizes fencing; successful P&A + verification is the certificate. Same host previous boot: proved boot transition + registration replacement/P&A.
- Bootstrap sequence: Phase1 establish boot identity + PR key (no slot claim / fs write before a valid PR identity); Phase2 bootstrap coordinator lease, claim slot with new (node_id,epoch) PRESERVING the prior occupant's dirty recovery generation (change layout if it cannot represent live tenant + unrecovered prior generation); Phase3 scan old slots/ledger, observe through death interval, re-scan before each fence, never fence a newly live boot, P&A each dead foreign boot key, persist certificates; Phase4 recover own previous slice after own key cleared, foreign slices only with certificates, term-fenced ownership, release coordinator last. Lone survivor replays 32 slices.
- Tests (19) incl. all-32 simultaneous boot, boots straddling the death timeout, same-boot dirty remount still refused, duplicate IQN refused, cloned VM refused, multipath predecessor on a non-current path, old key is holder vs registrant only, PTPL reset between P&A and verify, torn ledger update, forced key collision, target says success but READ FULL STATUS still shows old key -> mount fails, peer publishes new key while first node scans (not preempted), first node crashes mid-fence / mid-own-replay, 32-bit-key node mount rejected.
