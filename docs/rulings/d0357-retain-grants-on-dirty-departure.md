# sess433 RULE-5 ruling — D-0357 (dirty unmount releases on-disk grants before replay -> notheld)

Verdict: the fix shape (in-core teardown WITHOUT on-disk unlock on a recovery-required departure; grants stay held by the withdrawn incarnation; survivor's P&A + manifest seal captures them; existing post-replay purge frees them) is correct and makes dirty unmount == crash. Conditional on:

1. STOP-SHIP predicate: not raw `xfs_is_shutdown()`. Explicit one-way departure state: RECOVERY_REQUIRED (default, fail-closed) vs CLEAN_RELEASE_OK (set only after durable clean-unmount proof: unmount record written, flush/FUA ok, no shutdown/withdraw intervened). Invariant: an incarnation may release its on-disk grants only after durable proof that no replay-eligible image of that incarnation can require them. `release_on_disk_grants => CLEAN_RELEASE_OK && hb not WITHDRAWN && no remote recovery required`; `WITHDRAWN || PR key retained || recovery_required => no on-disk unlock`. The WITHDRAWN stamp and the PR-key retention must key off the SAME classification (they already use xfs_is_shutdown at put_super — unify).
   Cases that must stay recovery-required: GOINGDOWN variants, umount -f, EIO/flush failure on the final unmount record, an MXFS withdraw that did not force XFS shutdown, partial teardown, anything unknown.
2. STOP-SHIP ownership: grants must be owned by {node_id, incarnation}; a same-node remount must not adopt/unlock/recognize the predecessor's grant (MXFS: node_id is minted per mount from a random UUID, so identity is per-incarnation by construction — verify the lock-table compare uses it and the plain-acquire fast path cannot alias).
3. STOP-SHIP ordering state machine: withdrawn observed -> P&A complete -> predecessor cannot CAW/write -> serialize against all purge/reclaim -> seal manifest from a consistent view -> replay -> durably commit completion -> purge -> allow new-incarnation acquisition. P&A failure/ambiguous = no seal, no purge, no adoption. NO purge on ATOMIC-SKIP/POLICY-REFUSED/manifest mismatch: grants stay held, domain quarantined, slot consumption is the intended fail-closed (needs an explicit admin repair story). Crash after replay-commit before purge must be idempotent.
4. STOP-SHIP audit every indirect unlock path: ICLUSTER sweepers, shrinker/LRU eviction, final puts, error unwinds, delayed unlock work, mount-shutdown cancellation ordering. Lifetime invariant independent of unmount: `on-disk unlock => no replay-eligible image can still require this grant generation` (ICLUSTER churn makes violations likelier; if sweepers can release during normal operation while tokened images are unlanded, fixing put_super alone is insufficient).
- Departer-sealed manifest: WORSE as the authority (cannot prove completeness / no-writes-after); usable only as diagnostic/cross-check.
- Manifest will be a SUPERSET of needed grants (cached unused grants) — fine if matching is sound and purge handles surplus.
- Tests: NOLOGFLUSH dirty departure (held through teardown, kind16, manifest has AG+ICLUSTER grants, replay complete, purge after); final unmount-record EIO; flush failure; umount -f + every GOINGDOWN mode; MXFS withdraw w/o XFS shutdown; clean-unmount control; same-node remount before recovery (must wait/fail); stale BAST; contender during teardown; P&A failure; crash at every recovery boundary; premature-purge injection; refusal keeps grants/quarantine; ICLUSTER-only dependency; sweeper race; mixed AG/ICLUSTER; near-capacity table; repeated failed recoveries; 3-node recovery contention.
