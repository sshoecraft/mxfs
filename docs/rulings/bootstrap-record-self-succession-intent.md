# sess439 GPT ruling — bootstrap record + self-succession (docs/whole-cluster-restart.md §5)

Question asked: (A) self-succession at REGISTER -EEXIST via identity+ledger then REGISTER-IGNORE + ledger FENCED-by-successor; (B) no bootstrap record, rebooter claims a free slot ACTIVE and runs the existing pre-mountfs barrier over all dead records; (C) full occupancy 64 dead; (D) refusals.

Verdicts: A UNSAFE, B UNSAFE for total outage, C(a) dedicated slotless bootstrap record SAFE+recommended, C(b) claim own predecessor slot into GUARD conditionally safe (fallback only, not general: replacement hardware, needs provisional identity anyway), C(c) 63-node cap unnecessary if C(a), D SAFE baseline + additions.

A hazard (concrete): peer P wins the predecessor slot's fence-intent CAS; S REGISTER-IGNOREs old_key → P's P&A sees KEY_ABSENT_UNPROVEN; S crashes before its ledger FENCED → unprovable residue (sess93 bug reintroduced). Fix: REGISTER-IGNORE is issued ONLY by the owner of a durable CAS fence intent on the predecessor slot's descriptor with method=SELF_SUCCESSION naming {victim tuple, old_key, old_key_gen, old_boot_uuid, successor provisional identity, expected transport-ID digest, bootstrap term, nonce}. Peer-owned intent always wins: S waits/consumes P's PREEMPT_ABORT_DONE and registers normally from absent state, never writes SELF_SUCCESSION_DONE. If S wins, peers issue no P&A for old_key. Certificate kind SELF_SUCCESSION_DONE valid iff: boot_uuid differs, target-confirmed nexus reinstatement (old task set aborted) on every predecessor path, READ FULL STATUS shows old_key absent on ALL transport IDs and new_key present on every successor path, no unclassified registrant/holder; result+certificate CAS'd under that intent; later slice-recovery owner consumes it by intent id/term, never infers from absence. Unknown absence stays KEY_ABSENT_UNPROVEN.

B: per-slot descriptors answer "who fences/replays THIS slice"; they do not give (1) closed recovery manifest for the outage term, (2) durable provisional identities/terms for slotless actors, (3) no ACTIVE publication / no xfs_mountfs before global RECOVERY_COMPLETE(term), (4) global completion evidence, (5) registrant-set closure (old keys with no slot). Cross-slice LSN ordering NOT required if the sealed-manifest token model is order-independent (it is) — bootstrap owner may delegate slices. The mounter being ACTIVE during the barrier is the ordinary survivor model but UNSAFE in bootstrap: the fresh incarnation is BOOTSTRAP_PARTICIPANT/GUARD, not ACTIVE. Async settle residue is not an escape: wait or abort, never mountfs.

Bootstrap record (dedicated CAW sector): state IDLE|CLAIMED|MANIFEST_SEALED|RECOVERING|RECOVERY_COMPLETE; bootstrap_term; owner provisional identity {host_uuid, boot_uuid, provisional node_id/epoch, pr_key, key_gen, nonce}; heartbeat stamp; fs_uuid; sealed victim-slot bitmap; ledger generation/hash; manifest hash; completion bitmap; crc. Claim/takeover/seal/stage/complete = CAS; heartbeat = CAW against expected term/owner. Stale owner: fence/certify its key FIRST, then CAS to higher term, then take over its per-slot terms.

Descriptor additions: bootstrap_term, intent_id, method PREEMPT_ABORT|SELF_SUCCESSION, expected old key/key_gen/boot_uuid, transport-set digest, command result, certificate. Ledger additions: FENCE_INTENT state, bootstrap term, successor relationship, slot intent id, method+certificate ref; ledger-only intent for a manifest registrant with no slot.

Order: Phase 1 acquire bootstrap identity (validate all slots+ledger+bootstrap rec+READ KEYS/FULL STATUS on every path; refuse on inconsistency; fence prior bootstrap owner; CAS CLAIMED; heartbeat; CAS MANIFEST_SEALED with bitmap/hash). Phase 2 successor registration (ledger PREPARED with succeeds(); CAS predecessor descriptor to SELF_SUCCESSION intent; confirm boot boundary + reinstatement; REGISTER-IGNORE on our paths; stable FULL STATUS on all paths; CAS SELF_SUCCESSION_DONE; CAS pred ledger FENCED ref cert; CAS ours REGISTERED; skip 2-7 if PREEMPT_ABORT_DONE already certified). Phase 3 fence every manifest registrant (one CAS intent each; consume self-succession certs; unknown absence aborts bootstrap). Phase 4 recover every slice (GUARD, consume cert, CAS ownership+term, token-gated replay, purge grants, CAS per-slot RECOVERY_COMPLETE; concurrent OK; do not zero evidence before global completion). Phase 5 verify all complete → CAS bootstrap RECOVERY_COMPLETE(term, hash) → then convert GUARD→ACTIVE or zero+claim → ACTIVE heartbeat → xfs_mountfs.

Additional refusals: old key tied to >1 host_uuid; >1 non-retired predecessor candidate for our host; our boot_uuid under another identity; key/key_gen rollback/ABA; unclassifiable transport ID; FULL STATUS unsupported/unstable/inconsistent across paths; unknown reservation holder; old key on a transport ID not proven ours; nexus teardown unprovable on any predecessor path; incomplete multipath (a path unavailable); ledger/slot/bootstrap/FULL STATUS disagree on fs/host/boot/key/gen; live intent owner on predecessor descriptor; bootstrap term owned by a live different incarnation; bad crc/slot binding/stale term; old key absent with no cert/intent explaining it.
