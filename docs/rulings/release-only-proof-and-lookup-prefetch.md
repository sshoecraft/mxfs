# sess495 GPT RULE-5 ruling — D-32NODE-SHARED-DIR-CREATE-PACE levers (2026-09-04)

Input: in-tenure create 15.2 ms on 0.70.12 = lkp 4.8 + dirsig 4.0 + other 2.3 + post_other 1.1 + rfr 1.0 + dlk 0.9 + dia 0.6; private dir 6.8 (lkp 0.3, dirsig 0). K~12, gap p50 7.7 s, h~45 ms.

## A. Release-only flush (dir_persig_flush 1 -> 0)
- The 32-node coherency A/B is necessary, NOT sufficient. Proof = an ORDERING proof per tenure epoch E: admission closed after BAST -> active modifiers zero -> log force through high_lsn(E) -> every write obligation of E COMPLETED (not submitted) incl. blocks removed/freed/committed-unwritten during the tenure, the dir inode core + fork map, alloc metadata -> unresolved=0 assert -> blkdev_flush COMPLETE -> only then CAW release submit -> peer acquire -> peer invalidate -> peer FUA read.
- Central implication: conflicting_acquire(E+1) => durable_home_frontier(E). For a normally visible unlock, replay must NOT be needed. Crash-before-release: acquisition must be recovery-gated.
- Trace assertions: no MOD_ADMIT after ADMISSION_CLOSED; every committed tx of E <= high_lsn(E); every obligation completed/superseded before DRAIN_COMPLETE; no release CAW before flush completion; no peer acquire before release completion.
- Strongest kill arm: observe durable release completion, kill holder before any later holder I/O, peer's direct FUA image must be correct WITHOUT replay of that tenure. Fault-injection points after every step from ADMISSION_CLOSED to peer first read.
- Required op arms before flipping the default: final create; unlink as final op incl. last live entry in a block; create-unlink / unlink-create same name; link+unlink; same-dir rename; cross-dir rename both lock orders; rename-over; mkdir/rmdir incl. final rmdir; names at block boundaries; shortform->block; block->leaf->node growth; data block alloc, leaf/node split, free-block updates; deletions that free a block/mapping; dir inode size/format/extents/gen; log wrap; forced replay for crash-before-release.
- Mode 1 could be masking: a drain that walks only current extents (misses removed/freed buffers); wrong obligation retirement; inode buffer omitted; peer acquiring before release completion; gen invalidation loss; grantless lookup/readdir; d_revalidate stale dentries; PR holder using cached bufs across invalidation; readdir cursor across epoch; RCU path-walk without grant validation; recovery granting before replay+flush.

## B. Lookup term (if H-L1 holds)
- PREFERRED FIRST: epoch-prefetch using the NORMAL xfs_buf read + verifier machinery — submit per-block FUA reads asynchronously / bounded parallel after the tenure-start evict. Extent-staging (one READ(16) per extent + copy into buffers) is a SECOND buffer-I/O implementation (locking, in-flight exclusion, verifier selection, b_ops per block type, LSN/owner checks, DONE ordering) — only as a second optimization if command count remains the bottleneck, and only with: buffer-lock + recheck after the I/O (still !DONE for the new epoch, no in-flight, dirty, pin, log item, obligation, stale; mapping unchanged); exact verifiers chosen by logical region + whitelisted magic; DONE then epoch stamp then fresh, publish last; page-based (not high-order contiguous) memory; honor max transfer size.
- Trylock-skipped evict buffers: keep an epoch on every buffer; a skipped buffer retains its old epoch and the read path must detect+reread; never a dir-global "evict done" bit.
- Torn-image risk: none beyond the on-demand path IF the release proof (A) holds — the extent is a stable image after flush-complete -> unlock -> acquire.
- Evidence: per-epoch prefetch submit/complete, per-block daddr/type/verifier/epoch, trylock skips, recheck failures, fallback on-demand reads; assert no prefetch before EX acquire, no block accepted with older epoch, no copy into dirty/pinned/logged; results identical to a cold on-demand traversal; test with concurrent local lookup/readdir pressure at tenure transition.

## C. Tenure batching (K)
- Secondary and riskier: doubling K saves ~1.9 ms/create vs 7-8 from A+B. Never op-count-only quantum after BAST; need wall-clock AND op bound, no renewal while a waiter exists, no barging, FIFO/oldest-waiter, age threshold collapsing the quantum, immediate yield when holding other grants. First establish why first-in-tenure waits average 5 s.
- Priority order: (1) prove+enable release-only, (2) drop modify-refresh under continuous EX, (3) fix lookup amplification, (4) remeasure h/K/5 s wait, (5) only then a bounded quantum.
