# sess463 GPT ruling — symmetric directory sharding, stages 1-2 concrete shape (D-32NODE-SHARED-DIR-CREATE-PACE / D-401; owner doc docs/dir-sharding.md)

Verdict: directionally acceptable, NOT code-ready as proposed (S4-S9 must not be coded literally). Invariant: an ordinary op takes LOGICAL-PARENT PR + exactly ONE shard lock; no MDS, no per-op RPC.

## Q1 flags/manifest vs metadir
- Use two newly allocated MXFS-private di_flags2 bits (AUDIT free bits — do not assume bit 6), the MXFS incompat sb bit + envelope flag + proto-gen; a reserved ROOT-namespace manifest xattr on the visible parent. Do NOT build an upstream metadir tree. Flags accepted only when sb incompat + envelope + proto gen agree (and clustered mode). Update XFS_DIFLAG2_ANY users, formatters, copy/bulkstat/scrub paths.
- dinode verifier enforces only dinode-visible facts: container = S_IFDIR + flag requires feature + not also parent-flag + legal fork formats (be careful with strict nlink==1 — transient values in deletion/recovery; make nlink a scrub check unless proven constant); parent = S_IFDIR + attr fork legal. Manifest validity is a separate mxfs_dirshard_manifest_load() under the parent lock: magic/version/exact length/N in {16,32,64}/hash id/key/set uuid/state/no dup inos/inos valid/nonzero gens/entry count consistent with state (COMPLETE/PUBLISHED exactly N; ALLOCATING committed prefix or validity bitmap)/parent ino+gen bound/reserved zero/explicit length + digest.
- Do NOT make generic xfs_iget refuse containers (wrong layer; scrub/replay/inactivation need it). Instead: containers never have dirents (finding one via lookup = corruption); exportfs/open-by-handle reject; bulkstat/enumeration/handle/scrub/repair policies; internal mxfs_dirshard_iget() validating {ino, gen, flag, owner set}.

## Q2 lifecycle (unlinked ALLOCATING parent accepted as anchor IF transactionally closed)
- Each shard: create container + append {ino,gen} to manifest in ONE txn (never a committed container with nlink 1, no unlinked membership, no manifest ref). "Allocate then append next txn" is REJECTED.
- Publication atomic in one txn: add visible dirent + remove parent from unlinked list + normal link state + COMPLETE->PUBLISHED (else define COMPLETE+linked as a legal recoverable state everywhere; atomic preferred).
- Deletion restartable: parent unreachable + unlinked-anchored; DELETING; per entry: verify {ino,gen}, free container, atomically clear/mark the entry; parent freed LAST. Restart must distinguish still-owned / already free / freed-and-reused (gen check => "already gone", never free the new inode, never fatal).
- Unlinked-inode processing calls a shard-aware inactivation BEFORE generic truncation/free; foreign replayer: true parent DLM EX, load+validate manifest, each container under its own authority, resume cursor, parent last. Crash injection after every txn boundary.

## Q3 routing/locks
- GLOBAL ILOCK_EXCL->DLM PR remap REJECTED (chmod/chown/ACL/xattr/project/timestamps/flags/repair/rmdir all legitimately modify the parent core). Introduce explicit modes: MXFS_DIR_PARENT_PIN (parent DLM PR, manifest immutable) and MXFS_DIR_PARENT_BARRIER (parent DLM EX); native ILOCK_EXCL unchanged (= DLM EX). Ordinary sharded create/lookup/unlink explicitly take pin + one shard lock; never infer distributed mode from ILOCK_EXCL.
- Do NOT redirect inside xfs_dir_createname (too low: manifest load, iget, DLM acquire, ilock, ijoin there breaks reservation/join/lock assumptions). Add an upper dispatch layer: pin -> load manifest -> canonicalize+hash -> iget+lock shard -> create txn with the SHARD as physical dp -> call unchanged dir2 primitive; a descriptor carries {logical parent, physical shard}. Lookup must not ijoin.
- Timestamps: shard core changes; parent core not dirtied; getattr synthesizes into kstat ONLY (never copy synthesized values into the parent in-core inode); include the parent's own core ctime (chmod etc.).
- nlink: with container nlink baseline 1, logical nlink = 2 + sum(container_nlink - 1) (NOT -2). Child dir '..' = visible parent; needs special child create/remove handling (shard summary changes, parent persisted base nlink unchanged); generic xfs_dir_add_child cannot just be handed the shard.
- True parent EX needed for: rmdir/emptiness (parent EX + all shards in canonical order + remove dirent + enter deletion atomically), chmod/chown/project/ACL/xattr/timestamps, manifest repair, fsync barrier, resharding, lifecycle transitions.
- Lock order (document + lockdep, stage-2 prerequisite): 1 parent pin/barrier; 2 shard inode locks by ino/resource number; 3 target inode locks per XFS rules; 4 AG DLM/AGI/AGF in established order. Never iget/shard-DLM while holding AG DLM/AGI; resolve+lock shard before inode-allocation sections.

## Q4 stat/readdir/dcache
- stat O(N): measure cold path (N=64 x ~6 ms rebuild). mtime/ctime = max(parent core, shards); define st_size AND st_blocks policy. NO per-node "never go backwards" clamp (nondurable, skew-prone). i_version folded sum is NOT a monotonic change attribute — use a documented hash cookie or a durable logical sequence later; never the sole dcache mechanism.
- readdir: reserve cookies 0/1 for logical . and ..; skip each shard's own ./..; unpack logical cookie {shard idx, local dataptr}, pass only local dataptr to shard readdir, repack; 7 bits or an explicit EOF sentinel (index 64 not representable in 6 bits); never set the sign bit; handle llseek/telldir/seekdir/partial buffers/resume at shard boundaries; test shortform/block/leaf/node incl. max-size dirs.
- dcache: shard-keyed events do NOT invalidate visible-parent dentries. Need one of: event translation {shard ino,name}->{parent ino,name} invalidation; d_revalidate hashing the name to its shard and checking a shard change sequence; or negative-dentry lifetime pinned to a cached shard PR grant + BAST invalidation. Cover negative/positive after peer unlink/rename/eviction/event-ring overflow (overflow => invalidate all dentries of affected parents or force revalidation)/missed notification. STOP-SHIP (board tests readdir/lookup coherency).

## Q5 stage-2 exposure: Model A (strict experimental opt-in) recommended: default OFF; activation narrow (ioctl/inheritance flag, NOT a mount-wide "all mkdirs" option — that would shard the rsync per-node dirs and fail rename-over-existing); unsupported ops fail deterministically -EOPNOTSUPP (not -EXDEV); never fall through to the parent's empty dir2 fork; directory fsync either real (parent EX + all shards barrier) or -EOPNOTSUPP with the feature nonproduction. Child mkdir under a sharded parent: implement full '..'/summary semantics or refuse. Model B (board-transparent) requires rename same/cross-shard/-over-existing, sharded<->unsharded rename, hardlinks, child dirs, rmdir, recreate, fsync, crash handling = the later stages.

## Q6 hash: keyed strong hash — SipHash-2-4 with a per-directory 128-bit random key in the manifest (crc32c + public seed is adversary-weak); manifest fields hash_id, hash_key[16], name_canon_version, N; route on the exact canonical key dir2 comparison uses (mkfs_mxfs has no asciici, so exact bytes today); versioned, byte-order specified.

## Q7 ranked STOP-SHIP: 1 explicit lock modes (pin/barrier); 2 routing above dir2; 3 transactionally closed lifecycle; 4 dcache correctness; 5 rmdir/emptiness barrier; 6 real directory fsync before production exposure; 7 nlink formula + child '..'; 8 readdir cookies; 9 feature-bit + verifier audit; 10 namespace coverage/gating; 11 written lock graph + lockdep; 12 quota/accounting policy (charge shard blocks to the visible dir's owner/project; containers not exposed).

## Pre-stage-3 rig evidence (N=16/32/64 + unsharded + private baselines, >=5 clean runs each)
Perf: unchanged 32-node workload wall per run, median/worst, per-node distribution, 3200 count, cold checksums, zero retries/EIO/verifier errors/event overflow; HARD GATE every production-default board run < 90 s; explicitly sharded run materially better than 70-100 s; N=32 near the private baseline — stage gate p95 <= 30 s. Report per N: parent DLM EX acquisitions in ordinary ops (expect 0), parent PR + cache hit rate, shard EX acquisitions/waits/BASTs/handoff latency, ops per shard min/max/sd, shard cold rebuilds count/time, log-force/writeback/flush time from handoffs, txn retries, manifest cache misses.
Stat/readdir: warm+cold stat p50/95/99, cold igets per stat, full readdir time, small-buffer repeats, telldir/seekdir at every shard boundary, all 4 formats, no dup/missing, exactly one ./.., peer mutation during readdir.
Dcache: A negative -> B creates -> A resolves without drop; positive then peer unlink; replace; ring overflow injection; shard eviction with parent negatives; BAST during lookup; drop caches everywhere and repeat.
Lifecycle crash matrix: kill/fence after every txn boundary (parent alloc/unlinked insert, manifest create, each shard append, COMPLETE, publication, PUBLISHED, namespace removal, DELETING, each container free/clear, parent free); after replay: no partial visible dir, no lost published dir, no leaked container, no stale manifest freeing a reused inode, no parent stuck unlinked, chk clean; AGs spread, allocating node fenced.
Namespace (if board-enabled): rename incl cross-shard/over-existing, hardlinks, child mkdir/rmdir + '..' traversal, rmdir+mkdir same name, create vs rmdir races, chmod/chown/ACL/project vs peer creates, fsync vs mutations; else prove the narrow opt-in refuses with EOPNOTSUPP and board dirs are not sharded.

## Final shape: three explicit objects — Manifest pin (parent DLM PR, immutable PUBLISHED manifest, validated cached shard table); Physical-directory resolver (canonicalize+hash, internal iget with gen/owner check, one shard PR/EX, returns {logical parent, physical shard} BEFORE txn setup); Parent barrier (true DLM EX, blocks pins; lifecycle/rmdir/parent metadata/fsync/repair).
