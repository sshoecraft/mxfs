# sess440 GPT ruling — item 5 (slotless bootstrap) build-level review

Plan put to it: A entry = survivor scan (2 reads ≥ dead window; no advance + ≥1 member record ⇒ bootstrap regardless of free slots); B provisional identity {node_id, fresh epoch, key}, owner_slot=0xFFFF; C seal = keys named by dead records only, slotless REGISTERED entries left alone, unclassifiable key ⇒ abort; D phase-3 fencing via the existing recovery_acquire pipeline in dlm_init; E dlm_init returns BOOTSTRAP_OWNER (node_slot=-1), xfs_mountfs hook before xfs_log_mount runs the barrier loop with the `!mp->m_log` guard relaxed; F RECOVERY_COMPLETE ⇒ ordinary claim/join from the hook; G waiters poll bounded.

## Verdict: phase structure (claim, seal, fence all, replay all, global commit, then ACTIVE) CORRECT; implementation NOT shippable as proposed.

### Q1 survivor scan — acceptable: one dead window, two samples. It is a failure detector, not proof; safety comes from fencing every presumed victim. Requirements: FUA/validated reads, monotonic clock, each record unchanged ≥ full death interval INCLUDING read-loop duration, torn/unparseable occupied records fail closed, re-read bootstrap state right before claiming and SEAL FROM A FRESH SCAN AFTER winning CLAIMED, detect identity/state/generation changes not just stamp increments. Ledger is NOT a liveness vote. Winning CLAIMED must close ordinary admission (already: P-BOOT-ADMISSION-REFUSED).

### Q2 epoch — mint ONCE; the provisional epoch MUST be the epoch that later becomes ACTIVE (never mint a second in phase 5). Sentinel 0xFFFF UNSAFE until every owner_slot consumer is audited; prefer an explicit owner_kind=BOOTSTRAP field: `if owner_kind==BOOTSTRAP: require owner_slot==NO_SLOT, consult bootstrap owner_is(node,epoch,term/nonce) else: owner_slot<nr_slots, consult HB sector`. Audit list: every owner_slot index/sector offset, liveness/steal paths, CAS validation, bitmaps/shifts, range asserts, u16/int/-1 conversions, tracepoints/chk_mxfs decoders, slice-from-owner-slot derivations, cleanup/terminal handling.

### Q3 slotless registrants — UNSAFE to exclude: under WE-AR a registered key can WRITE; a process that registered then stalled before claim can resume. Manifest must account for EVERY non-owner key. Classify each key at seal: owner / victim-with-slice / slotless pre-bootstrap registrant (FENCE, nothing to replay) / post-claim waiter explicitly bound to this term (durable ledger state WAITING_FOR_BOOTSTRAP{term}, I/O-inert) / valid self-successor / unclassifiable ⇒ abort. Simplest robust: fence ALL non-owner keys at the seal cut; waiters re-register after RECOVERY_COMPLETE. At global completion re-run READ FULL STATUS: no unexplained key may remain. manifest_hash is not a manifest: takeover needs the immutable key/identity/gen records themselves.

### Q4 m_log==NULL shadow replay — STOP-SHIP on a 2-line relaxation. Must audit every accepted item handler (buffer/inode/quota/intents: xfs_log_force, mount AIL, xfs_trans alloc, delwri ownership, verifier shutdown paths, workqueues outliving the shadow log, completion writes through mp->m_log, silent skips when NULL). Proof = call-graph audit + test with m_log POISONED (not NULL) + lockdep/KASAN + fault injection + all item types + assert no trans/mount-AIL/DLM/grant use + synchronous drain before return. Never temporarily assign shadow to mp->m_log. Alternative (needs its own review): fence whole sealed set → pick one victim slice → recover it through the NORMAL xfs_log_mount path → adopt as provisional recovery journal → use for remaining slices; requires proof cross-slice ordering permits it + durable GUARD/adoption protocol.

### Q5 per-slot zeroing before global completion — NO. complete_bitmap+CRC cannot reconstruct erased record/key/gen/certificate/outcome. Either preserve every victim sector+descriptor until the global RECOVERY_COMPLETE CAS, or ESCROW {victim identity, certificate, replay result, completion gen} durably on the bootstrap side before zeroing. Per-slice order: cert durable → recovered metadata durable → slice log clean/adoptable durable → workers/delwri drained → per-slot completion evidence durable → bootstrap bit durable → only after GLOBAL completion erase. Terminal/quarantined slice ≠ recovered: global completion must be a terminal volume-level refusal (or RO/admin) unless quarantine containment is separately proven for RW.

### Q6 peer self-succession vs owner P&A of old key O (peer new key N): (1) swap wins + successor entry durable ⇒ owner consumes SELF_SUCCESSION_DONE, N is NOT a victim; (2) swap wins, ledger not yet durable ⇒ KEY_ABSENT_UNPROVEN, retry later; a peer crashing permanently between swap and publish is PERMANENTLY unprovable — needs an admin/protocol repair path (pre-existing hole), never guess from seeing N; (3) P&A wins ⇒ peer's swap(rk=O) fails, peer re-registers N fresh as a waiter, must NEVER publish a false `N succeeds O`; (4) ambiguous transport completions resolved ONLY by READ FULL STATUS: O present/N absent retry; O absent/N present+durable successor ⇒ cert; O,N absent + sealed P&A evidence ⇒ owner cert; O,N absent no evidence ⇒ unproven; both present ⇒ do not certify, investigate multipath; (5) a successful no-op P&A on an absent key proves NOTHING. Waiting N must be either a durable term-bound inert waiter or fenced as slotless — never ignored.

### Q7 adopted slice for xfs_log_mount after foreign replay: before per-slot completion: all recovered metadata durable, delwri/workers drained, post-recovery head/tail/cycle durable, slice marked clean/unmounted OR adoption gate durably set (reuse slice_adopted only if it encodes these), no shadow AIL refs, completion marker ordered after, HB sector not zeroed before that point. Do not rely on replay idempotence. ACTIVE slot allocator selects only in-range, successfully recovered+adoptable, non-terminal slices.

### Q8 takeover after owner crash mid-phase-4: immutable sealed manifest (full identities), persistent per-victim certificates, persistent per-slice completion evidence ordered after replay writes, owner fencing before takeover then CAS term+1, resume trusting a completion bit only with validated evidence, re-acquire/replay every incomplete slice, reconcile READ FULL STATUS before resume and before global completion, no new victims added to an old manifest without a reseal/new-term protocol. MISSING FROM PLAN: exact-owner SAME-BOOT RESUME (same key cannot be P&A'd, self-succession proves nothing here): resume keyed by {host,boot,node,epoch,pr_key,key_gen,nonce,term} with local single-process exclusion, resuming the SAME term. Every destructive op revalidates term before starting and before publishing; -ESTALE stops promptly; drain outstanding I/O before relinquishing.

### Q9 STOP-SHIP list: (1) slotless keys unfenced without a term-bound waiter protocol; (2) post-seal registrant races not reconciled before replay and before global completion; (3) m_log==NULL replay without the full audit; (4) evidence erased before global completion; (5) same-key same-boot retry called takeover; (6) no precise durable ordering (replay → log-clean → descriptor complete → bitmap → zero); (7) terminal slice counted as globally recovered; (8) provisional ≠ ACTIVE epoch; (9) 0xFFFF sentinel without audit/owner_kind; (10) no final READ FULL STATUS reconciliation.
