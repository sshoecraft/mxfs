# sess453 design ruling for 0.60.0 (the review-#3 conditions)

Proposals D1-D9 as sent are in the transcript; verdicts:

- **D1 (settle_absent: fresh bracket + CAS under probe_lock; monitor only enqueues ABSENT_CANDIDATE to a settle worker) — ACCEPT WITH CHANGES**: (1) key must be incarnation-unique or keep a durable registration/settlement interlock — hazard: settler proves absent, a later incarnation re-registers the reused key, settler flips EMPTY, new incarnation crashes before claiming → live registration with no record [MY NOTE: MXFS keys are {host,boot,LUN}-derived and reused only by the same host within one boot under its departure mutex; every REGISTER is ledgered (P-PRKEY-PUBLISHED) so a pre-claim crash is the ledger-orphan case (D-377 item 4), independent of settlement — state this in review #4]; (2) the settle worker must take the host-wide departure mutex: lock order departure_mutex → probe_lock → snap_lock; (3) every local PROUT under the departure mutex (assert); (4) never hold snap_lock over the CAW (check inval_seq under snap_lock, drop it, CAW under probe_lock); (5) reservation loss / conflict → UNKNOWN, never success; CAW via the same PR-protected path. Delete the ABSENT-use ring only with incarnation-unique keys. Use an enum out-param, not int-overloaded states.
- **D2 (spinlock gate; reject after FROZEN with -EIO; wait for inflight==0) — ACCEPT WITH CHANGES**: freeze first, reject later submissions, THEN drain those admitted before the transition; any rejected submission → DIRTY (no release, no unregister); inject -EIO at the bio level through the normal end-I/O path exactly once (never bypass b_io_remaining); a drain TIMEOUT must not free completion state (abort+drain, keep waiting, or a refcounted accounting object that outlives the last completion) — "continuing teardown while inflight != 0 is not acceptable"; timeout must account for dm-multipath retry/queue_if_no_path; decrement+zero test under the lock (or atomic with documented ordering), wake on transition to zero.
- **D3 (free sb/workqueues/shutdown_devices BEFORE freeze/release) — REJECT**: order = unmountfs + final flush → FROZEN → drain admitted I/O → freesb/workqueues/shutdown_devices (gate rejects anything they submit → DIRTY) → release CAW via the cloned disklock handle → late unregister via a separately pinned bdev/PR handle → release handles.
- **D4 (counter audit a-d) — ACCEPT WITH CHANGES**: one token per logical xfs_buf lifecycle; b_mxfs_io_counted set/test under a rule preventing two submitters; decrement exactly once on every terminal completion (success, error, partial-inode, rejection, cancel, shutdown completion, resubmit exhaustion); detect overflow too; never repair-then-retire; audit direct bios/flushes/discards/log+rt devices/split-clone; late-completion test (force timeout DIRTY then complete → no UAF, no release CAS); lockdep/KCSAN runs.
- **D5 (admission requires REGISTER/READ KEYS/READ RESV/RESERVE + nonzero key; -EOPNOTSUPP refuses clustered; override no longer sets self_retire_ok) — ACCEPT WITH CHANGES**: fence_capability_override must NOT admit clustered RW without proved fencing (diagnostic / non-clustered / RO only); single_node_exclusive stays the explicit escape hatch; a failed admission probe must clean up its REGISTER/RESERVE (no untracked registration); combine with D7's CAW verification.
- **D6 (proof struct + validate_fn adjacent to CAS; mutex assertion; MULTI → refuse) — ACCEPT WITH CHANGES**: token must be non-copyable in effect (identity + used state kept inside scsipr; caller gets an opaque id); hold probe_lock from validation through CAW (snap_lock only for validate+consume); a failed CAW still consumes the token; peer P&A during CAW → conflict/UNKNOWN; assert the exact mutex owner; MULTI refuses without touching records or claiming; repair requires fencing/verifying the key first.
- **D7 (delete -EOPNOTSUPP→FUA fallback in settle paths; P304-RETIRE-NOCAW; WAITING) — ACCEPT**; companion: exercise CAW against the real disklock LUN/path stack at mount (size, alignment, atomic compare, via dm-multipath under the reservation) and refuse clustered v5 on failure; runtime CAW loss fails closed; other fallback sites must be unreachable for an admitted mount.
- **D8 (atomic probe flags; bounded join; deliberate leak on timeout; watchdog) — ACCEPT WITH CHANGES**: on join timeout → DIRTY, no unregister while a bracket may be active, quarantine the WHOLE probe object (ctx, bdev/path refs, request state, callbacks, module ref), thread must hold no pointers to mount/disklock/sb/workqueues, stop kicks before join, reaper on eventual exit, global tracking + persistent marker + refuse another clustered mount on the same device/host until resolved; prefer bounded/fail-fast PR IN; the settle worker blocked in settle_absent needs the same treatment.
- **D9 tests — ACCEPT, drop none, ADD**: key-reuse/incarnation (pause after KEYS B, register from a later incarnation); malformed brackets (gen change, own key missing in A or B, resv type/holder change, duplicate keys, truncated/overflow) → UNKNOWN + no CAW; local PROUT vs paused settle_absent; runtime CAW loss → record byte-identical; probe-stop timeout/quarantine; late completion after drain timeout; proof replay; CAW compare mismatch (-EAGAIN, reread); multipath failover between bracket and CAW, queue_if_no_path. No-PR injection: opcode-selective SCSI fault injection / scsi_debug, not a dm error target.

**Landing order (changed)**: G1 = D5 + D7 + admission/fail-closed tests; G2 = D1 + D6 + D8 + settlement/replay/race/stop-quarantine tests; G3 = D2 + D3 + D4 atomically + freeze/drain/late-completion tests; G4 = remaining D9 + multipath + full board. Each group independently fail-closed and rig-verified.
