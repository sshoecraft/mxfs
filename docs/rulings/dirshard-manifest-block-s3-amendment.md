# sess464 ruling — dir-sharding manifest placement (amends the sess463 "manifest xattr" shape)

Why: 512-byte inodes (mkfs_mxfs) => a 1120-byte manifest can never be shortform; a leaf xattr modified inside a running transaction goes via xfs_attr_defer_add = deferred attr intents, atomic with the first commit ONLY under LARP (ATTRI/ATTRD intents) — which would add a new intent type to foreign-slice replay while D-FOREIGN-SLICE-INTENTS-ABANDONED is open. Without LARP the append is torn across a crash.

## Ranking
1. S3 (chosen): ROOT xattr "mxfs.dirshard" = immutable 12-byte LOCATOR {manifest_ino, manifest_gen}, written once at parent allocation while the attr fork is empty (guaranteed shortform, synchronous, same transaction as the parent + PARENT flag). Authoritative manifest = one fsblock of an internal HOLDER inode (S_IFREG, CONTAINER flag, UNLINKABLE, nlink 1), written as a LOGGED METADATA BUFFER (symlink-remote pattern, NEW block type — never XFS_SYMLINK_MAGIC): header {magic, offset, bytes, crc32c, uuid, owner, blkno, lsn} + reciprocal {parent_ino, parent_gen, holder_ino, holder_gen} + the manifest. Every lifecycle step = memcpy + xfs_trans_log_buf in the SAME transaction as the container allocation / publication / deletion step.
2. S2 (2048-byte inodes) — correctness fallback, likely fails the derived-budget rule; bigger inodes don't guarantee shortform once ACL/security attrs arrive.
3. S1 (deferred xattr + LARP) — REJECTED while foreign-slice intent recovery is open.
Amendment text: "The ROOT xattr is the immutable manifest locator; the authoritative manifest body is a verified metadata block owned by the locator-designated internal inode. Both are validated while holding the visible parent's DLM EX/pin."

## Holder inode containment (all required)
No dirent; exportfs/open-by-handle reject; no mmap/read/write/DIO/iomap/reflink/swapext/verity/truncate/speculative prealloc/page-cache instantiation; the extent is accessed ONLY through xfs_buf with the manifest xfs_buf_ops; exactly one mapped block, no holes/COW/shared; validate magic, uuid, blkno, holder ino, parent ino+gen, manifest gen/count, crc, version/LSN; scrub/repair/chk_mxfs know nlink==1 + no dirent is intentional (never lost+found); inactivation must not truncate it for being unreachable. xfs_bmapi_write inside the creation txn OK only with worst-case reservation (ialloc + extent alloc + locator insert + block init/log), NO xfs_defer_finish/roll before all four are present, block fully initialised + fully logged before commit, ENOSPC/cancel leaves neither holder nor locator committed. Require fsblock >= header + 1120 (else feature disabled). rmap off => inode ownership suffices (holder = owner if rmap later); reflink/COW forbidden. Define quota policy (system identity or explicitly exempt; never surprise EDQUOT). Count inode+block in statfs/reservations.

## Locator soundness conditions
Insert before ACL/security/LSM init (or reserve literal space); insertion API must not roll or defer; log PARENT flag + locator in the same transaction/inode log item; prevent removal/replacement via every xattr interface; later shortform->leaf conversion by unrelated attrs must not lose/rename/expose it (crash-test the conversion). Don't repurpose an existing dinode field. Locator >= {manifest_ino, manifest_gen}; block reciprocally carries {parent_ino, parent_gen, holder_ino, holder_gen}.

## Cross-slice recovery ordering (STOP-SHIP #1)
Raw per-log LSNs from independently advancing slices are NOT comparable; DLM EX serialises live writers but does not give a durable recovery order (slice A old image vs slice B newer image). Need ONE of: (1) globally comparable durable monotonic authority/version token embedded in the image + log image, replay applies only if newer than on-disk (monotonic across handoffs/reboots/log-cycle reuse, unique or tie-broken, survives owner death — an ephemeral LVB alone is insufficient, carried by ALL mutable objects or used to order whole transactions); (2) forced handoff/checkpoint rule (log-force + durable before EX transfer; dead owner's slice recovered before the EX is granted) with proof that two slices never hold competing uncheckpointed images; (3) globally ordered replay. A custom xlog_recover_get_buf_lsn case suffices only if the "LSN" is globally comparable. Also live coherency: dirty ownership flushed/transferred/invalidated under the DLM protocol before another node mutates the block. (sess464 note: MXFS already has the cross-slice buffer-LSN veto rule from D-0517 (0.61.3-0.61.7) and authority tokens on log images — the manifest block must ride the SAME mechanism as every other logged buffer; verify, don't assume.)

## Ranked STOP-SHIP (S3)
1 cross-slice global ordering/fencing proof; 2 fix foreign-slice EFI/EFD handling before relying on reap/inactivation (S3 adds no intent type but teardown/free/inactivation/reap still generate existing intents); 3 prove "one transaction" = one commit (audit rolls, deferred bmap/free, dir splits, ialloc, log-reservation exhaustion); 4 prove locator shortform creation; 5 deletion sequencing: remove publication/manifest authority atomically first, physical reclamation via a crash-recoverable orphan/reap state (no roll required in the namespace step); 6 recovery/type plumbing (XFS_BLFT_*, verifier restore, replay validation, crc, log-range reservation, stale-image veto, scrub/repair/metadump, endian tests); 7 internal-inode containment; 8 capacity/accounting (min fsblock, ENOSPC reservation, quota, worst-case log res); 9 generation + reciprocal ownership checks everywhere (inode reuse); 10 crash matrix before/after each commit (holder alloc, append, publish, unpublish, parent delete, holder inactivation, node death, foreign reap) with replay order permuted across slices.
