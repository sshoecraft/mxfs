# sess439 ruling — PR key: register before ledger

MEASURED (chain 17 s438c, 0.43.0 sv 7B7247CB): first node mounts + takes WE-AR; every later node's ledger CAS (a write) → RESERVATION CONFLICT (`P-PRKEY-PREPARE-FAILED idx=1 rc=-52`) BEFORE it registers → `P-PRKEY-SELECT-FAILED` → mount ENOTCONN on 31/32 nodes. Under WE-AR only registrants may write ANY on-LUN metadata (ledger, bootstrap record). No separately writable area exists.

Ruling:
- Ledger-before-REGISTER is unimplementable. Permitted order: derive key → establish/replace ONLY our own registration → verify → durably publish → only then any op affecting other registrations. The initial REGISTER may create an unattributed PTPL registration but must never preempt/unregister another nexus.
- Derived key SAFE: domain-separated canonical hash(host_uuid‖boot_uuid‖fs_uuid[‖LU id]); boot_uuid invariant across reloads; forcing bits costs entropy (document ~63-64 bits); check derived key against PR registrations AND non-retired ledger entries; collision = hard refusal, NO redraw. key_gen=1 is not the ledger slot's CAS generation (keep seq).
- Order: derive K → generation-consistent READ FULL STATUS/READ KEYS → classify: K on our TransportID = reuse; K on foreign TID = collision refuse; predecessor key on our own nexus = self-succession; unregistered = REGISTER(RK=0,SARK=K) → verify K on required paths → CAW ledger entry to REGISTERED {K, host, boot, fs, node_id, transport set, generation} (no PREPARED) → re-verify → claim.
- Loss vs before: crash between REGISTER and ledger write = orphan registration, an explicit protocol state (UNCLASSIFIABLE); same-boot retry repairs it (same derived key); a different boot may stay fail-closed; peers must never guess and delete. Only a host-local trust anchor could close that fully.
- Self-succession: option (iii) — ordinary REGISTER(RK=Kold, SARK=Knew) on each own nexus holding Kold (target-side compare; conditionally changes only this nexus; NO on-LUN intent needed). Never REGISTER AND IGNORE EXISTING KEY as the normal path. Then FULL STATUS verify Knew present / where Kold remains → CAW successor ledger entry REGISTERED{Knew, succeeds={Kold, old_boot, old descriptor generation}} → if Kold remains ELSEWHERE: CAS predecessor descriptor to SELF_SUCCESSION_INTENT, only the holder issues P&A, verify absent, CAS certificate. Peer-owned intent ⇒ successor never replaces/P&As; peer consumes successor evidence.
- Peer P certifying an absent Kold as REPLACED_BY_SELF_SUCCESSOR requires ALL: P still owns the exact intent generation; stable global absence of Kold across ports; durable CAW'd successor REGISTERED record naming exact Kold + old boot/descriptor generation + Knew + succeeds; FULL STATUS shows Knew on the expected TID set; transport continuity rule satisfied; no conflicting chain; honest certificate kind (not "P preempted"). Absent Kold with no successor record = KEY_ABSENT_UNPROVEN, retry; never certify.
