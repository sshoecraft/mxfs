# sess428 GPT ruling — D-0349 eager page activation (2026-08-28)

Design put to GPT: an eager pass in the 500 ms handoff tick that runs dlm_page_acquire on every page the view names ours but not yet ACTIVE(self), N per tick, gated on the 20 s settle window; measured motivation = 1092 P-TAUTH-REMASTER-PARKED on 1083 distinct pages in the s430 token sweep (first-touch parking at 100 ms retry cadence).

## Rulings
1. Formation flood: **option (c)** — the exclusively-fenced bootstrap node does `UNOWNED -> PREPARED(target, target_inc)` in ONE durable transition (nothing to drain from UNOWNED; intermediate ACTIVE(bootstrap) buys nothing). CAW must compare the complete expected UNOWNED image incl. seq; target = owner under the bootstrap's SETTLED membership generation; D-0347 fencing guarantee retained; stale bootstrap op harmless after a generation change. **REFUSED (b)** (each node claims its own UNOWNED pages: under false death the wrongly-surviving node could win the race first). Lowering per-tick alone is NOT the fix (leaves the serialization bottleneck): required = bootstrap-side bounded DEDUPLICATED queue keyed by (page, generation), an accepted/pending reply so requesters stop 500 ms re-sends, rate from completed durable I/O, demand handoffs prioritized over eager, durable ops OUTSIDE the TCP message handler and the tick (bounded ledger-I/O worker). Until that exists: **2/tick/node as a temporary safeguard** (not 16).
2. Concurrency: no distinct durable eager state, but one shared per-page acquisition object (in-progress, expected seq/state, membership gen, target inc, outstanding req id, retry deadline, waiters); eager + request callers JOIN the same in-flight op rather than each sending FREEZE_REQ; completion re-checks durable header + membership gen. The tick should only ENQUEUE, never call a blocking acquire.
3. Keep the settle gate. Eager-acquired pages have identical semantics; every acquisition generation-bound (revalidate before each durable transition; obsolete-generation completions never satisfy current waiters; grant only if durable ACTIVE identity AND view assignment match).
4. Do not use a plain bool (lost wakeup vs a membership change mid-pass): `eager_required_gen` / `eager_completed_gen`; publish completed=G only if view gen still G, fair scan done, all our pages ACTIVE, no pending transition; per-generation scan cursor.

## What sess428 landed (stage A, w038 → tree): option (c) `mxfs_tauth_ledger_prepare_unowned` used by the FREEZE_REQ handler; eager pass with required/completed gen + cursor; knob `mxfs.tauth_eager_per_tick` default 2; stats in P-TAUTH-DLM-STATS (eager_passes/acquired/parked, handoff_parked) + `P-TAUTH-EAGER` line per productive pass.
