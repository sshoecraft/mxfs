## 1. Root cause of BOTH wedges: SCST `scst_pr_read_full_status()` overflow
- `/src/scst/scst/src/scst_pres.c`: `size`/`size_max`/`offset` signed, `rec_len = 24+ts` is `uint32_t`; `size` accumulates SKIPPED registrants too, so once it passes `size_max` the `size_max - size > rec_len` compare promotes to unsigned (~4e9 > rec_len) and every remaining registrant's TransportID is memcpy'd past the command data buffer. `scst_pr_read_keys()` above it is safe only because its literal `8` keeps the compare signed. Arms when the registrant list outgrows MXFS's 4096-byte probe (`pal/linux/kern.c:3813 mxfs_pal_scsi_pr_read_full_status`, standard SPC resize-on-ADDITIONAL-LENGTH): ~53 iSCSI registrants; 32 nodes × 2 mpath paths = 64. Nothing about MXFS is wrong; single-digit/16-node evidence unaffected.
- 08-21 victim: a live QEMU page-table page — `Bad page map pte:66786d2d36317473` = LE ASCII "st16-mxf"/"s-node,i" (TransportID `...test16-mxfs-node,i,0x...`); oops in `vm_normal_folio <- change_prot_numa`, vCPU exited irqs-off → `migration/49` stuck >387 s in `multi_cpu_stop` → RCU stalls → jbd2 `__wait_on_buffer` with nvme idle → journald unkillable → manual reset. Preceded by `scst_set_resp_data_len ***ERROR***: Too big response data len 4496/4848/5024 (max 4096)`.
- 08-20 victim (CORRECTION of the first read "pure jbd2 deadlock from the trace flood"): pstore/ERST `dmesg.txt` oops #3 `jbd2_journal_grab_journal_head+0x29` with RDX=`bh->b_state`=ASCII "stq9-mxf": bit 16 (BH_JBD) set by accident → `b_private` NULL → `jh->b_jcount++` at NULL+0xc = the faulting address. That boot reached Oops #9, tainted `G D W` by oops #3; the corruption timestamp was ~23 h before the wedge — the host was corrupting memory for 2+ days.
- Fix `+caw-abort-reclaim.4` (built, installed, verified): bound against `offset`, signed types, clamp to `min(buffer_size, cmd->bufflen)`, stop at the first non-fitting descriptor, ADDITIONAL LENGTH still reports the full length; two wrap-prone guards hardened (`ext_size+28` ~1234, `tid_buffer_size+24` ~1759). **iscsi-scst MUST be rebuilt too** (SCST_INTERFACE_VERSION) or the target silently never comes up. `tests/scst_pr_bounds_check.sh` (+`tests/scst_pr_fullstatus_bounds.c`) proves OLD SIGSEGVs at 64 registrants vs NEW stops at offset 4056/addl 5632 against a PROT_NONE guard page, and asserts the INSTALLED scst.ko is .4+. NEVER reproduce against an unpatched module. Worth upstreaming.

## 2. Evidence rules learned
- A wedged host's journal is not the record: journald stops when root ext4 wedges — `journalctl -b -N -k` showed zero BUG/Oops for a boot with nine. Read `/var/lib/systemd/pstore/*` (systemd-pstore drains `/sys/fs/pstore` at boot; empty pstore proves nothing) and the ERST header `Oops#N`. clyde's backend is erst.
- The 182 lines/s SCST `scst_check_scsi_atomicity` TRACE_BLOCKING flood (1.07M lines/98 min) swallowed the overflow's own `Too big response` warnings, filled the 40 MB journal tail and 716 KB ERST buffer, and drove the reclaim that hit the corrupt buffer_head. Absence of the printk is NOT evidence the overflow did not occur. Debug tracing left on destroyed the evidence for the bug it was left on to find.
- 32-node MXFS evidence gathered while `+caw-abort-reclaim.3` or earlier was loaded (the sess385/386 split publications, #361 chain, node deaths, 474 legs) is SUSPECT — the overflow can land in another SCSI command's data page (data in flight to the LUN). Re-measure on `.4`; do not close/reopen ledger entries on that basis alone (precedent: sess137 ruling on the fileio bvec UAF).
- 25 stale PR registrants survived the host reset with 0 sessions; with 32 rejoining that is 89 registrants (bigger overflow on old code; phantom peers to MXFS fencing). Check/clear stale registrants at rig bring-up.

## 3. The structural coupling (sess385 wedge shape)
`/sys/kernel/scst_tgt/devices/mxfs/filename=~/disk.img` (o_direct) AND all 32 guest qcow2 root disks live on clyde's ONE 92%-full ext4 (`/dev/nvme0n1p2`, 1.8T); one jbd2 journal serializes all of it. Symptom order: guests answer ping not ssh; guest serial logs show `jbd2/dm-0-8` (guest ROOT, not mxfs dm-1) blocked; `virsh destroy` times out; on clyde 875 D-state threads (813 qemu `worker`, 47 `iscsi_conn_cleanup`), loadavg 870, nvme 1.6% busy, 39 GB free = lock deadlock, stacks `ext4_buffered_write_iter <- pwritev` queued behind `jbd2_log_wait_commit`. Tipping load was my own per-AG-release probe (P85 census ~1000 lines/node/chunk → guest journald → virtio → qemu pwrite into qcow2): instrumentation that cannot be left on is not instrumentation — P85/P86 are now anomaly-gated. Standing fix (user's call): move the LUN + guest images off root ext4 or keep it <80%. Triage: `sudo tools/clyde_wedge_diag.sh` (the unkillable-wedge rule-safe: /proc stat/comm/stack only; reports, never acts).

## 4. One wedged qemu domain (sess384, test4) — `tools/recover_wedged_domain.sh`
qemu leader zombie with D-state sub-threads in `ext4_buffered_write_iter` (writing the SERIAL log on host ext4 — not MXFS); libvirtd fine but deadlocked on that domain object (`virsh domstate test4` never returns, `virsh list --all` hangs). Five blockers surface one at a time: `/run/libvirt/qemu/<d>.*`; virtlogd lock on the serial log (keyed by PATH, survives rename → repoint XML); virtlogd lock on `<d>.log`; virtlockd lease on the image (unbreakable while the zombie holds the fd → point the domain at a COPY, `cp --sparse=always`, 26 GB/75 s); machined `MachineExists` → `machinectl terminate qemu-<id>-<d>`. ~3 min, no host reset, restarts libvirtd+virtlogd (guests survive). Does NOT scale to 12 domains (312 GB copies vs 151 GB free). The restarted guest has no /src (NFS not an fstab automount). `run.sh` `power_cycle_node()` virsh calls are now `timeout 60` — never add an unbounded `virsh`. A domain that cannot be power-cycled stays mounted and self-fences `P131-SELF-FENCE fs_uuid mismatch` when prep re-mkfs's under it (prep convergence stuck at active_count=30).

## 5. Guardrails now in place (the guarded-host rule)
| thing | does |
|---|---|
| `scripts/clyde_preflight.sh` (run.sh calls it before `marker_read`) | hard-fails on halt flag, taint BAD_PAGE/oops/softlockup/MCE, D-state >20, SCST < `.4`, SCST trace mask, kernel-log rate, fs floor (<90% used AND ≥60G free), journald caps; `MXFS_PREFLIGHT_SKIP=1` only when the gate itself is broken |
| `tools/clyde_kmsg_guard.sh` + `mxfs-clyde-guard.service` | tails /dev/kmsg; halts rig (`.rig_halt`, snapshot to `/src/mxfs/.evidence/`) on CORRUPTION/PRECURSOR/FLOOD (>60 lines/s for 2 consecutive 5 s windows; a single long window lets a mid-window flood escape); bound-pauses guests via `virsh suspend` on CORRUPTION only; never reboot/sysrq/destroy/rmmod/dmsetup/sync; reads only stat/comm/stack |
| `scripts/scst_setup.sh::reset_trace` | resets SCST trace mask every rig build |
| `tests/scst_pr_bounds_check.sh` | proves the PR fix is in the INSTALLED modules |
| `/etc/systemd/journald.conf.d/50-mxfs-rig.conf` | SystemMaxUse=4G, KeepFree=100G, RateLimitBurst 2000/30 s |
Calibration: clyde kernel log during a full 32-node campaign ≈1 line/s. Traps: `kernel.dmesg_restrict=1` → a rate check that reads nothing looks quiet (preflight FAILS when it cannot read); parse `/proc/<pid>/stat` state after the `)` closing comm; guard uses bash `[[ =~ ]]`/`$SECONDS`, no fork per line; evidence to /src (NFS), never clyde's root ext4. Later (2026-08-21, user decision): `panic_on_oops=1, panic=30` + `mxfs-crash-latch.service` archives pstore and halts the rig on the boot after a crash.
