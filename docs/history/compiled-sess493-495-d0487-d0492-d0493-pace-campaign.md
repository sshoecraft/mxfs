## D-32NODE-SHARED-DIR-CREATE-PACE (post-closure focus, sess494-495)

Baseline (0.70.12): in-tenure create cost 15.2ms = lkp 4.8 + dirsig 4.0 + other 2.3 + post_other 1.1 + rfr 1.0 + dlk 0.9 + dia 0.6; private-dir baseline 6.8ms (lkp 0.3, dirsig 0). Per sess487's GPT ruling this decomposes into 3 levers: (A) release-only flush (`dir_persig_flush` 1→0), (B) lookup term, (C) tenure batching (K).

- **H-L1 (lookup = cold FUA re-reads) REFUTED.** sess494 MID3/MID4 queued s494h (0.70.13, `lkp_fua`/`lkp_fua_ms`/`lkp_rd` instrumentation on P132) to test it. sess495 MID2 result: in-tenure `lkp_ms` 4.85, but `lkp_fua_ms` only 0.36 (7% of lookup cost), p50 FUA=0 (67% of lookups do no FUA read at all), and ~23 plain (non-FUA) read bios per lookup node-wide vs 0.30 in a private row. The FUA reads are not the cost — H-L1 dead; live hypothesis H-L2 is the plain bios (or msleep waits). 0.70.15 added `lkp_trace` (`P495-LKP-WIN`/`P495-LKP-RD`, `LKP_TRACE=1`) to attribute them. `docs/history/docs/history/docs/history/compiled-sess493-495-d0487-d0492-d0493-pace-campaign.md` `docs/history/docs/history/docs/history/compiled-sess493-495-d0487-d0492-d0493-pace-campaign.md` `docs/history/docs/history/docs/history/compiled-sess493-495-d0487-d0492-d0493-pace-campaign.md`
- **Mode 0 (persig=0, chain 139 A/B, 0.70.12).** Coherency-clean: mode 0 passed every coherency row A passed, `cc_FAIL` 0 across all B sweeps — release-only is not unsafe on this evidence. But it is NOT faster: `cc_fresh_B` 0/32 reached verify (vs some in A), in-tenure 14.3ms vs A's 15.2ms is barely better, and first-in-tenure creates fell (K ~7 vs ~11) meaning tenures got smaller/more frequent under B. Conclusion: mode 0 alone is not a viable lever; needs the ordering proof below before being taken seriously as a fix, not just an A/B pass. `docs/history/docs/history/docs/history/compiled-sess493-495-d0487-d0492-d0493-pace-campaign.md`
- **GPT ruling (sess495) on all three levers:**
  - Release-only (A) needs a formal per-tenure-epoch ORDERING PROOF, not just a clean A/B: admission closed → active modifiers zero → log forced past high_lsn(E) → every write obligation of E completed (not merely submitted), including removed/freed/committed-unwritten blocks, inode core+fork map, alloc metadata → unresolved=0 assert → `blkdev_flush` COMPLETE → only then CAW release → peer acquire → peer invalidate → peer FUA read. Central invariant: `conflicting_acquire(E+1) => durable_home_frontier(E)`. Crash-before-release must remain recovery-gated. Required a large op-coverage matrix (final create, unlink-as-final-op, create/unlink interleavings, renames both lock orders, dir format growth transitions, log wrap, forced replay) and a kill arm (kill holder right after durable release completion, before any later I/O; peer's direct FUA image must be correct with NO replay).
  - Lookup term (B): PREFERRED approach is per-tenure-start epoch-prefetch using the *normal* xfs_buf read/verifier path (async/bounded-parallel per-block FUA submit), not a second bespoke extent-staging I/O path — the latter only if command count remains the bottleneck after B lands, and even then needs full relock/recheck-after-I/O, real per-block verifiers, correct DONE/epoch/publish ordering. Torn-image risk is bounded by the release proof (A) holding.
  - Batching (C): lowest priority/highest risk — doubling K only saves ~1.9ms/create vs 7-8ms from A+B combined; needs op-count AND wall-clock bound, FIFO/no-barging, before touching it. Priority order given: (1) prove+enable release-only, (2) drop modify-refresh under continuous EX, (3) fix lookup amplification, (4) remeasure h/K/5s-wait, (5) only then consider a bounded quantum. `docs/rulings/release-only-proof-and-lookup-prefetch.md`
- **Adopt-skip (dir_gen term).** 0.70.14 chain 141 leg A: skip fired on only 4/32 nodes, `rfr_ms` unchanged at 1.0 — peers' `DIR_MODIFY` ring bumps `i_dlm_dir_gen` mid-tenure and re-arms the read, defeating the skip. 0.70.16 fix drops the dir_gen term from the skip condition and prints `P495-ADOPT-READ` naming the mismatched term when it still fires. `docs/history/docs/history/docs/history/compiled-sess493-495-d0487-d0492-d0493-pace-campaign.md`
