## The three arms (sess180 measurement) and governing ruling
`docs/rulings/dirty-slice-teardown-and-claim-recovery.md`:
- Arm A (race): GOINGDOWN queues withdraw work; immediate umount cancel_work_sync'd it before it ran → withdrawn=false → clean release of dirty slice. Fix: depart_clean must include !xfs_is_shutdown + log-clean; put_super synchronously persists WITHDRAWN before DLM teardown; stamp failure fails closed (retain ACTIVE).
- Arm B (claim): disklock treated any non-ACTIVE non-GUARD sector as claimable → WITHDRAWN slice consumed dirty. Ruling: state machine ACTIVE → WITHDRAWN → RECOVERY_GUARD → durably-complete → CONSUMABLE; claimers must REFUSE WITHDRAWN (P274-CLAIM-WITHDRAWN-SKIP); claim-triggered recovery reuses the SAME survivor engine (CAS WITHDRAWN→GUARD, fence, replay, durable completion, zero, separate ordinary claim). GUARD is the mutex between survivor and next-mounter. PR fence + completion is NOT lineage authority for untagged images (inherits #1 status).
- Arm C (ordering): v5_shutdown zeroed the slot BEFORE xfs_unmountfs wrote the unmount record. Ruling: zero only after the unmount record + prior writes are durable (storage ordering); CONSUMABLE = "recovery completed durably OR clean unmount completed durably".
- single-node/no-PR recovery allowed only as HARD exclusivity with an explicit operator flag, never inferred from "PR unsupported". GOINGDOWN NOLOGFLUSH is crash-equivalent for slot disposition.
