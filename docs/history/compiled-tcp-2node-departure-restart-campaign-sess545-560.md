## D-0928 — never-live frozen heartbeat slots never declared dead ("ghost slots") (FIXED, verified)

Filed + fixed in `docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: `check_dead` (`dlm/disklock.c`) required `nt->live`, but a record already frozen at first sight (auto-monitored, `changed_samples=1 < LIVE_THRESHOLD`) never satisfies it and is never declared dead — the TCP path has no counterpart to CAW's step-6.5 stale-deferred mount-settle routing. Practical effect: two nodes restarting within a minute of each other means nobody ever recovers anything (measured: 21min post-boot, 0 deaths, 0 fences, 173 lock failures/node). Fix 0.75.70: `check_dead` fires when `equal_samples>=threshold && (live || last_timestamp!=0)`, new probe `P-HB-GHOST-DEAD`. Verified s559c: 6 ghost deaths declared, fences began.

## D-0929 — purged-PR-key previous-boot fence unprovable with only 2 live members (FIXED, verified)

Filed + fixed in `docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: on 0.75.70, all 6 fences came back `KEY_ABSENT_UNPROVEN`/`P238-FENCE-ABSENT-NO-SUCCESSOR` because the QNAP purges SCSI-PR registrations with the session (no self-succession record), and the sole-survivor gate (fence kind 20) requires `nlive==1`. Fix 0.75.71: new fence kind 21 `MXFS_FENCE_KIND_BOOT_SUCCESSION_ABSENT` — proof chain is victim identity frozen → `mxfs_disklock_host_live_other_boot` (same host, different live boot) → `mxfs_disklock_boot_advancing` (double-read 2.5s apart, refuse if advancing) → `mxfs_scsipr_exclusion_holds` (WE form, own key present, victim absent) → certify. Soundness argument: with N=2, every dead incarnation is either the sole peer (kind 20) or a previous boot of one of the two hosts (kind 21). Decided without a GPT consult per user rule. Verified in `docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: kind 21 certified on both nodes at 0.75.72 (`P238-FENCE-BOOT-SUCCESSION`, RMAN snapshot/seal, "foreign replay of slot N complete").

## D-0932 — dead provers' FENCING attempts never taken over (FIXED, verified)

Root-caused in `docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md` (H2, platter proof via `tools/disklock_hb_dump.py`): the ordinary (non-bootstrap) mount path never calls `v5_note_dead_inc` for a certified-fenced incarnation — that call exists only inside `if (ctx->bootstrap_owner && ctx->bootstrap)` in the ladder — so a dead prover's outstanding FENCING attempt is never recognized as REVOKED and never taken over. Fix plan: call `v5_note_dead_inc` at 4 sites — fence-certify success, `mxfs_v5_dlm_recovery_acquire` post-claim, the ordinary ladder, and `v5_recovered_cb`.

`docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: 0.75.74 built with the 4 sites + `P238-FENCE-HOLDER-STATE` instrumentation; s563 showed all six holders `UNKNOWN why='node not in the heartbeat table'` (their records had been zeroed by the D-0931 publish fix) — zero takeovers. 0.75.75 adds `v5_holder_slot_state(ctx, dead_slot, desc, holder, hepoch, why)`: a platter-read fallback when `v5_incarnation_state` returns UNKNOWN — reads the descriptor's `owner_slot` directly and classifies all-zero / other-tenant / EMPTY-under-same-tuple as REVOKED.

`docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: s564 on 0.75.75 — verdict REVOKED x6 both nodes, `P238-FENCE-TAKEOVER` x6 fired, CAS split correctly (winner term 1→2, loser -16 then correctly waits). D-0932 mechanism verified; blocked immediately after by D-0933.

`docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: `v5_holder_slot_state` extended in 0.75.77 to scan all 64 records for the victim tuple (not just the one descriptor slot) after 0.75.76 exposed "descriptor owner is not the holder being judged" x280 for provers that had already unmounted — EMPTY|RETIRE_PENDING under the tuple, or no record anywhere, now also classifies REVOKED. Full campaign PASS at 0.75.77 (s566): both nodes MOUNTED (80-82s), holder-state REVOKED found correctly, kind-21 fencing/replay/publish all converged.

## D-0933 — victim PR key not frozen at mount-pending admission; wrong key used for takeover (FIXED, verified)

Found in `docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: s564 (0.75.75) got `P-PRKEY-FENCE-REFUSED` x36 on test2 — `mxfs_disklock_victim_key()==0` because the mount-pending sweep (`mxfs_v5_dlm_mount_pending_recovery`) marked guard records pending without freezing the victim's PR key (only `fire_dead`'s `hb_ident_freeze_victim` and the bootstrap manifest did that), and separately the takeover call was passing the dead node's *node id* as the fence key instead of the real PR key. Trap noted: a census grep of `P-PR-` silently misses `P-PRKEY-` lines — grep with `-o 'P[0-9]*[A-Z-]*'` before concluding "nothing logged".

Fixed 0.75.76: `v5_mark_pending_from_record` (before `mxfs_v5_dlm_mount_pending_recovery`) freezes the victim identity at admission when record+epoch match, GUARD|WITHDRAWN, and identity/PR-key are valid (`P-ADMIT-VICTIM-FROZEN`); takeover now reads the real key and refuses cleanly (`P238-FENCE-TAKEOVER-NOKEY`) if absent.

`docs/history/docs/history/docs/history/compiled-tcp-2node-departure-restart-campaign-sess545-560.md`: s565 (0.75.76) surfaced two further causes, both fixed in 0.75.77 — (1) `hb_ident_crc` covers `flags`, but guard writers moved `flags` without `hb_ident_rebind`, invalidating the identity block; fixed by rebinding on flag moves. (2) the 280x "descriptor owner is not the holder being judged" case, fixed by the `v5_holder_slot_state` tuple-scan described under D-0932. s566 (0.75.77): PASS — six stale slices fenced (kind 21), replayed, published; both nodes MOUNTED.
