## D-0349 create-path root cause (2-node), fix candidates undecided
Reproduced on 2 nodes: `tests/tcp_token_plumbing_verify.sh` 2000-file token workload times out (rc=124) on both nodes with no PHASE line — create phase alone exceeds 30s. Traced with new harnesses `tests/ftrace_create_probe.sh` and `tests/create_grow_probe.sh`: single-node create cost rises from 6-7ms (first 400 entries) to 13-22ms once a dir passes shortform/one-block. `xfs_create` breakdown: `mxfs_dialloc_two_phase` (4.3-5.8ms, dominated by `mxfs_v5_dlm_inode_reserve_try` = EX NOQUEUE DLM lock on the new inode = ONE durable authority-ledger commit per create via `mxfs_tauth_page_write`) + `mxfs_dlm_dir_modify_refresh` (0.66-1.17ms, re-reads dir blocks every create once >400 entries) + lookup/icreate. H1 (ledger-commit-per-create) PROVEN. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

sess544 deepened this into a full design memo (no GPT consult, per user directive): a grant to a fresh inode resource costs 9 LUN round trips (2 reads + CAW ticket + flush + FUA body + flush + CAW publish + flush + readback, ~3ms avg, tauth_ledger.c/tauth_store.c). Remote grants commit inline on the single per-peer recv thread (serializes a master to ~285 commits/s). Inode resources hash to random pages (fnv1a), so consecutive creates never share a page and the per-page batch commit API can't amortize. Already-held resources are free (local/remote grant shortcut, no page write). Four fix shapes weighed, none decided: (A-par) prefetch/parallelize reservations — still IOPS-bound, can't clear 2x native; (B) deferred grant durability with a log-write barrier — contract change, needs a master-death pending-grant census; (C) AG-implied authority for fresh inodes in an AG this node holds EX — moves cost, changes token/replay model; (D, favored) route inode resources by inode GROUP so N consecutive inodes share one home page and one page-commit reserves up to 16 at once (~0.2ms/create) — requires `hash_version 3` + PROTO_GEN bump + mkfs/chk changes, also allows skipping the 2 base reads for a page this node solely writes. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

## D-0923 filed (critical) and FIXED — AG-meta track-hold leak on freed btree block
Root: `mxfs_ag_meta_track` (`xfs_trans_log_buf`) takes a hold + increments `pag_dlm_meta_pending`, released only via `mxfs_dlm_ag_meta_iodone` (write completion) or the reclaim-abort path. A btree block freed after being logged (`xfs_trans_binval` on leaf-merge/root-collapse) completes via `xfs_buf_item_finish_stale` — no ioend fires — so the hold+pending leaks for the mount's life; every subsequent release of that AG on that node then pays the full 2s Phase-3 bound (peer's 1s BAST deadline expires first). Reproducer: `tests/agmeta_stale_leak_2node.sh` (punch bnobt/cntbt to force btree-split/collapse, force AG hand-off, re-acquire). Fix (0.75.62, sv FE3D230637BE17CAB4390F6): `mxfs_ag_meta_reclaim_abort` renamed `mxfs_ag_meta_reclaim(bp, why)`, now called from both `xfs_buf_item_finish_stale` (new "stale" path) and the original abort branch; `P55-STUCKMETA` gains `stale=`/`tracked=` counters for verification. Awareness debt: `xfs.md:111` / `pal.md:1780` still reference the old `_abort` name. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

sess544 confirmed the second D-0923 consequence (an `xg_ref`/"Internal error" on unmount of the pre-fix build) was gone on 0.75.63. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

## D-0924 filed (critical), OPEN — xfs_buf slab leak at module unload
0.75.63's clean unmount check for D-0923 surfaced a new symptom: `rmmod` on test1 hits `kmem_cache_destroy mxfs_buf: Slab cache still has objects` (6 objects) every time an AG-meta-stale lap (agleak) preceded it; test2 stays clean. New harness `tests/fleet_unload_check.sh`. the instrument-first loop loop: added `P-STALE-FIN` (finish_stale completion, hold != 1) and `P-BCACHE-LEFT` (buf-cache teardown) probes — both fired SILENT while the leak still reproduced (6 objects again), ruling out staled-in-cache btree buffers as the cause. Added a global live-buffer registry (`mxfs_buf_live`, alloc/free tracked) reported via `mxfs_report_leaked_buffers()` after `rcu_barrier` in `xfs_destroy_caches` — this also came back silent on the leaking run, meaning the 6 buffers were *not* in any tracked cache/registry state at teardown. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md` `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

Further sampling showed the leak is **nondeterministic**: 6 objects on s544g/s545b/s545d (including an idle mount with no agleak lap at all — ruling out the agleak lap as a precondition) but 0 objects on s546a (a registry-instrumented build, idle, parallel unmount). Hypothesis H4: the 6 buffers are freed by a `call_rcu` callback that fires *after* `xfs_destroy_caches`'s `rcu_barrier` (i.e., a pending RCU free straddles the teardown window) rather than being truly unfreed. Built (0.75.64, third rebuild): `mxfs_buf_caches_destroying` flag set at `xfs_destroy_caches` entry; `xfs_buf_free` prints `P-BUF-FREE-LATE` + stack if freed after that point; registry now reports at two stages (after-barrier, before-cache-destroy). New harness `tests/unload_laps.sh <label> [laps] [mode] [idle]` to run N x {prep, idle, fleet_unload_check} and drive the sample size up. ## D-0925 filed (major), OPEN — concurrent whole-cluster unmount is slow, releases dropped
Concurrent unmount on both nodes: each node's DLM releases to its peer (as master) are dropped by the peer's own teardown quiesce (`P-TEARDOWN-MSG-DROP type=1`), retried 3x, then `P-TAUTH-RELEASE-WAIT unacked=N after 3000ms` — a straight 3s tax per concurrent unmount, leaving ledger records un-retired (consequence under a following remount-without-mkfs unmeasured). Attribution (sess544 MID4): the unmount wall clock is actually purge scan (~4.0-4.6s) + takeover scan (~4.0-4.4s), each being `mxfs_tauth_store_scan` walking all 26426 ledger pages x2 copies in 64KiB runs (206MiB total) at the LUN's ~116MiB/s. `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md` `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`

Fix designed at sess544 END, **not yet built**: (1) `mxfs_tauth_ledger_purge_owner_keep` — replace the full 206MiB candidate-scan pass with a walk of only this node's cached pages (`l->pages[p]`, `pg->img` + an ACTIVE(self) entry), since a page can only be ACTIVE(self) through this node's own cache; idle-mount check found cand=0 in 4.5s of scanning that could instead be near-zero. (2) `TAUTH_SCAN_RUN_PAGES` 16->256 (64KiB runs -> 1MiB runs, `kzalloc GFP_NOFS` via `mxfs_pal_alloc_io`) with a 256->16->1 fallback ladder, cutting the takeover scan from ~4.0-4.4s toward ~1.8s. Verification plan: `P-DEPART-WORK purge_ms` ~0, `takeover_ms` < 2000, serial last-out umount < 2.5s, and a death lap must still show `cleared>0` on the survivor's purge with replay verified. Must build only after the in-flight s547 unload-laps chain finishes (every prep copies the tree's `mxfs.ko`). `docs/history/docs/history/docs/history/compiled-tcp-2node-agmeta-bufleak-unmount-campaign-sess535-544.md`
