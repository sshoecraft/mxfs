## D-0517: foreign replay drops cross-slice buffer updates

**Root cause** (found chain 80, stated `docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`): `pal/linux/xfs_buf_item_recover.c::xlog_recover_buf_commit_pass2` (~line 1110) runs the upstream `disk lsn >= txn lsn` skip test unconditionally on foreign/clustered replay. Cross-slice LSNs are not comparable (each slice numbers its own log independently), so the test fires spuriously when the on-disk stamp belongs to a numerically-higher foreign slice. The inode-item recovery path already avoids this by using `di_changecount` instead of raw LSN (`xfs/xfs_inode_item_recover.c:400-434`); the buffer-item path did not. Effect: a victim's FREE core item is applied but the paired inobt/finobt bucket-free update is silently dropped — the mirror image of the earlier known create-half-applied bug. Exposure is any LSN-stamped shared block type (AGF/AGFL/AGI, btrees, dir/da/symlink, SB) left stamped by a numerically-higher slice without an in-tenure flush.

Probe `P-FR-BUF-LSN` (verdict SKIP|APPLY, blkno/magic/blft/txn_lsn/disk_lsn) landed as 0.61.3.

**H4 proven** at chain 81 lap 1 (`docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`): slot 26/AG 1 — AGI vetoed twice against a foreign disk_lsn, inobt/finobt not vetoed → chk shows inobt free=61 vs AGI freecount=60 (agino 130 FREE core, half lost). Contrast slot 25/AG 0 — AGI/inobt/finobt all vetoed but disk_lsn equals the victim's own head (it flushed after its last txn) → chk clean. Conclusion: the on-disk stamp cannot distinguish harmless same-slice idempotent veto from a genuine lost cross-slice update; only the token admission verdict (APPLY) is a sound authority.

**GPT ruling (the design-consult rule)** on the fix proposal (`docs/rulings/d0517-buf-lsn-skip-bypass-stop-ship-6-items.md`): STOP-SHIP on the first-cut design ("bypass on untrusted/clustered replay"). Required instead:
1. Bypass predicate must be exact `item verdict == APPLY` lineage/authority check, not a coarse "untrusted" flag — REDUNDANT_CLEAN/untagged/stale-lineage must stay fail-closed.
2. APPLY must correspond to a TERMINAL protected tenure (fenced after death, no successor grant before replay completes, no re-replay after a successor tenure) — assert this as an invariant, don't just infer it.
3. Scope audited per block class: AG headers/btrees and inode-adjacent structures serialized by the inode DLM resource are the only classes provisionally safe; primary/per-node SB, dquots/shared-quota blocks, RT metadata, and mixed-ownership buffers must keep the LSN check.
4. Do not touch `xlog_recover_dquot_commit_pass2`.
5. Preserve all non-LSN validation (verifier attach, UUID/owner checks, cancel table, malformed rejection) — the token is permission to write, not proof of validity.
6. The same exposure applies to **own-slice trusted recovery** — standalone recovery keeps upstream behavior, but clustered replay without a proven APPLY verdict must not simply disable the LSN compare.

**Fix landed 0.61.4** (`docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`): `xfs/libxfs/xfs_log_recover.h` adds `ri_mxfs_class`, set alongside the token verdict; `xfs_log_priv.h` adds `l_mxfs_buflsn_overrides` counter; `xfs_buf_item_recover.c` bypasses the LSN veto when `untrusted && verdict==APPLY && class AG|INODE`, logging `P-FR-BUF-LSN verdict=SKIP|OVERRIDE-APPLY tokverdict= class=`. New defect filed from this work: `D-OWN-SLICE-PASS1-RECLAIM-REPLAY-CROSS-SLICE-LSN-VETO-0521` (critical) — PASS-1 own-stamp reclaim replays the node's own dirty slice as *trusted*, with no token check at all (inode path there falls back to raw `di_lsn`), i.e. GPT ruling item 6's own-slice exposure, unaddressed. As of sess460 MID1 D-0521 was measured **unreachable** in the current build (`docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`): `node_uuid_path` is never set, so node_id is random per mount and PASS-2 always sees a fresh claim — fix owed once persistent node identity is wired.

**Fix verified** (`docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`, `docs/history/docs/history/docs/history/compiled-d0517-buflsn-review5.md`): chain 82 (0.61.4 LAB) laps 1-3 chk clean, SKIP=0; lap 3 shows `OVERRIDE-APPLY=4` (genuine cross-slice overrides, e.g. slot 30 AG-5 disk 0x1000010b6 > own head 0x1000010b5).
