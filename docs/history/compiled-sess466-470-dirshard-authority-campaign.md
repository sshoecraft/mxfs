## Dir-sharding stage 1 wired, then broken three ways
Stage 1 (docs/dir-sharding.md, 16 checklist steps: incompat bit, BLFT, dinode verifier, replay veto, ioctl 0xB7, mkfs/chk gates, PROTO_GEN 17->18) landed as tree 0.64.0, scratch-compiled clean (sv 93EE466F) with a design deviation — cache validity keyed on `ip->i_dlm_epoch` instead of hooking all 11 DLM-release sites — and one gap the checklist missed: `xfs_remove` needed a shard-emptiness barrier so rmdir of a full sharded dir doesn't orphan files. `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`

It did not work on the rig, in sequence:
1. **ENOTTY on every dirshard ioctl (0.64.0/0.64.3).** `pal/linux/xfs_ioctl.c` was never in Kbuild — the module's actual `xfs_file_ioctl` was the `xfs/xfs_stubs.c` stub (GOINGDOWN only), so the sess466 dispatch edit was dead code (objdump confirmed no reference to `mxfs_dirshard_ioctl`). Fixed in 0.64.4 by adding the `_IOC_TYPE(cmd)==MXFS_IOC_TYPE` dispatch to the stub itself. `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`
2. **MKDIR -> EUCLEAN (0.64.4).** `mxfs_dirshard_locator_set` demanded `i_af.if_format == LOCAL`, but `XFS_ICREATE_INIT_XATTRS` initializes the attr fork as EXTENTS and `xfs_attr_try_sf_addname` converts EXTENTS->LOCAL itself later — the precondition fired before the conversion ran. Fixed (0.64.6) by checking `xfs_attr_is_shortform(dp)` as precondition and LOCAL+empty-dfops as postcondition, plus new probes P-DIRSHARD-LOCATOR-FORK / P-DIRSHARD-STEPA-FAIL. `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`
3. **D-0526, three roots, filed critical (0.64.6 lap, chain 103).** (a) Creator side: `mxfs_dirshard_alloc_parent`/`alloc_container` never called `xfs_setup_iops` (only `xfs_setup_inode`), leaving empty i_op -> `DCACHE_AUTODIR_TYPE` -> ENOTDIR on every op under the sharded dir, on the creator only (peer used `xfs_setup_existing_inode` and was fine). (b) Peer side: `mxfs_dirshard_iget` used `XFS_IGET_UNTRUSTED`, which reads AGI/inobt *without* the AG DLM lock, so peer-allocated members ("legitimately not yet visible") reads back -EINVAL; `free_container` treated -EINVAL as "already freed," leaking container 133. Fix: a trusted iget probe (`mxfs_dirshard_iget_probe`, -ENOENT/-ESTALE only means gone) since a manifest entry is itself a dirent. (c) `xfs_readdir`'s IOLOCK assert fired on containers (no dentry/i_rwsem holder), producing 588 WARNINGs; fixed by skipping the assert for containers (the parent's i_rwsem is the container's real namespace lock) plus a new per-shard settle path (`mxfs_dirshard_shard_settle`: consumer_refresh + i_dlm_stale loop). Fixed 0.64.11/0.64.12 (sv E75DB637), GPT-reviewed. `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`

## D-FOREIGN-SLICE-INTENTS-ABANDONED: classless-image census and the A/B/Q3 ruling
Chain 93's intents burst showed 41 classless images (v=3 class=0, wrongly st=4 MISLABELLED): 39 one-block bmbt images from a fragmented-file create (contiguous runs, two block groups) and 2 DINODE_BUF images from iunlink `di_next_unlinked` updates. Root of MISLABELLED: `mxfs_auth_classify` falls back to that state whenever the AG epoch was held, the buffer isn't AG-authorized, and `mxfs_ownauth_measure` didn't return DURABLE — the real outcome (NOOWNER/UNCACHED/STALE/NONE/UNPUB/RELEASING) never reaches the wire. Instrumented in 0.64.1: P239-OWNAUTH-NONDUR, P227 blft/classless_blft histograms, `tests/intents_classless_attribute.sh`. `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`

**H1** (inactivation-image root): `xfs_inactive` takes the raw per-inode EX lock directly (`mxfs_v5_dlm_inode_lock(..., NULL)`), which never calls `mxfs_dlm_authority_install` — only the `ilock_begin` acquire path installs DURABLE_EX. An idle demote in the droplink->inactivation gap revokes the unlink's certificate before truncate/ifree dirty, so those images capture NONE/RELEASING at write time (the "recorder gap" class from sess104). The 2 DINODE_BUF images are NOOWNER by construction — inode cores aren't AG-authorized.

GPT RULE-5 ruling on fix order — **B, then A, then Q3**, never an interim AG/ICREATE inference:
- **Q2/fix B (accepted, landed 0.64.5):** iunlink DINODE_BUF images are legitimately AG class *only* for the iunlink-format image (di_next_unlinked lives in AG X by construction). Guard: exact AG EX grant at dirty time, AG(ino)==AG(buf)==AGI-txn-AG, restricted to `xfs_trans_inode_buf`/iunlink format (replay applies only di_next_unlinked). New `mxfs_buf_iunlink_ag_authorized`, `mxfs_auth_classify` now takes `tp`, P-IUNLINK-AGCLASS probe; replayer refuses a class-AG DINODE lacking `XFS_BLF_INODE_BUF` as MALFORMED. Requires the cross-slice buffer-LSN veto as a hard prerequisite (replaying a stale di_next_unlinked into a reallocated cluster corrupts).
- **Q1/fix A (accepted narrowly, reworked twice under GPT STOP-SHIP):** an inactivation certificate is sound *only* if installed from a completed grant result (never inferred from `i_dlm_mode==EX`), gen/routing rechecked under `i_dlm_lock`, installed before first dirty, revoked by exact {resource,epoch,lineage} at EXREL with no dirtying after revoke. First cut missed that GONE-at-EXREL must fail closed (a cert can vanish before final dirty) and that permanent refusal must escalate rather than silently persist — GPT caught both. Final shape (0.64.9): `i_mxfs_auth_inact` lifecycle (ACTIVE/LOST/DEFERRED), P-INACT-CERT-LOST, GONE/FOREIGN->shutdown, refusal-escalate >8->shutdown, seqcount-protected, knobs `mxfs.inact_cert_inject 1..5`. docs/authority-certificate.md tracks the mandatory verification arms. Not yet rig-verified end to end at sess470 close (chain 105/108 arms queued).
- **Q3 (rejected as unsound):** treating unpublished-EX bmbt images as safe-to-apply via AG-grant/ICREATE co-presence was refused — AG grants authorize allocation metadata, not inode-private bmbt contents, and authority can legitimately live on different nodes. Needs a real durable delegation protocol (parent AG tuple + owner ino/gen + child blkno/len/type + delegation id, proven by the frozen manifest); no interim heuristic.
Verification-arm target: victim destroyed inside EFD hold, `policy_refused_txns==0`, `classless_images==0`, `authority_mismatch_images==0`, quarantine reason == 8 only. `docs/rulings/intents-classless-images-fix-shapes-a-b-q3.md` `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`

## D-0525 — orphan-scan iget bucketed zombie (critical, filed and fixed same session)
From chain 99's peerloss kernel log: orphan scan can iget a member into a legacy single-node bucket, reload it, and hand it to inodegc without checking this node is authorized to reap that bucket. GPT design ruling, three parts: (1) bucket layout must be a persistent fs property, not the dynamic `single_node` predicate — a lone-survivor's legacy inserts are a leak hazard; (2) the find-across-64-heads walk needs AG DLM EX serialization as an explicit resolve/preflight phase, not embedded in reload callers; (3) after iget, stamp+reload only if this node is authorized to reap that bucket, otherwise suppress inactivation instead of ireleasing into inodegc. Fixed 0.64.10 (sv 1147AC59): static slot layout, `mxfs_iunlink_find_bucket` under AG EX in the ifree preflight (P-UNLPRE-FOUND), orphan-scan membership prewalk before iget, `MXFS_IF_FOREIGN_ZOMBIE` bit + P-INACT-FOREIGN-ZOMBIE-SKIP. Residual noted: pre-fix single-node legacy inserts still exist on disk. `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`

## Rig/harness traps hit during this campaign
- `tools/mxfs_pgrep.sh <pattern>` matches the *calling* Bash tool's own cmdline (it carries the pattern) — a kill loop that doesn't filter on the actual chain's script prefix (e.g. `bash tests/<chain>`) kills the invoking shell itself (exit 144). Hit twice (sess467, sess470). `docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md` `docs/history/docs/history/docs/history/compiled-sess466-470-dirshard-authority-campaign.md`
