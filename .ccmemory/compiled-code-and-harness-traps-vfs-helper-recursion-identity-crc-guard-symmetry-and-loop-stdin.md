This is an `assorted` group: the clusterer found no single topic. The notes split into code-level traps (kernel API, on-disk checks, guards, allocator liveness, mount ordering) and harness/measurement traps (where a run reads, what it counts, how it is launched).

## Code-level traps

**Same name, different function across kernel versions.** [[trap-a-vfs-helper-that-keeps-its-name-across-kernel-versions-can-become-the-dispatcher-that-calls-you-back]]: `inode_update_time(inode, flags)` on 6.x is the dispatcher into `->update_time`. On 7.x the same name is the helper that sets stamps and returns I_DIRTY_*. Called from inside `xfs_vn_update_time` on 6.x, it calls itself: 169 alternations, stack guard page, panic. The compiler cannot warn, because the older signature accepts the call. Before calling a same-named function under an `#else` arm, read its body in the older tree. Fix: take upstream 6.8's branch verbatim (`generic_update_time`) and use the guard `flags != (I_DIRTY_SYNC | I_DIRTY_TIME)`. The pre-5.12 guard `!(i_state & I_DIRTY_TIME)` is false on every call since 5.12, so the hook was inert. A live lap found the panic first, not the durability question it was built to ask.

**A CRC over a mutable field.** [[trap-a-crc-that-covers-a-mutable-flag-field-invalidates-an-intact-identity-block-and-the-fix-reached-only-one-of-its-readers]]: the disklock identity CRC covers `hb->flags`, but the guard writers move a victim to RECOVERY_GUARD without re-binding it, so an intact block reads invalid. The first fix (`mxfs_hb_guard_identity_valid`) reached only the admission reader. `dlm/bootstrap.c` kept the strict predicate and counted the guarded victim `noident`; `P-BOOT-KEY-UNCLASSIFIED` then refused bootstrap and no node could mount (`MOUNT_RC=32`). Lessons: prefer not covering a mutable field; when a laxer predicate is added beside a strict one, enumerate the strict one's callers then (`grep -n mxfs_hb_identity_valid dlm/*.c`, check each for a flags test excluding RECOVERY_GUARD).

**A guard written for the self direction.** [[trap-a-guard-written-for-the-self-direction-leaves-the-symmetric-peer-direction-open]]: the SCSI PR key is per boot, so two incarnations on one host share it. `P238-FENCE-OWN-KEY` blocks preempting our own previous incarnation, but a peer fencing a dead incarnation whose host has remounted preempts the live successor. When a guard's predicate names self, substitute any other live member and ask if it is reachable. Enforce at the primitive callers funnel through (`mxfs_scsipr_fence_node`, which covers all four fence paths). Exclude the victim by node id, not liveness alone. The guard fails closed, so test both directions: a control arm with a key nobody holds must not trigger it.

**Userspace SCSI tool and FUA.** [[trap-a-userspace-scsi-tool-that-sets-fua-in-the-cdb-fails-every-command-on-the-shipping-lun]]: the 2/tcp LUN answers READ(16) with FUA or DPO with ILLEGAL REQUEST 24/00. The kernel (`pal/linux/kern.c`) latches `mxfs_fua_read_unsupported`; `tools/recov_forge`, `caw_slotdump` and any new CDB-building tool do not. Mirror the fallback (retry once without FUA, latch, say so on stderr). A non-FUA read is fine for a sector you wrote yourself through the same nexus, not for arguing another initiator's write reached the platter. Never remove FUA unconditionally. `recov_forge` is built by no Makefile; a stale checked-in binary silently runs old code, so a harness must `cc` it first.

**Geometry macros before `xfs_mountfs`.** [[trap-a-mount-hook-before-xfs-mountfs-cannot-use-the-fsb-to-daddr-macros-because-m-blkbb-log-is-still-zero]]: `m_blkbb_log` is set only inside `xfs_mountfs`. Earlier in `xfs_fs_fill_super`, `XFS_FSB_TO_DADDR` and friends return fs blocks, off by 8x. The slice lifecycle zeroed 64 MiB of the data area at the wrong offset while the harness said READY and the control passed. In pre-mountfs code derive from `mp->m_sb` directly (`sb_agblklog`, `sb_agblocks`, `sb_blocklog`). Print the absolute offset acted on and compare it to an independent tool (`tools/slice_image.py geom`). A harness asserting only the fix's own log line passes a fix that hit the wrong bytes; the platter-side assertion carries the verdict.

**AG-exhausted vote.** [[trap-withholding-the-ag-exhausted-vote-from-own-refusals-hangs-a-create-whose-sole-free-number-is-refused-for-good]]: D-DIALLOC-REPICK-STORM carved 24 inode chunks against a one-chunk reservation. Making `swept` vote only on peer contention hung the create where the sole free inode number was refused for good (ILOCK held, 120 s budget abort, test1 power-cycled twice). `swept` means "no usable candidate this lap", whoever refused. Bound the dangerous action at the action (one carve per `xfs_dialloc` call, `mxfs_dialloc_carve_gate`, `P-DIALLOC-CARVE-BOUND`) and leave the signal honest. Reset `rs->swept` per AG. When a flag feeds two consumers, starving it to fix one starves the other. Verify a storm fix with the non-storm phases too.

## Harness and measurement traps

**Detectors run on nodes.** [[trap-suite-detectors-run-on-the-nodes-where-no-ssh-credentials-exist]]: `tests/suite/*.sh` detectors execute on the test nodes, which hold no ssh secrets. A helper reaching another host fails silently and returns its "unknown" path, so the cell shows SKIP with the wrong reason (`tools/mxfs_rig_tag.sh` read the LUN vendor over ssh). Read the node's local sysfs first; use the `/src` NFS mount for repo facts; for cross-node facts record them in the cluster marker at prep time. Verify the helper from the node: `tools/mxfs_sshpass.sh test1 "cd /src/mxfs && ./tools/<helper>"`.

**Busy text is not a cause.** [[trap-mount-busy-covers-two-different-ebusy-causes-and-the-discriminator-is-whether-the-kernel-began-a-mount]]: `mount(8)` prints "mount point busy" for every `-EBUSY`. A 2 s leftover holder is vacuous; a 123 s admission-barrier refusal is the measurement. A vacuity gate that exited before taking the kernel window discarded the only evidence. Take the window first, then classify by whether the kernel saw a mount (`P304-PREOBSERVE`, `P-BARRIER-CLOCK`, `P240-QUAR-IMPORT`, `Mounting Filesystem`), not by message or wall time. Capture evidence before classifying. The exit path must restore everything the lap took, including remounting the fleet.

**Key spelling.** [[trap-a-kernel-printed-hex-key-is-unpadded-and-compares-unequal-to-a-zero-padded-normalization]]: kernel `%llx` is unpadded, `normkey` pads to 16 digits, so about one key in sixteen (top nibble zero) fails an identity assertion from two spellings of one number. Normalize both sides of every key comparison.

**Run-id ties.** [[trap-two-board-rows-tied-by-the-run-id-must-run-in-one-run-sh-invocation-or-the-second-reads-indeterminate]]: `alloc_witness` seals evidence under its run id and `chk_clean` refuses a witness from another run as INDETERMINATE (by design; an insufficient witness yields VACUOUS). Two `./run.sh` calls give two run ids. Rows sharing evidence go in one call: `./run.sh 2 tcp alloc_witness chk_clean`. Read the INDETERMINATE reason text before calling it a design outcome.

**Stdin in loops.** [[trap-a-harness-run-inside-a-while-read-loop-drains-the-manifest-as-its-stdin-and-the-loop-runs-one-entry]]: a harness run inside `while read ...; done < manifest` inherits the manifest as stdin, and an ssh that does not redirect stdin swallows the rest. The gate reported `PASS entries=1` for a 55-entry manifest. Put `< /dev/null` on every command in the loop and compare `entries=` to the manifest count. [[trap-a-selection-step-keyed-on-a-cumulative-dmesg-count-picks-the-previous-runs-target]] has the same bug in its candidate search; use `done 3< file` with `read ... <&3`. Also from the first note: an identity read (`chk_mxfs -v`) taken while another harness formats the LUN is a torn read, not a defect; resolve again and compare.

**Selection from a cumulative dmesg count.** [[trap-a-selection-step-keyed-on-a-cumulative-dmesg-count-picks-the-previous-runs-target]]: `tests/tcp_lockreq_blackhole.sh` chose its target inode from an unscoped `dmesg | grep -ac`. The ring survives module swaps, so run s578c inherited 15 hits from the previous run, armed the fault on an inode locally mastered in that incarnation, and printed nine PASSes, including its own vacuity gate, without touching the code under test. Mark the log at run start and scope every count to the mark. A vacuity gate compares to a baseline sampled immediately before the measurement, not to zero. Mastership is a hash over resource id and active node set, so it changes per cluster formation; rediscover the target each run and never cache an inode number across a module swap.

## Common thread

A check that passes is only as good as what it measured. Several traps share one shape: the signal read is not the property claimed (message vs cause, log line vs platter, cumulative vs scoped count, one reader of several, self vs peer direction), and the harness reports PASS regardless.
