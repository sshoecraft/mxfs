Topic: how MXFS's release drain (the BAST-driven path that gives a grant to a peer) is parked, probed and reasoned about, and the recurring ways tests and fixes lie about it. Most items are harness or hypothesis traps; four are real product defects (async DIO, join flush, stale cluster buffer, residue lock bit).

## Release-pause / park knobs (`dbg_bast_pause_ino`, `dbg_rel_pause_*`, `dbg_bast_defer_ino`)

- The knob fires on EVERY release drain of that inode on that host, including the holder's own self-demote and its re-release after a re-cache. It is not once-only. Related lessons below all follow from this.
- Parking all releases (`dbg_bast_pause_ino=2^64-1`) parks the ANCESTOR directory's release first, and the peer's path walk waits on it, so no subdirectory is ever asked for (PARKED=1, lap "NOT EXERCISED"). Settle grants on every ancestor the peer's lookups need BEFORE arming (`ls -f $G` from the peer; `ls -f` on targets so only the directory grant is requested). Then PARKED=16 and the control reproduces deterministically. [[trap-parking-every-release-drain-parks-the-ancestor-directory-first-and-blocks-the-peers-path-walk]]
- A directory holder still caching PR after a peer listing upgrades PR->EX via -EDEADLK self-demote, which goes through the release drain. Arming the pause first parks the holder's own create for the whole pause. For a directory target: re-dirty first (holder takes EX), then arm. Directory grants stay cached PR/EX at the last holder; a peer listing leaves the previous EX holder at PR, not NL. A file does not do this. Wait for `P-D512-RELPAUSE-END` before the next lap; `clear_knobs` after the msleep started does not shorten it. [[trap-a-directory-holders-own-upgrade-takes-the-self-demote-release-drain-so-a-release-pause-armed-first-parks-the-holder]]
- Clear the pause knob the moment the operation under test returns, BEFORE any verdict-side access (`drop_caches`, stat, md5sum, getfattr) to the target on the node carrying it. Each drop_caches evicts the inode, releases a re-cached grant, and parks the bast worker; the ssh `timeout 30` then kills an empty capture (`got=none want=...`). A verdict wall consistently one ssh-timeout longer than a passing lap is a hung capture, not a slow node. The knob's set-call can itself hang behind the pause; wait for RELPAUSE-END count == RELPAUSE count before trusting the rig is idle. Fixed in 0.84.21. [[trap-a-release-pause-knob-left-armed-through-the-verdict-parks-the-holders-own-re-release-and-empties-every-cold-capture]]
- A BAST work item (`i_dlm_bast_work` / `i_dlm_bast_dwork`) is armed under `igrab` and holds the ref until after `mxfs_dlm_bast_process`, so while a delivered BAST is outstanding the inode cannot be evicted, freed or recycled. "BAST pending, inode freed" is unreachable by parking the work item (the park pins the inode); parking the drain after mode NL (`dbg_bast_pause_ino`) is the other window and it is the stale form. Recycle only meets the stale form; `recycle_bast_kept` non-zero anywhere means the invariant broke: investigate, do not accept. A delivered BAST on the immediate path is state BAST with pending flag CLEAR; key any rule on either signal. [[trap-a-bast-work-item-holds-the-inode-ref-so-a-corpse-cannot-be-recycled-under-a-live-bast]]

## Harness mechanics

- `$(stage ...)` whose backgrounded subshell inherits the substitution's stdout pipe blocks until its 40 s timeout (ssh waits on the fifo until the parent runs `exec 7>fifo`); two stages ate the 100 s budget with an empty evidence dir. Return the pid in a global (`STAGE_PID=$!`), never via command substitution.
- A fixed `sleep 1.5` before a trigger that must land in a ~1 s window (holder's quiet-age release) is not "peer ready". Make the remote print READY before `read x`, poll the capture (`grep --line-buffered`), abort after 10 s.
- A print-budgeted line (`P139-RECYCLE-UNLINKED`, ~200 per module load) is not a shape witness across runs; use an exact counter (reset before, read after).
- A knob hook inside the durable loop is unreachable if a branch above it exits first (regular-file early-out `!IN_AIL && pincount==0`); when an injected hook never fires, find the branch above before doubting the knob. 0.87.10 falls through while the force knob is armed. [[trap-staged-ssh-session-in-a-command-substitution-hangs-on-its-fifo-and-a-fixed-sleep-misses-the-login]]
- In a user-mode mesh test, run the control and the fixed lap on DIFFERENT resources: the control leaves its wait queued at the master, and the same requester's next request is a re-send that notifies only on the re-fire interval, so the fixed lap measures the interval (9 s, 2.5 s) instead of the fix (5 ms). [[trap-naming-the-owner-of-a-residue-lock-bit-does-not-make-the-owner-answer-for-it]]

## Hypothesis discipline

- Before predicting how a counter, clock or strike escape converges under a shape, walk every gate from trigger to sampler and show the shape is admitted at each. In the strike-counter case every gate treated `i_dlm_acq_inflight > 0` as a live acquirer (`P-ACQWIN-PARK`, bast_dwork busy check), so ZERO samples occurred; H1's FAIL "matched" while its mechanism was wrong. Instrument the sample COUNT (`P15-REL-ABORT ino=<n>` inside the window) beside the cadence; zero is the discriminator. `grep -n i_dlm_acq_inflight xfs/xfs_mxfs_dlm.c` lists the gates. [[trap-a-convergence-hypothesis-about-a-counter-must-first-show-the-sampler-is-reached-under-the-shape]]
- When a wait deadlocks, ask what it was MEASURING before asking how to stop it blocking. A barrier waited for the heartbeat thread, was called from the heartbeat thread, and was "fixed" by beating inline; the dependency was the proof that the service is alive. A node with a parked heartbeat then certified retirement and could replay past a lease interval while peers fence it. The deadlock was in the call graph (a 30487 ms fence running inline in a lease-renewal loop); move the work off that thread, never teach the proof to accept a substitute. When a harness arm reverses 8 assertions at once after a fix, "the injector is too weak" is the trap reading; a wedged heartbeat thread is exactly what the lease detects. [[trap-removing-a-waits-dependency-on-another-threads-schedule-can-delete-the-property-the-wait-was-measuring]]
- When a fix depends on "the other side will respond", find the code that sends the response and the state it needs. A shared holder bit named for its owner still blocked: a mounting node has no handler and parks what it gets (`P-BAST-PARKED`), a mounted handler releases nothing for an inode it never held. Answer from the layer that knows what the node holds without the filesystem (`mxfs_dlm_answer_unheld`: lock table plus pending-request list). A reply that can cross a request must be distinguishable from a real release (a generation no grant carries). Read `P-LKTIMEOUT-HOLDER` tuples against slot claim and first touch: a holder naming a node that has not touched the resource is residue. [[trap-naming-the-owner-of-a-residue-lock-bit-does-not-make-the-owner-answer-for-it]]

## Product defects with a general form

- A DLM holder count is not an I/O count. Async direct I/O drops its IOLOCK ride at `-EIOCBQUEUED` with bios outstanding; only `i_dio_count` says busy (11-16 releases per lap committed with `i_dio_count=1`, `P-REL-DIO-INFLIGHT`). Fix (0.87.7): `inode_dio_wait` only from a quiescent entry (no holder, else deadlock on its nested ILOCK; let the holders gate abort and re-arm); wait BEFORE log force/AIL drain (completion barrier, not durability); terminal guard under the spinlock BEFORE the NL store; refuse polled DIO (IOCB_HIPRI / IOPOLL) on a clustered mount. Completions run on a kernel thread admitted by the cached-grant fast path (`dioend_kthread` counted, `dioend_task=0`); count where X actually runs, and "admission counter is zero" was the tell. io_uring IOPOLL drivers must re-enter until the CQE appears (47 phantom errors per 500 ops otherwise). Before releasing ownership, enumerate counters that outlive the lock (`i_dio_count`, writeback, pinned buffers, pending ioends). [[trap-a-dlm-holder-count-cannot-see-asynchronous-direct-io-after-eiocbqueued]]
- A bounded "drain then invalidate" at a membership transition must quiesce writers, never race them. `peer_joined_flush` (5 rounds on a discovery thread) never converged against a live workload, shut the filesystem down (`P232-INVAL-STUCK`), the node died, the peer fenced it, and appended data in 32 files plus 34 directories were lost. Log force plus AIL push do not write file data. Shipped 0.83.4: `freeze_super` on a per-ctx join worker, view installed under the freeze, peer registered after prepare, settle gate covering PR and fail-closed; freeze 104 ms, no loss. Not converged means the peer stays unadmitted and retries, never a shutdown; never freeze from the lease UDP or accept thread; a view-hash beacon only orders what is gated on it (gating EX and not PR left reads open). [[trap-a-join-time-flush-that-races-the-local-workload-and-answers-with-a-shutdown-is-the-data-loss]]
- Never `xfs_buf_stale` an inode cluster buffer with `_XBF_DELWRI_Q` set (0.90.24): the flag clears, `xfs_buf_delwri_submit_prep` drops the write, flushed inode items stay `XFS_LI_FLUSHING` (0x21) in the AIL forever. Cost: 5 s per contended inode in the release drain (`P113-DRAIN-WEDGE`, `P136-DRAIN-RESCUE`) and a 127 s unmount (`P128-AILSTUCK`), about 1 lap in 8 of `tests/quiesce_remount_access.sh`. Signature: flags 0x40, `hold == nli`, `onlist=0`, `last_delwri_submit=never`. Use `mxfs_buf_has_uncheckpointed_mods(bp)`; a buffer with items attached and nothing flushed may be staled. `P-STALE-WITH-ITEMS ... delwri=1` is this fault. The reload verify-retry loop in `xfs/xfs_mxfs_reload.c` still stales unguarded and never fired in 160 node-logs; do not patch from reading. [[trap-staling-a-delwri-queued-inode-cluster-buffer-cancels-its-write-and-strands-the-flushing-inode-items]]

## Checker technique

- chk_mxfs offline dirent walk: inobt is the allocation authority (holemask bit covers four positions), the dinode a separate validity check (magic, v3, `di_ino`, CRC, mode != 0); `di_nlink` is never an allocation criterion. Parse traps: `XFS_DIR2_LEAF_OFFSET` is 32 GiB in bytes (differs by `sb_dirblklog`), bmbt pointer array based at capacity, XDB3 tail `count` includes stale slots, shortform `i8count` widens every number including parent, entries must end exactly at `di_size`. Print counts on every exit path; any skip is an error. Report-only under `-a`. Offline rows are authoritative on a live LUN. Harness `tests/d0964_chk_dangling_dirent.sh`. [[technique-an-offline-dirent-walk-uses-the-inobt-as-allocation-authority-and-the-dinode-only-as-a-validity-check]]
