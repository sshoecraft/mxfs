# run.sh / drbd_rig.sh rig-lock traps, harness coverage gaps, and silent transport/ordering traps

Topic group: mostly the `/tmp/mxfs_run.lock` rig lock and harness scripts (run.sh, drbd_rig.sh), plus four code-level traps with the same shape (state or behaviour silently absent on one path). Cluster boundary is loose; grouped by what each note teaches.

## A. The rig lock (`/tmp/mxfs_run.lock`) and who holds it

- **Never overlap run.sh with a live drbd_rig.sh**, even on a different rig group (and including a harness's `prep_cluster`). drbd_rig.sh takes the lock SHARED via `tests/lib/runlock.sh`, but run.sh's orphan check only recognises run.sh process trees, so it prints `WARN: ... held only by orphans of a dead run.sh — reaping` and kills drbd_rig's ssh/LUN-login children (drbd_rig exited 143 mid-LUN-allocation). Sequence them. [[trap-run-sh-reaps-a-live-drbd-rig-sh-as-orphans-of-a-dead-run]]
- **A daemon started inside run.sh inherits its lock fds.** The netconsole `socat` listener launched by `tools/netconsole_listen.sh start` via `nohup … &` inherited `exec 9>"$RUNLOCK"` and held the lock from PPID 1 after the run ended. The old exclusive path reaped it silently on every next whole-rig run (prep then restarted it); a shared rig-group lock just failed. Anything that must outlive a lock holder closes inherited fds above 2 first; rig-group runs use dynamic fds (`exec {fd}>>`), not just fd 9. Verify with `ls -l /proc/<pid>/fd` (never `cmdline`). [[trap-a-daemon-started-inside-run-sh-inherits-the-rig-lock-fd-and-holds-it-after-the-run-ends]]
- **`timeout N ./run.sh … | tail` does not stop the board.** `timeout` signals the pipeline's reader; the pipeline status is `tail`'s (exit 0), run.sh keeps running as an orphan and holds the lock, so later runs exit 3 ("another run.sh holds /tmp/mxfs_run.lock") with no evidence dir. A driver that then takes "the newest evidence dir" re-scores the previous lap (four A/B laps "reproduced" a failure none ran). Redirect to a file instead; a run is finished when `.last_run.json` and `tools/criteria.py` show no PENDING rows; use `fuser` + `/proc/<pid>/stat`,`comm` to see whether the holder is progressing before killing it (killing mid-flight leaks the module refcount and breaks next prep); drivers must require a NEW evidence directory. [[trap-timeout-around-run-sh-piped-to-tail-kills-the-reader-not-the-run-and-orphans-the-cluster-lock]]
- **A filtered run after a rebuild needs `prep_cluster` ALONE first.** The cluster marker `.cluster_marker.<group>.json` must name the same config and srcversion; the forced-prep branch requires `ONLY == (prep_cluster)` exactly (~run.sh:2103), so listing it with other tests does not help. Two invocations: prep, then the test. A node set mounted by `drbd_rig.sh mxfs` does not satisfy the marker. [[technique-a-filtered-run-sh-after-a-rebuild-needs-prep-cluster-run-alone-first]]

## B. Harness scripting and coverage

- **Bare `wait` in a script that keeps LUN-holder background processes never returns** (`tail --pid=$$ -f /dev/null &` per allocation lives until the script exits; drbd_rig.sh `up` sat in `wait` from 20 s to its 620 s budget). Collect `$!` per job and `wait "${pids[@]}"`; kill holders in an EXIT trap (tail notices pid death only on a ~1 s poll, so an immediate re-invocation saw "test1 is held by lun03's allocation"); spawn holders with lock fds closed or they keep the node/config flocks. Also never edit a bash script while an invocation is live: bash resumes at a byte offset and re-reads the new text. [[trap-a-bare-wait-in-a-script-that-keeps-a-lun-holder-process-never-returns]]
- **A rig that reformats before every mount never exercises remount or retirement.** On the DRBD attachment a clean unmount leaves the heartbeat slot RETIRE_PENDING with key 0 (settled only by SCSI PR evidence): remount hung in admission (P-ADMIT-RETIRE-PENDING-HELD), whole-cluster restart was refused (P304-RETIRE-UNKNOWN-STALLED). Two sessions passed because `drbd_rig.sh mxfs` and run.sh prep both mkfs first. For any new attachment/transport/retirement path test: one node unmount+remount with peer up (several cycles), and all-nodes clean unmount then mount without mkfs. Now covered by `scripts/drbd_rig.sh remount-test`. [[trap-a-rig-that-reformats-before-every-mount-never-exercises-remount-or-retirement]]

## C. Code-level traps (state or behaviour silently missing on one path)

- **Post-mountfs initialiser zeroing state the mount barrier wrote.** `mxfs_dlm_cache_init` runs AFTER `xfs_mountfs` and `bitmap_zero`'d `m_mxfs_foreign_dead_slots`, discarding the barrier's handoff (`P-OBL-BARRIER-OPEN slot=1`). The reap worker saw an empty dead set, cleared the replay duty (`bitmap_subset` of two empty sets is true) and swept into a frozen AG: `P-OBLF-AG-WAIT`/`TIMEOUT` after 120 s, kworker in D state. Check call order in xfs_super.c before passing barrier state through mount fields (`mxfs_defer_reap_init` before, `mxfs_dlm_cache_init` after); a later `bitmap_zero` on a kzalloc'ed struct is a discard; a sweep blocked on a freeze is a symptom, find who emptied the set. Hidden because only a case first met inside the barrier hits it. [[trap-a-post-mountfs-init-that-zeroes-state-the-mount-barrier-already-wrote-drops-the-barriers-handoff]]
- **Hand-numbered inode flag bits shared bit 28.** `MXFS_IF_ACQ_REFUSED` and `MXFS_IF_ADOPTED_UNLINK` were both `1U<<28` in xfs_inode.h; a DLM denial read as freer authority at inactivation. Fix: `scripts/inode_flag_bits_audit.py` (step of `tests/full_verify.sh`), `static_assert(MXFS_IF_ALL_FLAGS == MXFS_IF_ALL_FLAGS_SUM)` in the header (sum equals OR iff no shared bit), a second assert against upstream XFS flags, and ACQ_REFUSED moved to `1UL<<32` (added to `XFS_IRECLAIM_RESET_FLAGS`; 64-bit pinned). `XFS_IPINNED` (bit 8) is a wait-bit key, so FOREIGN_ZOMBIE on bit 8 is deliberate. When a flag appears set with no probe from any setter, enumerate the flag table first. [[trap-hand-numbered-inode-flag-bits-shared-bit-28-check-sum-equals-or]]
- **`MXFS_LKF_DEMAND` was CAW-only** (before 0.75.42): dlm_caw.c CASes the sticky revoke bit, dlm/dlm.c ignored it at both NOQUEUE deny sites and denied with MXFS_ERR_DEADLOCK without BASTing the holder. On 2/tcp the pre-acquire poll expired 84/84, unlink 1.5 s to 41 s. Fix: `demand_collect_holders` + `demand_fire` BAST granted holders without queueing (probe P-DEMAND-BAST). Check a DLM flag's semantics in BOTH engines (dlm/dlm.c and dlm/dlm_caw.c) before building on it. [[trap-mxfs-lkf-demand-was-caw-only-tcp-noqueue-deny-never-basts-the-holder]]
- **`mxfs_v5_dlm_ag_held()` returns constant 1 on TCP**, so the stranded-AG repair was gated `is_caw` and on TCP logged `disk_held=-1 repair=0` forever; the strand lives in the local grant table and the orphan NAK refuses -EBUSY on any local entry. Peer creates timed out every 61 s for 400+ s and cascaded into four unrelated failures. Fix 0.89.74: `mxfs_v5_dlm_ag_strand_held()` (slot on CAW, `mxfs_dlm_settled_grant_nb()` on TCP). Lessons: check what a "held?" helper answers on EACH transport; a run of consecutive timeout failures usually means one stuck grant (P-LKTIMEOUT-HOLDER with growing held_ms) or a test injector (P200-STRAND-INJECT); `ag_strand_repair` arms `mxfs.ag_strand_inject=-1` on every node and an unrepaired strand poisons the rest of the run. The initial "lock-order inversion" reading was wrong. [[trap-ag-held-answers-one-on-tcp-so-a-repair-gated-on-it-is-caw-only-and-a-tcp-strand-hangs-forever]]

## Recurring shape

A path nobody exercises (other transport, remount, the in-barrier case, an orphan-only lock holder) hides the defect; each of these was found only after a harness or reading checked the path explicitly.
