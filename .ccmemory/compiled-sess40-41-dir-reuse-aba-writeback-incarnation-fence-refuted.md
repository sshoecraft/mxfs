Fix must be **allocator-side** (bnobt/cntbt/agf coherence on AG-lock acquire; cf. sess42 `C6970FF9`, sess43 `BB54A138`) — a write-submit guard cannot reach it. HARDEST.

### sess40 REFUTATION #1 — inode-cluster incarnation fence (`C22056240`)
The fence (`xfs/xfs_inode.c mxfs_iflush_cluster_merge_dirs ~5226-5258`, hooked in `xfs_iflush_cluster:5549`): for an EX-held/own-flush directory slot whose in-core `di_gen` ≠ fresh on-disk `di_gen`, overlay the canonical on-disk dinode; logs `P-CLMERGE-DEADINCARN`. Design reasoning (why it *looked* correct) is preserved in [[sess40-fence-reconciles-sess27-and-tcp-root-why-correct]]: it reconciled sess27 (durable on-disk corruption, both nodes agree after drop_caches) with the tcp-root (node2 stale in-core extent map block0→daddr112, a freed prior-incarnation daddr) as ONE bug — a stale inode FORK made durable in the dinode (`xfs_inode_to_disk` writes the extent map), so cold-reiget reads block0 @ 112 (missing first-wave) while leaf lookup still works. `di_gen` was argued a faithful proxy because `xfs_inode_from_disk` rebuilds gen+fork together.

**REFUTED** ([[sess40-fence-REFUTED-real-root-dirdata-clobber-plus-AG-doublealloc]]): `tests/drc_loop.sh 5` @ `inode_mht_ms=300 dirwr=1` → 4 PASS / 1 FAIL; the fence `P-CLMERGE-DEADINCARN` fired **0× on every iter including the FAIL** → inert and irrelevant (RULE 4 step 2a). iter3 FAIL was COMPOUND = Bug A (dir-data block-0 clobber, rounds 12/14) + Bug B (inode-cluster double-alloc EFSCORRUPTED, rounds 15-20). Also proven inert here: the existing chokepoint skip `mxfs_buf_xfsaild_skip_dir_write` (`xfs_mxfs_dlm.c:15469`) only skips when owner `i_dlm_mode==NL`, but `P16-DIRBLK-SUBMIT` shows these writes at mode=3(PR)/5(EX), nl=0 ALWAYS; and the tenure arm reads `tenure=0 epoch=0 tmism=0` (i_mxfs_ex_grant_seq==0 → stamps 0) so nothing catches the held-mode stale flush.

### sess40 REFUTATION #2 — dir-block ABA-incarnation writeback skip (`B9F9326E`)
Built as a 6-edit fix ([[sess40-FIX-dirblock-ABA-writeback-skip-build-B9F9326E]]) on the theory that xfsaild flushes a DEAD prior-incarnation block-0: skip when `b_mxfs_dir_incarn != 0 && != VFS_I(ip)->i_generation` at `mxfs_buf_xfsaild_skip_dir_write`; stamp incarn in `mxfs_dir_data_track` (modify hook) and `xfs_dir3_data_init` (fresh get_buf); struct fields incarn_aba/buf_incarn/cur_incarn in `xfs_mxfs_dlm.h`; new always-on `P40-INCARN-ABA-DIRSKIP` log.

**REFUTED DECISIVELY** ([[sess40-ABA-fix-REFUTED-clobber-is-current-incarn-stale-tenure]]): with same-moment `bincarn`+`cincarn` in `P16-DIRBLK-SUBMIT`, daddr=120 writes show **bincarn == cincarn in ALL 272 cases (aba=0)** and `P40-INCARN-ABA-DIRSKIP` fired 0×. The clobbering buffer's incarnation ALWAYS equals the dir's live `i_generation` → not a dead prior incarnation. `i_generation` is the WRONG token — reconfirms sess16: `di_gen` doesn't differ on reuse. The **real Bug A token is TENURE**: 16 of 272 daddr=120 writes had `b_mxfs_dir_gen < i_dlm_dir_gen` (stale tenure = current-incarnation buffer logged in a prior EX tenure; we yielded EX, peer advanced block-0 on disk, we re-acquired and xfsaild flushed our stale-tenure cached image). `P29 daddr=120` showed buf_cnt decreasing (99,98,97..., disk_cnt=buf_cnt+1) = progressive stale-tenure reverts.
