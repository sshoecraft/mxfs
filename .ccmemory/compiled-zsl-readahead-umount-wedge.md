## Compiled: zero_silent_loss unmount-wedge family (sess74 → sess76)

Central topic: the `zero_silent_loss` (zsl) ship criterion was blocked by a chain of wedges that all surfaced under the dir-create storm (`zsl --iters N --dpn 100 --mode 1`, `dirwr=1`, 16-node v5 cluster over `/dev/sda` SCST_FIO virtio-scsi). Three distinct root causes, fixed in order: (1) a readdir SHARED→EXCL ILOCK self-deadlock that hung the verify pass; (2) a `bt_readahead_count` percpu leak that wedged inter-iter umount in `xfs_buftarg_wait`; (3) an orphaned readahead `b_hold` leak that then wedged umount one layer down in `xfs_buftarg_drain`. All three share one mechanism family: a bmbt sibling block gets prefetched as async READ_AHEAD and then synchronously re-read on the same `xfs_iread_extents` path before the async ioend runs, so `_xfs_buf_read` clears `XBF_READ_AHEAD` while accounting/holds are still outstanding.

### Build progression
- `64932978` (sess73 baseline) → `3E4F5777` (P74-DINEXT-REGRESS detector, BTREE-only, inert) → `01A3F1A7` (P74-IFNEXT-SKEW torn-dinode barrier) → `67597818` (FIX1 readdir self-deadlock; sess74 head) → `CE6B0445` (sess75 readahead COUNT-leak fix) → `EAE5F4C076DD06896DCAAD8` (sess76 readahead HOLD-leak fix; **zsl PASS**).

### sess74 — two fixes, verify-hang root [[sess74-readdir-ilock-self-deadlock-and-torn-dinode-barrier]]
- **FIX1 (readdir ILOCK self-deadlock, DECISIVELY PROVEN via `P73-ILOCK-STUCK`, KEEP, build `67597818`):** `pal/linux/xfs_file.c xfs_file_readdir` took `xfs_ilock(ip, XFS_ILOCK_SHARED)` unconditionally across `xfs_readdir()`. For a NON-shortform dir whose data-fork extents aren't loaded (`need_iread=1` — the state a peer-driven `mxfs_dlm_reload_inode` leaves via `xfs_idestroy_fork`+`xfs_inode_from_disk`), `xfs_readdir`→`xfs_ilock_data_map_shared` takes `ILOCK_EXCL`. Same thread upgrading SHARED→EXCL on one rwsem deadlocks forever. Proof: `P73-ILOCK-STUCK ino=131 want=EX rd_held=1 wr_last=xfs_ilock_data_map_shared` (same pid `1353`=find holds SHARED + wants EXCL). BMBT reload then BAILs "DLM reload BAIL i_lock contended", `need_iread` never clears, `ls`/`find` hangs. **Fix:** hold outer SHARED ONLY for LOCAL/shortform dirs (`xfs_dir2_sf_getdents` takes no ILOCK, reads inline `if_data`); for all other formats let `xfs_readdir` take its own lock with no outer lock held. `consumer_refresh()` above already settles peer reloads + fires the DLM hook. Residual risk: a LOCAL→block conversion inside `xfs_readdir`'s own reload while holding SHARED could re-trip (rare; P73 would show it).
- **FIX2 (write-side torn-dinode barrier, Gemini-designed, KEEP, `P74-IFNEXT-SKEW`):** `xfs/xfs_inode.c xfs_iflush`, before `mxfs_iflush_force_bmbt_durable`+`xfs_inode_to_disk`: for a multi-node DIR with extents loaded (`!need_iread`), walk the iext tree counting real extents; if `real != if_nextents`, log `P74-IFNEXT-SKEW` and RECONCILE `if_nextents = real`. Restores upstream invariant so a torn dinode is never published → avoids EFSCORRUPTED/CORRUPT_INCORE shutdown → avoids the SCSI-PR reservation-conflict cascade. Addresses sess60/65 proven root (in-core `if_nextents` diverges from iext tree; `xfs_inode_to_disk` packs a torn dinode). Correct-by-construction but fired 0× in the one instrumented run.
- **Loss multiplier (measured, build `01A3F1A7`):** corruption on ONE node (`xfs_iformat_extents`/`xfs_bmap_validate_extent_raw` on EXTENTS-format ino=131, di_format=2 growing; `xfs_trans_cancel` CORRUPT_INCORE shutdown on test12) → host SCST `Reservation conflict` storm across 15 initiators → `connection1:0 conn error (1020)` cluster-wide EIO → all 1600 mkdirs fail = 1600 silent. Gemini fix (c): contain `force_shutdown` so it doesn't disturb PR keys → no reservation storm (NOT yet done).
- Gemini consult (RULE 5 justified): DLM serializes mkdir ENTRY, not the metadata-writeback lifecycle across N buffer caches. (a) release fence should be LSN-based (`xfs_log_force_lsn`+`xfs_ail_push_sync(lsn)`); (b) assert real-iext-count==if_nextents at write boundary (→FIX2, reconcile not BUG); (c) contain force_shutdown; (d) delegation/RPC so only the lock owner caches/writes the hot dir.

### sess75 — count-leak umount wedge [[sess75-readahead-count-leak-unmount-wedge-fix]]
- **Big win:** FIX1+FIX2 (build `67597818`) deployed + verified on 16-node v5. `zsl --iters 1`: `total_fs_silent` dropped **1600 → 3**, no shutdown cascade, all 16 mounted, no verify hang. Residual ~3-9/iter = a real dir-block lost-update (`MISSING node6_dir94 creator=test6 CREATOR_MISSING creator_errs=[none]` — creator's own dirent durably lost, no mkdir error). NOT yet fixed; next root.
- **NEW BLOCKER (RULE 4, proven):** `zsl --iters 3` only completes 1/3 — iters 2-3 INFRA-fail because inter-iter `mount_cluster` umount wedges a node (different each run) in D-state: `xfs_buftarg_wait → xfs_log_quiesce → xfs_log_unmount → umount`. `/dev/sda` HEALTHY (dd works); flapping QNAP iSCSI `conn error 1020` (192.168.1.4) is UNRELATED noise. Root: `xfs_buftarg_wait` spins in `while(percpu_counter_sum(&bt_readahead_count)) delay(100)` — count leaks exactly +1. Mechanism: a dir extent-map reload (`xfs_iread_extents → xfs_btree_visit_blocks → xfs_btree_read_buf_block`) issues a bmbt readahead (inc at `xfs_buf_readahead_map`, pal/linux/xfs_buf.c:879), then the SAME lookup path synchronously reads the same bmbt block via `_xfs_buf_read`, which CLEARS `XBF_READ_AHEAD` while still counted; the eventual `__xfs_buf_ioend` sees the flag clear and SKIPS the gated `percpu_counter_dec` → leak → unmount spins forever. Proof probes: `P-RA-CLEAR-AT-BUFREAD daddr=<bmbt> ops=xfs_bmbt comm=touch` (stack through `mxfs_dir_bmbt_invalidate_stale`/`xfs_iread_extents`) + `P-RA-DECSKIP-IOEND` (kworker). Diagnostic trap: a global RAT tracking array showed false `outstanding=0` due to bp-pointer reuse — **percpu counter is the source of truth.**
- **FIX (build `CE6B0445`, `_xfs_buf_read` in pal/linux/xfs_buf.c ~668):** when `_xfs_buf_read` finds `XBF_READ_AHEAD` set (counted readahead being converted to sync read), `percpu_counter_dec(&bp->b_target->bt_readahead_count)` to settle accounting; pairs with the inc, re-submitted read completes with ra clear and won't double-dec. Marker `P-RAFIX-BUFREAD` (rate-limited).
- Reset note: multi-iter runs leave PR-reservation/wedge residue — always `scripts/cluster_reset_n.sh 16` (full virsh destroy/start) before trusting results. Single-iter zsl leaves FS mounted (no inter-iter umount) so it does NOT expose the wedge.

### sess76 — HOLD-leak umount wedge, zsl PASSES [[sess76-readahead-hold-leak-umount-wedge-FIXED-zsl-passes]]
- **Result:** `zsl --iters 3 --dpn 100 --mode 1` = **PASS** (build `EAE5F4C076DD06896DCAAD8`): `total_fs_silent=0 iters_with_loss=0/3 completed=3/3`. No umount wedge, no silent loss. `P-DRAINSTUCK=0` on all nodes; `P-RAFIX` still fires (steal handled cleanly). (This clears the count-leak fix AND the residual dir-block lost-update from sess75 — that run's ~3-9/iter loss did not recur.)
- **Root (RULE 4 proven): orphaned readahead HOLD leak.** The sess75 count fix settled `bt_readahead_count` but the wedge MOVED from `xfs_buftarg_wait` (count spin) to `xfs_buftarg_drain` (LRU spin on a buffer with `b_hold>1` that never drops). Intermittent, different node per run, sometimes none. `P-DRAINSTUCK` probe in `xfs_buftarg_drain_rele` (b_hold>1 skip branch): stuck buffer = `daddr=... ops=xfs_bmbt hold=2 flags=0x20(XBF_DONE only) pin=0 li_empty=1` — a clean completed bmbt read pinned at hold=2 (one leaked ref). `P-RAFIX` stack (comm=touch): `_xfs_buf_read <- xfs_buf_read_map <- xfs_trans_read_buf_map <- xfs_btree_read_buf_block (mxfs_dir_bmbt_invalidate_stale) <- xfs_btree_lookup_get_block <- xfs_btree_visit_blocks <- xfs_iread_extents`; state at steal `flags=0x15 (READ|READ_AHEAD|ASYNC), async=1, hold=3`. Mechanism: `xfs_btree_readahead` prefetches sibling leaves via `xfs_buf_readahead_map` (get_map +1 HOLD, inc count, sets READ|ASYNC|READ_AHEAD, submit); same thread then SYNC-reads the same sibling via `xfs_trans_read_buf` → `_xfs_buf_read`, finding it READ_AHEAD-set + unlocked (async completion never ran, else it'd have cleared the flag + relse'd). `_xfs_buf_read` clears flag + resubmits SYNC; the sync completion path does NOT relse → the readahead's HOLD (and pre-fix its COUNT) is orphaned.
- **FIX (build `EAE5F4C0`, `_xfs_buf_read` in pal/linux/xfs_buf.c ~672):** on entry with `XBF_READ_AHEAD` set, `percpu_counter_dec(bt_readahead_count)` (sess75) AND drop the orphaned hold:
```c
spin_lock(&bp->b_lock);
if (bp->b_hold > 1) { bp->b_hold--; }   // guard: never free read_map's own ref
spin_unlock(&bp->b_lock);
```
Safety argument: READ_AHEAD-set + we-hold-the-lock ⟹ no pending async ioend (it would still own the lock) ⟹ the readahead's hold is genuinely outstanding ⟹ safe to drop; `b_hold>1` guard preserves read_map's own reference. Markers `P-RAFIX-BUFREAD` (rate-limited) + `P-DRAINSTUCK` tripwire KEPT (cheap, event-scoped).

### Recurring lessons
- One symptom (umount D-state wedge) had THREE stacked roots; each fix EXPOSED the next (`xfs_buftarg_wait` count → `xfs_buftarg_drain` hold). Don't declare victory on the first wedge fix — re-run `--iters 3` to force inter-iter umount, which is the only thing that exposes these; single-iter leaves FS mounted and hides them.
- The `xfs_iread_extents` bmbt readahead-then-sync-reread pattern (via `mxfs_dir_bmbt_invalidate_stale`) is the common trigger for both the count leak and the hold leak — a single upstream-XFS assumption (async ioend always finalizes a READ_AHEAD buffer) that mxfs's sync-reread breaks.
- Percpu counter is the source of truth for readahead accounting; a bp-pointer-keyed tracking array lies due to buffer reuse.
- Torn-dinode corruption on one node is a cluster-wide loss MULTIPLIER via SCSI-PR reservation-conflict fencing; containing `force_shutdown` (Gemini fix c) is still open.
