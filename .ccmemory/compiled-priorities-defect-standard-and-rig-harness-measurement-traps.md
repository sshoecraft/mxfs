Compiled from 12 notes grouped by the user's standing priorities and the rig/harness traps that bite when a verdict is claimed. User directives come first, then the traps in the order they cost the most.

## User priorities and quality bar

- Priority order, user directive: 1) data integrity, no corruption at all, 2) stability, MXFS cannot crash the host, 3) performance, which is still a must-have and not optional. Any corruption stops all work, including the next wave and a release, until it is understood and fixed. Contention, load or rig timing is never an excuse for corruption; at most it is how a race gets exposed. [[user-the-three-must-haves-integrity-then-host-stability-then-performance]]
- Bar is zero known, reproducible defects. Never justify, normalize or tolerate an MXFS bug by citing GFS2, OCFS2 or any other clustered filesystem's bugs: people avoid those because they are buggy, so it argues for zero. Reproducible implies fixable. Method discipline (instrument, prove the cause, targeted fix, verify) is how to fix correctly, never a reason to leave a known bug. The one honest limit is a claim limit: never say fixed before proven, and never promise a new workload cannot surface a new bug; that is not permission to accept known ones. [[user-standard-zero-known-bugs-no-other-fs-excuse]]
- Never dispose of two incidents on one incident's evidence. A double-crash record was filed DISPROVED for both crashes on evidence from only the second (`nv_dma_map_peer` count 0 in the first pstore record, 120 in the second). The first was reopened as its own record. Before writing "both traces show X" or "all N runs show X", run the check per record and paste per-record counts into the evidence; a cross-incident claim needs a per-incident line. When the user challenges an attribution, re-derive it from the raw record before defending it; and a counter-attribution ("the first was you") also needs evidence, so the honest answer can be "neither", filed OPEN with mechanism unknown. In an oops, `[last unloaded: ...]` is the last module unloaded ever, not one that was live; read `Modules linked in:`. [[feedback-never-dispose-two-incidents-on-one-incidents-evidence]]

## Rig and lab directives

- The 2/tcp rig's iSCSI target is never restarted, by script or by hand, and no session asks again. This is a property of that one device, not of the target-restart tranche: restart laps run on a restartable bench target (LIO or SCST on serv or locally, APTPL on) declared in `data/rigs.json` under its own tag. Never write "blocked on appliance access" or "cannot be measured"; that biases later sessions into abandoning measurable work. The tree is published: name the device by role or rig tag, never by address or by what else it serves. `tests/target_restart_pr.sh` reads `restart_forbidden` first and aborts before resolving any credential; that guard is not bypassed. [[feedback-the-2tcp-rigs-iscsi-target-is-never-restarted-measure-restart-behaviour-on-a-bench-target]]
- `lab/` is a catalog of build recipes, not an inventory of what runs on clyde: a session told "verify against OS X" must be able to build that pair from `lab/vms.md` and `lab/README.md`. No IPs, hostnames, storage portals or home paths in the tree; site specifics live in `~/.config/mxfslab/lab`, read via `tools/mxfs_lab.sh`. Never point docs at another project's `/src/...` path (osimager is on PyPI). What osimager does is osimager's business; a missing spec is an osimager gap to report. osimager's qemu post-build registers with `LIBVIRT_DEFAULT_URI` or the uid default, so unprivileged builds land in `qemu:///session` (35 stale defs accumulated); build with `-D libvirt_uri=qemu:///system`. [[user-lab-dir-is-a-build-recipe-site-specifics-live-in-the-lab-file]]
- Platform roadmap is the registry (`tools/platforms.py`, `data/platforms.json`); read it rather than restating. macOS 26 is a kernel extension, never FSKit or user space. RHEL family is runtime-tested on AlmaLinux VMs (no RHEL subscription), build-checked in containers (`scripts/rhel_kbuild_check.sh`); the minor release, not the vendor, decides kernel APIs. SLES 16 only. RHEL 9 guests need an x86-64-v2 CPU model; osimager gives qemu64 and the installer panics, which the user fixes in their own osimager session, so do not edit osimager. [[user-platform-roadmap-pve9-now-rhel-8-9-10-and-freebsd-14-later]]
- A recovery clone is scratch. `test4r`/`test5r` were left defined with the live nodes' MACs; booting one took the live node's static address, and after destroying it the bridge kept forwarding the MAC to a vanished tap ("No route to host" with ARP REACHABLE) until the live node restarted. Undefine and delete a clone once the original is back, or give it a new MAC before defining. A VM name with no DNS entry that shares a MAC with a live domain is a clone; never boot it while the original runs. After a clone was up and a node shows No route to host, restart the node rather than chasing ARP. Rig guests test5+ also have iSCSI node records that log in at boot to an absent target, so boot waits about 2 minutes and `/run/nologin` can persist; root ssh works first. [[trap-test4r-and-test5r-are-mac-clones-of-test4-and-test5-booting-one-takes-the-live-nodes-address]]
- The 2/tcp suite's `run.sh` defaults `DEV=/dev/sda`, which on test1/test2 is the LIO bench LUN on test32, not the real rig LUN, so suite runs silently measured LIO. LIO deadlocked on PREEMPT AND ABORT of a destroyed node (`core_scsi3_pro_preempt` -> `core_tmr_lun_reset` -> `target_put_cmd_and_wait`) and served no initiator; MXFS on the survivor behaved per design (PROUT-ABORT-FAIL, FENCE-BLOCKED-AMBIGUOUS, HB-STALL, SELF-FENCE, bounded withdrawal), and the lap failed as crash_audit. Run 2/tcp verdicts with `MXFS_RIG_TAG` and `MXFS_DEV` pointing at the real LUN by id. When a death lap fails with the survivor self-fenced, read the target's kernel (test32 dmesg, D-state stacks) before any MXFS hypothesis. `hostload` is clyde's load and may come from the user's own jobs, not the rig. [[trap-the-2tcp-suite-binds-sda-which-is-the-lio-bench-target-and-lio-deadlocks-on-preempt-abort]]

## Harness and measurement traps

- DONE is not "rig free". The rig's real resource is `/tmp/mxfs_run.lock`. Four chains gated on a log's DONE line woke together (plus a stale parked chain from the previous session): one won the lock, two burned a launch to a one-second FAIL, and one started `make modules` in the tree while the winner's preps insmod'd `mxfs.ko`, which would have split srcversion across the fleet mid-board. Rules: wait on the lock via `tests/rig_wait_free.sh` (walks `/proc/*/fd` and `comm`, never `pgrep -f`/`ps aux`); sequence stages in one process instead of fanning out chains; a build is a rig operation and is exclusive with any run. Second-order: editing a script while an instance is parked in its gate loop corrupts it (bash reads by byte offset) and the instance ran detached from its logging. Check `/proc/*/cmdline` for that exact filename before editing; a parked script counts as running. [[trap-done-gate-is-not-rig-free-run-lock-is-the-real-resource]]
- A bound that counts its own poll sleeps is not a wall bound. The mount admission barrier advanced `waited_ms += 1000` per `msleep(1000)`, but each pass also ran replay rounds (6 s takeover observation, up to 45 s slice stabilize, ledger scan, sector reads) invisible to the counter, so a "122 s" bound ran far longer (a mount outlived `timeout 300` by 60+ s). `msleep` is uninterruptible and the loop never checked `fatal_signal_pending`, so SIGTERM from `timeout` queued until mount returned. Tests that find the class: grep every bounded loop for how it advances its counter (use `time_after_eq(jiffies, deadline)` from the loop start, judged before starting new work); every wait in process context (mount, umount, ioctl) needs a `fatal_signal_pending` check at recovery-safe boundaries with a killable sleep, returning -EINTR (never -EBUSY) on cancellation, and subordinate waits must re-sleep to the full interval and never certify early. Budget exhaustion is an availability refusal, never permission to admit with incomplete recovery; no new work starts past the bound; print `overrun_ms` and `last_round_ms` on exit (overrun greater than last round is a defect); pass remaining budget into the acquire and refuse a takeover that cannot fit. A failed mount leaves its debt on the platter. Harness `tests/d0980_barrier_killable.sh`; design `docs/rulings/mount-admission-barrier.md`. [[trap-a-bound-that-counts-its-own-poll-sleeps-is-not-a-wall-bound-and-a-mount-loop-with-no-signal-check-cannot-be-ended-by-timeout]]
- A lap that asserts the absence of a behaviour the module declares grades the inverse of the design. The network-partition arm held the DLM link down 120 s and required zero fence certificates, but the module's `tcp_death_grace_ms` is 40000, so a fence was the correct and guaranteed outcome and a textbook-correct resolution scored three FAILs. Read the module's own declared parameter at run time and grade against it; never hard-code the expectation in the harness. Grade on the observed outcome and let the declared bound decide which outcomes are allowed: inside the grace nobody may be fenced, past it exactly one side fences and owes the full chain (certificate, seal, slice replay, victim silent), and neither shape may produce two certificates. Near the grace (socket needs about 12 s to notice a block) either resolution is legitimate. [[trap-a-lap-that-asserts-the-absence-of-a-behaviour-the-module-declares-it-will-perform-grades-the-inverse-of-the-design]]
- A shared debug injector cannot change meaning without re-reading every harness that arms it. `dbg_auth_pump_pause_ms` skipped both the periodic gate call and the withdrawal pump, so one lap went VACUOUS three times (`reason=no-closure`). Moving the hold below the gate call would have fixed that lap and altered three others (`admitted_write_parked_across_fence.sh`, `auth_lease_resurrection.sh`, `fence_late_detection.sh`) that depend on the victim being blind. Before changing a knob, `grep -ln <knob> tests/*.sh` and read each use; a knob's semantics are part of every banked verdict. When a lap needs a different cut, add a second knob (`dbg_auth_withdraw_pause_ms`) and leave the first untouched. Name a knob for what it holds, not the thread it lives on. [[trap-a-shared-debug-injector-cannot-change-meaning-without-re-reading-every-harness-that-arms-it]]
