## Compiled: shortform-dir cross-node coherency — rebase clobber, rename-revalidate-miss, union merge, dir_reuse low-mht off-by-one (sess19–21, ccloop)

Central topic: making the **shortform (inline-data) shared directory** coherent at **low inode/dir hold-time (mht)** without either (a) clobbering a node's own un-checkpointed dir work or (b) blowing the RULE-0 speed budget. Two ship criteria are entangled: `dir_reuse_coherency` (needs coherent invalidation on peer dir-adds → wants HIGH mht) and `tcp_dlm_scaling` (150-round rename churn in a 60s window → needs LOW mht). The low-mht regime exposes the deep durable single-entry lost-update (`readdir=799 exp=800`) plus a rename-revalidate false-abort. All work runs under `./run.sh <N> tcp <criterion>`.

### The mht tradeoff (the core wall)
- `dir_sf_mht_ms=300` (high) → `dir_reuse` 8/8 PASS, but `tcp_dlm_scaling` too slow (fails "within window", RENAME-MISS=0 — pure speed; path-2/high-mht is dead).
- `dir_sf_mht_ms=100/150` (low, default) → `tcp_dlm_scaling` fast but `dir_reuse` loses one entry, and the rename-revalidate-miss appears. No single mht value satisfies both; a **format-gated mht** (low mht only for shortform dirs) was the sess20 breakthrough baseline but did not fully resolve either residual. See [[sess21-dir_reuse-lowmht-race-negatives-and-precise-localization]], [[sess21-diagnostic-ready-per-fire-rebase-log-A8911EE3]].

### sess19 — coherent-modify is correct but too slow; release-invalidate levers
Two-sided coherency levers landed as default-off module params on baseline build **15447D0C** (KEEP: inode-skip fix, mht default 300, all dir params off; the inode-skip fix gave cache_coherency 8/8):
- **RELEASE side `dir_release_invalidate=1`** (handoff-gated, at EX release; `mxfs_dir_release_invalidate_data_blocks`, xfs_mxfs_dlm.c:3109): invalidates the releasing node's own cache so its next re-acquire cold-reads. Cut mht=50 loss **18 → ~2**. Cheap-ish (~305s, slightly over the 300s budget due to cold-FUA re-reads). Residual 2 losses are a variable-hit-rate RACE — treat <~5 as "improved, not converged"; one run gave 2, another 11.
- **ACQUIRE side `dir_coherent_modify=1`** (`mxfs_dir_refresh_stale_data_blocks`, xfs_mxfs_dlm.c:1308): before each addname, plain-read every dir DATA block, invalidate if disk has MORE dirents than cached, SKIPPING own committed-unwritten work (no clobber). **PROVEN correct: `mht=50 + dir_release_invalidate=1 + dir_coherent_modify=1` = failrounds=0 through round 6.** BUT ~5× TOO SLOW (~60s/round vs ~13s; O(blocks×creates), not gated) → RULE-0 FAIL, killed mid-run. See [[sess19run-dir-coherent-modify-correct-but-too-slow-need-handoff-gated]].
- **Insight**: the reliable correctness signal is coherent-modify's per-block content-compare (dirent-count fingerprint); release_invalidate is handoff-gated/fast but only fixes the releaser's self-reacquire (misses the cross-node acquirer → residual 2). NEEDED: a HANDOFF-GATED acquire-side coherent invalidation firing once per cross-node dir-EX acquire (gen bump / P63-HANDOFF), not per addname. The existing gen-invalidation (xfs_da_btree.c:3176) is handoff-gated but uses XBF_TRYLOCK-SKIP + gen-stamp (lossy); marry it to the content-compare.
- **Build F141D09D** (UNTESTED, from 15447D0C, builds clean): implements that — added `uint32_t i_dlm_dir_coherent_gen` to `struct xfs_inode` (xfs_inode.h, after i_dlm_dir_evicted_incarn) and a handoff-gate in `mxfs_dir_refresh_stale_data_blocks` so the scan runs once per gen advance. Risk: relies on i_dlm_dir_gen bumping on EVERY cross-node handoff (P63-FASTEX-HANDOFF was 0 in this workload → likely OK; FASTEX fast-path gen-bump reliability is the gap if a residual appears). See [[sess19run-UNTESTED-handoff-gated-coherent-modify-build-F141D09D]].
- **REFUTED (RULE 4)** this session, do NOT re-try: `force_coherent=1` (24/24 loss); `dir_release_fua_write=1` (2→4); bounded trylock-retry (30× msleep(1) on -EAGAIN) + `MXFS_IF_DIR_RELOAD` backstop in release_invalidate (2→11 WORSE); `dir_coherent_modify` per-addname (correct but 5× slow). Common theme: **aggressive/ungated forced reload CLOBBERS in-core committed-undrained work** (MXFS_IF_DIR_RELOAD arming forces a full reload on next acquire that clobbers) — reload must stay surgical + handoff-gated + skip own undurable work; msleep in release also perturbs create timing. See [[sess19run-REFUTED-trylock-retry-and-dir-reload-backstop-in-relinval]].

### sess20 — rename-revalidate-miss ROOT and the DABUF-HOLE stale-leaf fix
- **Full `./run.sh 4 tcp` on build 4E047A49 (format-gate) = 16/17**, only `tcp_dlm_scaling` FAIL 3/4. NOT a window fail: test1/3/4 fast (11–17s, all 150 rounds); **test2 did 0 rounds** (elapsed 1.34s, broke round 1). See [[sess20-4tcp-16of17-tcp_dlm_scaling-rename-revalidate-miss-at-low-sfmht]].
- **ROOT (PROVEN)**: test2's `echo>n2_r1; mv n2_r1 n2_r1.done`. The rename's pre-RMW guard (`xfs_dir_lookup_locked` for src, xfs_inode.c:4320, the sess8 RENAME-REVALIDATE-MISS guard) got ENOENT (`lookup_rc=-2 cur_ino=0`) for test2's OWN private file → clean-abort → mv fails → loop breaks. Cause: before the guard, `mxfs_dlm_dir_modify_refresh(src_dp)` → `mxfs_dir_rebase_shortform(dp)` fires when a PEER advanced the shared-dir gen (`i_dlm_dir_gen != i_dlm_dir_evicted_gen`) between test2's create and its rename. rebase_shortform **RELOADS the shortform inline data FROM DISK**; if n2_r1's create is committed-in-journal but not yet checkpointed to the on-disk dinode (or the FUA reload reads the platter before iflush lands), the reload OVERWRITES the in-core dir (which HAD n2_r1) with the disk image (WITHOUT it) → lookup miss. So **rebase-shortform clobbers the node's own un-checkpointed create.** Rare at mht=300 (few handoffs land between create and immediate rename); frequent/flaky at `dir_sf_mht_ms=100`. Same family as dir_reuse low-mht + sess84/sess49 shortform lost-update / 3-way-merge. See [[sess20-rename-miss-root-rebase-shortform-clobbers-own-uncheckpointed-create]].
- **Build DCC2B8FD** (UNTESTED, from 4E047A49): first fix attempt — an OWN-WORK guard in `mxfs_dir_rebase_shortform` (~line 3838, after the `if_format != LOCAL` return) that SKIPs the wholesale disk adopt when `xfs_ipincount(dp)>0` or the log item has `XFS_LI_IN_AIL`/`XFS_LI_DIRTY` set. A clean PR/NL cacher (sess49 P43) has no log item/unpinned → still rebases → no regression. This is the *ownskip* guard — later superseded by union merge because ownskip regressed dir_reuse. See [[sess20-UNTESTED-rebase-shortform-skip-own-uncheckpointed-work-DCC2B8FD]].
- **DABUF-HOLE root PROVEN + fixed** (build 5C08C626 from F141D09D; P14-DABUF-HOLE/P15-EXTSHAPE probes in xfs_da_btree.c ~2826): the catastrophic dir_reuse low-mht shutdown `!(flags & XFS_DABUF_MAP_HOLE_OK)` at xfs_da_btree.c:2876 = a **STALE cached LEAF block** still referencing DATA blocks a peer LEGITIMATELY freed. In-core extent map was FRESH+CONSISTENT (loaded_gen==dir_gen at every hole); the leaf (only name→block structure) is the stale element (confirmed independent of dir_coherent_modify). FIX: `dir_postread_reread=1` re-reads the stale clean leaf under held lock before it's walked → DABUF-HOLE 6–60× → **0**. BUT postread on DATA blocks TEARS (hot dir3_data FUA-re-read hits platter → magic=0 zeroed-header CRC error → new shutdown), so added `mxfs_dir_postread_leaf_only=1` (default 1, xfs_da_btree.c) restricting re-read to LEAF/NODE ops (`xfs_dir3_leaf1/leafn/da3_node_buf_ops`). With leaf_only: DABUF-HOLE=0, CRC 60→10, shutdown pushed t=80s→430s (round 24). DEEPER UNSOLVED residual: dir3_data daddr 0x70 = fsb 14 (NOT in the fresh extent map {15,262153,leaf}) fails CRC → dir-block-shares-daddr / AG double-allocation family (sess38-47 bnobt); `dir_modify_extent_reload=1` didn't fire (epoch trigger dead per sess14) and shifted failure to `ltbno+ltlen>bno` in xfs_free_ag_extent (AG free-space double-free). See [[sess20-PROVEN-dabuf-hole-is-stale-leaf-fixed-by-postread-leaf-only]].

### sess21 — union merge + offset fix (KEEPER), and dir_reuse off-by-one localized
- **KEEPER build 7B66691E** (7B66691EE8F4F2E0C0347A6): `mxfs_dir_rebase_shortform` becomes a **UNION MERGE** (xfs_mxfs_dlm.c ~3912) instead of ownskip/blind-reload. When own_work (ipincount/IN_AIL/DIRTY), build merged shortform = disk entries ∪ our in-core-only entries (`dir_sf_rebase_merge=1`; `dir_sf_rebase_ownskip` legacy). This fixes tcp_dlm_scaling rename-miss (wholesale-adopt clobber) WITHOUT the ownskip guard's dir_reuse regression.
- **CRITICAL OFFSET BUG found+fixed** (was in 8D9D586E; fixed in 7B66691E): grafted sf entries were memcpy'd wholesale keeping their stale `offset` field. `xfs_dir2_sf_to_block` (xfs_dir2_block.c:1436) writes each entry at `b_addr + stored_offset` → grafted offsets COLLIDE with disk entries' → overlapping data entries → `xfs_dir3_data_verify` corruption (block 0x3fea88) + FS shutdown (seen on test1-4 in a prefix run). FIX: re-assign each grafted entry a fresh monotonic offset (running counter from `max(disk_entry_offset + xfs_dir2_data_entsize)` via `xfs_dir2_sf_put_offset`); preserve own offset only when disk has 0 entries. VERIFIED: dir_reuse 8tcp → ZERO corruption. **The offset fix is load-bearing — reverting reintroduces the dir3_data shutdown.** See [[sess21-FIX-union-merge-rebase-shortform-reconciles-rename-miss-and-dir_reuse]].
- **Criterion state on 7B66691E**: 1/tcp=16/16, 2/tcp=17/17, 4/tcp=17/17 (tcp_dlm_scaling 4/4 ×2). **8/tcp NOT met.**
- **dir_reuse off-by-one (readdir=799 exp=800) precisely localized** (build 7B66691E), a fast-handoff TIMING RACE in the low-`dir_sf_mht_ms` shortform/conversion window. CONFIRMED NEGATIVES (do NOT re-try): NOT a double-grant (ex_pop=1, sole EX holder — stale-base RMW by the sole holder); NOT the merge offset-fix (offset-fixed merge + sf_mht=300 = 8/8 PASS, no 799 — the 799 at low mht is independent, offset fix still KEEP); `dir_evict_prior_tenure=1` still FAIL (497s, slower); the reload read IS coherent (`mxfs_dir_rebase_shortform` reads via `mxfs_pal_bdev_read_plain_bdev` = direct submit_bio REQ_OP_READ, pal/linux/kern.c:648, bypasses initiator page cache, reads clyde's shared LIO fileio cache which HAS the releasing node's durable write); release-durability is correct (sess84 deterministic dinode flush + blkdev_issue_flush runs for ALL dirs on release, xfs_mxfs_dlm.c:7435 early-out is REG-only). **THE PARADOX**: release-durability + reload-coherency both correct in code, merge preserves both peers' entries, ex_pop=1 — yet one entry is durably lost at low mht only; extra hold-time at high mht masks it. Candidate: dir DATA block0 writeback at shortform→block CONVERSION not durable before release at fast handoff (sess68 EVDECIDE=0: `mxfs_dir_evict_data_blocks` never iterates for this dir → stale block0 RMW); sess61 "dirty bufgen=0 block0 on a stale base"; sess42 "double sf→block conversion lineage". See [[sess21-dir_reuse-lowmht-race-negatives-and-precise-localization]].
- **`dirwr=1`/printk instrumentation HIDES the race** (minimal 4tcp repro PASSES with dirwr=1) → must use non-perturbing atomic counters. **Diagnostic build A8911EE3** (A8911EE3859F78F3CEAA409 = 7B66691E + non-perturbing probes): **P21-RB** per-fire log (capped 4000) of every `mxfs_dir_rebase_shortform` fire (`ino own_work incore_cnt disk_cnt incore_bytes disk_sz comm`) — LOW-frequency because **rebase fires RARELY** (<256 fires per whole 8tcp dir_reuse; the dir is BLOCK format after ~8 entries, rebase runs only in the brief per-round SHORTFORM phase, so the every-256 P21-RBSTAT aggregate rarely dumps). Conclusion: union merge is largely IRRELEVANT to the steady-state block-format dir; the loss is in the per-round shortform→block growth window. dir_reuse 8tcp is FLAKY (counter build PASSED 8/8 once; other runs lose readdir=799 — fires ~half the runs, must run 3–5×). See [[sess21-diagnostic-ready-per-fire-rebase-log-A8911EE3]].

### Recurring failure modes / lessons
1. **Any ungated/forced dir reload clobbers own committed-not-checkpointed work** (force_coherent, MXFS_IF_DIR_RELOAD arming, wholesale rebase adopt). Reload must be surgical + handoff-gated + own-work-preserving. Union merge + fresh offsets is the shape that works.
2. **Low mht is a correctness/speed vise**: shortform-dir coherency wants hold-time; tcp_dlm_scaling rename churn wants fast handoff. Format-gated mht is the compromise baseline but leaves the low-mht off-by-one.
3. **printk/dirwr logging perturbs and HIDES these fast-handoff races** — use non-perturbing atomic counters, dump at unmount; run repeatedly (flaky ~50% hit).
4. **Reboot clean (virsh destroy+start ALL nodes) between EVERY run** — cross-run contamination is real.
5. **RULE-0**: dir_coherent_modify per-addname was correct but 5× too slow = a FAIL; speed is a first-class gate, not a knob to widen.
