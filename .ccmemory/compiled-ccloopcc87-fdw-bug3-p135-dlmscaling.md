# ccloop cc87fed3 — fence_during_write bug chain, BUG3, P135, dlm_scaling (2026-07-13→14, sess1–8)

Same criteria as every caw loop (1/2/4/8/16/32 caw multipath 100%). Sole gap at entry: `fence_during_write@8/caw`. The loop peeled a chain of seven-plus distinct bugs, ending with builds 0.10.102–104; the criteria were NOT met in this loop (closed later by ccloop 8ba7, see [[compiled-ccloop8ba7-dblalloc-caw-ladder]]). Its enduring value: five proven kernel mechanisms, two instructive reverted fixes, and the live-introspection toolchain.

## The fence_during_write chain (builds 0.10.76–0.10.84)

1. **Bug#1** i_dlm_demoter cleared before irele (0.10.76, pre-loop, see ccloop703f memory). **Bug#2** (0.10.78): `mxfs_pal_time_ms()` is boot-relative; the CAW fair-handoff yield ticket (`yield_set_ms`) is written by one node and aged by ANOTHER — independently-booted nodes have different origins, unsigned `now - yield_set_ms` underflows, fresh tickets look instantly stale (P-YT-STALECLR 83–251×/node → 0 after fix). Fix: `mxfs_pal_time_real_ms()` (wall clock) for all cross-node timestamps. Cross-node time MUST be wall-clock. ([[AAA-ccloopcc87-sess1-FIX3-resource-scoped-orphan-clock-VALIDATING]])
2. **Bug#3** (0.10.80): the orphan-strand/starve escape timers lived on `struct xfs_inode` — icache eviction+reinstantiation under hot-dir churn (proven via `i_dlm_init_seq` incarnation stamp) wiped them faster than the 3s threshold could accumulate. Fix: resource-keyed orphan-clock table in dlm_caw.c (4096 buckets, fnv1a of resource id) + NEW PAL primitive `mxfs_spinlock_t` — grant_meta's mutex CAN SLEEP and `bast_process` holds the `i_dlm_lock` spinlock at the call point (scheduling-while-atomic trap); also never share grant_meta's struct memory (its wholesale memsets under the mutex would race). Per-inode state does not survive eviction; per-RESOURCE state must live off the inode. Correction on record: `caw_fair_handoff` defaults to 0 (BSS), must be passed explicitly.
3. **FIX4** (0.10.81): `mxfs_dlm_pr_sweep_work_fn` walked `sb->s_inodes` with bare `continue` on every reject — held the GLOBAL `s_inode_list_lock` (preempt-disabled) unbounded. Upstream `drop_pagecache_sb` deliberately yields even on skippable inodes ("in case we need to reschedule to avoid softlockups"). ([[AAA-ccloopcc87-sess2-FIX4-pr_sweep_unbounded_lock_hold-VALIDATING]])
4. **FIX5** (0.10.82): FIX4's `need_resched()`-gated yield insufficient — with sibling vCPUs idle, need_resched can stay false forever (proven: RCU stall `csw/system: 0` for 750s+). Fix: unconditional yield every 2048 visits + 1M-visit hard cap bailout. Rule learned while writing it: NEVER `iput()` between `spin_lock(&sb->s_inode_list_lock)` and its unlock (iput recurses into eviction needing the same lock) — the one-behind `toput` pattern exists for exactly this. ([[AAA-ccloopcc87-sess2-FIX5-pr_sweep_unconditional_yield-VALIDATING]])
5. **FIX6** (0.10.83): the sess2 D-state deadlock (bast_process → filemap_write_and_wait → folio writeback → xfs_end_ioend → xfs_ilock EX → demote-wait; [[AAA-ccloopcc87-sess2-NEWBUG-bast-writeback-xfsconv-deadlock]]) had a purpose-built breaker (`mxfs_ilock_admit_ioend`, FIX-25) that NEVER engaged on CAW: `mxfs_v5_dlm_inode_granted_mode()` had no `ctx->dlm_caw` branch — returned NL unconditionally on CAW while every sibling accessor had the branch. Fix: `mxfs_dlm_caw_granted_mode()` returning the REAL per-node mode (do NOT reuse the boolean `caw_held` — a PR hold misread as EX would corrupt admit_ioend's mode upgrade). When adding a transport, audit EVERY accessor for the transport branch. ([[AAA-ccloopcc87-sess3-TWO-FIXES-caw-granted-mode-and-dwork-badref]])
6. **FIX7** (0.10.84): `mxfs_dlm_bast_dwork_fn` lacked the sess60 bad-ref guard its sibling `bast_work_fn` had — `mxfs_dlm_dwork_safe_irele()` (checks i_count<1 || I_FREEING|I_CLEAR, logs P124-DWFN-BADREF, skips) at all 4 exit paths. When one of a function pair gets a defensive guard, sweep the sibling.

## BUG3 — the ~20-30% iput() crash (sess3–5)

`VFS_BUG_ON_INODE(I_FREEING|I_CLEAR)` in `iput()` via plain `rm → do_unlinkat`, ONLY when `dir_reuse_coherency` ran immediately before `fence_during_write` in the same cluster session (15 isolated fdw runs never hit it — prior-churn precondition). The hunt:
- sess3: exhaustive audit of bast_notify (~15 exit paths, script-verified) / bast_process / dwork_fn found NO single-point imbalance ([[AAA-ccloopcc87-sess3-BUG3-refcount-audit-clean-still-hunting]]). Found instead 4 `queue_work()`-already-pending false-branch ref-LEAK sites (wrong polarity for BUG3).
- sess4 breakthrough: live capture showed `ihold+0x28` WARN at `do_unlinkat+0x272` — i_count already ≤0 BEFORE do_unlinkat's own protective ihold, i.e. BEFORE vfs_unlink and all the mxfs_inactive/B1-B5 machinery everyone had been auditing (downstream = where consequences get logged, not where the bug lives). ([[AAA-ccloopcc87-sess4-BREAKTHROUGH-ihold-WARN-in-do_unlinkat-before-vfs_unlink]])
- sess4 rejected fix (KEEP REJECTED): adding B4/B5's `i_dlm_mode==NL` gate to B2's gen-mismatch skip in `xfs_inactive`. GPT+Fable both refused it: captures show `dlm_locked=1` — a fresh EX re-acquire proves the mismatched read is NOT racy; the DLM lock is keyed by ino NUMBER not (number, generation), so EX proves exclusion, never incarnation identity. The gate would convert a crash into silently freeing a peer's live blocks. Topology A (genuine over-release) proven structurally: mark_reclaimable has exactly one userspace-reachable caller (destroy_inode ← evict ← final iput). ([[AAA-ccloopcc87-sess4-BUG3-B2fix-REJECTED-topologyA-confirmed]])
- sess5 ROOT (airtight — three stack traces sharing the literal same RDI pointer in one second): `mxfs_dlm_ilock_end`'s idle_arm and need_flush branches + `mxfs_inode_dlm_defer_bast` used raw `ihold()` to arm deferred releases. `ilock_end` runs re-entrantly from within an inode's OWN eviction (xfs_attr_inactive takes/releases a nested ilock while I_FREEING is set, i_count 0) — raw ihold resurrects a phantom ref, arms a phantom dwork, whose later extra release makes rm's legitimate iput the fatal one. Fix (0.10.85): `igrab()` + proceed-only-on-success + P134-ILEND-FREEING at the 3 sites. THE RULE: every arm-a-deferred-release site must use igrab, never ihold — two more raw-ihold sites flagged unaudited here (P-DEMWAIT-REDRIVE ~21283, queue_pr_demote ~26802) were exactly the family 8ba7 sess1 later swept. ([[AAA-ccloopcc87-sess5-BUG3-ROOT-CAUSE-PROVEN-FIXED-ilock_end-raw-ihold]])

## P135 — sb->s_inodes self-loop corruption (sess5–7)

Found during BUG3 validation: `fault_netpartition@2/caw` after churn → a self-referential `s_inodes` entry → pr_sweep AND stock `drop_pagecache_sb` spin on `s_inode_list_lock` for 600–800s (no natural termination; new SSH sessions hang mid-wedge — you get ONE shot via the already-open dmesg stream). Proven pre-existing/unrelated to BUG3 by revert-bisection (same hang on the reverted build). ([[AAA-ccloopcc87-sess5-SEPARATE-BUG-prsweep-list-corruption-bailout]])

The consumer-side mitigation ladder (each proven insufficient in turn): single-pointer cycle check (0.10.86) → 32-entry ring buffer (0.10.87 — catches cycles ≤32 only; a trailing window structurally cannot catch longer periods; Floyd's tortoise-hare is the right algorithm if ever needed; and stock kernel walkers remain unprotected regardless, so consumer-side can never be sufficient) ([[AAA-ccloopcc87-sess6-ringbuf-built-0.10.87-validating]], [[AAA-ccloopcc87-sess6-ringbuf-INSUFFICIENT-worse-hang-need-tripwire]]) → GPT's sweep-pin tripwire fired ZERO (refuted "sweep's pinned inode evicted under it") → heartbeat probes showed pr_sweep silent 28s before hangs — the holder was stock code walking the corrupted list ([[AAA-ccloopcc87-sess6-tripwire-REFUTED-adding-heartbeat]]).

Fable consult supplied the key structural insight: a self-linked node with a dangling predecessor can ONLY arise from `inode_sb_list_add()` called TWICE without an intervening delete (double-evict is a no-op) ([[AAA-ccloopcc87-sess6-fable-consult-recycle-race-hypothesis]]). The P139 probe (recycle entry finds `list_empty(&i_sb_list)`) fired 14×/run and led to a blind re-link fix (0.10.91) that made everything WORSE (visited=17 cycles, new dir_reuse failures) — REVERTED ([[AAA-ccloopcc87-sess6-ROOT-FIX-recycle-relink-0.10.91]], [[AAA-ccloopcc87-sess6-END-fix-reverted-fable-refused-next-GPT]]).

sess7 TRUE root cause: P139's framing was BACKWARDS — evict() unlinks i_sb_list strictly BEFORE ->destroy_inode, so list_empty at recycle entry is the by-construction ALWAYS-true state (P142, the genuinely-anomalous still-linked case, fired zero). The real bug: `xfs_setup_inode()` called `inode_sb_list_add()` UNCONDITIONALLY (stock `inode_insert5` guards with list_empty). The MXFS-only `mxfs_dlm_reset_inode_for_create()` path reuses a LIVE, never-evicted struct (skips evict by design) whose i_sb_list is still linked; the subsequent xfs_icreate→setup double-add splices it to a new position, stranding the old neighbor's pointer — the observed visited=2–3 signature once that incarnation evicts. Fix (0.10.94): guard the add with `list_empty` exactly like stock. Validated A/B on the identical repro (pre-fix hang reproduced, post-fix 3-test + 16-test suites clean). NOTE: reset-for-create has NO single-node exclusion — this bug could bite at 1/caw. Meta-lessons: instrument the ONE true call site, not one step removed; a probe firing at an expected-state location is not an anomaly; criteria.json accumulates per-test rows across builds and P141-class corruption fires silently DURING passing tests — only trust fresh full-suite runs on the current build (`matrix_check.py --since <build-epoch>`). ([[AAA-ccloopcc87-sess7-ROOT-CAUSE-FIXED-double-add-reset-for-create-0.10.94]])

sess7 secondary: one durable fdw own-data mismatch @16/caw — reset-for-create also skips evict's `truncate_inode_pages_final`, so stale pages (dirty ones survive drop_caches) can serve under the new identity. Defensive `truncate_inode_pages()` at reset entry + P143-RESET-STALE-PAGES (0.10.95). INCONCLUSIVE — P143 never fired; keep watching, mechanism unproven. ([[AAA-ccloopcc87-sess7-SECONDARY-fdw-page-cache-hypothesis-inconclusive-0.10.95]])

## sess8 — dlm_scaling@32 and the reverted cache-coherency clobber

- **FIX 1** (0.10.102/C9D0F29C): sess7's post-hoc `invalidate_epoch` no-op'd 100% (P144-DIAG 2190/2190 `reason=noslot`) because `find_slot()`'s contract only matches LIVE slots — a tombstone is never "found". First reshape (separate find+read+CAS after unlock) fixed the epoch but regressed the test to 0/32 — the known TRAP 1: any extra synchronous per-free FUA CAW op eats the shared iSCSI command-rate ceiling even off the latency path. Final shape: `mxfs_dlm_caw_unlock_gen(..., is_free)` zeros dir_epoch/last_ex_slot in the SAME image the unlock's tombstone CAS already writes — zero extra I/O (this was the original authoritative 0d6e174d design sess7 never actually implemented). Aggregate 1319–1650 → stable 1794–1805 ops/s. ([[AAA-ccloopcc87-sess8-dlm_scaling32-TWO-FIXES-plus-residual-variance]])
- **FIX 2**: sf→block conversion could drop a peer's just-logged dirent — the adopt-check caught FORMAT staleness only; added face 1b (LOCAL/LOCAL with `disk_sz > i_disk_size`), call site re-enabled gated on `i_dlm_dir_gen > 0` to bound the FUA-read cost. Fired once ever; watch on recurrence.
- **Residual variance** (never closed in this loop): one rotating node occasionally 41–43 ops/s vs floor 50, two-phase rate pattern, CAW retry counters clean, SCST threads_num 8→32 no effect, 128 vCPU on 56 cores suggestive but ~30% host idle at peak. (8ba7 later attacked adjacent causes: printk volume and host memory pressure.)
- **cache_coherency@32 "uv gone" attempt REVERTED** (tree left safe at 0.10.104 = C9D0F29C): symmetrizing the xfsaild dir-clobber guard to `dcnt != bcnt` regressed posix_multi@8 (renamed content empty, hardlink dirent gone — reproducible). `bcnt > dcnt` is AMBIGUOUS between a stale buffer resurrecting a peer-removed entry (bad) and our OWN post-EX-release async destage that disk hasn't caught up to (normal-by-design: commit→release→async-flush). Only `dcnt > bcnt` is unambiguous. Any reintroduce-direction fix needs PER-ENTRY provenance, and posix_multi (rename+hardlink) is the mandatory canary. ([[AAA-ccloopcc87-sess8-END-cachecoh-bidirectional-clobber-REVERTED]]) — Superseded in practice: 8ba7's P150 removed the underlying stale-image family.

## Reusable toolchain and hygiene (proven here, referenced by later loops)

- **Live guest introspection with zero guest cooperation**: `virsh qemu-monitor-command <vm> --hmp "info registers -a"` (2 samples to prove a frozen/oscillating RIP); raw bytes via `x/Nxb <rip>`; symbolize module RIPs by unique byte-sequence match against local mxfs.ko (objdump -h section offset + nm -n); recover per-boot KASLR slide via idle-HLT RIP mod 0x200000 against `/boot/System.map` (sudo cp out); stack walk via `--hmp "cpu N"` + `x/80gx <rsp>`.
- For D-state hangs with SSH alive, skip all of that: `ps -eo stat,pid,etimes,comm` + `cat /proc/<pid>/stack`.
- `addr2line -e mxfs.ko -f -C <objdump-base + offset>` — only valid when local .ko srcversion matches the node's loaded module.
- **Live per-node `dmesg -T -w` streaming is mandatory for diagnostics**: the serial console is loglevel-filtered and misses ALL pr_warn probes; once a wedge starts, new SSH sessions hang — pre-instrument, keep the stream open, one shot per repro.
- "No route to host" mid-run ≠ softlockup: check the serial log for oops/invalid-opcode FIRST — a crashed kworker can take networking down.
- Check `mtime(mxfs.ko)` vs source mtimes before trusting VERSION or cluster_reset ALL_OK — sess6 nearly validated a stale binary.
- Kill orphaned `run.sh`/`dmesg -T -w`/bare-ssh trees by lstart before live-capture work (grep `"ssh .*root@test|sshpass.*root@test"` — wrapper-name grep misses the grandchildren); stale processes can run fault_netpartition's `fuser -k -m /mnt/shared` against your live run. `rm -f /tmp/mxfs_run.lock` before fresh sequences.
- Reference kernel is at `/src/linux` (absolute path; `~/src/linux` doesn't resolve in the Bash tool).
- SCST live knobs: `/sys/kernel/scst_tgt/devices/mxfs/threads_num` writable live; per-session stats under `targets/iscsi/.../sessions/`.
- Consult-chain history: GPT-then-Fable was the sess4 order; Fable refused twice in sess6 (refusal = failure → GPT). Current CLAUDE.md rule is GPT-only — Fable is self-consultation now that Claude Code runs on Fable.
