Topic: the on-disk magic decision, and a cluster of traps where a verdict (verifier, checker, harness, inference) is vacuous or about the wrong thing. Nine notes folded in.

## Decision: MXFS has its own magics

[[user-mxfs-gets-its-own-magics-and-old-volumes-are-refused]] (user, 2026-09-26; landed 0.90.0). After a linux-xfs reviewer asked for distinct magics so an MXFS image is not mistaken for XFS, every XFS-derived magic became MXFS-specific: superblock and per-AG copies, AGF/AGI/AGFL, all btrees, inodes, dquots, dir/attr/symlink blocks, log record and transaction headers. Two corrections, both delivered angrily:
- Names are `MXFS_SB_MAGIC`, `MXFS_DINODE_MAGIC`, `MXFS_LOG_HEADER_MAGIC_NUM`, never `XFS_*_MAGIC` with a new value. Same for the userspace tools' private copies.
- No legacy: no "legacy XFSB" define, no "last version that reads it" string, no old-format refusal message citing a previous release. An old volume fails the ordinary bad-magic check; that is the whole compatibility story.
Table lives in `xfs/libxfs/xfs_format.h`, `xfs_da_format.h`, `xfs_log_format.h`. `tests/mxfs_magic_isolation.sh` proves stock xfs_repair, blkid and xfs.ko do not recognise a new volume.

## Vacuous verdicts: a check that cannot fail

- [[trap-a-verification-condition-that-a-healthy-build-cannot-produce-is-vacuous-by-construction-inject-it-at-the-verdict]] (D-0947): the record demanded `P947-VALIDATE-NOMAGIC` > 0 from churn, but since sess444 every carved chunk is FUA-initialised and read back before ICREATE, so a healthy build can never produce it. A clean lap with the count at zero measures nothing. Before a lap whose closure needs a probe count, ask whether the build can reach the probe at all. Fix: inject the verdict (test-only knobs `dbg_validate_nomagic_n`, `dbg_validate_nomagic_ino`, consulted after a clean read), `tests/d0947_nomagic_repick.sh`. Also: a variable defined only in one mode's pre-phase killed the remote command under `set -u`, and the empty round line was scored `mounted=0` ("filesystem died"). A missing round line is a harness ABORT; names used inside a remote command must be defined in every mode.
- [[trap-a-short-btree-interior-walk-that-puts-the-pointers-after-numrecs-keys-reads-the-superblock-as-a-child-and-the-audit-walkers-pass-vacuously]] (chk_mxfs, fixed 0.89.7): V5 short-format btree child pointers start at `56 + MAXRECS*keylen` (kernel `xfs_btree_ptr_offset()`), not `56 + numrecs*keylen`. At 4 KiB: inobt/finobt ptrs at byte 2076, bnobt/cntbt at 2744. The wrong offset read zeros, child agbno 0, i.e. the superblock; never fired before because no test fs had more than one inobt leaf per AG (>16128 inodes). Two failure directions: walk_inobt/walk_freespace_btree printed errors (false CORRUPT); orphan/dangling-parent/dirent audit walkers silently `return` on magic mismatch and printed `OK (0 allocated inodes)` (false CLEAN). Any earlier chk_mxfs verdict on an AG with >16128 inodes or >505 free extents was read through this defect. Proven before patching by `dd iflag=direct` of the root block. Harness lesson: `tests/chk_mounted_node_reads_platter.sh` PASSed its own field assertions while the checker printed ten errors and rc 4; a harness running a verifier must assert the verifier's verdict (rc 0, zero ERROR lines). Anchor greps for `AG 0 inobt` or the per-record lines flood context.
- [[technique-to-exercise-a-refusal-for-a-record-this-build-cannot-produce-inject-at-the-write-not-at-the-check]]: a guard against records an older build wrote is unreachable by construction and is an unexercised upgrade-path guard. Inject at the durable WRITE (substitute the value just before the seal, every producing check still running against the proved value): it cannot loosen anything, the seal/CRC covers the substitution so the record is byte-for-byte a legacy one, and the substitution is logged so it doubles as the harness's non-vacuity gate. Injecting at the CHECK removes the safety being measured. Building the old version for a real legacy record is stronger but costlier; do it only when injection cannot reproduce the state.

## Inference traps in the inode allocator (D-0947 / D-0948)

- [[trap-no-inode-magic-does-not-mean-nothing-was-ever-written-there]] (sess572): "no dinode magic at the home" was taken as "nothing ever written there" and allocated on; the block held a live XDD3 dir3 data block (ino 4321728), producing `xfs_inode_buf_verify` failures and a forced shutdown. Each premise was true; the failure was the step between them. Where inference cannot separate two causes (our un-destaged cluster vs. someone else's block), act and re-observe: `xfs_log_force(SYNC)` + `xfs_ail_push_all`, re-read; ours now has magic, not-ours does not; refuse transiently (cooldown, re-pick) instead of allocating or hard-failing. Ask "what else produces exactly this observation?"
- [[trap-an-inobt-record-corruption-line-after-a-pick-is-the-allocator-naming-a-hole-decode-holemask-before-hunting-a-stale-write]] (sess572 to 615): the evidence had `start inode 0x41f1c0, count 0x20, freemask 0x...fffe, holemask 0xff` 15 ms before shutdown. `count < 64` means sparse record; holemask bit i covers offsets 4i..4i+3; a cleared free bit under a set holemask bit is a pick inside a hole. Cause: `mxfs_dialloc_pick_in_rec` walked `ir_free` without masking `xfs_inobt_irec_to_allocmask()` (upstream `xfs_inobt_first_free_inode` masks it; a sparse record stamps `ir_free = ALL_FREE`). Three sessions wrongly chased a stale cached dir buffer written over a fresh cluster. Rules: decode startino/count/holemask/freemask first; a "no magic"/"foreign metadata" verdict on a candidate is not platter evidence until the candidate is shown to be carved (check holemask); any code walking `ir_free` must mask holes (counters `dialloc_holemask_n`, `dialloc_holepick_n`, knob `dbg_dialloc_pick_holes`). The later s574dv 398/702 failed creates (`P-CR62 ... disk_di_mode=0177777`, 26501 quarantine refusals) are the same shape, not the D-0947 "un-destaged chunk" explanation.

## Measuring the wrong thing: devices, writers, VMs

- [[technique-the-device-under-test-is-a-declared-identity-and-the-wrong-instrument-fixture-is-the-real-lun-under-a-wrong-declaration]] (0.87.20): a path naming another valid device (e.g. `/dev/vda`) answers every probe with well-formed output, so the verdict is about the wrong instrument (203 sites in 159 scripts chose a device by rig-specific spelling). `data/rigs.json` declares the LUN WWID per rig tag; `tests/setup/dev_identity.sh` reports readlink, major:minor, WWID, envelope fsid (direct read of sector 0, `MXFS` at byte 0, uuid at 16), live mount; `mxfs_dev_resolve`/`mxfs_dev_check`/`mxfs_dev_same` in `tests/lib/rig.sh` enforce it. Undeclared rig resolves nothing; no WWID is refused; never fall back to path/size/model; a marker filled from whatever prep selected is circular. The rejection fixture that proves the comparison exists is `MXFS_LUN_WWID=naa.000...dead`, the real LUN under a wrong declaration (`/dev/vda` alone rejects for a missing WWID and would pass with no comparison). tcpmp chains must name the LUN; transport and storage profile are independent. `tests/rig_lib_contract.sh` cases 12c/12d.
- [[trap-a-slot-record-advancing-under-a-torn-down-fleet-is-a-foreign-host-with-a-stale-fstab-mount-on-the-shared-lun]] (s62e to s67): the "node from the previous lap still heartbeating" behind the mkfs verify FAIL (0x4b 'K' of MXLK at slot 2) was an inference, never measured. The prep guard fired with both VMs torn down. `ts_ms` is the writer's boottime (136,190,000 ms = 37.8 h, neither VM); `fs_gen=0 epoch=0 pr_key=0 boot=0 ident_magic=0` is a pre-identity build, which rig nodes skip silently (`hb_gen_foreign`) so no journal names it. A scratch WE-AR reservation froze the stamp, confirming a foreign writer landing only in unreserved windows. Found by LAN sweep: serv (192.168.1.5), DKMS mxfs.ko from the physrig era, fstab `/mnt/shared mxfs` with `_netdev`, `heartbeat write failed: -52` bursts in the reservation windows. Fixed by umount, rmmod, fstab line disabled. Lessons: a stamp advancing under a torn-down fleet is never a previous-lap node; read the writer clock and identity fields, then sweep the LAN; `tools/mxfs_whohas.sh` finds holders without the fuser/lsof mmap_lock walk. `mxfs_disklock_claim_slot` treats a foreign-generation ACTIVE record as CLAIMABLE with no liveness test (filed s67). The QNAP LUN outlives every rig; after any lab power event dump the heartbeat table under a torn-down fleet before trusting a prep. Use `journalctl -k -b` / `-u` under `timeout`, not a full journal over ssh.
- [[trap-rig-vm-definitions-have-no-acpi-so-virsh-shutdown-and-guest-poweroff-never-power-off]] (fixed 2026-09-23): rig VM libvirt definitions (test1..test32, pve9-1/2) lacked `<features><acpi/>`, so `virsh shutdown` was ignored and guest poweroff finished but never powered the machine off. `scripts/libvirt_add_acpi.sh` added `<acpi/><apic/>` to all 36 domains (effective at next start; run it for any new VM). A VM that won't shut down is first a definition question: check `journalctl -b -1` for poweroff.target; `virsh destroy` only after the guest reached poweroff and nothing is mounted.

## Common thread

A verdict is only evidence if it could have come out the other way: assert the verifier's own verdict, confirm the probe is reachable on the build under test, confirm the instrument is the declared device, and when two causes give identical bytes, run an experiment rather than a better argument.
