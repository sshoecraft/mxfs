Five traps sharing one theme: the configuration or discriminator a test believes it is exercising is not the one actually in force. The first three are about loading and configuring mxfs.ko; the last two are about instrumentation and harnesses that cannot distinguish the cases they claim to.

## Loading and configuring a test module

- **insmod skips modprobe.d.** Swapping a hand-built mxfs.ko onto a package node with `insmod` does not apply `/etc/modprobe.d/mxfs.conf` (`force_transport=1`, `target_cache_protected=1`). Without `target_cache_protected` the RW mount is refused (P-DOMAIN-REFUSED, rc=32), and a probe that then touches `/mnt/mxfs` runs on the underlying root-fs directory and reports a meaningless result. Load with `insmod mxfs.ko $(sed -n 's/^options mxfs //p' /etc/modprobe.d/mxfs.conf | tr '\n' ' ')`, gate every probe on `grep -q ' /mnt/mxfs mxfs ' /proc/mounts || exit 1`, restore with rmmod + modprobe. A lone mount on a LUN with an unclean slot runs whole-cluster bootstrap and waits the 62 s death timeout before replay, so a mount budget under ~150 s is killed by `timeout` and the mount aborted after it completes. [[trap-insmod-skips-modprobe-d-options-so-a-test-module-mount-is-refused-and-the-probe-runs-on-the-bare-dir]]
- **A charp module parameter containing a space needs literal quotes in the insmod argv.** kmod joins argv into one string and the kernel splits on whitespace in `next_arg()` (`/src/linux/lib/cmdline.c:227`), which honours `"` only if the quotes are still present. `target_retire_contract="QNAP:iSCSI Storage:..."` arrived as `QNAP:iSCSI`, and the module refused every certificate for a product mismatch it invented. Pass `'name="value with space"'` (or `ARGS+=("name=\"${VALUE}\"")` as in `tests/setup/prep_node.sh`). It was caught only because the harness read `/sys/module/mxfs/parameters/<name>` back and asserted it before grading; any harness configuring the module through a parameter should do the same readback. [[trap-a-module-parameter-whose-value-contains-a-space-needs-literal-quotes-in-the-insmod-argv]]
- **Documented mount options that the live parser never had.** `docs/discovery.md` and `mxfs(5)` listed ~11 options (`broadcast`, `multicast=`, `discovery_port=`, `port=`, `dlm_transport=`, `block_cache=`, `inode_cache=`, `dir_cache=`, `node_slot=`, `journal_offset=`, `disklock_offset=`) that existed only in the retired `dlm/mount.c` (`struct mxfs_mount_opts`, not in Kbuild); users got "unknown mount option". Check `xfs_fs_parameters[]` in `pal/linux/xfs_super.c` before documenting or using an option. Real knobs are module parameters (`force_transport`, `cache_mem_pct`, `inode_cache_max`, `block_cache_max`, `dead_timeout_ms`, `dirshard_mkdir_enable`; see `modinfo`) and, since 0.89.74, mount options `peers=A/B/...` (slash-separated, the option string splits on commas) and `cluster=NAME`. Discovery/lease hardcode multicast 239.66.83.1 and port defaults in `dlm/v5_mount.c`. [[trap-documented-mxfs-mount-options-did-not-exist-in-the-live-parser]]

## Discriminators and reproductions that cannot tell the cases apart

- **A caller tag or return address names the funnel, not the caller's intent.** `xfs_buf_item_relse` exempted `why == "iodone"`, but that tag is stamped by `xfs_buf_item_done`, which nine overlay release-drain/acquire-evict arms call with no I/O. The adjacent probe printed `__builtin_return_address(0)`, always `xfs_buf_item_done` inside `xfs_buf_item_relse`; 145 firings were dismissed as benign completions because the discriminator was already discarded. Sticky provenance fields can be stale and `XBF_WRITE` is wrong the other way (`xfs_buf_ioend_fail_unsubmitted`). Fix: the caller declares the property as a parameter (`enum xfs_bli_release_ctx { XFS_BLI_NO_IODONE, XFS_BLI_IODONE_FOLLOWS }`; only `__xfs_buf_ioend` passes FOLLOWS), and change the prototype rather than adding an optional argument so the compiler enumerates call sites (it confirmed ten). Separately: closing the hole did not prove it was the leak's route (the arms are gated on dir-buffer predicates, disjoint from the AG-meta `b_ops` set; the verification lap measured zero firings). Say "unsound contract, now sound", keep the defect open. [[trap-a-caller-tag-or-return-address-cannot-discriminate-callers-that-all-funnel-through-one-function]]
- **A synthetic harness misses the preconditions the real criterion produces.** For D-0963 (shortform dir's deleted entry resurrected by 3-way merge), `tests/d0963_sf_dirent_resurrect.sh` ran 0/20 because (1) the platter adopt (P174-STALEGEN-ADOPT) is skipped on the node that created the directory (`sf_disk_check` requires `!i_mxfs_self_created`) and the harness had the deleter create it, and (2) the deleter's fork must stay stale-gen through its removal loop, needing the re-acquire to skip the rebuild (P34F-RELOAD-SELFAHEAD-SKIP: pin=1 ili=0x1, loaded_gen frozen while dir_gen advanced), but the harness forced the log at each handoff. The real `cache_coherency` unlink_visibility phase produced both at 1 lap in 5. Drive the real criterion in a lap loop with diagnostics armed (`tests/d0963_cc_laps.sh`) before inventing a shape; when a synthetic reads 0/N, check each probe's gate conditions against which node plays which role (self-created, pinned, post_release) instead of assuming the chain is wrong. [[trap-a-synthetic-dirent-harness-misses-the-two-preconditions-the-real-criterion-produces]]
