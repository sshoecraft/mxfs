Compiled from nine notes sharing one theme: a lap, probe or derivation that printed PASS/FAIL or a root cause without measuring what it claimed. Two further items are bounded-wait technique and rig-host hygiene. The group is topic-clustered, loosely.

## Opening a race window: the knob must widen only the window under test

- [[trap-a-test-delay-in-a-serial-service-thread-keeps-the-other-side-out-of-the-window-it-was-meant-to-widen]]: a 300 ms `peer_recv_start_delay_ms` in `start_recv_thread` was applied to BOTH the outbound connect path and the accept thread. There is one accept thread per mount serving every peer, so the delay made it answer nobody else; inbound setups queued in the listen backlog and arrived after every outbound window had closed. The control lap lost no thread yet printed `PASS overlaps=2`, because the accept thread waking from its own delay and accepting the next queued connection from the same peer satisfies "replaced within 50 ms of store" (`by=accept age_ms=304`).
  - Put a widening delay only in the path whose window is widened, never in a serial service thread the other side must pass through.
  - Instrument lines name both parties (`by=` and `inst_by=`) so the harness requires a cross-direction event instead of inferring one from timing.
  - Write the "exercised" test from the prediction's own wording (the queue said `thread_pid=0`; a looser test let a vacuous lap pass).
  - A control lap that reproduces nothing is not evidence against the hypothesis until its precondition line is read; here the fix arm's `P-PEER-REPLACED by=connect-install state=0` named the real path, no timing window needed.
- [[trap-the-iflush-pause-knob-misses-cluster-passengers-and-holds-xfsailds-whole-delayed-write-list]]: `dbg_iflush_pause_ino` is keyed on the pushed inode, not the cluster. If the parent shares the child's inode cluster and is pushed first, the child rides as a passenger unpaused (pause_n=0 every round); fix is padding the parent with 64 files so the child lands in another cluster. Second, the sleep sits inside the AIL push loop, so buffers already queued are submitted only after it returns, and a release drain waiting on its own flush waits out the pause, landing parent and child together (pause_n=1, drain_ms=2537, window never opened). Fix: pin the child with `dbg_ail_pin_ino` for one `ail_push` kick, unpin, arm the pause, kick again. The pin is also honoured inside `xfs_iflush_cluster`, which the release drain calls, so a pin left armed across the peer's coordination makes a fix look broken.
- Common lesson: two vacuous laps preceded each working one. Read the knob's own counter (`pause_n`, `overlaps`) before trusting a lap's verdict.

## Scoring: assert the violation, not its ingredients

- [[trap-co-occurrence-of-two-probes-is-not-a-race-waking-is-not-acting]]: `takeovers >= 1 && P236-FENCE-INTENT-RESUME >= 1` reported "two actors under one attempt" and was wrong three ways: RETIRE_PENDING was never published (an earlier assertion in the lap had already failed saying so), the resumed worker issued nothing (`KEY_ABSENT_UNPROVEN(6) proves_excl=0`), and the in-node guard had refused it five times (`P304-FENCE-PROVE-BUSY`).
  - Count the violation (the old prover proving exclusion under the old term after a takeover raised it), not co-occurring events; the term is the cross-node guard.
  - A FAIL message must not narrate a mechanism the lap did not establish.
  - When an earlier assertion has failed, dependent later assertions are unscoreable; exit VACUOUS rather than report downstream FAILs about a state never reached.
  - A bound shorter than the injection it must outlast measures the injection: a 90 s unmount bound against a 300 s test hold failed by construction. Derive it as `HOLD_MS/1000 + slack`. When a lap refutes its own hypothesis (the unmount blocking was correct serialisation against the node's own outstanding attempt), assert the safe property directly instead of deleting the test.

## Reading probes and the ring

- [[trap-check-cumulative-vs-last-value-before-dividing-probe-fields]]: two wrong root causes from real data. (1) A subtracted residue (35.1 ms wall minus 9.3 ms sleep, over 2.7 attempts = 9.42 ms) was named "slot I/O service time"; it held everything else in the loop, including un-instrumented `find_slot` and `caw_inode_backoff`. Name a residue "unaccounted" and look for a direct probe; absence of one is the finding. (2) `read_ms` is assigned (`=`) per poll, `reads` is cumulative; dividing them is meaningless. `slept_ms` printed `last_sleep_ms` while cumulative `sleep_tot_ms` existed unprinted. A claim of "~242 ms per acquire wait unaccounted" had to be retracted for mixing cumulative `el_ms` with last-value fields. Before dividing: grep each field's assignment (`+=` vs `=`), confirm numerator and denominator count the same episodes, check whether a direct probe already ships, and print a residue as a residue. `tools/caw_unlock_audit.py` encodes this.
- [[trap-a-mount-time-info-line-rotates-out-of-the-guest-ring-before-a-windowed-lap-reads-it-so-expose-the-fact-as-a-module-parameter]]: a once-per-mount INFO line (`P290-AUTH-WITHDRAW-THREAD`) had rotated out of the victim's ring 150 s later (thousands of capped probe lines per mount, P74-GRANT alone capped at 8000 per boot); a whole-ring `dmesg | grep -c` read 0 and the lap FAILed on that alone. Thread comm cannot substitute (all PAL threads are `mxfs-worker`), and a post-prep capture races ring churn. Expose the fact as a read-only module parameter maintained by the code (`auth_withdraw_threads`, read from `/sys/module/mxfs/parameters/`), falling back to the ring only for a module lacking it and saying so in the assertion text. Companion to `technique-ask-the-built-module-which-probes-exist-before-trusting-any-harness-that-counts-one`.

## Measuring a target you do not own

- [[technique-measure-a-targets-task-retirement-from-the-initiators-when-you-do-not-own-the-target]]: for a closed-source appliance, `tests/pr_retirement_probe.sh` has the victim run N O_DIRECT threads writing a rising 64-bit counter into N blocks, the survivor read the window O_DIRECT in a tight loop emitting a row on every change, and the victim power-cut (`virsh destroy`), never shut down. Counters stopping is the victim's death in the observer's own data, so no cross-host clock is needed; any change after a quiescent gap is a late landing from the dead nexus.
  - O_DIRECT needs a block-aligned buffer, not just offset: use `mmap.mmap(-1, n)` with `os.preadv`/`os.pwritev`, since pymalloc memory gives EINVAL that reads as "write refused".
  - Rate-limit change rows to one per 50 ms (never hides the post-gap row).
  - Quiescence at the end of observation counts: the gap runs to `READER_DONE wall=`.
  - A positive control is mandatory (survivor saw the window advance while the victim lived). State the resolution.
  - A clean result is a qualified contract for that target, firmware, backend and topology; declare it in `data/rigs.json` with evidence, read it fail-closed, and re-measure on change.

## Bounding a wait for a caller that holds no lease

- [[technique-bound-a-slotless-callers-wait-with-the-window-that-lets-a-peer-take-its-role]]: the slotless bootstrap-owner barrier hang (diagnosed in `trap-a-barrier-whose-two-exits-are-both-slot-derived-hangs-forever-for-the-one-caller-that-has-no-slot`) was cured by swapping the source of both exits (beat: disklock heartbeat to bootstrap record write timestamp; authority-closed: lease deadline to abandon window since our last landed record write, or term already taken over), not by a timeout or letting the waiter satisfy its own wait (0.89.34 self-beat was reverted in 0.89.36 for deleting the property under measurement). Ask what window lets someone else take the caller's role and bound the wait with that. Stamp issue time, not completion time. Verified: `P307-LURESET-BARRIER ... arm=bootstrap-term beat_landed=1 wait_ms=1021`, with `deadline_ms=0 incarnation=0` showing the authority object never armed. A pinned module (rmmod refcnt=2) plus `/proc/<pid>/comm` and `/stack` proved the heartbeat thread alive before any fix was written. `MXFS_AUTH_NOT_ADMITTED` reports authority HELD by design, so any "has my authority closed?" gate answers no forever for a caller that never lands a beat; check that when an authority-gate wait does not terminate.

## Rig host: timer loss and evidence loss

- [[trap-vsphere-guest-jiffies-jump-then-freeze-stalls-every-mxfs-sleeper-at-once]]: guests on an oversubscribed host lose kernel timers (nested vSphere: jiffies +516,630 in 1.4 s then frozen; plain KVM rig guests with clyde at loadavg 300-400: soft lockups 39-194 s, RCU "timer wakeup didn't happen"). Every MXFS thread sits in S state in a timed sleep at once while userspace may run; the result looks like MXFS failure (lone node's lease expiry and self-fence, a peer declared dead hundreds of seconds late, survivor EIO that is its own correct self-fence). Three critical/high records were filed and later removed. Before diagnosing "every thread stopped" or "rig VM unreachable", check clyde `/proc/loadavg`, the guest serial log (`sudo -n tail /var/log/libvirt/qemu/<vm>-serial.log`), and compare `jiffies:` in `/proc/timer_list` minus INITIAL_JIFFIES (4294667296, HZ=1000) with `/proc/uptime` in ms (`tests/vsphere_lone_mount_stall.sh` samples this). Do not add load: never two full kernel builds in parallel; a `docker exec` build whose client dies keeps compiling.
- [[trap-long-rig-run-evidence-in-scratchpad-is-lost-to-a-host-reboot]]: a 6-lap board with `D385_OUT` in the session scratchpad was lost with a clean host reboot ~15 min in; the rig needed a ~7 min rebuild and the whole board rerun. Anything a later session must read (lap logs, dmesg harvests, probe sweeps) goes under `tests/evidence/<topic>/` (NFS) at launch, not copied afterwards; same for `AGIFC_OUT`, `TMPC_OUT`, `FTR_OUT`. Also: a self-numbered session label can disagree with the loop's resume numbering, so label evidence unambiguously.
