Compiled from seven traps about staging on-disk state for recovery/replay/crash tests and about reading their results. Common thread: a staging step or control that cannot produce the state it claims, or a negative claim checked too narrowly, reports success or failure that means nothing.

## Staging a dirty log or unlinked-inode state

- Unlink-while-open workload that closes each fd before the next unlink logs no dinode image. `xfs_iunlink_insert_inode` logs `di_next_unlinked` only when the AGI bucket is non-empty; closing the fd frees the inode and empties the list again, so no `XFS_BLFT_DINO_BUF` image is ever formatted. Replay-guard injectors then read `fired=0 declined=0`. Fix: hold every fd open across all unlinks and past the point the image must survive; detach the holder so it outlives the ssh command. Closing later can stale the cluster, emit a CANCEL record and make replay skip the injected image (vacuous lap). Bucket arithmetic: `agino % 64` for single-node (need >= 65 files to collide), but `mxfs_iunlink_slot_buckets = 1` funnels a clustered mount into one bucket; check the knob. Make every injector rejection path name itself, because "never called" and "called and rejected everything" look identical. BLFT is `blf_flags >> 11`. See [[trap-an-unlink-workload-whose-fds-close-between-unlinks-logs-no-dinode-image-at-all]].
- A node does not recover its own dirty log at its next mount. A remount makes a fresh disklock claim, the slice is zeroed (P-SLIFE) and "slice ADOPTED"; the old slice is foreign and replayed by whichever survivor fences it. Result: "Ending clean mount", `Starting recovery` count 0, `replayed=0`. To give a mount recovery work: dirty the PEER, force shutdown and unmount it, make sure no survivor exists (unmount the measured node first), then mount the measured node. Discriminator is `P163-RECOVERED` and the `replayed=` field of the barrier-complete line, not `Starting recovery`. See [[trap-a-remounting-node-adopts-a-fresh-log-slice-so-dirtying-its-own-log-stages-nothing-for-its-own-mount]].
- Killing a background fd-holder by pidfile does not release its descriptors if it forked a child (`sleep 900` inherited all 48 fds); the PID liveness check passed while umount returned "target is busy". Use `setsid` and signal the group (`kill -TERM -"$pid"`), assert on the mount (unmount succeeds) not the PID, or park on a short `sleep 2` loop polling a release file. A staging step that can leave a mount held needs a bounded fallback (`umount -l`) on its failure path. See [[trap-a-background-holders-sleep-child-inherits-its-open-descriptors-and-keeps-the-mount-busy-after-the-holder-is-killed]].

## Shell facts in ssh node commands

- `( list ) &` in a non-interactive shell double-forks: `$!` is a wrapper whose child owns the fds (wrapper fds=3, child fds=403 on clyde), while the Bash tool's shell showed them in `$!`. Count over `$!` plus `/proc/$!/task/$!/children`; `wait $!` timing still holds.
- `a && b && ( list ) &` backgrounds the entire AND-list, including setup (`rm -f flag fifo && mkfifo fifo`). A stale flag from the previous leg satisfied the foreground wait, both sides waited on different fifos, harness reported "hung" nodes with no umount task. Write setup as its own statement with `|| exit 1`; use per-leg unique names or clean in the foreground; verify what a node command did from the node (`/proc`, read-back) and abort the leg on mismatch. "Hung" with no task in the hang capture means the harness, not the kernel. See [[trap-background-subshell-double-fork-and-and-list-precedence-in-ssh-node-commands]].

## Crash controls that cannot fail

- A one-block shared directory (~120 short names) is re-logged by every create, so the last create's surviving item makes the AIL push write the whole block; the D-0492 control passed `missing=0` on both the buggy 0.70.9 and fixed 0.70.11. The discriminating shape is multiblock (prefill 220 24-char names across 3 data blocks; unlink from block 0, fsync'd create into the hole, then a 100-char create landing in block 2), where 0.70.9 lost 5/5 creates and undid 5/5 unlinks. Before trusting a crash control, state which block's last modification is unprotected and show the census line proving the arm fired on it afterwards; print the at-risk population by name, including reappeared unlinks. See [[trap-a-one-block-directory-crash-control-cannot-lose-the-last-create-relogs-the-whole-block]].

## Methodology traps in diagnosis

- A negative claim about the tree needs a tree-wide search. "Containment never implemented" was written into two ledger records after reading only `xfs_create`; it lived in `mxfs_dialloc_validate_candidate()` (`xfs/libxfs/xfs_ialloc.c:1657`), because a candidate inode number does not exist before dialloc, so "before dialloc dirties the transaction" means inside dialloc. Run `grep -rn` across `xfs/` before writing "no check for Z". The corrected finding: the validator ran and allowed the inode, with two distinct allow paths (pubob lookup early return at :1676, or `mxfs_dbg_disk_di_mode_coherent()` returning free while the raw reader saw LIVE; different readers at `xfs_mxfs_dlm.c:42254` vs `:42096`); `P946-VALIDATE-ALLOW via=pubob|coherent-free` names the branch; patch neither until it reports. See [[trap-absence-in-one-file-is-not-absence-in-the-tree-containment-was-implemented]].
- A struct built field by field at N sites misses a new field at one of them, and an unassigned stack field reads as a valid value on the wire. D-0977 (0.89.0 to 0.89.1): the REAFFIRM arm of `process_remote_request` (dlm/dlm.c) never set `dlm_grant_ids.open_holders`; the holder mirror adopted the zero mask unconditionally, so an unlink's idempotent re-acquire (P-INACT-CERT) freed an inode under the peer's open descriptors. Deterministic on TCP, not a race. When adding a field, grep every `struct dlm_grant_ids` declaration and every `send_grant(` caller (8). Receiver rule: replace the snapshot only on a new durable grant id (`grant_seq64`/`authority_epoch` differ), else OR; never OR across fresh commits. `dlm_import_holder` (takeover) had the same omission and now stamps `lk->open_holders = e->open_holders`. Design: docs/tcp-authority-ledger.md. See [[trap-a-grant-identity-struct-built-per-path-leaves-a-new-field-unassigned-on-the-re-affirm-and-an-exclusive-re-grant-that-adopts-it-frees-an-open-file]].
