Central topic: the `dir_reuse_coherency` criterion on the 2-node TCP-transport config (`./run.sh 2 tcp`) — the sole FAIL out of 17 applicable tests across sess25-26 (ccloop run `8ddb16a2`). Repro harnesses: `tests/drc_probe.sh`, `tests/drc_probe2.sh`. The workload: node1 (rank1, dir owner) does `mkdir` + `rm -rf` of the SAME dir name (`.drcp`) each round; both nodes create data+md5 files; cold-verify uses `drop_caches` then stat/readdir. Names repeat every round (`node2_fN`) so only the **inode number** reveals staleness. The blocker turned out to be a stack of distinct bugs peeled one at a time; the final proven root is a WRITE-side durable lost-update under daddr/inode REUSE surfacing as an ABA stale-BLI FUA-skip.

## sess25 — inode resurrection is the upstream root; gen-based discrimination is a dead end

PROVEN ROOT ([[sess25-drc-leaf-double-alloc-live-evidence]], build `254E0DBE`, parent of `0302171A`): **INODE RESURRECTION**. `P-IRESURRECT=201`, `P119-NONEX-FLUSH-SKIP=0`, `P17B-EPOCH-GHOST-SKIP=0` — 201 stale-inode flushes by `xfsaild/sda` all PROCEEDED. Each flush: `incore_mode=0100644 (live file), disk_mode=00 (FREED), incore_nlink=1, disk_nlink=0, disk_gen=incore_gen+1, i_dlm_mode=5 (EX)`. These are node2's .md5/data files, freed by node1's rm-rf; node2 keeps them stale-live in-core and xfsaild resurrects them.

Causal chain to leaf corruption: md5 file F owns data block B → rm-rf frees F (disk mode=0, B → bnobt free) → node2 keeps F stale-live (still claims B) → dir recreated, grows to leaf format, bnobt allocs B for the dir LEAF → xfsaild RESURRECTS F (flushes stale F, reclaiming B) → B double-claimed by F + dir-leaf → md5 hex data lands on B → `EFSBADCRC` in `xfs_dir3_leaf_read_verify` (P54-DIRBLK-PROBE saw dir leaf daddr 2093760 holding md5 hex "a27b") → readdir/lookup fail. The earlier "double-alloc" framing is a downstream symptom; resurrection is upstream. Not a fresh-allocator double-pick (sess55/111 correctly ruled that out).

Why existing guards miss it: P119 skips iflush only if `i_dlm_mode!=EX`; P17B skips only if `dirty_seq!=ex_grant_seq`. These inodes have STALE `i_dlm_mode=EX` (peer freed the UNPUBLISHED new inode without BASTing node2) and `dirty_seq==ex_grant_seq` → both guards pass.

FIX attempt `P25-RESURRECT-SKIP` (`xfs/xfs_inode.c` `xfs_iflush`, after the P17B block): skip flush (set `ISTALE_CAW`, error=0, goto flush_out) when the coherent dip is FREE + strictly-later incarnation. Discriminator iterations ([[sess25-resurrection-guard-iteration]], runtime param `mxfs.resurrect_gen_window`):
- v1 `disk_gen > incore` (`0302171A`): REGRESSED — readdir=0 every round, ~50% false-positive on fresh-chunk inodes (chunk-init randomizes `di_gen` via `get_random_u32`).
- v2 `== incore+1` (`82050E75`): no regression but `P25-SKIP=0` — real `dirwr=0` timing lags >1 free.
- v3 bounded `1<=delta<=64` (`046691B9`, window=64): `P25-SKIP=0` at `dirwr=0` — real resurrections have gen deltas OUTSIDE [1,64] because chunk-REINIT fully re-randomizes gens (whole inode chunks freed by rm-rf → realloc → new random gens).

**Verdict: ABANDON gen-based discrimination.** sess119 was right — cross-node gens are incomparable; any gen test either false-positives (`>`) or misses (bounded). The `dirwr=1` single-free `disk=incore+1` lag was a SLOW-TIMING ARTIFACT; the resurrection→leaf-CRC corruption is largely a `dirwr=1`/`instr` artifact (100x slowdown hides the real race). Real `dirwr=0` blocker re-characterized as **dirent-VISIBILITY divergence, not leaf-CRC**: round 3, node1 (dir owner) readdir=0/200, node2 readdir=100/200, lookup_fail=0, leafCRC=0 — node1 reads its OWN dir EMPTY after drop_caches.

KEEP from sess25: the guard STRUCTURE + param (shape is correct, only discriminator needs replacing), `P-DBLALLOC` detector (`xfs_alloc.c`, gated), `drc_probe.sh`. Build `046691B9` deployed = INERT+SAFE. Proposed gen-free replacements (not yet done): (1) **inobt-allocation check in `xfs_iflush`** — when dip is FREE and in-core live, look up `ip->i_ino` in inobt; FREE→resurrection→skip, ALLOCATED→legit→flush. Gen-independent/definitive. Risk: AGI lock-ordering (iflush holds cluster buffer; AGI normally locked first) → use `xfs_buf_incore(AGI, XBF_TRYLOCK)`, fall through if not cached. (2) **publish-on-create** DLM root fix so a peer's free BASTs the creator (bigger change, fixes resurrection AND dirent coherency).

## sess26 — three-layer onion; two fixes landed, then true root reframed twice

[[sess26-leaf-rebuild-and-b5-bnobt-fix-progress]] (build `68485F02`): at REAL timing the failure had THREE layers.

1. **Leaf-hash hole** (readdir=200, lookup_fail=97, `node2_f10`+ missing from LEAF index but present in DATA blocks; durable both nodes). FIXED by making sess21's `mxfs_dir_rebuild_leaf_from_data` fire RELIABLY. Root: the flag-only trigger (`MXFS_IF_DIR_LEAF_STALE`, set solely on an evict-SKIP of an undurable leaf, P21S) fired ZERO times → rebuild never ran → a node durably destaged a SHORT leaf. Fix: arm the flag once per cross-node tenure in `mxfs_dlm_dir_modify_refresh` (`xfs/xfs_mxfs_dlm.c` ~2422): `if (new_incarn || dp->i_dlm_dir_gen != dp->i_dlm_dir_evicted_gen) xfs_iflags_set(dp, MXFS_IF_DIR_LEAF_STALE);` (computed BEFORE evict updates evicted_gen/incarn). Rebuild only ADDs missing hashvals from coherent DATA blocks unioned with plain-bio snapshot. Confirmed LEAF1 format, `P26-REBUILD-OK` nent up to 201. lookup_fail 97→0. Firing on EVERY multi-node createname (113x/run) was REVERTED — perturbed timing, tripped bug #2; once-per-tenure (~82-116x) is the keeper.

2. **bnobt double-free shutdown** (`Corruption of in-memory data (0x8) at xfs_defer_finish_noroll`, `xfs_defer.c:721`; P47-INACT/P81-DEXT/P28/P33). PROVEN ROOT: ino 1956 freed at t=64s, REUSED, ifree'd AGAIN at t=86s — each ifree preceded by `DLM inode lock failed: ino=1956 mode=5 rc=-35` (EDEADLK). The sess78 TOCTOU fix (`xfs_inactive` ~2773) acquires per-inode EX but on EDEADLK sets `mxfs_inact_dlm_locked=FALSE` and PROCEEDS to free without it; the unlocked FUA disk read is stale → B1 (`disk_mode==0`) misses → double-free. **FIX = B5** (`xfs/xfs_inode.c` ~2876, added to B1-B4 skip block): `bool mxfs_b5_nolock = !mxfs_inact_dlm_locked && !mxfs_local_unlink && ip->i_dlm_mode != MXFS_LOCK_EX && !xlog_recovery_needed(mp->m_log);` → skip destructive inactivation. Rationale: a node that legitimately unlinked holds EX (acquire returns 0); EDEADLK means we hold only NL/PR → stale cached copy we don't own → real owner frees it. Reason string "ex-lock-unavailable-stale-copy". RESULT: no more 0x8 bnobt shutdown, both nodes alive, **node1 PASSES all rounds**. B5 is PROVEN-necessary KEEP.

3. **RESIDUAL: node2 short readdir** = readdir=100-117/200, lookup_fail=0, FS alive. node1 reads full 200 from the SAME LUN → LUN HAS 200 → node2's cold (drop_caches) read is STALE, missing node1's entries. `drc_probe2.sh` (ino 2869): rounds 1-3 perfect, round 4 node1 hit a *different* `Metadata I/O Error (0x1) at xfs_trans_read_buf_map` (`xfs_trans_buf.c:313`) shutdown — not bnobt, B5 held.

### Reframe A: the failure is IGET-FAIL = WRITE-side durable lost-update

[[sess26-iget-fail-is-real-root-write-side-durable-lostupdate]] supersedes the "leaf-hash hole" framing. Added `P26-IGET-FAIL` at `xfs_lookup`'s `xfs_iget` (`xfs/xfs_inode.c` ~799). Detectors: `P26-LKERR`=0, `P26-LKFMT`=0 → the dir LOOKUP SUCCEEDS (leaf+data find every name). `P26-IGET-FAIL`=200 on BOTH nodes: `dp=131 name="node2_f10" inum=2099081 err=-2(ENOENT)` — the dirent resolves but `xfs_iget(inum)` returns ENOENT because that inode is FREE on disk. inums are CONSECUTIVE (2099073,74,75…) = node2's files from a PRIOR round's incarnation. Both nodes cold-read the SAME stale inums → DURABLE on the LUN.

This is WRITE-side, not read-side: `echo 3 > drop_caches` DOES drop clean xfs metadata buffers (`xfs_buftarg_shrinker` under drop_slab), so cold lookup reads FRESH from LUN and STILL gets the freed inum. Read-side fix REFUTED (build `C99F988B`): mirroring the modify-path `mxfs_dir_force_evict` bypass onto reader path `mxfs_dlm_dir_consumer_refresh` (removing its `!new_incarn && gen==evicted_gen` early-return) → IGET-FAIL still 200. Conclusion: a node RMWs a reused dir DATA block from a STALE prior-incarnation cached base and destages it, reverting current-incarnation dirents (the sess69 durable WRITE-side lost-update family). The leaf-rebuild only "worked" (build `68485F02`, lookup_fail 97→0) as a side effect: rebuild's `xfs_dir3_data_read` FUA-read of ALL data blocks on the create path refreshed in-core data to current inums — a red herring; DEFAULT it OFF (`mxfs.dir_leaf_rebuild=0`).

### Reframe B (FINAL): ABA clean buffer with stale attached BLI → mxfs_buf_read_fua SKIPS FUA

[[sess26-FINAL-root-aba-buffer-stale-bli-fua-skip-and-exact-fix]] (build `C99F988B` deployed, cluster rebooted clean; GPT-consulted per RULE 5; supersedes earlier sess26 framings). ROOT, airtight: the in-core dir DATA buffer (daddr-keyed xfs_buf) is a **CLEAN prior-incarnation (ABA) buffer that still has a STALE `b_log_item` (BLI) attached**. `mxfs_buf_read_fua` (`pal/linux/xfs_buf.c:2077`, `P91-FUA-SKIP-LOGGED`) SKIPS the FUA pierce whenever `b_pin_count>0 || !list_empty(b_li_list) || b_log_item` → keeps the stale in-core buffer, never refreshes → plain-bio reads serve SCST's STALE per-initiator read cache. The LUN backing store is FRESH (raw `mxfs_pal_scsi_read_fua_bdev` read returned the CURRENT inum; `dir_merge=1` drove IGET-FAIL→0 but caused DLM-timeout shutdown rc=-110, unusable).

Why the obvious fixes failed: read-side force-evict (in `C99F988B`) leaves the BLI attached → FUA still skipped; `fua_disable=0` alone doesn't help because the buffer is KEPT (BLI skip), never hits device; the evict's clean branch only does `dbp->b_flags &= ~(XBF_DONE|_XBF_FUA_FRESH)` (SOFT invalidate), doesn't detach the BLI.

GPT verdict: never manually abort a DIRTY/in-AIL BLI (unsafe); for a CLEAN buffer `xfs_buf_stale` is safe. The dir DLM RELEASE path already waits `!in_ail && !pinned && data_durable` before unlock (`xfs_mxfs_dlm.c:4386+`), so the peer's cached ABA buffer IS clean — just keeps a leftover attached BLI.

**EXACT NEXT FIX (first thing in sess27)** in `mxfs_dir_evict_data_blocks` (`xfs/xfs_mxfs_dlm.c`, the `if (!undurable)` CLEAN branch ~line 2128; `bip = dbp->b_log_item` in scope; recompute `incarn_aba`/`in_ail`): detect ABA (`b_mxfs_dir_incarn != 0 && != VFS_I(ip)->i_generation`) that is `!d_in_ail && !d_dirty && !ispinned && !(_XBF_DELWRI_Q) && (XBF_DONE) && list_empty(b_li_list)`, then `xfs_buf_item_relse(dbp)` (`pal/linux/xfs_buf_item.c:77`, takes `struct xfs_buf*`) + `xfs_buf_stale(dbp)` + clear `b_mxfs_dir_incarn`/`b_mxfs_dir_gen` (fire `P26-ABA-STALE`, capped); else keep the existing soft path. Loop already `xfs_buf_relse(dbp)` at line 2200. MUST run with `fua_disable=0` (post-stale fresh read needs FUA to pierce SCST; default is 1) — test via `MXFS_EXTRA_MODARGS="fua_disable=0"` first, then decide whether to flip the default (RULE 0 perf check). `xfs_buf_item_relse` must be gated STRICTLY clean — if the ABA buffers turn out dirty/in-AIL, detach is unsafe → pursue GPT's release-side sync-log-force invariant instead.

VALIDATION PLAN: `bash tests/reboot_cluster.sh 2; MXFS_EXTRA_MODARGS="fua_disable=0" ./run.sh 2 tcp dir_reuse_coherency` → expect P26-ABA-STALE fires + P26-IGET-FAIL→0 + readdir=200 + no shutdown; then full `./run.sh 2 tcp` ×3 for 100%.
