## dir_reuse_coherency on 4/tcp — root causes and fix architecture (sess12 / ccloop)

Central topic: the `dir_reuse_coherency` ship-criterion fails only at 4 nodes over TCP DLM. Sessions traced it to concurrent cross-node directory mutation producing durable dirent loss, isolated the dominant root (a BAST dir-release drain+EX-demote racing an active create with no ILOCK serialization), and produced a unified tenure-rebase design. Criterion remained NOT met at end of these sessions.

### 4/tcp clean baseline (build F0D7B279, default params)
[[sess12run-CLEAN-BUILD-4tcp-baseline-two-real-bugs]]. On a CLEAN local build (defaults `dir_epoch_adopt=0, dir_coherent_modify=0, dir_force_evict=1, dirrefresh=0, dir_leaf_rebuild=0`), `./run.sh 4 tcp` = 13 PASS / 4 FAIL. The 4 FAIL = **2 real bugs + 2 contamination cascades**:
1. `dir_reuse_coherency 0/4` — REAL. Single-dirent durable readdir loss (`readdir=399/400`); missing entry is always a node1 `.md5` and ALL nodes incl. the node1 creator miss it. No shutdown.
2. `fence_during_write 0/4` — REAL, SEPARATE root. Nodes 2/3/4 hit `XFS (sda): Corruption of in-memory data (0x8)` at `xfs_defer_finish_noroll+0x2b6` (xfs_defer.c:721) / `xfs_trans_cancel` (xfs_trans.c:1061) → shutdown. Same family as the `tcp_dlm_scaling` `__xfs_trans_commit:890` shutdown. This is AG/bmap deferred-op corruption, NOT the dir_reuse root.
3+4. `fault_netpartition 1/4` and `tcp_dlm_scaling 1/4` — CONTAMINATION (run after fence_during_write already shut those nodes down; clear once fence stops shutting down nodes).

13 PASS list: precond_readiness, cache_coherency, strong_consistency, posix_multi, mmap_coherency, zero_silent_loss, dlm_fairness, dlm_membership, scaling_curve, dlm_scaling, rsync_paired, crash_consistency (4/4), soak. `crash_consistency` was 0/4 only on sess11's experimental build 890C3B13 (`dir_coherent_modify=1`) — that experimental build was itself the regression; the resume note blaming crash_consistency was a contamination artifact. 2/tcp = 17/17 on the same cluster, so the delta is purely multinode metadata coherency at 4+ nodes. `dir_epoch_adopt=1` "fixing" it is a documented ~1/5 FLUKE (comment xfs_mxfs_dlm.c:3081).

Reset between runs: power-cycle test1-4 via `virsh -c qemu:///system destroy+start`. Standalone repros: `./run.sh 4 tcp dir_reuse_coherency` (~175s); faster `tests/tcp/drc4_capture.sh 24` (`dirwr=2`, ~55s; runs its own virsh reset — run ONE at a time or it wedges prep; Bash `timeout` ≥ 480000ms).

### Storage substrate: LIO, not SCST
[[sess12run-CRITICAL-tcp-cluster-is-LIO-not-SCST-fua_disable-suspect]]. The TCP cluster test1-4 `/dev/sda` reports `LIO-ORG mxfs` (vendor/model), so the `project_test_cluster_scst` memory does NOT apply here. `fua_disable=1` (a sess45 SCST-shared-cache perf lever) assumes a coherent/peer-visible write-back cache — invalid on LIO, which drops the SCSI FUA bit and (sess26) reports CAW CAS-success without persisting cross-node. Theory: on LIO a plain-bio read after evicting a stale dir block returns the stale per-initiator cache image, not the peer's durable write. **REFUTED as the root:** `fua_disable` was tested both 0 AND 1 and NEITHER fixes the loss — the node uses a stale CACHED buffer/fork it never re-reads; it is not read staleness. (Also 2/tcp passes 17/17 with `fua_disable=1` on the same LIO cluster.) This memory also carries a CORRECTION: `daddr=27211984` was later found to be the dir LEAF block (magic 0x3df1@off8), not a btree double-alloc — see the caveat under the double-alloc finding below.

### Root-cause vector taxonomy (all one disease: stale-base RMW)
[[sess12run-THREE-VECTORS-stale-base-RMW-and-ABA-writeback-fix]]. Durable loss is multi-vector; a node modifies+destages a dir image missing a peer's committed entries. Manifests at different dir-format stages:
- **Vector 1 — ABA writeback clobber (block/leaf), multi-entry.** PROVEN: `P-LEAFWRITE tag=CLOBBER daddr=2093296 buf_cnt=127 disk_cnt=402 bufgen=0 comm=dd` — a stale in-AIL dir leaf/data buffer from a prior EX tenure re-flushed by background xfsaild (comm=dd) over a daddr the peer grew, dropping 275 hash entries. Dir inode often RECLAIMED (in_core=0) at flush.
- **Vector 2 — shortform→block re-conversion clobber, single/few entries (sess61 family).** PROVEN: lost `node4_f1` created `P-CRNAME fmt=1` (SHORTFORM). A node with a stale in-core shortform `i_df` re-converts sf→block writing only its own entries. `modify_refresh`'s `mxfs_dir_evict_data_blocks` only refreshes DATA BLOCKS — shortform has none, so the stale `i_df` is used with NO refresh. sess61 `mxfs_dir_modify_adopt_disk_format` refuted (format-compare never fires; divergence is CONTENT-level at equal format).
- **Vector 3 — intra-create single-dirent revert (sess11 DECISIVE).** A create commits a dirent (`rval=0`) but it is ABSENT from in-core ~30µs later at durable_signal, SAME thread, ILOCK_EXCL held, gen bumped 4→5 (peer modified during the create).

### DECISIVE raw-disk proof: dir-block / AG-btree double-allocation
[[sess12run-DECISIVE-dir-block-doublealloc-with-AG-btree-block-PROVEN]]. Build F0D7B279, `dirwr=2`, `drc4_capture 24` → FAIL round 4 ino=131, 9 entries lost on all 4 nodes (node1_f5/f11/f18/f21/f34 + node2_f35/f42/f44/f46.md5), all in ONE dir data block. `P-RELFLUSH` on test1 dumps that block `daddr=27211984` as in-core `magic=0x0`. Raw physical read (offset = `(daddr + xfs_data_offset/512)*512`; `xfs_data_offset=100704256` from `chk_mxfs`) shows a **v5 XFS short-form btree block** (`xfs_btree_block`: self blkno 0x019f38d0=27211984 @0x10, FS UUID `da513779-8f75-43f0-a3cd-187268c40d84` @0x20, owner@0x30, crc@0x34, magic zeroed) — bnobt/cntbt/inobt/finobt. CONCLUSION: the daddr is DOUBLE-ALLOCATED as an AG free-space btree block AND the dir data block — the bnobt reported it free while in-use, `xfs_bmap_btalloc→xfs_alloc` handed it to the dir grow, dir entries written in-core but the durable image is the btree block. Same root as the `fence_during_write`/`tcp_dlm_scaling` corruption-0x8 shutdowns → ONE root unifies all real 4/tcp failures. Root layer = cross-node AG free-space (AGF/bnobt/cntbt/inobt) incoherency: dir is serialized by dir DLM EX but underlying block alloc only by AG-DLM; a node allocating from an AG with stale in-core bnobt/cntbt double-allocates (sess24/42-47/79-90 family). NEXT (RULE 4): audit whether AG-DLM acquire invalidates the btree BLOCKS under AGF/AGI (not just the header roots) and whether release drains those btree-block writes before unlock. Suspicion: only AGF/AGI roots are invalidated/drained, not the child btree blocks.

**CAVEAT / correction:** the [[sess12run-CRITICAL-tcp-cluster-is-LIO-not-SCST-fua_disable-suspect]] note later reclassified `daddr=27211984` as the dir LEAF block (magic 0x3df1@off8), calling the real signature "cross-node stale-base dir RMW revert" rather than a btree double-alloc. The double-alloc reading and the vector-3 reading coexist in the record; vector-3 became the empirically dominant blocker (below).

### BREAKTHROUGH: vector-3 root PROVEN — BAST release races an active create
[[sess12run-BREAKTHROUGH-vector3-BAST-release-races-active-create]]. Decisive trace (build 40AC2A0C, `dirwr=2`, drc4_repro round 10, test1, lost = node1_f15.md5):
- 433.578685 `P11-FLUSH-CLEANSKIP daddr=112` (release drain in progress)
- 433.578886 `P16-RELEASE-UNDESTAGED daddr=112`
- 433.579289/579748 `P11-FLUSH-UNCACHED daddr=112 comm=kworker` (block uncached, SKIPPED)
- 433.580905 `P11-DATALOG daddr=112 off=2136 name=[node1_f15.md5] comm=bash` (create writes entry)
- 433.580913 `P-CRNAME-DONE rval=0` (create succeeds)
- 433.580971 `P11-POSTADD PRELOGF daddr=112 names=[...f7..f14]` (durable_signal: 112 LACKS f15.md5)
- f15.md5 in ZERO PRELOGF lines clusterwide → durably lost.

ROOT (PROVEN): the dir BAST RELEASE (kworker, drain + EX demote) runs CONCURRENTLY with the bash CREATE on the same dir because the release path takes NO inode ILOCK — `mxfs_dir_data_durable` / `mxfs_dlm_dir_inode_durable` / `mxfs_dir_flush_data_blocks` operate on buffers directly (xfs_buf_incore + buffer lock), by design (the "ILOCK held across CAW poll" deadlock tension). While bash holds dp ILOCK_EXCL mid-transaction, a kworker BAST drains the dir and DEMOTES the dir DLM EX to a peer; the create's dirent added AFTER the kworker snapshotted/uncached daddr 112 is lost — the peer takes EX with the pre-f15 image. This is NOT reload-under-ILOCK (impossible); it is concurrent release+demote with no serialization vs the active writer. Matches GPT-5.5's vector-3 prediction exactly.

### Precise code gap and the BAST trigger site
[[sess12run-VECTOR3-precise-gap-ilock-released-before-flush-demote]]. In the inode-BAST release function (`xfs/xfs_mxfs_dlm.c` ~5940-7080): the drain loop acquires `ip->i_lock` read via `mxfs_drain_ilock_read` and flushes each dir block under it, but does `up_read(&ip->i_lock)` at ~6372 (and between blocks) and then runs the FINAL durability + handoff with NO inode lock — `mxfs_dlm_dir_inode_durable(ip)` at 6431 (log_force→iflush→delwri→blkdev_flush) and `mxfs_v5_dlm_inode_unlock(...)` at 7079 (the EX demote). After the last up_read, `xfs_create` grabs `i_lock` WRITE via `mxfs_dlm_ilock_begin` and does addname while the BAST flushes+demotes. The release-before-flush is DELIBERATE deadlock-avoidance (holding i_lock-write across log_force/blkdev_flush/CAW unlock is the "ILOCK across CAW poll" wedge; sess18 saw DLM rc=-110 timeouts from over-holding) — so the fix must serialize without reintroducing that.

[[sess12run-VECTOR3-precise-BAST-site-14430-defer-during-create]]. The peer-side trigger: BAST handler at `xfs/xfs_mxfs_dlm.c:14430` (`if (type == MXFS_EVICT_TYPE_DIR_MODIFY)`) bumps `i_dlm_dir_gen` (the observed 4→5) and arms `MXFS_IF_DIR_RELOAD` (sess54: every dir format) under spinlocks only. The create's own subsequent `xfs_da_read_buf` (leaf/data read during addname split/rebalance) or durable_signal then CONSUMES the armed gen/flag → invalidates/cold-reads the peer image → reverts the just-added dirent. Other candidate mid-create gen-bump sites: xfs_mxfs_dlm.c:11364, 14367, xfs_dir2_readdir.c:698.

### Existing defer infrastructure and the SURGICAL fix
[[sess12run-VECTOR3-SURGICAL-FIX-recheck-holders-before-demote]]. The mechanisms needed already exist:
- The create's `xfs_ilock(dp, ILOCK_EXCL)` → `mxfs_dlm_ilock_begin` fast-path does `ip->i_dlm_ex_holders++` (xfs_mxfs_dlm.c:10712-10713), so a dir modify DOES register as a holder.
- A PROVEN defer-on-holders path exists in the MHT dwork: `i_dlm_ex_holders/pr_holders/i_dlm_pin_count > 0` → re-arm `i_dlm_bast_dwork` (`queue_delayed_work(..., msecs_to_jiffies(4)+1)`) and return WITHOUT releasing (xfs_mxfs_dlm.c:7194-7206; bounded, peer not stranded).
- BUG: the inode-BAST processing reads holders ONCE near the start, then runs the whole drain + `mxfs_dlm_dir_inode_durable` (6431) + `mxfs_v5_dlm_inode_unlock` (7079) without re-checking; the drain releases `i_lock` (6372), so a create acquiring the dir lock DURING the drain bumps holders too late to be seen.

FIX: RIGHT BEFORE the final unlock at 7079, re-check under `i_dlm_lock`; if `i_dlm_ex_holders > 0 || i_dlm_pr_holders > 0 || i_dlm_pin_count > 0`, a writer raced in during the drain → DEFER: re-arm `i_dlm_bast_dwork` (reuse the 7200 pattern), keep state CACHED + `i_dlm_bast_pending=true`, RETURN without unlocking. The drain already ran (idempotent flush, harmless); only the EX handoff defers until the create's `mxfs_dlm_ilock_end` drops holders to 0 and re-fires the BAST. Safe: bounded (create completes in µs-ms, poll ~4ms; cap consecutive re-arms ~250≈1s then proceed to avoid stranding on an AG↔dir ABBA); no resurrection (flush not evict — sess96 evict-on-release was refuted; keep the flush, defer only the unlock); reuses PROVEN sess124 MHT defer infra. Verify create-side `mxfs_dlm_ilock_end` honors `i_dlm_bast_pending` on holder-drop (~xfs_inode.c:387 "process deferred BAST if last"). Test target: `dir_reuse_coherency 0/4 → 4/4`, watch dmesg for DLM rc=-110 (peer stranded) and `tcp_dlm_scaling` (EX-handoff latency) for regressions.

### GPT-5.5 unified tenure-rebase architecture
[[sess12run-GPT-DESIGN-tenure-rebase-dir-coherency-unified]]. UNIFIED INVARIANT subsuming all 3 vectors: a directory's in-core XFS state is valid ONLY for the DLM EX tenure that instantiated it. On EX (re)acquire after a peer may have held EX → REBASE (not merge) the COMPLETE dir object (i_df fork + data/leaf/free buffers + extent map/bmbt) from the durable on-disk image BEFORE the first mutation. On EX release/demote → drain all dirty dir state to HOME LUN locations, then mark local cache invalid. Tag cached state with a per-inode dir tenure id; reject old-tenure reads-for-modify and writebacks.
1. **Shortform fix** — in-place data-fork REBASE under ILOCK_EXCL when tenure advanced: read the durable dinode via an UNCACHED private read (`xfs_buf_read_uncached` or reuse `mxfs_pal_bdev_read_plain_bdev` of inode-cluster block+boffset, as in `mxfs_dir_evict_data_blocks` ~L2549) — do NOT trust the cached inode-cluster buffer, do NOT `xfs_buf_stale` it (holds other inodes). Verify (`xfs_dinode_verify`, `xfs_dir2_sf_verify`); if disk `di_format==LOCAL`, destroy stale `dp->i_df` and replace from the dinode literal area (kmemdup `XFS_DFORK_DPTR`, if_format=LOCAL, if_bytes=di_size, update i_disk_size/i_size). DO NOT mark dirty (cache rebase, not local change); do NOT call full inode-reload (avoids down_write(i_lock) deadlock under ILOCK_EXCL). Valid because Invariant #1 drained the prior holder → disk is authoritative. Gate strictly on tenure-advanced. Wire into `mxfs_dlm_dir_modify_refresh` (xfs_mxfs_dlm.c:3483) BEFORE the data-block evict, for the shortform branch.
2. **Vector 3** — valid order: ilock EXCL → acquire/upgrade dir DLM EX → if tenure changed rebase from disk → re-lookup name on coherent base → addname → log → commit → durable_signal → end_modify → unlock. A gen bump / BAST MUST NOT mutate/reload in-core while a create txn is active. Per-dir coherence state machine: `begin_modify` sets `writer_active` under a mutex after rebase; BAST during `writer_active` sets `revoke_pending` (does NOT reload/demote); `end_modify` processes the deferred revoke. Pin EX for the whole create.
3. **Release path** — stop new writers → wait active writer → commit → force log for dir → push AIL until inode+dir buffers reach HOME (not just peer's log) → verify no dirty dir buffers/fork remain → mark cache invalid → demote. Old-tenure buffers must not remain dirty/writeable after EX release (INVALIDATE on release, not skip on write).
Performance: NOT a per-modify FUA read — fast path (same node still holds EX, `cache_tenure==grant_tenure`) pays nothing; cost only at the EX lease boundary (one uncached dinode read + invalidate), which is the correct place for a 4-node-bounce-one-dir workload to pay.

- **890C3B13** (sess11 experimental, `dir_coherent_modify=1`) — left on the cluster; caused the false crash_consistency 0/4; a regression, removed.
- **F0D7B279** — clean baseline build used for the raw-disk double-alloc proof.
- **B5FB078A** — vector-1 fix `dir_ex_write_guard=1` (default ON, KEEP), `pal/linux/xfs_buf.c` sess41 dir-write-guard block: a dir DATA/LEAF block may be DESTAGED only by the node holding dir DLM EX; when writing without EX (`!in_core || i_dlm_mode != MXFS_LOCK_EX`), plain-read the on-disk block and if it proves strictly more/divergent dirents (disk_cnt>buf_cnt, or equal+fingerprint differ) SKIP the write (emulate clean ioend; probe `P12-DIR-EXGUARD-SKIP`). SOUND vs the refuted `dataclobber>=2`: legit removes/conversions/fresh-leaf writes all run under EX so are never caught; the disk-proven check prevents false-skips. Verified no false-skip on mode=3 non-EX clobber=false writes.
- **40AC2A0C** (KEEP, default-on, NO regression) — adds `dir_sf_rebase=1` (`mxfs_dir_rebase_shortform`, called from modify_refresh: wholesale rebase stale in-core SHORTFORM `i_df` from durable dinode on tenure-advanced modify, uncached plain-read, gated `gen!=0 && gen!=evicted_gen` + memcmp guard). This is the relay/current build.

### RESULT: vector-1/2 fixes sound but INERT; vector-3 dominant
[[sess12run-RESULT-vector1-2-fixes-sound-but-inert-vector3-dominant]]. Empirical on 40AC2A0C (drc4, `dirwr=2`): Run 1 = 24 rounds CLEAN (first clean run of the session) but `P12-SF-REBASE=0` AND `P12-DIR-EXGUARD-SKIP=0` — NEITHER fix fired; the clean pass was STOCHASTIC luck. Run 2 = FAIL round 10, single entry node1_f15.md5 lost (LOOKUP_ENOENT all nodes), both probes still 0×. Full 4/tcp suite on B5FB078A (vector-1 only) = 12 PASS (no core regression), dir_reuse 0/4, fence_during_write unchanged. INTERPRETATION: the DOMINANT failure is single-dirent loss = VECTOR 3, which neither fix touches. Also the ABA leaf clobbers (vector 1, e.g. buf_cnt 127 vs 402) apparently happen while the writer DOES hold EX (`dir_held_ex`), which the EX-guard intentionally does NOT skip — so EXGUARD never fired; vector 1 may itself be an under-EX revert, not purely a background not-EX flush. KEEP both fixes: sound, no regression, necessary-but-insufficient parts of the unified tenure-rebase architecture.
