# Compiled: 16-node concurrent shared-dir create lost-update + 120s barrier visibility (run14d / ccloop 14d31183)

Central topic: the single ship blocker `posix_semantics_multi16` (later `cache_coherency` / `scaling_curve` at `--nodes 16`) on ccloop run `14d31183`. 18/19 (later 11/12) criteria pass; the failing one is 16 nodes each creating a file into ONE shared directory, and 16 nodes signalling a shared shortform barrier dir `.mxfs_barriers/<name>/<nodeid>`. Two symptoms that are the SAME class of bug: (a) a peer's just-added dirent is **durably lost** (last committer clobbered), and (b) 120s barrier soft-timeouts that dominate the RULE-0 time budget (~385s of a 560-600s cap). Real op work is <1s/test; the timeouts are the cost. Fixing the concurrent-create durable lost-update fixes BOTH correctness and slowness ([[sess46-barrier-timeout-and-lostupdate-same-root]]).

Distinct root causes were peeled off in layers over sess41→sess50, each with its own proven fix. Build progression (all KEEP unless noted): E25DD67F (AGI deadlock, sess41) → 564532078173F7EB (sess42 FIX1 SF readdir) → 863173A4 (sess42 FIX2 P34D) → 7BD3933D (sess43 P136) → C6DF0D70..2C9BEB06 → D9D22CF3 (sess44 settle fixes) → C63A349 (sess48 waiter-drop) → 2E28291 → D8ADC3D → ABD1F70849A484A3 (sess49) → 5276B108 = VERSION 0.5.7 (sess50 phantom-EX root fix, VERIFIED).

## Layer 1 — shortform-dir evict gap (barrier visibility) — sess41/sess42
[[sess41-shortform-dir-evict-gap-root]]: ROOT of the 120s barrier timeouts. `EVICT-RING-DIRMOD` (consumer `mxfs_dlm_evict_inode_cb`, xfs/xfs_mxfs_dlm.c:8335) on peer DIR_MODIFY only does `ip->i_dlm_dir_gen++`, which relies on the next readdir's `xfs_da_read_buf` to invalidate cached dir DATA/LEAF blocks. That path fires ONLY for block/leaf dirs. For `XFS_DINODE_FMT_LOCAL` (shortform), `xfs_readdir` (xfs/xfs_dir2_readdir.c:511) returns `xfs_dir2_sf_getdents()` reading inline `dp->i_df.if_data` with NO ILOCK/DLM reacquire and never calls `xfs_da_read_buf` → gen bump is a no-op, inode never reloaded. Fingerprint: DATA dir (1600 entries, block/leaf) count always correct; barrier dir (~16 shortform entries) peer's add invisible → 120s soft timeout. The reload primitive already existed: `mxfs_dlm_reload_inode(ip, ftype)` (called at xfs/xfs_inode.c:875,1010 under XFS_ISTALE_CAW) does in-place inode-cluster + dir-fork reload from disk; it just wasn't wired to DIR_MODIFY/readdir.

FIX (sess42 FIX1, build `564532078173F7EB568677F`, VERIFIED KEEP — [[sess42-sfdir-fix-and-p34d-fua-cache-root]]): new flag `MXFS_IF_DIR_RELOAD (1U<<20)` in xfs/xfs_inode.h (added to `XFS_IRECLAIM_RESET_FLAGS`); evict cb DIR_MODIFY branch drops the `i_dlm_dir_gen!=0` gate and sets the flag for live LOCAL-format dirs (spinlock-only); `xfs_readdir` LOCAL branch, in multi-node mode with flag set, calls `mxfs_dlm_reload_inode(dp, FT_UNKNOWN)` before `xfs_dir2_sf_getdents`, re-arming if reload BAILed. Event-driven on the peer-set flag — do NOT poll disk every getdents (per-readdir CAW polls caused sess38/91 d_revalidate barrier timeouts). VERIFIED: standalone concurrent_touch 5/5 PASS, all 16 nodes 50-54s, zero barrier timeouts, `sf_reload=1` firing. GOTCHA: `make clean` wipes tools/ → must `make tools` too or reset4 mkfs silently fails.

## Layer 2 — P34D platter-adopt lost-update (FUA vs SCST cache) — sess42
[[sess42-sfdir-fix-and-p34d-fua-cache-root]] FIX2 (build `863173A494A37C7D093F817`, built+deployed, UNVERIFIED at handoff): remaining 600s blowout = each test's first barrier durably loses EXACTLY ONE node's signal (victim touch rc=0, own readdir=1 immediately after, then 120s later own_lookup=0/own_readdir=0, file never on disk for anyone; same dir_ino victim+peers so mkdir-race REFUTED, P-SFDIR-REVERT=0 so count-revert REFUTED). Smoking gun: victim had `P91-RELOAD-PROTECT`=13 + `P34D-RELOAD-FRESHSRC`=13. ROOT: with `fua_disable=1` (running default) the cluster coherence point is the SCST target write CACHE — completed buffer writes are plain-read-visible but not yet on platter. `mxfs_dlm_reload_inode`'s kept_protected branch (P34D, xfs_mxfs_dlm.c ~4102) FUA-read the PLATTER and adopted any valid image unconditionally → adopted an image OLDER than victim's own last flush → in-core fork reverted, own dirent dropped, next RMW made loss durable cluster-wide. FIX: P34D fresh-source read uses `mxfs_pal_bdev_read_plain_bdev` when `mxfs_fua_disable` (else FUA); log `src=plain|fua`. NOTE: other `mxfs_pal_scsi_read_fua_bdev` callers (d_revalidate gen check, s91_dmode lookup reads, P95) share the FUA-vs-cache hazard, untouched.

## Layer 3 — dir-DATA block CIL pin not drained before unlock — sess43
[[sess43-dirdata-pin-rootcause]] (build 7BD3933D, P136 rescue): PROVEN root of concurrent_touch loss on block/leaf dirs. Cold full `--phase cluster`: concurrent_mkdir PASS; concurrent_touch FAIL 1599/1600 AND 225s wall (RULE-0 perf fail too). Standalone on a warm cluster PASSES — intermittent race needing cold first-barrier contention; DO NOT trust standalone PASS. Always-on evidence: `DIR-STALE-SKIP` ~30×/node (~480 total, the lost-update window) + `SESS50-STARVE` ~20×/node (~330, the slowness). Decisive DIR-STALE-SKIP fields on shared touch dir (ino=18874858): `buf_gen=0 inode_gen=61 dirty=0 in_ail=0 pin=1 has_bli=1 bli_flags=0x2`. Mechanism: cached dir block is BOTH stale (buf_gen=0; peers advanced i_dlm_dir_gen to 61) AND pinned (our own prior dir txn committed-but-uncheckpointed in CIL). The gen-invalidation hook in `xfs_da_read_buf` (xfs/libxfs/xfs_da_btree.c ~L3055) correctly REFUSES to refresh a pinned buffer (re-reading a pinned/dirty/in-AIL buf → SHUTDOWN_CORRUPT_INCORE, sess43/64). So a MODIFYING read (tp!=NULL addname path) RMWs the stale gen-0 base missing peers' 61 generations → commit writes a block missing a peer's dirent → durable lost file. WHY pinned survives 61 releases: `mxfs_inode_cluster_durable` and mxfs_dir_flush_data_blocks/push_data_ags handle the inode cluster + known dir DATA blocks, but the dir-DATA block's CIL pin is NOT checkpointed+written before DLM unlock on the contended release path (note one stale blk=0x1000000 = high dablk, a leaf/free-index block — drain may not cover ALL data-fork blocks). FIX DIRECTION: EX-release drain for block/leaf/node dirs must guarantee EVERY dir-data-fork buffer is UNPINNED (xfs_log_force(SYNC)) AND written to SCST cache before `mxfs_v5_dlm_ag/inode_unlock`; iterate the full data-fork extent map, wait `xfs_buf_ispinned()==0`, write each — not just `!in_ail`. Candidate sites: dir-inode BAST release, noino BAST path (sess88), mxfs_dlm_evict. Prove by DIR-STALE-SKIP→0 and count=1600/1600.

## Layer 4 — dir-gen fresh-read stamp + unlink latency — sess44
[[sess44-unlink-latency-fixes-and-pr-wedge]] (VERIFIED, C6DF0D70..2C9BEB06 line): the coherency hook stamped `b_mxfs_dir_gen` ONLY in its invalidate branch; cache-miss/-ENOENT and fence-invalidated (!XBF_DONE) reads stayed gen=0 → false DIR-STALE-SKIP + a doubled FUA re-read per cold dir block. Fix (xfs/libxfs/xfs_da_btree.c, v0.5.6): stamp on true miss (`dir_stamp_fresh`+`dir_gen_snap`) and on !DONE in-core. RESULT: cold 16-node concurrent_mkdir PASS + concurrent_touch PASS (sess43's blockers). Newly exposed behind them (NOT regressions): concurrent_write (1/20, 4 nodes), rename_vis_dbg (node16 whole 20-file batch created OK, barrier OK, then own `mv` ENOENT on all 20 — wholesale dirent-batch loss), rename_visibility varying. P137/P138 latency decomposition (PROVEN via live `/proc/PID/stack` sampling — cheap, do before building instrumented kernels): cross-node unlink 53-70ms vs native <1ms; `xfs_inactive_ifree` msleep(10) settle + drain ≈22ms; holder `bast_process` sess29 `msleep(20)` settle ≈20ms; UDP BAST delivery is FAST ~1-2ms (not the problem). Settle fixes (build `D9D22CF3B3B61BB19D1C52A`, UNDEPLOYED at handoff): sess29 async CIL→AIL race is closable deterministically by pincount — per-item AIL-insert happens before iop_unpin in xfs_trans_committed_bulk, so `xfs_ipincount(ip)==0` ⇒ insertion done. Replace both msleeps with bounded pin-wait polls (`!in_ail && xfs_ipincount==0`); expected holder release ~3-5ms, cross-node unlink ~8-12ms. Cleanup `rm` storms are the 600s-budget eater.

## Layer 5 — barrier-timeout AND lost-update are one root; escalation to on-disk corruption — sess46
[[sess46-barrier-timeout-and-lostupdate-same-root]] (build D9D22CF3): the KEY unifying finding — barrier-timeout slowness AND concurrent_touch loss = SAME root (concurrent create into a shared dir durably clobbers a peer's dirent; block dir loses file dirents, shortform barrier dir loses signals → 120s hang). `present=[...]` diag was GLOBALLY consistent across all 16 observers and victims' OWN `own_lookup=0 own_readdir=0` → dirent DURABLY LOST on disk, not per-node cache staleness. ESCALATION: the lost-update durably CORRUPTS a dir3_block — test1 force-shut-down twice on remount (`__xfs_dir3_data_check` fail on `xfs_dir3_block` block 0x1fd9f0 → shutdown at xfs_buf_submit, pal/linux/xfs_buf.c:1972; `xfs_trans_cancel at xfs_remove` Corruption 0x8). On-disk FS becomes corrupt → MUST re-mkfs. Discriminate remaining sites with runtime `dirwr=1` probes (P105-ACQ/REL-DIRINODE: acquirer disk_size < prior releaser's = stale read; P106-EXGRANT/EXREL overlap = concurrent EX). DIR-STALE-SKIP now ~0 so the block-dir drain (sess83/88/133) is mostly closed; residual is shortform/inode-cluster path.

## Layer 6 — phantom EX-waiter bit leak (reader wedge) — sess48 → sess50 root fix
[[sess48-phantom-ex-waiter-bit-leak-rootfix]] (build `C63A349955BC8AC3721F0E5`): on D9D22CF3 the dir lost-update was effectively fixed (concurrent_mkdir/touch/write PASS, DIR-STALE-SKIP 0-10/node); the phase instead WEDGED on test_cross_visibility >600s. PROVEN: every blocked D-state thread on all 16 nodes was a SHARED reader (`find`/`ls` in xfs_readdir→`mxfs_dlm_ilock_begin`); ZERO EX requesters anywhere. Yet the barrier-dir slot (ino=23069101) froze at `waiter_mode=5(EX) waiters=2 h_ex=0` → the 2 EX "waiters" are ORPHANED bits. `defer_for_waiter` (dlm/dlm_caw.c ~1805/1865) then defers every reader's fresh SHARED acquire forever → total wedge. Why it leaks: barrier `touch` = create = PR→EX upgrade (registers EX waiter bit); a waiter that gives up must clear its bit, but `caw_wait_for_grant`'s timeout cleanup was a bounded 10-iteration CAS loop that loses the 16-node CAS-storm race → bit left set permanently. Fix: new `caw_drop_own_waiter(ctx, slot_idx)` — re-read slot + CAS-clear our node_bit from `waiters` + recompute_waiter_mode, retry with backoff (bounded 1000, cap 8ms) until a fresh read confirms clear; wired into 3 give-up sites (caw_wait_for_grant timeout, mxfs_dlm_caw_lock exhaustion, caw_convert exhaustion). msleep is uninterruptible so cleanup completes even for a SIGKILLed waiter.

That fix was INSUFFICIENT: [[sess50-phantom-ex-waiter-recompute-rootfix]] (build `5276B108E3284AEC8E85A95`, VERSION 0.5.7, PROVEN + VERIFIED) found `recompute_waiter_mode()` (dlm_caw.c:232) returned `slot->waiter_mode` UNCHANGED whenever `waiters!=0` ("we don't track per-waiter modes on disk"). So when the EX waiter's bit cleared but PR waiters remained, waiter_mode stayed sticky-EX forever — sess48's caw_drop_own_waiter cleared the bit but recompute defeated it. FIX: added on-disk `uint64_t waiters_ex` bitmap (nodes waiting EX/PW), carved from `reserved[392]→[384]` (512B `_Static_assert` holds; fresh mkfs each run = no migration). recompute now: `waiters==0→NL; (waiters_ex & waiters)→EX; else→PR` (DOWNGRADES). Set at both waiter-register sites (~2138 lock, ~2594 convert/upgrade); cleared at all 5 sites (caw_drop_own_waiter ~963, promote ~1079, release ~2744, dead-node ~2880/~3053). VERIFIED on fresh 16-node: concurrent_mkdir 22s PASS (was >580s wedge), touch 30s, write 15s, cross_visibility 7s — wedge GONE.

## Layer 7 — residual co-resident inode-cluster stale-buffer clobber — sess49
[[sess49-16node-shortform-dir-lost-update-3fixes-residual-cluster-clobber]] (cache_coherency 4/4 PASS on sess128 build; remaining blocker = 16-node criteria). `test_cross_write_read` wedged/failed: 16 nodes each create a file in ONE shared shortform parent → one node's dirent durably lost. concurrent_mkdir PASSES at 16 (mkdir hit the proactive flush; file-create did not — the gap). Three PROVEN KEEP fixes, each reduced the failure:
- FIX1 folio self-deadlock (xfs/xfs_mxfs_dlm.c ~L4864, mxfs_dlm_reload_inode S_ISREG): node14 md5sum hung 122s in `folio_wait_bit_common`. Chain: xfs_file_buffered_read→iomap_readahead→read_pages (folios LOCKED)→xfs_read_iomap_begin→xfs_ilock→mxfs_dlm_ilock_begin→reload→`invalidate_inode_pages2` blocking on a folio THIS task holds = self-deadlock when a peer EX BASTs mid-read. FIX: `invalidate_inode_pages2`→`invalidate_mapping_pages(mapping,0,-1)` (non-blocking trylock). Build → `2E28291`.
- FIX2 shortform-dir self-skip (xfs/xfs_mxfs_dlm.c ~L3779, the sess36 P36-RELOAD-SELFSKIP): the self-skip (own log item in_ail||dirty||ili_fields||pin>0 → keep in-core, skip reload) wrongly fires for a SHORTFORM dir that RELEASED EX then re-acquired (peer modified between; ili_fields/pin are residue of our own already-drained add). Proven: disk had count=16 incl f_9, node kept stale in-core, xfsaild flushed → clobber. FIX: exclude `S_ISDIR && if_format==XFS_DINODE_FMT_LOCAL` from the skip (kept for extents/btree = sess36's real regression; SF dinode is drained on EX release per Invariant 1 so disk is authoritative). Build → `D8ADC3D`.
- FIX3 proactive durability for FILE creates (xfs/xfs_inode.c ~L1687): `mxfs_dlm_dir_inode_durable(dp)` was gated `du.ip && S_ISDIR(du.ip) && !dp->i_mxfs_self_created` — ONLY mkdir children flushed; file creates into a shared SF parent never flushed → last committer (never BAST'd) loses its dirent (P127-DIRMISS sfcount=15 missing f_10). FIX: drop `S_ISDIR(du.ip)` → `du.ip && !dp->i_mxfs_self_created`. Helper no-ops unless parent is SF dir; self-created gate still skips rsync node-private parents (no rsync regression; 12 rounds/98s, no CAW starvation). Dropped fail rate 80→16 obs, ~3/8→~1/14. Build → `ABD1F70849A484A3CBBC609`.

RESIDUAL (NOT fixed): ~1/14 rounds still lose the genuinely-last committer (f_16, highest node); disk ends f_1..f_15. PROVEN chain (dir ino=361 blkno=0x160): nodeLast writes f_1..f_16 durable; a co-resident node Z holds a STALE cached inode-cluster buffer for 0x160 (= f_1..f_15) KEPT by `P91-RELOAD-PROTECT` (mxfs_dlm_reload_inode ~L3847, `mxfs_buf_has_uncheckpointed_mods` true because a CO-RESIDENT inode in the same 4K cluster has this node's logged-not-checkpointed mods); node Z's `xfs_iflush_cluster` writes the whole cluster back; dir 361's slot is `P119-NONEX-FLUSH-SKIP`'d (xfs_inode.c ~L4144, i_dlm_mode!=EX) so NOT refreshed → stale f_1..f_15 written → durably CLOBBERS f_16. Start next at xfs/xfs_inode.c:4303. Candidate fix: before iflush_cluster writes a multi-node cluster containing a P119-skipped (non-EX, peer-owned) slot, RE-READ that slot/cluster from disk; or make P91 refresh the specific reloading slot instead of keeping the whole stale buffer — carefully, iflush_cluster still must preserve the co-resident's own EX-owned in-core mods.

## Layer 8 — torn dir-444 LOCAL→EXTENTS dinode (FS shutdown) — sess50
[[sess50-cwr-torn-dir444-extents-content-tear]] (after phantom-EX fix 5276B108, cluster tests 1-4 PASS): test_cross_write_read FAILs ~246s (≈ two 120s barrier timeouts) + on-disk corruption → FS shutdown on test15/test16 (others EUCLEAN). Reading dir inode 444 (0x1bc) = `.mxfs_test/cross_write_read`: `from_disk FAILED ino=444 rc=-117 (EUCLEAN)`, `xfs_bmap_validate_extent_raw` "Bmap BTree record corruption ... data fork", then `xfs_dabuf_map: bno 8388608` HOLE → xfs_trans_cancel → shutdown. Corrupted dinode first 16 bytes decode to ASCII "`data_no`"/"data_node…" — the dinode core says di_format=EXTENTS but the literal area still holds LOCAL (shortform) dir content = a torn LOCAL→EXTENTS conversion image. RULED OUT: inodesize=512=sectsize=512, so a dinode is exactly ONE sector → atomic at storage → intra-dinode sector tearing IMPOSSIBLE; the torn 512B dinode was written as a unit by SOFTWARE. No P133-DIRINO-WR/REVERT fired for ino=444 → the torn image did NOT go through the instrumented inode-log-item write path. `mxfs_iflush_cluster_merge_dirs` (xfs_inode.c:4332) memcpy's whole dinodes so cannot mix core+literal (SF-ahead guard at 4539 covers only BOTH-LOCAL; LOCAL→EXTENTS transition unguarded but overlay still can't create the mix). Reload path (~4320) already runs xfs_dinode_verify(snap) + 8× re-read (RELOAD-VERIFY) and BAILs if bad — so the source dinode PASSES xfs_dinode_verify (structural: nextents vs forkoff, CRC valid) but FAILS xfs_iformat_extents→xfs_bmap_validate_extent (extent CONTENT garbage; xfs_dinode_verify_fork does NOT decode extent block numbers, iformat does). LEADING HYPOTHESIS: the iflush copy-in (xfs_iflush_int) writes a dir-444 dinode with in-core `i_df.if_format==EXTENTS`/di_nextents set but fork bytes copied are stale LOCAL — an in-core torn fork (sess114-class) on the LOCAL→EXTENTS dir-growth transition → structurally-valid, valid-CRC, extent-content-garbage dinode that the structural write-verifier passes → reaches disk → every reader's iformat fails. dir-444 legitimately MUST convert (34 entries: 16 data_node + 16 .md5 + . + ..) — the conversion is the hazard. NEXT: write-side producer probe `P-IFLUSH-DIRTORN` at xfs_iflush_int end for S_ISDIR EXTENTS/BTREE — decode first data-fork extent, on failure pr_warn ino/di_format/nextents/forkoff/first16/comm + dump_stack (gate dirwr=1) to catch the producer at write time.

## Recurring failure modes / methodology
- Intermittent race: standalone `--test` on a warm cluster PASSES; loss only fires under cold full `--phase cluster` first-barrier contention. Never trust standalone PASS ([[sess43-dirdata-pin-rootcause]]). Cheap 4-node cross_write_read passes; loss only at 16-way ([[sess49-16node-shortform-dir-lost-update-3fixes-residual-cluster-clobber]]).
- 120s barrier soft-timeouts, not raw op slowness, are the RULE-0 budget eater; slowness IS a failure. SESS50-STARVE count is the field metric.
- Coherence point under `fua_disable=1` is the SCST target write CACHE, not the platter — FUA-reading the platter can adopt a STALER image than a peer's cache-visible flush ([[sess42-sfdir-fix-and-p34d-fua-cache-root]]).
- Live `/proc/PID/stack` sampling is cheap and decisive — do it before building instrumented kernels ([[sess44-unlink-latency-fixes-and-pr-wedge]]).
- Always kill remote orphans (`pkill -f "run_tests|mxfs_test|find /mnt|touch"`) + full `cluster_reset_n.sh 16` before trusting any result. Standalone PASS lies.
- Detectors (all-on, in tree): DIR-STALE-SKIP, SESS50-STARVE, P91-RELOAD-PROTECT, P119-NONEX-FLUSH-SKIP, P127-DIRMISS, P-SFDIR-RELOAD, P34D-RELOAD-FRESHSRC, P133-DIRINO-WR/REVERT, P137/P138 latency.

## Infra hazards (recurring, run14d)
- Stale SCSI Persistent Reservation wedges mkfs/mount (`reservation conflict -52`, EBADE "Invalid exchange"): all 16 VMs share one IQN distinguished by ISID/I_T-nexus; sg_persist preempt/clear/release rc=24 from freshly-registered nodes because SCST binds registrations to nexus identities the re-logged sessions don't match. Recovery: destroy ALL VMs → on clyde truncate /var/lib/scst/pr/disk1 + `scstadmin -resync_dev disk1` (or restart scst) — never reboot clyde (RULE 2) ([[sess44-unlink-latency-fixes-and-pr-wedge]], [[sess42-sfdir-fix-and-p34d-fua-cache-root]]).
- SCST atomic-blocked-cmd wedge (READ op0x88 ↔ CAW op0x89 deadlock, iscsi_conn_cleanup D-state×10, PR CLEAN): recover ~2min via scripts/scst_atomic_edges.py over gdb on /proc/kcore + scripts/scst_unwedge/scst_unwedge.ko blocker/blocked addrs. NEVER power-cycle VMs mid-mount/mkfs — it re-triggers this ([[sess46-barrier-timeout-and-lostupdate-same-root]]).
- After `cluster_reset_n.sh`/`reset4.sh`, `/mnt/mxfs-src` is an EMPTY stub — run_tests.sh needs `mount --bind /src/mxfs /mnt/mxfs-src` on EVERY node or every test errors rc=127 (false all-FAIL, no wedge). reset4.sh does NOT set it up.
- `make clean` removes tools/ binaries → run `make tools` or reset4 mkfs silently fails.
