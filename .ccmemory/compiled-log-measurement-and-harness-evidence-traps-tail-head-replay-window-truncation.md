# Log geometry, replay-window and evidence-truncation traps

Topic: two clusters sharing one failure shape, a harness or reader concluding from an observation that does not measure what it claims. (1) What the XFS log marks and replay window actually contain. (2) How truncated or buffered evidence (print budgets, ring buffers, subagent tables, `tail` pipes, fixed message buffers, dmesg windows) produces wrong conclusions.

## XFS log geometry and what reaches the log

- `log_tail_lsn` (sysfs) is the AIL minimum; with an empty AIL it is `last_sync_lsn`, the START of the last record. `log_head_lsn` is the END of the write position. On a covered idle log the tail sits one last-record-length (3 blocks measured) behind the head; equality is unattainable. Verdict for a tail-pin harness: record the head at burst end and PASS when the tail reaches or passes it (`lsn_ge` on cycle:block). A tail that never moves is the pinned tail; one that moves but stays below the burst-end head is something else pinning the AIL. [[trap-log-tail-never-equals-log-head-on-a-covered-idle-log-measure-the-tail-against-the-burst-end-head]]
- Head discovery consumes the cycle stamp of every block, including obsolete record bodies whose headers were overwritten by a shorter record after a wrap. A reader-side uuid mask that zeroes blocks no current-uuid header covers turns a dirty wrapped log into "totally zeroed" and skips recovery: silent loss. Filtering recovery's input can lose data as surely as zeroing the platter; a malformed or null-uuid header must never become "untrusted, therefore zero". The cheap fix passed a plausibility read and would have passed the harness (no wrapped-log arm). The ruled fix is the durable per-slice lifecycle record (INIT_REQUIRED at mkfs, claimant zeroes via FUA and persists READY before first journal write). When a fix changes what recovery may see, ask what upstream discovery assumes about every block. [[trap-surviving-record-headers-do-not-cover-the-cycle-stamps-log-head-discovery-depends-on]]
- A buffer log item is re-formatted on every relog and each format replaces the previous log vector; only the last format before the CIL checkpoint reaches the log. An injector writing into the log copy is erased by any later relog of that buffer. Arm the knob between the last two transactions touching the buffer and force the log right after; the dirty map is cumulative so late arming loses no coverage. Two other blockers stood in front of the same arm, to be asked in order: was an image of the right kind logged at all (unlink workload must hold fds open), was it inside the replayed span (pin the tail with `dbg_ail_pin_ino`: 2 checkpoints/19 images became 53/411), did the value survive to the log. An injector whose decline path is silent makes the first question unanswerable; every rejection path must name itself. [[trap-a-relogged-buffer-item-is-reformatted-so-only-the-last-format-before-the-checkpoint-reaches-the-log]]
- A cleanly released tenure's image is outside the victim's replay window by construction: the release drain lands the block, the AIL delete moves the tail, the marker's forced commit carries it. Do not require `REDUNDANT_CLEAN >= 1` or `P227-FR-REDUNDANT-SKIP >= 1`; assert the marker was in the window (`P273 relmarks >= 1`) and nothing refused (`notheld=0 staleep=0 wlineage=0 untagged=0`), and report the redundant count as information. A plain-lap "manifest hits >= 1" guard fails such a window. `mxfs_relmark_publish` prints only `P-RELMARK-FAIL`; the positive is the survivor's evaluator `relmarks=`. If the stream continues after the release, the window holds only the stream's last transactions and the arm passes vacuously. [[trap-a-cleanly-released-tenures-image-is-outside-the-replay-window-assert-the-marker-not-the-redundant-count]]

## Reading evidence that has been cut

- A probe count is meaningless when its print budget (`<= 20`) and the ring buffer both truncate it. "2 SYNCINIT vs 53 carves" was read as 51 skipped durable inits and written into a ledger as a defect that did not exist. Check `dmesg | head -1` before trusting any whole-log count (if it is not the mount banner, every total is a lower bound); read the probe's print condition (`<= N`, `% 500`, ratelimited, which caps at 10) before quoting its number; never divide counts with different truncation rules. Count both sides with the same unbudgeted instrument or an always-incremented counter. [[trap-a-probe-count-is-meaningless-when-the-print-budget-and-the-ring-buffer-both-truncate-it]]
- A one-shot knob confirmation that counts 0 has three causes: the thread took the knob late (cadence plus a monitor pass on a saturated LUN), the start-of-lap anchor aged out of the ring, or the thread never ran. The consumer clears a one-shot knob, so read it back: `0` means taken and the zero count is the window's fault; the written value means the thread never reached its loop. Report knob-now, anchored count, anchor presence (`dmesg | grep -c <mark>`) and an unanchored tail count together. Anchor on a mark written immediately before arming, poll rather than sleep, and derive the bound from module numbers (6 cadences = 12 s, a fifth of the 62 s dead threshold). Two s131 laps (404 s of rig time) were lost to this. [[technique-a-one-shot-knobs-own-value-discriminates-a-thread-that-never-took-the-arming-from-a-window-that-lost-the-anchor]]
- A truncated subagent table is a sample. "All 53 releases at PR" came from 80 of 647 rows selected by position (head/window/tail); the full histogram was 36 PR / 17 EX, with EX releases in the omitted middle. Any "every row has X" claim from a truncated report is unsupported without a full-population count; ask for `field -> count` histograms first, rows second, and re-derive any always/never with one `grep -c` in the parent before building a hypothesis on it. [[trap-a-truncated-subagent-table-is-a-sample-never-generalize-a-field-from-the-shown-rows]]
- A message composed as context-first, conclusion-last into a fixed buffer loses its finding: a 220-byte `why` cut the refusal reason mid-word and the lap FAILed on a phrase the kernel never printed (the enclosing printk was 921 chars; the ceiling was the inner snprintf). Lead with the finding. Size buffers for worst-case interpolated identifiers. Before trusting a grep that grades a phrase taken from source, read one real line of evidence. [[technique-put-the-finding-first-in-a-message-that-can-be-truncated-by-its-own-buffer]]

## Tooling traps

- Never end a `run_in_background` invocation in `| tail -N` (or `head`, `grep`): the pipe buffers until exit, the task output stays empty for the whole run (14 minutes on the D-0932 probe), and the decisions that needed progress (is it safe to edit `run.sh`, is it safe to `make modules`) are held blind. Let the command write its full output and filter when reading. One `Read` of the output file is not a poll. [[trap-piping-a-background-run-through-tail-hides-all-progress-until-it-exits]]
- Raw kernel logs, `Call Trace` blocks, and dumps of hex flags, node ids and incarnations in tool results trip the server-side safeguard classifier, which scores the whole assembled request, so every dump stays in the request for the rest of the session. Two sessions were terminated and a third cut mid-turn. Extract `grep -c` counts, first/last timestamps, `grep -o | sort | uniq -c` tag histograms and one or two `cut -c1-200` lines; describe stacks in prose; read prior transcripts only through a `miner` told to report prose with no verbatim output; cap sweeper reports to file:line and prose. [[feedback-raw-kernel-log-and-stack-dumps-in-tool-output-trip-the-safeguard-classifier-extract-counts-and-prose-instead]]

## Shared lesson

A zero, a ratio, an equality or an "every row" from a window, ring, budget or sample is a statement about the window. Establish the window's coverage first (anchor present, banner present, budget unexhausted, population counted), then interpret the number.
