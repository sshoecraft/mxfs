# Verify before believing: stale queue prose, hidden fields, proxy guards, packed constants, implicit witnesses

Loose topic group. The shared failure is acting on a statement or value that looks authoritative (a queue record's next-step, a summary view, a guard's printed justification, a hex constant, a return value) without asking what would make it wrong. Each note records the cheap check that was skipped.

## The defect queue misleads in three ways

- **A next-step can carry a hazard another record has already disproved.** A top blocker's next-step claimed an LU reset leaves a bystander command wedged "until power-cycled". That drove a long design detour toward moving the reservation from Write Exclusive - All Registrants (0x07) to an Exclusive Access form, which would have needed a MXFS_PROTO_GEN bump and broken cross-version clusters. A different record (`D-A-BYSTANDER-INITIATOR-HANGS-ON-AN-UNANNOUNCED-LU-RESET`) held the measured disproof: ten resets six seconds apart stranded exactly one command, libiscsi's ladder rescued it after 538 s (the device command timeout MXFS sets is 180 s, not the 30 s the original reading assumed), the write retried, no errors, no node declared dead. The queue has no cross-references, so a stale justification never looks stale. Before designing around a hazard a record asserts, grep the whole queue for the hazard word (`tools/defects.py | grep -i <word>`). The gate's justification changed (it defines when an LU-scope op is the right tool at all; PREEMPT AND ABORT retires another registrant's work precisely), not its shape; the reservation type stayed. See [[trap-a-records-next-step-can-carry-a-hazard-assessment-another-record-in-the-same-queue-has-already-disproved]].
- **A summary view can show one of several fields.** Ledger records carried `next`, `next_step` and `next_steps`; the list view's `nextstep()` returned the first non-empty, hiding about 130k characters on 18 of 86 open records, sometimes more text than the shown field. `ledger_set.py prepend <ID> next_step` wrote into whichever field was named, so work could land where nothing read it, and the session-start hook shared the function, so sessions opened on a partial queue. The list view now shows every populated variant, labelled. The single-record view was never affected. Before writing, run the single-record view to see which field the record already uses. A query on `next_step` alone reported 56 records with "no next step"; the real count was one. Before believing a count, ask what would make it wrong; the same habit caught a `pr_warn_ratelimited` probe reporting exactly 10 (the burst ceiling) and a harness regex matching `[PASS]` against output printing a bare word. See [[trap-ledger-next-vs-next-step-two-fields-and-the-reader-showed-only-one]].

## A guard must test the property its comment names

`run.sh` `power_cycle_node` refused recovery when `MXFS_NODE_LIST` was set, as a proxy for "external host, no virsh domain". Every 2-node harness exports `MXFS_NODE_LIST=test1,test2`, which are local domains, so wedged test1/test2 were refused and the lap discarded (twice in one session; hand `virsh destroy`+`start` recovered instantly). Fix: ask directly with `timeout 20 virsh -c qemu:///system domstate "$n"` (rc 0 for any existing domain including shut-off, rc 1 for unknown); a libvirtd that cannot answer within the bound also refuses (fail closed). A proxy guard fails exactly where proxy and property diverge, and the failure looks like the guard working because it prints its own justification. Also: a `fence_lost_response` lap ends by design with a blocked slice, module held and mount up on the prover, so the next lap's prep power-cycling it is expected, not a wedge. See [[trap-a-guard-whose-test-is-a-proxy-for-its-stated-question-refuses-the-wrong-cases]].

## SCSI logging level is ten packed 3-bit fields

`/proc/sys/dev/scsi/logging_level` is not a bitmask. Shifts: ERROR 0, TIMEOUT 3, SCAN 6, MLQUEUE 9, MLCOMPLETE 12, LLQUEUE 15, LLCOMPLETE 18, HLQUEUE 21, HLCOMPLETE 24, IOCTL 27. A harness chose `0x1F80` because it "looked like the error bits"; that sets SCAN=3, MLQUEUE=7 and MLCOMPLETE=1, logging every command completion on a node under continuous O_DIRECT writes, the shape of the trace-flag incident (1.07M host kernel lines in 98 min, jbd2 deadlock). Error recovery plus timeouts at full verbosity is `(7<<0)|(7<<3)` = 63; derive from the shifts and write the derivation in the harness. Companion: `/sys/module/libiscsi/parameters/debug_libiscsi_eh`=1 narrates `iscsi_eh_cmd_timed_out()` (`timer reset` versus `shutdown or nh`). Both are off by default, so a silent node kernel is weak evidence about error recovery. Disarm both in an EXIT trap every time. See [[trap-scsi-logging-level-is-a-packed-three-bit-field-and-a-plausible-hex-constant-turns-on-per-command-logging]].

## A return value can be a witness through serialization, not a tag

`ioctl(SG_SCSI_RESET, DEVICE|NO_ESCALATE)` returning 0 does attribute to this LU RESET even though `iscsi_tmf_rsp()` (libiscsi.c:996-1014) never checks the ITT. The association comes from one-TMF-per-session: every TMF entry point takes `eh_mutex` then `frwd_lock` and requires `tmf_state == TMF_INITIAL` (LU reset :2536, abort :2422, target reset :2698); a timed-out TMF fails the connection (`ISCSI_ERR_SCSI_EH_SESSION_RST`, :2552-2555; send failure :1922-1927) so no stale response meets a new request; `iscsi_exec_task_mgmt_fn` returns `-ENOTCONN` on session age or state change (:1945-1957). General rule: absent a correlator, look for an enforced one-at-a-time invariant before calling a result ambiguous. But it weakens silently to inference if a later version allows two in flight, with no change to the value read, so durable evidence minted from it must pin the audited versions and refuse the rest, and record which invariant the claim rests on. Auditing a version without full source: the fleet runs 6.8.0-101-generic, only `/src/linux` (7.1.0-rc7) has source, kernel source download is forbidden; the distro `linux-headers-<ver>` ships `include/scsi/libiscsi.h`, and the `TMF_*` enum, `eh_mutex`, `ehwait`, `tmhdr`, `tmf_timer`, `tmf_state`, `lu_reset_timeout`, `frwd_lock` matched at identical lines. Report that as a structural cross-check, not a body-level audit. See [[technique-a-kernel-return-value-can-be-a-matched-witness-by-one-at-a-time-serialization-even-when-nothing-checks-the-tag]].
