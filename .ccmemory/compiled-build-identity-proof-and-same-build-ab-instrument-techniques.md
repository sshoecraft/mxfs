Topic group: how to build and measure so a verification result means something. Loosely a topic cluster (build hygiene plus test-instrument design); organised below by build hygiene first, then instrument design.

## Build hygiene

- **Clean before rebuild on multi-file changes.** An incremental `make modules` after a `.c` + `.h` change (static made non-static, struct fields added) can produce a stale `mxfs.ko`; a fix that passed suddenly fails after unrelated edits. First diagnostic step for a suspicious result is a clean rebuild, not debugging the change: `make -C /usr/src/linux-headers-6.8.0-101-generic M=/src/mxfs clean` then `modules` (~1 s clean). [[Make clean before rebuild for multi-file changes]]
- **But `make clean` also deletes the userspace tools, and `make modules` does not rebuild them.** Build is rc=0 and `mxfs.ko` is correct; the failure shows one step later as `FS_PREP_FAIL: mkfs tool not found/executable` and a chained prep->lap->lap driver loses every lap in ~40 s with zero measurements. Use `make clean && make modules && make tools`, and before queuing rig work `ls -l tools/mkfs_mxfs tools/chk_mxfs tools/recov_forge`. `fence_kind_matrix.sh` builds `recov_forge` itself, which hides the gap. [[trap-make-clean-removes-the-userspace-tools-and-make-modules-does-not-rebuild-them-so-every-rig-lap-aborts-at-prep]]
- **Proving a comment/whitespace/move refactor changed no code.** Build before and after at the SAME path (the external-module build embeds its directory via `__FILE__` and DWARF comp_dir, so two scratch dirs differ in 161/161 objects). Force the second build: `rsync -a` preserves old mtimes so `make` compiles nothing and the compare is vacuously identical; `make clean` first and check the `CC [M]` count equals the object count. Save baseline `.o` files to an explicitly named dir (`ls -dt tmp.*` once picked the build tree and compared it to itself). Compare non-debug sections only (`objdump -h` minus `.debug*`, then `objdump -s -j <sec>`). Whitespace reindent legitimately moves UBSAN `source_location` column words in `.data` (offset 12..15 of each 16-byte record; 3,640 differing bytes in 0.89.89, all column words), verified with `objcopy -O binary --only-section=.data`. Keep line counts identical so `__LINE__` users stay identical. [[technique-prove-a-source-transform-changes-no-code-by-same-path-rebuild-and-non-debug-section-compare]]

## Instrument and harness design

- **Same-build A/B with a knob that restores exactly the old answer.** Two builds leave every other difference as an alternative explanation and the old build lacks the new instruments. Add a test-only module parameter restoring the pre-fix answer for exactly the case the fix changed (e.g. `dbg_auth_tail_blind`), run the harness twice on one build. The knob must restore, not approximate; must log loudly and count separately; the harness must disarm it at the end; and a third arm with no injection is required, otherwise "zero refusals" in the blind arm is indistinguishable from an instrument that never fired. [[technique-measure-the-before-and-the-after-on-one-build-with-a-knob-that-restores-exactly-the-old-answer]]
- **A decision function's do-nothing branch must log its verdict.** `v5_bootstrap_run()` returned 0 silently on "not a total outage", so "scan decided no", "scan never ran" and "null guard returned" were identical in the log, forcing source-reading inference. Log counted inputs plus the verdict in words (`victims=N moved=N unread=N noident=N window_ms=N - <meaning>`), at a level on in the failure case, and cover the early `if (!a || !b) return 0;` guard, the return most likely to be silent. [[technique-a-decision-functions-nothing-to-do-branch-must-log-its-verdict-or-a-skipped-call-looks-identical-to-a-considered-one]]
- **Make a lagging-flush race deterministic instead of hunting it (D-0963).** The resurrected-dirent defect reproduced 1 in ~5 laps on a busy board and 0/40 on a quiet rig. Knobs: `dbg_ail_pin_ino` (xfsaild never flushes the inode), `dbg_iflush_pause_ino`/`dbg_iflush_pause_ms` (sleep after `xfs_iflush_cluster` copied the image, before write queueing; counter `dbg_iflush_pause_n` proves it fired), and debugfs `ail_push` (calls `xfs_ail_push_all`; `sync(2)` does not push the whole AIL here). Sequence: unpin, arm, kick, wait for the counter, do the op that must see the OLD platter, wait out the pause, do the op that must see the NEW image. `tests/d0963_sf_lagging_flush.sh` gave 3/3 repro fix-off, 3/3 clean fix-on, under a minute. Also: a documented A/B lever (`sf_fastpath_adopt`) with no `module_param` is unusable by a harness until exposed. [[technique-hold-xfsaild-cluster-write-after-copy-in-to-make-a-platter-lag-race-deterministic]]
- **Prove a PR registration is on OUR nexus with an idempotent RESERVE, not by comparing key values.** READ KEYS / READ FULL STATUS return key values; a different I_T nexus could carry the same value. A RESERVE with scope/type matching the reservation in force completes GOOD only for a nexus registered with that key (RESERVATION CONFLICT otherwise), and under WRITE EXCLUSIVE - ALL REGISTRANTS is idempotent. Safe only if (1) the reservation is read first (with none in force the RESERVE would create one and hide the non-registrant-write window) and (2) the PAL primitive `mxfs_pal_scsi_pr_reserve()` is used and -EBUSY read, not `mxfs_scsipr_reserve()`, which treats a matching-reservation conflict as benign. Cost 9 ms on 2/tcp, PR generation unchanged. [[technique-prove-a-registration-is-on-our-own-nexus-with-an-idempotent-reserve-not-by-comparing-the-key-value]]
- **Forge the durable record to test a class the build never mints, and keep a supported class as discriminator.** Routes: inject at the durable write (`dl_fence_cert_kind_inject`) or forge the sector with `tools/recov_forge mkguard ...` into an unused heartbeat slot on the real LUN (`tests/fence_kind_matrix.sh`). A matrix of refusals alone proves nothing, since a missing-field rejection refuses as loudly as a class rejection; forge supported kinds 17 and 23 with one field blanked (`--fence-prover 0`) and require refusal naming the field and no revoked class. Never forge a fully valid certificate (it would authorise replaying a live journal slice); acceptance is proven by a real fence on a real victim (`tests/fence_strong_basis.sh proven`). Grade certificate fields, not the whole-sector crc. Measured 2026-09-20, eight arms `fails=0`. [[technique-to-test-a-class-a-build-will-never-mint-forge-the-durable-record-on-the-real-lun-and-keep-a-supported-class-as-the-discriminator]]

## Shared failure mode

Each entry is a way a green or quiet result was vacuous: nothing compiled, a tree compared with itself, a refusal matrix with no accept arm, a silent branch, a race window the quiet rig never opens, or a gate that never ran. Every one is fixed by adding a discriminating arm or a counter that proves the path executed.
