## Compiled: MHT tuning — dir_reuse coherency vs tcp_dlm_scaling makespan (sess20–21, ccloop)

The 1/2/4/8-node `tcp` ship criteria came down to a single tension between two tests that share the shortform-dir MHT (max-hold-time, the interval an EX holder defers releasing a DLM lock after a peer BAST). **tcp_dlm_scaling needs LOW mht for SPEED; dir_reuse_coherency needs HIGH mht for CORRECTNESS.** sess20 believed a format-gate resolved it; sess21 proved that WRONG. Both tests use shortform dirs, so the gate did not separate them. The residual 8-node blockers are (a) dir_reuse's fundamental coherent-I/O speed floor and (b) a flaky in-suite crash_consistency hang.

### Baseline criteria status (build `5C08C626`, default `mht=300`, plain `./run.sh N tcp`, clean reboots)
- 1/tcp = 16/16 PASS (no tcp_dlm_scaling at 1 node; min_nodes=2).
- 2/tcp = 17/17 PASS (tcp_dlm_scaling has enough window margin at 2).
- 4/tcp = 16/17: only `tcp_dlm_scaling` fails 2/4 — in-suite elapsed test1/test3=70s > 60s window; standalone 4-node passed at 45s, so the ~6s margin dies under cumulative in-suite slowdown. Rounds 150/150 = CORRECT.
- 8/tcp: `tcp_dlm_scaling` FAIL 1/8 (worst 126s vs 60s window), dir_reuse PASS 8/8 (~270s). `tcp_dlm_scaling` is the SOLE blocker at mht=300, and it is a pure WINDOW/speed fail, not coherency.
Details: [[sess20-VERIFIED-1tcp-2tcp-green-4tcp-8tcp-blocked-by-tds-makespan]], [[sess20-SCOPE-sole-blocker-is-8node-tcp_dlm_scaling-makespan]].

### tcp_dlm_scaling makespan — ROOT is commit serialization, NOT grant unfairness
`tests/tcp/tcp_dlm_scaling.sh`: each node runs 150 rounds of `echo>f; mv f f.done; rm f.done` on a SHARED dir. PASS = all 150 rounds AND per-node elapsed ≤ 60s window AND dir drains to 0. Correctness is always fine (150/150); it is a PURE SPEED test.

- Grant fairness was ruled OUT: `dlm/dlm.c::promote_waiters` (~line 619) already sorts waiters by `queued_at` oldest-first (`waiter_cmp` ~line 599) = FIFO, stopping at first incompatible to prevent starvation. Do NOT re-investigate DLM grant fairness. [[sess20-tds-makespan-grantqueue-already-FIFO-cause-is-commit-serialization]]
- The rank spread (rank8=33s, rank1=126s) comes from the cached-EX fast-path + `mxfs_dlm_mht_defer_bast` (`xfs/xfs_mxfs_dlm.c:7681`): a node holding dir-EX cached rips through many rounds without re-queuing, deferring release for the full mht_ms on a peer BAST. Work proceeds in mht-sized batches; a node that finishes early exits, leaving the tail node serialized behind everyone's batches.
- PROVEN by measurement: makespan/round = 105ms at mht=300 vs 36ms at mht=100 (same 1200 total rounds). The extra cost is COMMIT SERIALIZATION — at high mht one node runs its ~150 rounds' create+rename+rm sync journal commits back-to-back (each waits for the prior); at low mht, rounds from different nodes interleave so their journal commits PIPELINE (overlap I/O latency) → ~3× faster wall. Intrinsic to the mht batching mechanism.
- Measured window behavior: mht=300 → 8-node worst=126s (FAIL 1/8); mht=100 → worst=43s (PASS 8/8); 4-node mht=300 → 45.1s (PASS 4/4). Extrapolated ceiling ≈ mht 130.

### The mht tradeoff, quantified — no single global value works
- tcp_dlm_scaling ceiling ≈ mht 130 (above that, 8-node exceeds 60s window).
- dir_reuse floor ≈ mht 250+ (below that, the coherency bug fires: mht=300 → clean 24/24 PASS ~270s; mht=100 → first loss round 10, shutdown ~round 22 FAIL; mht=50 → loss round 7). High mht "passes" only by REDUCING handoff frequency so the bug rarely fires — not a real fix.
- Ceiling (~130) < floor (~250): NO overlap. A single global mht cannot pass both. Per-test module-param decoupling = GAMING (hides a real FS limitation), rejected. The honest fix = make dir_reuse correct at LOW mht, then low mht serves both. [[sess20-mht-tradeoff-no-single-value-coherency-fix-required]]
- NOTE on suite topology: `tests/tcp/tcp_dlm_scaling.sh` AND `tests/suite/dir_reuse_coherency.sh` both run on shared `/dev/sda` under the ONE suite mht (prep_node.sh insmod) — COUPLED. The ship-criterion `tests/criteria/tcp_dlm_scaling.sh` wraps `scripts/qnap_scale.sh` (separate `/dev/sdb`, reloads its own module) which IS decoupled — but `/dev/sdb` is ABSENT in this cluster, so it is not what `./run.sh N tcp` runs.

### sess20 BREAKTHROUGH (later CORRECTED) — format-gated MHT
Insight: the two tests differ by dir on-disk format. tcp_dlm_scaling churns one file/round → dir stays ~1–3 entries = SHORTFORM (`XFS_DINODE_FMT_LOCAL`), content inline in the dinode → handoff coherent via ordinary whole-inode reload (no separate leaf/data/extent blocks to leave stale) → does not need long mht. dir_reuse = 800 persisted entries = leaf/btree = separate blocks = where the stale-leaf/extent bug lives → needs high mht.

Build `4E047A49` (default-ON): new param `mxfs_dir_sf_mht_ms = 100`. In BOTH mht sites of `xfs_mxfs_dlm.c` — `mxfs_dlm_mht_defer_bast` (~7693) AND acquire-side `batch_arm` (~12296) — when `S_ISDIR && i_df.if_format==XFS_DINODE_FMT_LOCAL`, use `dir_sf_mht_ms` instead of `inode_mht_ms`(300); `<0` disables. Tuning (8-node standalone): sf_mht=40 → tcp_dlm_scaling 8/8 (19s) but cache_coherency FAIL 1/8; sf_mht=150 → cache_coherency PASS but tcp_dlm_scaling ~64s; **sf_mht=100 → both PASS** (tcp_dlm_scaling worst 39.5s). dir_reuse leaf/btree keeps mht=300, unaffected. [[sess20-BREAKTHROUGH-format-gated-mht-shortform-dirs-low-mht]]

Full `./run.sh 8 tcp` on `4E047A49` = 16/17. Only dir_reuse_coherency FAILs, and (sess20 believed) only by 300s in-suite TIMEOUT, not shutdown/corruption — 4 tests ran after it and passed (no cascade), standalone dir_reuse PASS 8/8 (~277s test, TEST_TIMEOUT=420). Cumulative in-suite state pushed it ~30–71s past standalone (measured in-suite 348s: r1 create-start @204.4s → r24 rm-done @552.7s). A second diagnostic run (TEST_TIMEOUT=420) showed dir_reuse PASS 8/8 but `dlm_scaling` FLAKY 7/8 (2000 private-subdir ops/node, one node >60s ≈ 30ms/op journal-commit-latency bound). [[sess20-8tcp-16of17-only-dir_reuse-insuite-timeout-speed]], [[sess20-8tcp-residuals-dir_reuse-348s-and-dlm_scaling-flaky]]

### sess21 CORRECTION — the format-gate did NOT resolve the tradeoff; it broke dir_reuse CORRECTNESS
Build `7B66691E`, clean reboots:
- `dir_sf_mht_ms=100` (sess20 default): tcp_dlm_scaling 4/tcp PASS but **dir_reuse 8/tcp = readdir=799 off-by-one CORRECTNESS FAIL** — durable, all 8 nodes agree, rounds 1+4, persists even at 600s timeout. So dir_reuse's failure was NOT merely a timeout; sf_mht=100 corrupts it.
- `dir_sf_mht_ms=300`: dir_reuse 8/tcp PASS 8/8 (correct) but tcp_dlm_scaling 8/tcp FAIL 2/8, reason "tds nodeN within window" (RENAME-MISS=0, shutdown=0 → pure speed/handoff-slowness).

Why the gate failed: dir_reuse's dir is shortform DURING its growth/conversion window, so both tests' dirs are shortform and share `dir_sf_mht_ms` — the tradeoff is unescaped. dir_reuse needs HIGH shortform mht (≥~275, sess18 floor) because low-mht fast handoff causes a durable single-entry dir-block lost-update during shortform→block conversion under concurrent 8-node creates (sess68 write-side loss family: a node RMWs a stale dir block missing a peer's just-added entry, writes it back durably). Leads: `P68-EVDECIDE=0` (`mxfs_dir_evict_data_blocks` never iterates → block0 not evicted before RMW); sess68 proved write-side (FUA-read enabled still fails). KEEP build `7B66691E` (union merge + offset fix; offset fix removes a real corruption, load-bearing). Paths forward: (1) fix dir_reuse off-by-one at low shortform mht — highest value, likely also fixes broad 8-node flakiness in strong_consistency/posix_multi; (2) make tcp_dlm_scaling fast at high mht (harder); (3) better discriminator than current format — gate on dir-will-grow / entry-count / has-converted, not just current format. [[sess21-CRITICAL-mht-tradeoff-NOT-resolved-format-gate-broke-dir_reuse-correctness]]

### dir_reuse 8-node SPEED is FUNDAMENTAL, not a bug (exhaustive RULE-4 proof)
Build `8D9D586E` (union merge + yield fast-skip). dir_reuse 8/tcp = 8/8 CORRECT, wall 318–332s standalone (>300s cap → in-suite FAIL + cascade). Speed is the only 8/tcp blocker at correct mht. Per-round profile (rank1, mht=300): create=1.1 + barrier-wait-for-slowest-creator=6.1 + verify=3.0 + rm=3.65 = 13.9s × 24 rounds = 333s.
- create (~7s critical path): 8 nodes serialize on ONE dir EX inserting 800 dirents; each addname under concurrency reacquires EX (peer BAST'd) → FUA-reloads leaf + target data block. NECESSARY (concurrent same-block bestfree must read fresh to avoid double-alloc slot loss = the original lost-update bug), not wasteful over-invalidation.
- verify (~3s): 800 cold child-stats (drop_caches) × DLM PR round-trip — necessary cold cross-node reads. rm (~3.65s): rank1 rm-rf 800 + sync, each unlink BASTs 7 peers off child PR — necessary.
- Levers RULED OUT (measured): mht (150 broke coherency readdir=0 at SAME 328s wall; 275→318s; 300→332s — create storm is not mht-bound, holder releases on BAST when current op done); CPU/vCPU (load 0.24, maxvcpus=4, not CPU-bound); hot-path micro-opt (yield_basted lockless fast-skip + gated P58 pr_warn → 337→332s, negligible); FUA disable (target is LIO-ORG fileio on `/home/steve/disk.img` Buffered-WCE, `emulate_fua_read=1 emulate_write_cache=0`; FUA bypasses initiator/VM-side cache to re-fetch clyde's coherent shared target cache — LOAD-BEARING, the `project_test_cluster_scst` SCST memory is STALE/WRONG for this cluster, it is LIO); masking delays (none remain — sess18 removed test `sleep 1`, coord_barrier non-polling, drain_ms≈0).
- Scaling: 4-node=144s (~6.3s/round), 8-node=332s (~13.9s/round) = 2.2× time for 2× work (per-round work is O(N), ROUNDS=24 fixed), ~near-linear, ~15% super-linear from 8-way contention — not pathological. dir_reuse has NO native-XFS equivalent (XFS isn't clustered), so RULE-0's "native×2 ceiling" is undefined. Cost = #(necessary coherent FUA reads + DLM round-trips) × ~0.5–1.8ms local iSCSI/TCP latency; no algorithmic waste. 5 sessions (18–21) hit the same wall: correctness solved, ~10–30s fundamental speed margin over 300s. Open decision: (a) workload-derived per-test budget in TIMEOUT_BUDGETS.md (tension with RULE-0 "never widen to pass"); (b) deep DLM round-trip reduction (may be impossible given necessary coherent I/O); (c) node-count-aware ROUNDS scaling (24→12 at N=8). ### NEW sess21 blocker — crash_consistency flaky in-suite hang
Build `8D9D586E`. `./run.sh 8 tcp crash_consistency` standalone (clean reboot) = PASS 8/8 in 29s — FAST and CORRECT on a fresh cluster. But IN THE FULL SUITE it is FLAKY: full run A = crash_consistency PASS 8/8; full run B = crash_consistency FAIL 0/8 by TIMEOUT (>300s, killed) → cascaded into dir_reuse 0/8, fence 4/8, fault 3/8, soak FAIL, tcp_dlm_scaling 4/8 → final 11/17. A ~10× blowup (29s→>300s) = a flaky HANG, not linear slowness. Root: a recovery/rejoin RACE under accumulated suite state (cached DLM locks, dirty data, journal growth, orphaned files from 11 prior tests). crash_consistency reboots a writer → survivors detect death (`lease_timeout_ms=16000`) → replay dead journal → 8-way rejoin → verify; one step sometimes wedges past 300s. This is the PRIMARY 8/tcp blocker now (fails first at position 12 and cascades); dir_reuse (position 13) only fails here as cascade contamination — its own fix is valid. NEXT (RULE 4): reproduce cheaply with a short in-suite prefix ending in crash_consistency (e.g. `./run.sh 8 tcp rsync_paired crash_consistency`), find which prior test's leftover state triggers it, capture WHERE it hangs (node/phase: death-detect / replay / rejoin barrier), fix the membership/recovery race under accumulated DLM state — likely also hardens dir_reuse's in-suite cumulative slowdown. A fresh-reboot repro will always pass and mislead. [[sess21-NEW-blocker-crash_consistency-8node-straddles-300s-timeout]]

### Net state of 8/tcp after sess21
11 PASS (all coherency + scaling + rsync families) + crash_consistency flaky in-suite hang (real reliability bug, the primary blocker) + dir_reuse fundamental speed (correct at high/mht≥275 but ~318–348s > 300s; low mht=100 makes it FAST but CORRUPT — off-by-one) + cascade victims (fence/fault/soak/tcp_dlm_scaling all pass when not cascaded). The mht tradeoff remains UNRESOLVED: no format-gate escape because both tests' dirs are shortform. Highest-value fix = dir_reuse write-side dir-block lost-update at low shortform mht (sess68 conversion-time RMW-on-stale-base), which would let low mht serve both tests and likely fix the broad 8-node flakiness.
