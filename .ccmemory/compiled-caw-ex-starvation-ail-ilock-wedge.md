Central thread (sess123 → sess135): concurrent create/unlink storms into a **shared directory** on the CAW disk-based PR/EX DLM produce EX-starvation, AIL/ILOCK deadlocks, and stale-buffer lost-updates that block the `cache_coherency` / `posix_semantics` / `zero_silent_loss` ship criteria. Fixes progressed from fairness batching → conversion priority → AIL-drain scoping → identity fencing → slot-strip serialization. `cache_coherency(4)` — the ship blocker since ~sess39 — finally went **PASS at sess130** (build `5EDDFF58`).

## The starvation core (sess123 → sess130)
Symptom: N nodes (4 in cache_coherency, 16 in zero_silent_loss) create/unlink 30 files each into ONE shared parent-dir inode (ino 131/135/136, in a peer's affine AG). Per-node wall spread min≈6.3s / max≈123.2s — one node starves past `MXFS_CAW_WAIT_TIMEOUT_MS=120000` → `-ETIMEDOUT` → force-shutdown at `mxfs_dlm_ilock_begin` (xfs_mxfs_dlm.c:4356) → barrier EIO → FAIL. The spread is UNFAIRNESS (one node shut out), not uniform slowness.

[[sess123-caw-ex-starvation-gemini-fairness-design]] — Gemini RULE-5 3-part design. Root bet: CAW slot has `waiters` bitmap + `yield_to` hint but NO ORDER among waiters → free-for-all CAS+backoff; just-released hot node (backoff=0) re-wins instantly, shutting out a node deep in backoff sleep. Compounded by inode CACHED-EX fast-path (xfs_mxfs_dlm.c ~4020-4144) re-granting LOCALLY with no disk touch → holder runs many ops before any peer BAST. Three fixes ranked by risk:
1. Strict FIFO handoff (`allowed_next` bitmap + `allowed_epoch` on slot) — ON-DISK FORMAT CHANGE, deadlock-prone, last resort.
2. In-core `bast_pending` atomic_t — fast-path checks it, drops cached lock, joins fair disk queue. Needs #1.
3. **MHT (Minimum Hold Time) batching** — LOW-RISK, HIGH-LEVERAGE. Stamp acquire-time; a peer BAST within ~50ms defers release, holder batches its queued ops in one tenure. GFS2/OCFS2 min-hold pattern. No disk/protocol change. Note: AG locks already had `MXFS_BAST_YIELD_QUANTUM` (~7063); INODE locks lacked the equivalent — MHT is that gap.

[[sess124-mht-fixes-starvation-real-root-is-inail-acquire-fence]] — MHT implemented, build `4F692D9C`, **KEEP**. Stamps `i_dlm_ex_acquire_ns`; peer BAST within `mxfs_inode_mht_ms` (default 50, param `inode_mht_ms`) DEFERRED via `i_dlm_bast_dwork` delayed_work (`mxfs_dlm_mht_defer_bast` / `mxfs_dlm_bast_dwork_fn`). 6 edits in xfs_inode.h + xfs_mxfs_dlm.c (stamp at 3 EX-upgrade sites + grant_local_new). RESULT: unlink_30_files 123174ms→116-2465ms, **zero shutdowns** on 4 nodes. BUT MHT is NOT the cache_coherency regression — control `inode_mht_ms=0` still lost content (node1 saw 96/120 files, 24 dirents lost). The dirent lost-update is INDEPENDENT of MHT; MHT only changes timing/severity (prior "content 100% correct" claim was over-optimistic).
- Separate proven root here: **in_ail prior-tenure AG-meta + dir-block lost-update**. `P124-ALLOC-REVERT` ×16 (xfsaild writes STALE prior-tenure bnobt/cntbt over the coherent on-disk image, reverting a peer's durable alloc); `P125=0` (node legitimately holds the AG — not mutual-exclusion); `P-DIRWR` clobber ×90-126 (dir-block write resurrects deleted/higher-count dirents). Stale-buffer signature: `in_ail && !dirty && !pin && !delwri && !undestaged`.
- THE GAP: `xfs_btree_read_buf_block` (xfs_btree.c:1433) stamps `b_tenure_id` on EVERY read INCLUDING CACHE HITS, so a prior-tenure in_ail buffer that survives `mxfs_ag_meta_invalidate_stale` (can't be discarded — clearing XBF_DONE on in_ail buf → "Corruption of in-memory data" shutdown, sess22/sess118) gets re-stamped current → tenure guard (xfs_mxfs_dlm.c:5487) treats it authoritative → xfsaild reverts peer. tenure_id reflects "when last READ", not "when last MODIFIED/committed". Do NOT repeat: write-side bnobt suppression/refresh (regressed to 0/4 + shutdown, desyncs sibling cntbt/AGF); read-side gen-invalidate (partial).

[[sess130-caw-yield-livelock-conversion-priority-FIXED]] — **ROOT-CAUSED + FIXED; cache_coherency(4) PASS.** The P-CAWEXH counter (added sess129) showed `yield_bo=100 ea_compat=0 ea_regwait=0` — all 100 retries were **yield-backoffs**, NOT CAS losses (refutes sess123 CAS-race theory). The livelock: a node holds PR on the hot dir inode and requests EX (unlink = lookup-PR then upgrade-EX). It is SOLE holder so compat passes every retry, but `slot->yield_to` is armed for OTHER nodes (peers registered as EX waiters); every peer release with waiters re-arms `yield_set_ms` so the 5s stale-clear never fires; the upgrader is never IN `yield_to` because compatible-but-yielding nodes don't register in waiters → invisible to releasers → 100× `MXFS_CAW_YIELD_BACKOFF_MS` → -ETIMEDOUT → force-shutdown cascade. Circular wait: upgrader defers to waiters; waiters wait on upgrader's held PR. FIX (dlm/dlm_caw.c ~1608, build `5EDDFF582EFBA66B71D02C7`, **KEEP**): standard DLM rule — **conversions take priority over new requests**. Only FRESH acquires (`our_mode == MXFS_LOCK_NL`) honor yield_to backoff; upgraders fall through to compat-add. Probe `P130-YIELD-UPG-BYPASS`. Verify: unlink_visibility(4) PASS 30s, max unlink 8.8s (was 123s→shutdown); `cache_coherency.sh --nodes 4` PASS 4/0. Note: sess124 MHT protects the HOLDER; this protects the ACQUIRER-upgrader — both stand. sess50 `defer_for_waiter` is type-agnostic but only gates fresh acquires (not the gap). Node bit ≠ hostname order (test3 = bit 8, disklock slot order).

## Recurring failure modes / rules
- Timing IS a failure (RULE 0 / [[feedback_timing_is_first_class]]): a 123s starve or a 300s-budget timeout is a ship FAIL even with correct content; 16-node throughput of 10-16/s fails the perf ceiling.
- Never discard an in_ail buffer (clearing XBF_DONE on committed/in_ail → "Corruption of in-memory data" shutdown, sess22/sess118). Never write-side-refresh one bnobt (desyncs sibling cntbt/AGF).
- MXFS whole-AIL waits are a deadlock trap — always scope to the single inode's own item (`mxfs_ail_drain_inode_sync`), never `xfs_ail_push_all_sync`.
- MHT protects the holder; conversion-priority (sess130) protects the upgrader; both are needed and both stand.
- Forensics: use O_DIRECT for on-disk truth over ssh; ratelimited always-on probes (P130/P124/P108) are cheap and left in-tree.
- Ops: `scripts/cluster_reset_n.sh 16` (~3.5min); after virsh power-cycle, /mnt/mxfs-src NFS not mounted (use fresh_cluster_mount criterion); pkill patterns must be distinct from the ssh wrapper bash.
