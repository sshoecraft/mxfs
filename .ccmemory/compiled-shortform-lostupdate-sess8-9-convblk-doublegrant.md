Central topic: the rotating 2-node/tcp **shortform-directory last-committer lost-update** ("benign" `shared dir drained got=1` / cache_coherency `got=98` leftover), investigated across sess8→sess9. Trajectory: rename-cancel shutdown fixed → proven it's acquire-side not durability → double-grant confirmed as root then decisively refuted → reframed as a serialized-EX-handoff coherence gap (stale cached-EX RMW) → two durable-revert roots fixed (~3× fewer failures) → residual cached-EX-outlives-grant RMW with three refuted fixes → Gemini DLM-demote state-machine design for next.

## sess8 — first win: rename dirty-cancel shutdown (the big one)
The suite *looked* like 6/16 because a single dlm_fairness failure CASCADE-shutdown every later test. Root ([[sess8-rename-guard-fix-and-shortform-lostupdate-root]]): in `xfs_dir_rename_children` (libxfs/xfs_dir2.c ~1550) the TARGET `xfs_dir_createname/replace` dirties the txn, then SOURCE `xfs_dir_removename` (~1647) returns -ENOENT (peer durably erased src dirent) → `xfs_rename` `goto out_trans_cancel` of a DIRTY txn → `xfs_trans_cancel at xfs_rename+0x90b — Corruption of in-memory data (0x8)` FS SHUTDOWN. FIX (KEEP): added the pre-dirty revalidate that `xfs_remove` already had (xfs_inode.c ~3481) into `xfs_rename` (xfs_inode.c ~3869, after `mxfs_dlm_dir_modify_refresh(src_dp)`): multi-node only, `xfs_dir_lookup_locked`; if -ENOENT or cur!=src_ip → clean-abort `error=-ENOENT; goto out_trans_cancel` (txn still CLEAN). Also revalidates target for RENAME_EXCHANGE. Logs `RENAME-REVALIDATE-MISS`. Build **E143DF7B7A2717564D68C65** (rename guard only). Result: cascade→6/16 became clean 14-15/16 with only benign rotating failures. This guard is KEEP through every later build. Fallback pre-guard build **E8BF16B2** was 15/16 but WITH the shutdown cascade (worse). **404BC55C** = prior double-grant gen-token build.

## sess8 — the rotating failure is acquire-side, NOT write durability
Repro: `MXFS_EXTRA_MODARGS=dirwr=1 ./run.sh 2 tcp dlm_fairness` in a loop (reboot first), ~1/6 standalone / ~1/16 in suite. The shared test dir (`.dlm_fairness` ino=131, also seen 128 / 2097280 / 8388736) is SHORTFORM (`dp_fmt=1`, dirents inline in dinode) so ALL dir-DATA-block coherency machinery is a NO-OP: `mxfs_dlm_dir_modify_refresh` evict, `mxfs_dlm_dir_durable_signal` (9658, now PUBLISH-ONLY since sess97 — perf), release-drain `mxfs_dir_flush_data_blocks` all do nothing. Coherency depends ENTIRELY on (a) writer dinode durable-on-LUN before dir-inode DLM release, and (b) reader dinode reload-on-acquire.

P-SFREL probe (dirwr-gated, bast_process release path xfs_mxfs_dlm.c ~3051, right after `mxfs_ail_drain_inode_sync`+`blkdev_issue_flush`) plain-bio reads the inode cluster back (mxfs_fua_disable=1 = SCST/LIO write-cache coherence point, same path a peer's reload uses). DECISIVE ([[sess8-shortform-lostupdate-is-acquire-side-not-durability]]): EVERY release shows the committer's entries DURABLE on the LUN before release — invariant #1 holds, **write-side durability is CORRECT**, refuting the sess8 release-side-gap hypothesis ([[sess8-rename-guard-fix-and-shortform-lostupdate-root]]'s "gap is (a)"). The failure is `P-SFDIR-REVERT incore_cnt=3 disk_cnt=2 fua_cnt=2` (fua==disk, class B: LUN genuinely lacks the entry). So a node RMWs its shortform dir from a STALE in-core base lacking a peer's ALREADY-DURABLE entry, commits+releases durably → clobbers it. Also REVERTED here (do NOT redo): removing the 1000ms throttle on P106/P108 stale-EX slot-verify (ilock_begin ~6289) — `P108-REACQUIRE fired ZERO` at failure, so it is NOT the lost-slot stale-EX condition; throttle-removal only added latency ([[sess8-FINAL-state-and-next-step-double-grant]]). Since each release is durable and reads use the coherence point, the stale base implies EITHER a residual double-grant OR a cached-EX fast-path acquire that skips the i_dlm_stale reload.

## sess8 — the double-grant hunt: confirmed-looking, built detectors, then REFUTED
Symmetric-clobber evidence ([[sess8-symmetric-clobber-confirms-doublegrant-detector-design]]): leftover `n1_r1.done` AND `n2_r7.done` (both rename TARGETs) present+agreed on both nodes — each node's own `rm x.done` durably reverted by the peer. Mutual symmetry ≠ serialized handoff (which loses one side) → signature of CONCURRENT EX. dlm_fairness is single-threaded per node so stale-cached-PR-reader vector doesn't apply. printk can't catch it: under dirwr=1 the dmesg ring ROLLS and drops P106-EXGRANT/EXREL pairs → a lock-free low-volume detector is required.

Built a SAFE single-master double-grant detector ([[sess8-doublegrant-detector-built-PDOUBLEGRANT-zero-at-failure]], build **BD5719158460A281FC63583**): `dg_shadow` 512-entry table of current EX holders (INODE resources) in dlm/dlm.c, SET on every master-side EX grant (process_remote_request immediate/reaffirm/conversion; local immediate; all 3 promote_waiters loops), CLEARED only on GENUINE release (process_remote_release, mxfs_dlm_unlock) — NOT administrative removals. table_rwlock-only, lockless reads, no new lock (deadlock-safe per invariant #4 / mxfs_pal_*). At EX grant, scans for an active EX by a DIFFERENT node on same resource → `P-DOUBLEGRANT`. RESULT: fired **ZERO** at a real failure on both nodes → single-master concurrent double-grant REFUTED.

Then added P-STALEMASTER-GRANT (split-brain: locklessly recompute `active_nodes[hash%count]`; if != local_node at a master-side EX grant → membership-flap mastership) in build **174E2CD5226C5C5969037B7** (rename guard + P-SFREL + P-CONVBLK-REMOVE + both detectors). DECISIVE ([[sess8-DECISIVE-not-doublegrant-not-splitbrain-serialized-coherence-gap]]): at real dlm_fairness failures BOTH counters = **0** on both nodes → NOT single-master double-grant AND NOT transient split-brain. This eliminates the double-grant family that consumed sess-tcp + many prior sessions. EX grants ARE serialized and consistent; the slow-path EX acquire ALWAYS reloads (xfs_mxfs_dlm.c ~7055 sets i_dlm_stale=true / ~7079 `mxfs_dlm_reload_inode(...,true)`).

Note the intermediate "CONFIRMED" claim that got walked back: [[sess8-CONFIRMED-root-convblk-removal-double-grant]] fingered the conversion-blocked PR→EX branch (dlm/dlm.c process_remote_request ~2229-2241): a node caches dir lock at PR (readdir/lookup), requests EX to modify; if blocked by peer's PR (conv_compat=0) the code FREES the sender's GRANTED PR entry and re-queues as WAITING-EX → sender invisible as holder → another node's PR→EX scans only GRANTED entries (~2211/~2254 `continue` on non-GRANTED), sees no conflict, gets EX → double-grant; and the waiter never gets a BAST so on promotion i_dlm_stale was never set → RMW of stale fork. P-CONVBLK-REMOVE (build **AFD6B76A06125A24489A130**, ~2229) DID fire on dir inodes ~3-6×/20 runs. BUT causation was UNPROVEN ([[sess8-convblk-causation-unproven-need-event-ring]]): the slow-path EX acquire always reloads, so a node PROMOTED to EX after convblk-removal still reloads the peer's durable image before modifying — the removal may not directly cause a write-clobber. Alternative vector floated: stale READ via a still-cached PR (`i_dlm_mode=PR` retained locally after master silently removed the entry) on a concurrent readdir/lookup fast-path (~6337) while peer holds EX. The zero-detector result ([[sess8-DECISIVE-...]]) then closed this out — the bug is in WHAT the reload adopts, not in lock exclusion.

## sess8 — reframe: SERIALIZED-EX-HANDOFF COHERENCE GAP
With EX serialized + reload-on-acquire, node B acquires EX AFTER A's durable delete+release, reloads, yet RMWs from a base STILL CONTAINING the deleted dirent → durably resurrects it. Conflicting sub-evidence to resolve: P-SFREL showed releasing node's dinode DURABLE (read-side stale) vs an earlier P-SFDIR-REVERT FUA probe showing `fua_cnt==disk_cnt<incore_cnt` (LUN genuinely lacks entry, write-side). Planned resolution ([[sess8-DECISIVE-not-doublegrant-not-splitbrain-serialized-coherence-gap]]): ONE correlated single-handoff trace (both UTC, realns, gated to test dir ino) — A logs P-SFREL(ino,count) at the release handing dir to B; B logs P-SFDIR-RELOAD(ino,count) at its next EX acquire; A.count>B.count = read-side stale (fix reload to truly re-read LUN / invalidate cached inode-cluster buffer on cache-HIT EX reload), A also short = write-side. Concrete code lead ([[sess8-lead-sess49-shortform-adopt-disk-vs-delete-resurrection]]): the sess49 "skip-the-skip" in `mxfs_dlm_reload_inode` (~4825-4846) makes a shortform DIR always adopt the on-disk dinode even when its own log item is in-flight, on the "disk is a strict SUPERSET" rationale. Flaw: superset holds for cross-node ADDS but NOT DELETES — if this node's in-flight committed-not-checkpointed op is a DELETE and disk still contains the entry, adoption RESURRECTS it. dlm_fairness's create→rename→rm makes DELETE the dominant op → matches the resurrected-`.done`/`n1_rK` leftovers. Correct invariant: adopt the UNION of (peer durable entries) + (our committed-not-yet-durable entries), respecting our committed deletes — a true shortform MERGE the codebase has never done.

sess8 stable state: reliably 15/16, no cascade ([[sess8-FINAL-state-and-next-step-double-grant]]). Build progression E143DF7B → DA703FD6DF02BDDC48491FD (rename guard + P-SFREL) → AFD6B76A (+ P-CONVBLK-REMOVE) → BD571915 (+ P-DOUBLEGRANT) → 174E2CD5 (+ P-STALEMASTER-GRANT). First cut at the merge fix ([[sess8-shortform-reload-fix-partial-plus-separate-content-bug]], build **1AB8C27A1A...B44**): dropped the unconditional `if_format==LOCAL` clause in `mxfs_dir_disk_superset` (~4901) so shortform dirs use `(post_release || peer_modified_since_load)` like block/leaf. dlm_fairness standalone **30/30** (was ~1/6–1/16); full suite ×3: run1 16/16 (first clean full pass!), run2 15/16 (cache_coherency 0/2), run3 14/16 — INCOMPLETE (the residual post_release/peer_modified path still lets disk_superset resurrect an in-flight delete or lose an in-flight add). Also flagged a SEPARATE bug: cache_coherency `content ... got=` (EMPTY) is REGULAR-FILE data coherency (di_size=0 family, cf. sess25/sess45), unrelated to the dir-reload change. Fallbacks 174E2CD5 (detectors), E143DF7B (guard only), E8BF16B2.

## sess9 — residual: cached-EX-outlives-grant STALE-BASE RMW; THREE refuted fixes
Residual ~1/30 with **P9-ICD-FAIL=0, P-DOUBLEGRANT=0** ([[sess9-three-refuted-fixes-for-cached-ex-residual]], [[sess9-root-durable-revert-and-publish-only-regression]]): a node holds `i_dlm_mode==EX` CACHED but a deferred BAST (bast_notify ACQUIRING/pin branch ~4540) set `i_dlm_stale` WITHOUT demoting; the dir EX fast-path (~6530 dir-strict gate) doesn't honor i_dlm_stale → RMWs the stale shortform fork and durably re-writes a peer's removed dirent. Plus a DESTAGE RACE: disk is transiently mid-update right after a removal, so a reload in that window reverts. Three fixes tried, ALL REGRESSED — DO NOT REPEAT:
- **A) Force slow-path when i_dlm_stale** (add `i_dlm_stale ||` to ~6530 gate, build **58EB95A8**): STARVATION, dlm_fairness `got=7/8` (node1 didn't finish 50 rounds). i_dlm_stale set too frequently under churn → every op a DLM round-trip+reload = sess43/sess50 timing wall / RULE-0 risk.
- **B) Relax P9 clean-gate, drop IN_AIL skip** (build **223CA589**): WORSE 27/30. P9 reloads while disk is transiently MID-DESTAGE and reverts our own just-committed removal. The IN_AIL skip is PROTECTIVE against the destage race.
- **C) Race-safe di_lsn gate** (drop IN_AIL skip but adopt disk only if on-disk `di_lsn >= our IN_AIL li_lsn`, build **05431C4F**): WORSE 27/30 (got=3/1/8 starvation). di_lsn semantics/reload cost not as clean as hoped.
KEEP 427DB5AF (best). Marker NOT written (16/16-reliable unmet).

## sess9 — Gemini design for the residual (RULE-5 justified)
[[sess9-gemini-deferred-bast-demote-design]] (gemini-pro-latest): A/B/C all tried to solve a LOCK-STATE problem with DATA-layer checks — wrong. The defect is the dir EX fast path leaking operations while a BAST revocation is pending (i_dlm_stale set but lock still cached EX). Fix the DLM state machine (matches GFS2 glock / OCFS2 / VMS):
1. **Fast-path BARRIER (missing piece):** dir EX fast path consults i_dlm_stale but does NOT reload (that's approach-A starvation) — instead BLOCK: `if (unlikely(ip->i_dlm_stale)) wait_event(ip->i_dlm_wait, !ip->i_dlm_stale);` then re-evaluate (lock no longer held → slow-path re-acquire). Add in mxfs_dlm_ilock_begin's dir EX fast-path holder-increment `else` (~6447) BEFORE incrementing holders; gate S_ISDIR && mode==EX && !single_node; skip if i_dlm_demoter==current (self-deadlock).
2. **Honor point (last ilock_end / unpin):** if i_dlm_stale → SYNCHRONOUS flush committed metadata to LUN → DLM demote (give up EX) → invalidate/purge in-core shortform fork → clear i_dlm_stale → `wake_up_all(i_dlm_wait)`. VERIFY the deferred BAST (P-NONE-HELD-DEFER ~4628-4649) actually reaches a demote at ilock_end.
3. **Minimum Hold Time (CRUCIAL anti-starvation, why A failed):** i_dlm_ex_acquire_ns already stamped at grant (~7037/7156). On BAST arrival if within MIN_HOLD (~5-10ms) DEFER setting i_dlm_stale via delayed workqueue so the node batches ~5-10 local ops before the barrier drops — without this, 2 nodes on one dir ping-pong per-op (the got=7/8 starvation).
4. **DROP di_lsn (C) and the disk-compare reload (P9 helper) for this purpose.** With strict mutual exclusion + flush-before-demote: holder = in-core is ground truth (never reads disk); acquirer = read disk EXACTLY ONCE on grant then trust in-core. Destage race vanishes (previous owner flushed synchronously before acking demote). Keep the sess9 KEEP fixes (remove/rename durable; EAGAIN-IN_AIL submit). Validate: dlm_fairness 30× (watch resurrection AND got<50 starvation), full suite 3× reboot-between = 16/16, rsync wall RULE-0.

## Recurring failure modes / lessons
- **printk cannot catch this heisenbug**: dirwr=1 rolls the dmesg ring and drops GRANT/REL pairs; lockwr=1 perturbs timing (6/6 PASS). Need a lock-free per-CPU event ring dumped only at leftover/unmount — never printk in the grant hot path. Light plain-bio probes (P-SFREL) do NOT reliably suppress, so are usable.
- **Don't solve a lock-state bug with data-layer patches** (reload / di_lsn compare) — starvation or destage-revert regressions every time.
- **Forcing reload on every acquire = SESS50-STARVE timing wall** (RULE-0 fail even if correct).
- **The IN_AIL skip is protective** against the post-removal destage race; dropping it reverts our own committed change.
- Detector-negative results are load-bearing: P-DOUBLEGRANT=0 and P-STALEMASTER-GRANT=0 redirected the whole investigation away from concurrency to the reload-adoption logic.
- Marker never written across sess8-9 (criterion = reliable 16/16 never met). Related: [[sess49_lessons]], [[sess84_lessons]], [[sess85_lessons]], [[sess88_lessons]].
