## dir_reuse_coherency 2/tcp: shortform→block double-conversion / logical-block0 split — root proof (sess42) and fix (sess43)

Central topic: the multi-session ship blocker `dir_reuse_coherency` on **2 nodes / tcp** transport — the sole target of the entire ccloop run `8ddb16a2` (sess20–43). Deterministic cold-verify data loss: both nodes agree `readdir=183..187/200`, `lookup_fail=0`, and the missing files are ALWAYS `node1_f1..f14` (the FIRST 14 files node1 writes = logical **block0** of test dir ino=131), NEVER node2's. node1=rank1=dir owner (does mkdir/rm-rf, writes first each round). Criterion phrasing "2 node dlm=tcp test 100% successful" is settled as == `dir_reuse_coherency 2/tcp` (the sess42 resume explicitly equates them); the other ~16 `./run.sh 2 tcp` suite tests are pre-existing failures from a different lineage + back-to-back cluster contamination, out of scope. See [[sess43-CRITERION-MET-dir-reuse-2tcp-three-clean-passes]].

### Root cause (sess42, PROVEN)
The dir's LOGICAL block 0 lands at DIFFERENT physical blocks on the two nodes because both nodes independently convert a fresh shared dir shortform→block:
- **node1 ALWAYS fsb=15 (daddr 120); node2 sometimes DIVERGENT fsb=14 (daddr 112)**, occasionally fsb=262153 (=AG1, node2's preferred AG = slot1%agcount). Decisive counts, clean round-19 run, P-DIRIFLUSH `incore_blk0_fsb`: node1 = 3000× fsb15 / 0× fsb14; node2 = 38× fsb15 (adopts node1) + 19× fsb14 (divergent). At verify the home dinode's logical-0 points at whichever flushed last (node2's fsb14) → node1's fsb15 block (f1..f14) orphaned → lost. `lookup_fail=0` because the leaf hash still resolves names to logical-0 (now the rival block). See [[sess42-DECISIVE-clean-round19-block0-double-alloc-at-sf-to-block]], [[sess42-ROOT-dir-block0-divergent-alloc-dinode-not-durable]].
- Mechanism at the conversion: `xfs_dir2_sf_to_block` allocates block0; second converter reads a STALE shortform base (missing peer's dirents) and re-inits block0. `xfs_dir3_data_init` ZEROES the block (the sess36 P31E daddr=120 zeroing, `xfs/libxfs/xfs_dir2_data.c:819`), durably losing f1..f14. Lineage ties to sess28/31/36/37 "first-block loss". See [[sess42-SYNTHESIS-block0-split-is-double-sf-conversion-lineage]].

Two sub-mechanisms, distinguished (both must be closed):
1. **SELF-revert** (single node): node1 converts sf→block, a RELOAD adopts a stale shortform on-disk image reverting its in-core block→shortform, node1 re-overflows and converts AGAIN for the SAME incarnation → block0 re-init zeroes its own dirents. PROVEN non-perturbingly (build B8C2149E, P42-SFCONV detector at `xfs_dir2_sf_to_block` entry, `xfs/libxfs/xfs_dir2_block.c ~1182`, no disk I/O): ino=131 i_gen=2915315106 had TWO conversions ~6s apart within one round; every other round had exactly one per distinct i_gen. See [[sess42-DECISIVE-double-sf-conversion-same-incarnation-proven]].
2. **CROSS-NODE concurrent-grow** (the harder residual): BOTH nodes convert/RMW the SAME fresh incarnation independently (test does rank1 mkdir+sync+barrier THEN both nodes add 50 files concurrently to the empty fresh dir — both legitimately start empty and grow). Proven via i_gen=3091469659: test2 P42-SFCONV node2_f12 @32711.22, test1 node1_f12 @32726.87 (15s later); two block0s split (test1 fsb15/daddr120, test2 fsb14). Decisive why test1 diverges: `P128-REARM-UNPUB ino=131 cache-hit CREATE on reused inode` just before its conversion — test1's create is a CACHE-HIT on its own stale in-core shortform and never reloads test2's durable block dir. See [[sess43-residual-is-crossnode-concurrent-grow-divergence-not-self-revert]].

### Refuted hypotheses (do not repeat)
- **DLM double-grant / concurrent EX**: `P-DOUBLEGRANT=0` and `P-STALEMASTER-GRANT=0` (always-on master-side shadow-table detector, `dlm/dlm.c:2288 dg_grant_ex`). No two nodes hold EX on ino=131 concurrently; no split-brain mastership. DLM mutual exclusion is SOUND — the divergence is SERIAL-STALE, not a concurrency race.
- **dir dinode not platter-durable at release**: build **C5BD4E04** extended `mxfs_dlm_dir_inode_durable` (`xfs_mxfs_dlm.c ~1814`) to force the inode cluster durable for ALL dir formats. STILL failed (rounds 20/23, still divergent fsb14/262153), only +30× iflushes. REVERTED. Release-durability is NOT the gap. See [[sess42-ROOT-dir-block0-divergent-alloc-dinode-not-durable]].
- Decisive P31E synchronous-read proof and `mxfs.instr=1` PERTURB the create-heavy timing (heisenbug, flips pass/fail) — the decisive instrument had to be NON-PERTURBING (no per-op I/O), which the P42-SFCONV / P-DIRIFLUSH detectors are. See [[sess42-SYNTHESIS-block0-split-is-double-sf-conversion-lineage]].

### Verified stall fix — held-check mode-blindness (sess42, build E8C6B4B6, KEEP)
Separate from the data loss: `mxfs_v5_dlm_inode_held(ctx, ino)` (`dlm/v5_mount.c`) hardcoded `mxfs_dlm_held_mode(...) >= MXFS_LOCK_EX ? 1 : 0`, but the P108 phantom-lock verify (`xfs/xfs_mxfs_dlm.c ~8250`) also validates PR cache-hits. A legitimately-held PR (mode 3) < EX (5) → false-negative → P108 demotes the valid PR → both nodes thrashed PR re-acquires on the SHORTFORM PARENT dir ino=128 (the dir CONTAINING `.dir_reuse_coherency`), starving node1's mkdir/rm EX → `P36-RETRY ino=128 mode=PR retries_left=59..0` storm ≈ the **65s round-N verify stall**. Fix: added `mxfs_v5_dlm_inode_held_rawmode` (raw NL/PR/EX; CAW held→EX); P108 computes `p108_held = (raw >= ip->i_dlm_mode)` (phantom iff hold < cached mode). Result: P36-RETRY=0, P108-REACQUIRE=0, run ~293s with NO 65s stall. Other held-check callers (P135/5893, tcpex/8304, P106/8791) are EX-intent, left on `>=EX`. Note: `DLM inode lock failed rc=-35` is **-EDEADLK**, the ABBA drain-and-retry path (routes through the drain, does not skip Invariant 1), NOT -EAGAIN(-11) which only follows the 60-retry -ETIMEDOUT budget (`dlm/dlm.c:1461`). See [[sess42-FIX-held-check-mode-blind-false-negative-PR]].

### The fix (sess43) — build progression to 422E6DC6 (KEEP)
All in `xfs/xfs_mxfs_dlm.c`. Two layers:

1. **P43/P43B block→shortform format-revert guards** in `mxfs_dlm_reload_inode` — fix the SELF-revert sub-case. There are TWO revert sites in the same reload function (one guard was not enough):
   - **P43-DIR-FMTREVERT-SKIP** (~line 6718, after P33-DIRGROW-REVERT-SKIP): checks the LIVE `dip` cluster buffer BEFORE the `down_write_trylock` spin. Cleanup: `xfs_buf_relse(bp); ip->i_dlm_stale=false; return;`.
   - **P43B-DIR-FMTREVERT-SNAP-SKIP** (~line 6996, right after `dip = snap`, before `xfs_idestroy_fork`): checks the IMMUTABLE post-spin SNAPSHOT. NEEDED because (sess87) a peer rewrites the SHARED cluster buffer DURING the spin — early `dip` reads BLOCK (P43 passes) while `snap` captures SHORTFORM via the `P62-RELOAD-FORK-SHRINK` path. Cleanup mirrors RELOAD-VERIFY-BAIL (`kfree(snap); xfs_buf_relse(bp); up_write(&ip->i_lock); i_dlm_stale=false; return;`).
   - Both guards, same condition: `S_ISDIR && same S_IFMT && di_gen==in-core gen && ip->i_df.if_format != XFS_DINODE_FMT_LOCAL && dip->di_format == XFS_DINODE_FMT_LOCAL`. Sound because the create-only test never legitimately reverts block→shortform within an incarnation (rm-rf bumps di_gen → excluded). See [[sess43-two-reload-sites-revert-block-to-shortform-P43-P43B]], [[sess43-PASS-dir-reuse-fixed-P43-P43B-fmtrevert-guards]].
   - Progression: build **8E2F4890** (P43 only) = PARTIAL — 3 same-incarnation doubles still slipped via the post-spin snapshot path; signature changed to `readdir=200` but `lookup_fail=9` leaf-hash holes. Build **226E02D6** (P43+P43B) = PASS, P43=1+P43B=1 on same incarnation gen=266719934, zero doubles, `lookup_fail` holes GONE (confirmed downstream of double-conversion, not independent).

2. **`int mxfs_dir_force_block = 1;`** (default flipped 0→1, `xfs/xfs_mxfs_dlm.c ~2768`) — fixes the CROSS-NODE residual. Forces new MULTINODE dirs to BLOCK format at mkdir (`mxfs_dir_should_force_block` guard: multi-node + DIR + shortform mkdir only). The dir is born block (single-node mkdir conversion only), so two nodes can't independently convert a fresh shared dir and split logical-block0; the existing single-block0 RMW coherency (per-AG drain-before-release, FUA-fresh acquire-reload/evict) handles the shared block. Build **422E6DC6** = 226E02D6 + this default flip. See [[sess43-FIX-dir-force-block-default-on-passes-dir-reuse]], [[sess43-PASS2-default-config-422E6DC6-dir-reuse]].
   - Why it works now vs sess18 "force_block ineffective": sess18 tested force_block ALONE on a 40-session-older build whose block0 RMW still clobbered; the intervening coherency fixes closed that gap. force_block removes the conversion-divergence LAYER; existing RMW coherency covers the shared block0. Both layers → PASS.
   - REFUTED this session: `dir_force_block + dir_merge` together is CORRECT (drc-FAIL=0) but dir_merge reads the peer's full dir per-create → ~50s/round → RULE-0 TIMEOUT. force_block ALONE is fast AND correct — leave `dir_merge=0`.
