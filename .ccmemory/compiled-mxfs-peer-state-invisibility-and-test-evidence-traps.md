Topic: two families of MXFS trap. (A) things a peer node does that never reach this node's in-core state, flags or counters, so a guard keyed on local state is wrong. (B) test and evidence methods that measure the trivial branch, read zero, or pass vacuously. Group is `topic`, compiled from 12 trap notes.

## A. Local in-core state does not see peer changes

- **Percpu admission counters.** `m_free[XC_FREE_BLOCKS]`, `m_icount`, `m_ifree` are set from the AG headers at mount and move only by this node's transaction deltas. A peer's frees never land: host A fallocates 6 GiB, host B removes it, A gets ENOSPC forever on an empty fs. `xfs_alloc_read_agf`'s `atomic64_add(allocbt_blks, &mp->m_allocbt_blks)` also ran at every summary rebuild, and MXFS rebuilds at every fresh AG tenure, so "unavailable" space grew per handoff. Fix (0.90.104, `xfs/xfs_mxfs_sb.c`): fold the peer's net change per AG at fresh-tenure rebuild, in statfs medium reads, and in a bounded-lock ENOSPC sweep. Lessons: any per-node cache of shared on-disk aggregates drifts unless something folds peer changes in; an unlocked read of a peer-held AG lags the peer's LOG (~30 s AIL push), so an ENOSPC decision must go through the AG lock so the release drain writes it home; `pag_dlm_lineage_open` means "changes not yet on the medium" and closes only after the release drain; `grep '=p' /proc/dynamic_debug/control` counts 0 even when enabled, check that lines actually appear. [[trap-xfs-percpu-free-counters-are-node-local-so-a-peers-frees-never-reach-them]]
- **VFS dead-directory flag.** `S_DEAD`/`IS_DEADDIR` is set only on the node that ran rmdir; peers see nlink 0 after the grant reload and no flag, and upstream `xfs_create` never checks parent nlink. A mkdir on another node committed into a removed directory, leaving a child with no name and `..` naming a free inode (0.90.37). Rule: any VFS guarantee enforced by an in-core flag on the operating node (`S_DEAD`, `I_WILL_FREE`, dentry state) does not exist on peers; re-check the equivalent from the reloaded inode once the grant is held. Fix: `xfs_create` returns -ENOENT when `i_nlink == 0` after the grant, before `xfs_dialloc` (a dirty cancel after dialloc shuts the fs down). link/symlink/rename into a peer-removed directory stays open (`D-LINK-SYMLINK-RENAME-INSERT-NAMES-INTO-A-PEER-REMOVED-DIRECTORY`). Caught by a forced-overlap shape (`tests/stress_rmdir_mkdir_race.sh`, every 200 ms) rather than waiting on waves; a post-commit "parent nlink == 0" probe can never see a mkdir because mkdir bumps the parent's nlink. [[trap-a-peer-removed-directory-reaches-other-nodes-as-nlink-0-and-no-vfs-dead-flag-so-the-fs-must-refuse-names-itself]]
- **Per-inode in-memory release mark.** `P-RELMARK-REINSTALL-REFUSED` compares against `ip->i_mxfs_relmark_res/epoch`. A release by eviction (drop_caches, reclaim) publishes the durable marker then frees the inode, so a later iget has no mark and the refusal never fires (0.90.102: 9 records adopted, clean). To exercise a check keyed on per-inode memory, the release must leave the inode cached: drive it from a peer (BAST via listing/stat on the other host), not by cache drops (`tests/pve_released_grant_ghost.sh` `RELEASE_BY=peer`). [[trap-a-release-by-eviction-frees-the-inodes-relmark-so-the-reinstall-refusal-needs-a-peer-driven-release]]
- **Write guard keyed on this node's grant, during recovery.** A replayer holds no grant (`in_core=0 mode=-1`), so `P12-DIR-EXGUARD-SKIP` completed a replayed directory-block write with no I/O (buf 32 names vs platter 42) while the inobt frees landed: dangling names, `chk_mxfs` rc 4 (0.90.27). Any filter that completes a write without I/O must ask the recovery question first (`_XBF_LOGRECOVERY`, 0x40000 in `bflags`); inode-cluster mask got it in 0.87.8, the older chokepoint filters and both `mxfs_buf_xfsaild_skip_*_write` predicates only in 0.90.27. It hid because a replayed CREATE has more names than the platter and passes; only a death inside a removal has fewer. A death lap proves a replayed removal only when the final platter shows a partly emptied directory and `dangling=0`; read per-directory checker lines, not the exit code. When replay says "applied" and the platter disagrees, read the REPLAYER's log for the block's daddr before theorising about the writer (the log-tail-moves-past hypothesis was disproved by the window holding the image). [[trap-a-write-guard-keyed-on-this-nodes-grant-drops-a-replayed-directory-removal-and-completes-it-as-written]]
- **Sole survivor has no grants.** A ruling "sole survivor takes the partial inode write exactly as multi-node" (D-0955) stranded the survivor: on single-node membership `mxfs_dlm_ilock_begin` bypasses the DLM and never sets `i_dlm_mode`, grant paths are gated on `!is_single_node`, and the release token is set only by the BAST drain. Every logged directory sat at NL without a token, `P56-NL-LOGGED-DIR-SKIP` dropped it, the reload read the peer's FREE image and poisoned (799 of 800 creates failed). Corrected: the sole survivor runs the real ownership protocol (grants from itself); only `mxfs_v5_dlm_never_multi()` may publish without a grant; "logged this round is authorised while single" loses the peer's change at the same generation. Lessons: enumerate a path's preconditions in code before landing a ruling of the form "take path X as under Y"; an A/B harness that alternates fixed and pre-fix arms lets the control arm rescue omissions, so verify omission bugs with an all-fixed-path campaign (`MXFS_D0946_ARM=1`); sum `cerr`/`derr` into the verdict; positive durability evidence is a cold-cache readback from the other node (`COLD_READBACK`, `STALESRC_READBACK`), since no clobber probe fires on bytes never written. [[trap-a-ruling-that-says-take-path-x-exactly-as-multi-node-assumes-every-premise-of-x]]

## B. Inode generation and incarnation logic on reused numbers

- **Ordering random generations is a coin flip.** `xfs_init_new_inode` draws generations with `get_random_u32()`; `xfs_ifree` bumps the freed image by exactly one. The only meaningful relation is equality or gen+1 across one free. 0.89.76: the evict-ring consumer gate `i_generation <= freed_gen` poisoned an open successor (victims 2, 4, 6 of six, ~50%), and the recycle gate `(s32)(disk_gen - incore_gen) > 0` kept a dead incarnation so the first read of a valid file returned -ESTALE. Rule: a generation gate asks "is this THE incarnation", never "is it older". Grep `i_generation <=`, `_gen <=`, `disk_gen <=`, `(s32)(...gen...) > 0`; alternation at ~50% across laps or victims is the signature. [[trap-an-order-comparison-between-two-xfs-inode-generations-is-a-coin-flip-and-a-poison-gated-on-it-kills-a-live-open-successor]]
- **Exposure test counted the opener's own descriptors.** 0.89.0's "exposed shell is immutable" poison read `i_mxfs_open_n > 0`, which `xfs_file_open` raises BEFORE `mxfs_dlm_open_protect` (required so a racing release publishes the mark); the reload under that same acquire then saw its own fds plus a generation mismatch and poisoned a fresh valid open (D-0979). The mark must cover an in-flight open; the poison must not count it. Fix: two counters, `i_mxfs_open_n` (all) and `i_mxfs_open_inflight`, raised in-flight first; `mxfs_inode_exposed()` = usable descriptors or mappings. A containment keyed on "has descriptors" must ask which incarnation they were opened on. The recycle gate's "adopt only strictly newer gen" is also wrong for a number the peer reallocated on a cache miss (random gen). [[trap-an-exposure-test-that-counts-the-openers-own-in-flight-descriptors-poisons-a-fresh-open-on-a-number-the-peer-reused]]
- **Clobber probe images cannot classify a live revert; tenure can.** `mxfs_dino_clobber_probe` (`pal/linux/xfs_buf.c`) "platter LIVE, memory FREE, different gen" had three false positives (sess583): a 96-byte detail buffer truncated generations (tell: decimal prefix, now 160 bytes); platter gen g vs memory gen g+1 with changecount ahead is our own free landing (`ownfree`); platter P vs memory Q+1 with P unrelated is our own churn two incarnations ahead (`ownchurn`). Discriminator: an inode held at EX or PR was reloaded at grant time, so the platter image is one we superseded; NL or not in core keeps the live-revert class. Read `live_revert=` only after those exclusions; before 0.83.3 a sole survivor held every inode at NL, blinding the discriminator. [[trap-platter-live-memory-free-different-gen-is-not-a-revert-unless-the-slot-is-unheld]]

## C. Harness and evidence traps

- **Crash knob after commit.** `mxfs.dbg_obl_engine_hold_ms` parked right after `xfs_trans_commit`, which only hands items to the CIL; the destroyed custodian's slice had no trace, the successor read entry 0 EMPTY and re-freed it, so the FULL branch the lap exists to measure was never reached (sess614, D-FOREIGN-SLICE-INTENTS-ABANDONED). A knob staging death "after X committed" must make X durable first (`xfs_log_force(mp, XFS_LOG_SYNC)` or the path's own durability point). Aggregate assertions (freed + already_free == census) hide it because re-freeing EMPTY equals skipping FULL; only a per-branch assertion sees it. Related: `trap-mxfs-slice-holds-only-last-txns-destage-kick-crash-tests-need-target-txn-last`. [[trap-a-crash-knob-parked-after-a-transaction-commit-kills-the-node-before-the-commit-is-in-its-log]]
- **Marker-bounded dmesg sweeps read zero.** Under a 32/caw board the node dmesg ring wraps within minutes (22,703 lines, last ~2 min after a 22-minute board), so `dmesg | sed -n '/MARK/,$p'` printed nothing and every counter read 0: a false clean on all 32 nodes; rebooted nodes lose the marker too. Record the mark TIME (`date -u '+%F %T'`) and sweep with `journalctl -k -q --since "$MARKTIME" -o short-monotonic`, printing `JOURNAL_LINES` per node so short windows show. Reproducers must verify the mxfs MOUNT before the workload; after `node_death_replay` /mnt/shared is a plain directory and every assertion passes vacuously. [[trap-dmesg-ring-wraps-under-board-kmsg-marker-sweeps-read-zero-use-journalctl-since]]
- **Background rig task killed by the tool host.** A `run_in_background` `scripts/module_swap_deploy.sh 2 tcp` was killed ("system is running low on memory") with 62 GB available; the threshold is the tool host's and reads the cache-heavy `free` column. Both nodes were left down with no module loaded. Run deploys and laps in the foreground (Bash allows up to 600 s per call, with the derived bound, not the cap, as the timeout), split longer work at a safe boundary, and after any killed rig task check both nodes' `srcversion`, mount count and the script's log tail before the next step. It is a session hazard, not a clyde hazard. [[trap-the-tool-host-kills-a-long-background-rig-task-under-its-own-memory-threshold-mid-deploy]]
- **`chk_mxfs` on unreplayed journals.** XFS v5 keeps icount/ifree/fdblocks lazily in the superblock, written only at clean unmount or freeze. `chk_mxfs -n` on a withdrawn DRBD pair returned rc 4 (`inobt free 102 != sb ifree 115`, fdblocks 8286699 vs AGF sum 6903535) while journals held committed transactions (replay allocated 358622 blocks). After one mount and a clean stop: rc 0. Never act on a counter finding from a filesystem whose last unmount was not clean; mount once, unmount cleanly, recheck. Never run `chk_mxfs -y/-a` there: it rewrites DIRTY slots as CLEAN (`tools/chk_mxfs.c` ~1788) and `dlm/journal.c:1600` skips replay of CLEAN slots (`D-CHK-MXFS-FLAGS-LAZY-COUNTERS-OF-A-DIRTY-JOURNAL-AND-ADVISES-REPAIR`). `scripts/pve_pair_update.sh CHECK=1` stops at such a finding by design; use `SKIP_INSTALL=1` (mount) then `SKIP_INSTALL=1 CHECK=1`. [[trap-chk-mxfs-on-a-filesystem-with-unreplayed-journals-reports-stale-lazy-counters-as-errors]]
