Two phases: (49) `dir_epoch_adopt=0` eliminates the deterministic FS-SHUTDOWN (AG double-free); (49b) a torn-disk reload gate + full-evict-on-handoff eliminates ALL remaining corruption, leaving only a node6-specific dir-DATA write-durability/visibility gap. ## sess49 — epoch_adopt=0 kills the shutdown

The 8/tcp failure was NOT mere dirent loss — it was a deterministic **FS SHUTDOWN** ~round 10: AG free double-free (`ltbno+ltlen>bno` at xfs_alloc.c:2254 in xfs_free_ag_extent), P21H-LEAFHOLE, and a DIR-fork DELAYSTARTBLOCK(-2)/hole where the leaf references a real block. dirs never use delayed alloc, so the -2 is mxfs-produced ([[sess49-8node-shutdown-is-agdoublefree-from-epochadopt-stale-reload]]).

Code-traced root: `mxfs_dir_epoch_adopt=1` (the sess14-48 default, xfs_mxfs_dlm.c:5291) sets `genuine_handoff=true` in `mxfs_dlm_reload_inode` when grant_epoch>valid_epoch (line 11181). genuine_handoff BYPASSES the keep-stale guards **P33-DIRGROW-REVERT-SKIP** (~11873-11894, `if (dg_inflight && !genuine_handoff)`) and **P43-DIR-FMTREVERT-SKIP** (~11983, `if ((dfr_dirty||dfr_grant_held) && !genuine_handoff)`). The reload then runs xfs_idestroy_fork + xfs_inode_from_disk, adopting a STALE-SMALLER disk dinode (our just-grown dir block not yet destaged), SHRINKS the in-core data fork, and a leaf-referenced block becomes a hole → dabuf_map !HOLE_OK + AG double-free → shutdown. Only 8 nodes: more handoff churn → higher chance the epoch advances while our grow is still in-AIL/un-destaged. The sess63 justification for the bypass ("genuine handoff ⇒ prior tenure drained ⇒ disk authoritative") is FALSE when the release-drain is incomplete for a dir grow ([[sess49-fix-design-genuine-handoff-must-honor-shrink-skip-when-dirty]]).

FIX (build **3B0EB406**): baked `mxfs_dir_epoch_adopt` DEFAULT 0. MEASURED via drc_dirtyskip.sh, 24 rounds, 8 nodes, fresh reboot each: epoch_adopt=1 → 0/8 deterministic shutdown ~round 10; epoch_adopt=0 → PASS 8/8, 0 RDMISS, 0 shutdown. 4-node PASSES with either value (corruption needs heavy 8-node churn). This recovers the sess18 (build 58360875) state where mht=300's longer EX hold masked the reload residual. `dir_gen_per_handoff` stays =1 (harmless read-invalidation counter). Refined "adopt-grow-keep-shrink" guard idea is EQUIVALENT to epoch_adopt=0 (guards already only fire on shrink) → won't add anything ([[sess49-BREAKTHROUGH-epoch-adopt-0-fixes-8node-shutdown]]).

epoch_adopt=0 reliably kills the shutdown but exposes an underlying FLAKY lost-update: ~1 PASS / 3-4 FAIL, no shutdown, all-nodes-agree (durable). TWO independent modes ([[sess49-residual-two-modes-write-clobber-and-reader-stale-block]]):

Same family as sess36 (xfs_dir3_data_init zeroes a block holding live dirents) and sess27 (intra-block slot-collision RMW) ([[sess49-residual-after-epochadopt0-is-node1-firstblock-durable-clobber]]).
2. **READER STALE BLOCK** (sweep-r1, late rounds 15-18): lookup_fail=0, readdir cumulative-short (751→701), missing=[]. Entries exist (lookup OK) but readdir enumerates a stale cached data block; gen-invalidation (`b_mxfs_dir_gen < i_dlm_dir_gen`) / readdir want_block_refresh not firing.

Both modes are INDEPENDENT of epoch_adopt (that's reload-side; these are write/read-side). REFUTED, do NOT retry: `dirskip=1`/`dataclobber=2` write-side enforce-skip → CATASTROPHIC empty dir (readdir=0/400, sess69); epoch_adopt=1 → shutdown.

## sess49 — GPT-5.5 DLM-grant-epoch design (RULE 5 consult)

Architecture for the write/read residual ([[sess49-GPT-design-dlm-epoch-authority-for-dir-buffer-coherency]]): the missing discriminator is the **current DLM grant epoch**, NOT disk content, i_generation, or the stuck in-core dir_gen. A cached dir-meta buffer is valid iff its stamped epoch == the inode's current grant epoch. DLM master keeps per-dir-inode monotonic `authority_epoch`, incremented on every EX grant + PR→EX conversion (PR doesn't increment), returned with grants; hold NL ref while any stamped cache exists. MXFS likely already has this as `grant_gen` / `i_mxfs_ex_grant_seq` (reliable, unlike lossy evict-ring dir_gen).

STAMPING DISCIPLINE (the crux — fixes prior over-suppression refutations): stamp bp.epoch = ip.grant_epoch at EXACTLY two points, NEVER at writeback/modify — (A) disk READ COMPLETION under valid PR/EX; (B) BIRTH-INIT of a newly-allocated block under EX before it's dirtied. Birth-stamp defeats the GHOST: a recreated dir reuses daddr but the fresh block gets the CURRENT epoch and overwrites the dead-incarnation ghost. Lazy stamp-at-modify blesses stale data (the sess40/41 bug). GATES: READ (reread on epoch/resid mismatch, fixes FACE 2); MODIFY (require EX + epoch match else reread/birth-init); WRITEBACK/xfsaild submit (require local EX + !closing + epoch==current, else DENY fail-closed, take authority_io_ref — fixes FACE 1). DEMOTE two-phase (closing→drain→invalidate-before-drop), never hand-order leaf-then-data (that's the P21H leaf-tear).

Actionable next step ([[sess49-NEXT-add-grant-gen-writeback-gate-exguard-already-on]]): `mxfs_dir_ex_write_guard=1` is ALREADY DEFAULT ON (xfs_mxfs_dlm.c:19662) and skips dir-meta writeback when mode!=EX — so GPT gate (a) "writeback requires EX" is already enforced, yet FACE-1 clobber persists → the clobbers happen while the node holds a cached/stale EX grant (mode==EX). The MISSING piece is gate (b): the per-buffer GRANT-EPOCH check. Implement: birth-stamp `bp->b_mxfs_grant_gen = dp->i_dlm_cached_grant_gen` in xfs_dir3_data_init (xfs_dir2_data.c ~887) + leaf/free init (read-completion already stamps at xfs_da_btree.c:3871); add a writeback gate (new param `mxfs_dir_grant_write_guard` DEFAULT 1) skipping the dir-meta write when `dsi.in_core && b_mxfs_grant_gen != 0 && b_mxfs_grant_gen != i_dlm_cached_grant_gen` — use the reliable grant_gen, NOT the lossy dsi.dir_gen; apply via the emulate-clean-ioend path (xfs_buf.c ~3062). WATCH: a writeback-denied DIRTY buffer must retire cleanly (emulate-clean-ioend retires BLI, no AIL wedge — sess37); Inv-1 release-drain is proven durable (sess41) so current work is never denied. Markers P49-GRANTWB-SKIP. Test with tests/drc_dirtyskip.sh then drc_reliability.sh.

## sess49b — root precisely localized: durable dir-map GAP born at middle-block free

Failure varies: (a) DABUF_MAP_HOLE cascade shutdown (1300-1700 hole hits), or (b) pure node-isolation (node6 declared dead after 40s) — (b) is downstream of (a) ([[sess49-8tcp-root-is-durable-dir-delalloc-extent-tear]]).

PROVEN ROOT (RULE 4): a durable on-disk dir dinode (ino 131) whose data-fork EXTENTS map has a GAP — a missing data block the LEAF still references. FUA-confirmed DISK-TORN (`P-HOLE-DISK DISK_MAPS_WANT=0`, disk extents e.g. [off0, off4, leaf], di_size=20480 → blocks 1,2,3 absent; or nextents=3 [blk0,blk2,LEAF] gap@blk1). NOT delalloc (`mxfs_dir_delalloc_tripwire` fired 0×), NOT the grow (dir2_grow_inode 0×), NOT reload-adopt (post_from_disk 0× once gated), NOT genuine_handoff (`mxfs_dir_handoff_adopt=0` → P63-HANDOFF 0× but HOLE still 1375-1672× → REFUTED), NOT gen-coupling (dir_gen always == loaded_gen at the hole).

WHERE BORN ([[sess49b-BREAKTHROUGH-torn-disk-reload-gate-partial-8tcp]]): `xfs_dir2_shrink_inode` freeing a NON-LAST (middle) dir data block (xfs/libxfs/xfs_dir2.c ~1078). xfs_bunmapi removes the middle block's extent but di_size is left UNCHANGED (only the last block shrinks di_size) → a data-region GAP with di_size still large. Benign single-node; becomes a durable TEAR multi-node when block-free and leaf update don't reach the platter atomically/consistently across a cross-node EX handoff (Invariant-1 violation) → a peer's stale leaf references the freed block → hole. Happens during per-round rm-rf + inode reuse.

PARTIAL FIX THAT LANDED (build **A9180EB2**, KEEP): TORN-DISK RELOAD GATE in mxfs_dlm_reload_inode just before xfs_idestroy_fork (~12788) — before adopting the disk dinode, parse its EXTENTS; if the data region (off < leafblk) has a HOLE for the same incarnation, REFUSE the adopt, keep in-core, set i_dlm_stale, re-arm DIR_RELOAD, return (`P-RELOAD-TORN-DISK-SKIP`). Effect: non-origin nodes keep good maps (incore_nx=9 vs disk_nx=3), oops ELIMINATED, no cascade → 1/3 PASS. Insufficient alone: the ORIGIN node's own in-core is gapped (from its shrink) and still flushes it (`P-IFLUSH-GAP-DETECT` ~230×) → re-torns disk. REVERTED (worse): iflush-side gap fence (skip flushing a gapped map) left the gapped in-core for xfs_dir2_leaf_addname → kernel OOPS (xfs_dir2_leaf_addname+0x733, write to RO leaf page); now detector-only. sess22 keeper build 1FE2C2DA (pre-genuine_handoff) had ZERO shutdowns via reorder-remove + rebuild-hole-skip — current build regressed to cascade.

## sess49b — full-evict-on-handoff eliminates ALL corruption

Decisive narrowing ([[sess49b-NEXT-leaf-vs-map-destage-atomicity]]): the stale-LEAF home-write comes from a node that HOLDS EX but whose cached leaf is STALE (from before a peer's middle-block free) and was NOT re-read on acquire, then flushed over the peer's durable leaf. Why existing guards miss it: `mxfs_dir_ex_write_guard` (DEFAULT 1, xfs_mxfs_dlm.c:20001) only skips a destage when `!in_core || mode != EX` — the torn flush happens while mode==EX, so it passes through (enabling more per-buffer guards is NOT the fix). The read-time leaf invalidation (xfs_da_read_buf re-fetch when `b_mxfs_dir_gen < i_dlm_dir_gen`) is gated on the LOSSY dir_gen (bumped only by async heartbeat evict-ring + slow-path reacquire), so a fast-path cached-grant EX re-acquire misses the bump → leaf stays stale.

FIX (GPT consult #3, sess47): on EX ACQUIRE of a multi-node dir that has seen peer activity, force-invalidate ALL cached dir LEAF/NODE/data buffers (NOT gated on lossy gen) so they're cold-re-read from the durable platter before the tenure modifies/flushes. Mechanism exists: `mxfs_dir_evict_owned_dir_blocks(ip)` (P68 owner-evict, map-independent, by header owner) — extend its trigger from SHRINK/incarnation-change to EVERY genuine cross-node EX acquire (reliable `genuine_handoff` signal, not lossy dir_gen).

Landed: build **4403BECE** then **EA485CE6** (KEEP — best foundation in 130+ sessions) = torn-disk reload gate + P68-PREEVICT owner-evict extended to fire on genuine_handoff with FULL evict (data+leaf; leaf-only was MEASURED to re-admit disk-torn/hole), placed AFTER the reload gate. Added `leaf_only` param on mxfs_dir_evict_owned_dir_blocks as a lever. RESULT: **HOLE=0, DISK-TORN=0, kernel-oops=0, no shutdown, no node declared-dead**; 2/tcp + 4/tcp still PASS. The DABUF_MAP_HOLE cascade, leaf-addname oops, disk-torn map — ALL gone. Safest state in the whole investigation ([[sess49b-evict-on-handoff-kills-corruption-exposes-visibility-gap]]).

## sess49b — remaining: node6 dir-DATA write-durability/visibility

Sharp diagnosis: it is a DURABILITY gap, NOT evict-too-aggressive. `mxfs_dir_evict_owned_dir_blocks` (xfs_mxfs_dlm.c:3899/3916-3923) already evicts ONLY clean/durable blocks — skips dirty/pinned/in-AIL/_XBF_DELWRI_Q/!XBF_DONE, so it does NOT drop test6's in-flight work. test6 reads 0 because the evict forces a cold re-read of test6's clean-cached dir DATA blocks and disk comes back EMPTY → **test6's dirents were never landed on the platter** (block marked clean/XBF_DONE in cache but content not durable, OR a peer's release-drain dropped them). The evict didn't cause the gap; it EXPOSED the long-standing "dir block released un-landed" / Invariant-1 gap previously masked by stale cache ([[sess49b-evict-on-handoff-kills-corruption-exposes-visibility-gap]], [[sess49b-FINAL-corruption-fixed-remaining-node6-write-durability]]).
