### FIX 1 — crash_consistency in-suite ABBA hang (the sess21/sess29 PRIMARY 8/tcp wall)
Verified PASS 8/8 in-suite across multiple runs. Root: the EX-release loop held `dp->i_lock(read)` across `mxfs_dir_flush_data_blocks`, which does a BLOCKING `xfs_buf_incore(...,0,...)`; a journal-replay/peer-BAST context held the dir buffer while needing `i_lock(write)` → two D-state threads (bast kworker + bash both blocked in `xfs_buf_lock` under `mxfs_dir_flush_data_blocks`) → hard wedge.

Structural fix (snapshot-then-act, mirrors `mxfs_dir_drain_evict_data_blocks`):
1. Extracted per-block flush body into i_lock-FREE `mxfs_dir_flush_one_daddr(ip, d, dir_blk_bb, startoff)` (buffer cache is keyed by daddr, needs no i_lock); inner `continue;` → `return;`.
2. `mxfs_dir_flush_data_blocks(ip)` keeps its contract (caller holds i_lock) for the 3 non-ABBA callers (reclaim EXCL ~14098 etc.).
3. NEW `mxfs_dir_flush_data_blocks_relsafe(ip)`: caller holds i_lock(read); kmalloc-snapshots ALL dir-block daddrs+startoffs under i_lock (no fixed cap → Invariant-1 safe), `up_read`, flushes each via one_daddr WITHOUT i_lock. Consumes/drops the lock.
4. The TWO release-loop ABBA sites (P97 release fence ~7529, P35F stale-retry ~7866) now call `_relsafe(ip)` and drop their own `up_read`. [[sess30-FIX-crashconsist-ABBA-flush-snapshot-relsafe]]

### FIX 2 — soak (4/tcp blocker)
soak failed because a rare `xfs_buf_verify_write: no buf ops on daddr` on an INODE buffer (mxfs reload/FUA left `b_ops==NULL`; xfsaild delwri-flushes it) did `dump_stack()` → tripped soak's DPAT `call trace` matcher → FAIL. Content was benign (inode di_crc stamped at iflush). Fix (pal/linux/xfs_buf.c): `mxfs_buf_ops_from_magic()` re-derives the write verifier from the on-disk magic (AGI/AGF/AGFL/inode/bnobt/cntbt/inobt/finobt/bmbt/dir3-block/data/free) when `b_ops==NULL` on a CRC fs, then runs verify_write to stamp CRC — no dump_stack. Probe: P30-OPS-RECOVER. [[sess30-WIN-4tcp-17of17-soak-fixed-by-P30-ops-recover]] [[sess30-HEAD-crashconsist-fixed-soak-P30fix-dirreuse-readdir0-parent-dirent]]

**Face 1 (2/4-node) — durable single-dirent TOTAL loss** (the deep ~130-session lost-update, aka Face C). Cleanest repro: `drc-RDMISS round=2 rank=1 readdir=199 missing=[node1_f10.md5]` (EXP=200 for 2 nodes); also 399/400, 799/800. node1's OWN just-created dirent vanishes from BOTH leaf-hash and data blocks after sync + drop_caches + cold-read (`P21H-LEAFHOLE name="node1_f10.md5" hv_in_leaf=0` + `drc-RDMISS/REREAD_MISS`). sess28 smoking-gun: an EX-holder destages a STALE in-AIL dir-DATA block, signature `held_mode=5(EX) in_ail=1 dirty=0 bgen=0 MERGE-NEEDED(disk_extra>=1, incore_extra=1)`; sess28 proved the modify-time read was coherent (diff1=0) — staleness develops in the AIL between commit and destage. [[sess30-LEAD-bgen0-clobber-block-origin-is-next-target]]

The key unexplained detail is **bgen=0** (`b_mxfs_dir_gen==0` = never gen-stamped). A dir-DATA block cold-read through the gen-stamping read hook (`xfs_da_read_buf` / `mxfs_buf_read_fua`) gets `b_mxfs_dir_gen` set to the current `i_dlm_dir_gen` (nonzero after handoffs). bgen=0 means the block was obtained WITHOUT the gen-stamping read path (e.g. `xfs_buf_get` / uncached, no read) — same class as the soak `b_ops==NULL` buffer. The holder RMWs/destages a stale base (missing the peer's add B) and the read-side gen-invalidation (`bgen<dir_gen → clear XBF_DONE`) can't help because it is a WRITE, not a read. [[sess30-LEAD-bgen0-clobber-block-origin-is-next-target]]

Precise-root characterization (best yet): the dir read-time gen/epoch invalidation hook (`xfs_da_read_buf`, xfs_da_btree.c ~3232) CANNOT invalidate an in_ail/pinned/UNDESTAGED stale dir buffer — clearing XBF_DONE on it corrupts (sess64), and an undestaged buffer holds this node's un-written add A. So a dir MODIFY that reads a stale prior-tenure in_ail-undestaged block (bgen=0, missing peer's add B) RMWs the stale base → destages base+A over disk base+B → durably drops B. The read hook already handles the DESTAGED in_ail case (sess133 `mxfs_dir_buf_is_undestaged` discriminator); the residual is the UNDESTAGED conflict. THE unavoidable fix = a transactional 3-way re-apply of A onto the freshly-read base+B at re-acquire (can't evict = lose A; can't destage = lose B; can't byte-merge at bio chokepoint = cross-block dup, refuted). Alternative: find why the modify obtains a bgen=0 block via get-without-read and fix that get site so no stale-base RMW occurs. [[sess30-refuted-prior-tenure-evict-levers-and-relay-boundary]]

**Face A / 8-node in-suite cascade = AGI EFSBADCRC shutdown, NOT a no-buf-ops write.** PROVEN (RULE 4, prefix repro, no fault tests so dmesg survived): the `mxfs-drc-FAIL readdir=0 exp=800 lookup_fail=0 missing=[]` signature is MISLEADING — the test's lookup loop reads names FROM `ls "$D"`, so readdir=0 ⇒ loop runs 0× ⇒ lookup_fail/missing auto-zero. Real signal: `ls /mnt/shared` returns EIO because the FS SHUT DOWN. Trigger (test1, ~t=303s, round-8 rm-rf mass inode-free, flood of P82-ADD iunlink-bucket adds freeing 800 inodes in AG0): `xfs_read_agi+0x11f` daddr 0x2 len 1 error 74 → `xfs_inactive_ifree+0x2e9` (xfs_inode.c:2653) Shutting down. daddr 0x2 = AGI of AG0, error 74 = EFSBADCRC. This is the sess22/39/45 AG-meta-corruption family; dir_reuse's rm-rf+recreate (800 inodes × ~24 rounds, all 8 nodes hammering AG0) exposes it most, cascading EIO into fence/fault/soak/tcp_dlm_scaling. P30 ops-recover NEVER fired for AGI (count=0) → the bad CRC is NOT a verifier-skipping write in our tree. AGI is never FUA-written (only dir blocks use `mxfs_pal_scsi_write_fua_bdev` @ dlm.c:1834); normal AGI writes run xfs_buf_verify_write → correct CRC. sess22 lead stands: AGI content structurally VALID, on-disk CRC wrong. Next: probe daddr 0x2 write-CRC + read-verify-fail (log write-CRC and on-disk-vs-recomputed CRC). Candidates: (a) concurrent in-core AGI modify during the write DMA window; (b) torn/stale FUA read at the LIO target under 8-node AG0 contention; (c) a node writing AGI mid-modify. [[sess30-dir_reuse-insuite-cascade-is-AGI-CRC-shutdown-not-dabuf]] [[sess30-HEAD-crashconsist-fixed-soak-P30fix-dirreuse-readdir0-parent-dirent]]

**Face B (build 04A615EE run) — readdir=0 with NO shutdown, FS healthy.** PROVEN: `drc-DIRID dirino=` EMPTY ⇒ `stat "$D"` returns ENOENT — the directory `/mnt/shared/.dir_reuse_coherency` does not exist at verify time.
