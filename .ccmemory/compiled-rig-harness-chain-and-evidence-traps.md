Compiled from 12 notes on one theme: how lap chains, prep and harness scripts on the MXFS rig produce results that measure the harness, not the filesystem. Each section is a failure mode and the check that catches it.

## Chain lifecycle: what survives, what cascades, what is left mounted

- **Stopping a chain from outside leaves node loads running.** `tests/mpath/pathload.py run` stops only on its stop file and keeps looping, counting failed ops. TaskStop or a killed `run.sh` never touches the stop file. The next `prep_cluster` power-cycles only nodes whose mount will not release; a node that released cleanly is not rebooted and its orphan resumes on the new mount. Measured at 0.90.53: one orphan logged 7,334,412 ops and held `/mnt/shared`, so `path_mount_degraded`'s first umount returned 32 (EBUSY) in 5 ms. Since then each row's `pf_start_gate` (`tests/mpath/lib.sh`) kills such loads via `tools/mxfs_pgrep.sh` and ABORTs if it cannot. When reading a lap after a stopped chain, compare the old run's `load_<node>/ops.log` tail time with the new lap's start. [[trap-stopping-a-lap-chain-from-outside-leaves-its-node-loads-running-into-the-next-lap]]
- **A gate that already says DONE starts the chain immediately.** A chain launched gated on a log already holding `DONE` collided with another chain gated on the same log: two concurrent preps, both ran `install_ko` into the same tree `mxfs.ko`, `sv=` came back empty, the harness did not abort on it, and a prep ran the wrong module. Run `grep -q '^DONE' $GATE` before choosing a gate; if DONE, gate on the chain actually running or queued last. Weakness to keep fixed: `install_ko` must fail on an empty or mismatched srcversion. [[trap-chain-gate-already-done-starts-immediately-killed-harness-done-trap-cascades]]
- **Killing a harness opens the next gate.** A DONE-on-exit trap turns `kill` into `DONE`, which starts the downstream waiter (run-lock collision, rc=3, then more invalid runs). On aborting a chain, immediately check and kill/relaunch every downstream waiter and archive the polluted logs, because a relaunch appends to the same log name. `timeout N ./run.sh ... prep_cluster` is its own process group: kill the `timeout` pid and the `run.sh` pid explicitly, then settle about one prep wall (90-100 s) for ssh fan-out remnants. A kill loop over `/proc/*/cmdline` matches its own shell; exclude `$$`, `$PPID` and shell-snapshot cmdlines. [[trap-chain-gate-already-done-starts-immediately-killed-harness-done-trap-cascades]]
- **The release chain leaves the RHEL9 pair mounted.** It ends with `PREP=rhel9 tests/tcp_peer_freeze_death.sh` (last step remounts the victim) and `tests/selinux_svirt_mxfs.sh`; nothing unmounts, so alma9-1/2 keep heartbeating into the LUN. The next `./run.sh 2 tcp` aborts with `FS_PREP_FAIL: a node is still heartbeating into <lun> — refusing to mkfs under a live writer`; that refusal is correct. Find holders with `grep " mxfs " /proc/mounts` on each lab node, then `timeout 60 umount`. The chain now appends that unmount as its last step; keep it. [[trap-the-release-chain-leaves-the-rhel9-pair-mounted-on-the-shared-lun-so-the-next-2tcp-prep-refuses-mkfs]]
- **mkfs "zero_region verify FAIL ... storage silently dropped writes" is a live heartbeat writer.** Offset 67118080 is slot 1 of the disklock table (starts 67117056); byte 0x4b is the `K` of the `MXLK` magic. The message names the wrong suspect. Check `tools/disklock_hb_dump.py <dev>` for ACTIVE records with advancing `ts_ms` before blaming storage. Prep must refuse to format while a record's ts_ms advances between two reads, and every node must be unmounted/unloaded first. A lap that fails at prep leaves the previous lap's ACTIVE records on the LUN, so the next lap's apparent fencing failures are residue; read the prior lap's prep log. [[trap-a-mkfs-zero-region-verify-failure-blaming-the-storage-is-a-node-still-heartbeating-into-the-disklock-region]]

## Tree and script stability while something runs

- **A running lap chain compares fleet srcversion to the tree's `mxfs.ko` every lap.** `tests/quiesce_remount_chain.sh` starts `tests/quiesce_remount_access.sh` fresh per lap. Do not run `make modules` in the tree (every later lap ends `INFRA ... the fleet does not run this tree's module`); compile-check in a `mktemp -d` copy, and not during pace-graded laps since the build loads the host. Do not edit the lap harness. `tests/release_gate_chain.sh` starts release verification by itself on pass and builds whatever the tree holds then, so fix the final source before launching the gate, or stop the wrapper (pid by `comm` from `/proc/*/comm`) and run `tests/release_verify_chain.sh` by hand. A lap that leaves a node unmounted turns all later laps into `INFRA: precondition not met` rc=2; read the first non-zero lap only. [[trap-a-lap-chain-compares-the-fleet-module-to-the-trees-mxfs-ko-so-nothing-is-built-or-edited-in-the-tree-while-it-runs]]
- **Never add or remove lines in a shell script that is executing.** Bash returns to a saved byte offset after each command, so inserting text above it makes the instance resume mid-command. Adding a `--after` option to `tests/lap_queue.sh` during a ~3 h, 10-lap queue was caught and reverted byte-exactly; the damage would have been a missing final `QUEUE DONE` hours later. A same-size edit is not safe either. Treat running scripts under `tests/` as read-only; put the change in a new file (`tests/lap_queue_chain.sh` exists for this). [[trap-editing-a-shell-script-while-an-instance-of-it-is-running-can-make-that-instance-resume-mid-file]]

## Load loops and windows

- **A fixed sleep is not a stop.** `tests/sf_base_overlap.sh` slept `LOAD_S+10`, then unmounted, but the loop tests its deadline only between cycles; with a 20 ms test delay one rsync+rm cycle outlasted the slack, so 7 umounts returned `UMOUNT_RC=32` in 0 s and the checker never ran (`load=` empty in the summary). Give loops a stop file plus the deadline (removed at start), clear test delays, touch the stop file, wait for the loop's `.done` with a bound derived from one cycle, and read `LOAD=` only after. Empty `load=` means the loop had not ended. `tests/multi_victim_containment.sh` has the same one-cycle-wide slack. [[trap-a-harness-that-waits-out-a-fixed-window-unmounts-under-the-loads-last-cycle-and-every-umount-answers-busy]]

## Fault injection and crash-test design

- **An injector that plants task-owned state confounds both arms when the task exits first.** The demoter-claim injector (`i_dlm_demoter = current`) in `tests/stress_rmdir_mkdir_race.sh` ruined four laps: planted for every user task (each `mkdir` exited, claims never cleared, nodes withdrew in both arms); set at module load (budget spent by `alloc_witness`'s `rm -f`); restricted to `rm` but the remover's last op hits the base directory, leaving dead-owner claims (`P-INODE-WEDGE`); and a dead owner's `task_struct` address reused 12 s later by an unrelated `mkdir`. Plant only where the same task provably acts on the object again, exclude objects it touches last, arm via sysfs only for the load window on the node running the target task, reset afterward, and read the injector's planted/consumed/left counters before the result. If the fix arm fails like the control arm, suspect the injector first. [[trap-a-test-injector-that-plants-state-owned-by-a-task-confounds-both-arms-when-the-task-exits-first]]
- **A victim's journal slice holds only its last 2-4 transactions.** `mxfs_destage_kick_fn` (`xfs/xfs_mxfs_dlm.c` ~2341) does an async log force plus `xfs_ail_push_all` per debounce window on every create/unlink. Crash/replay tests must make the transaction under test the victim's LAST: create one file at a time, stop when the producer probe fires or on the allocation fact (`ino % 64 == 0`), never `sync`/`syncfs` afterward, destroy immediately. `/proc/sys/fs/mxfs/` and `/proc/sys/fs/xfs/` do not exist on the nodes (`xfs_sysctl.o` excluded, Kbuild:157), so `echo N > .../xfssyncd_centisecs` is a silent no-op. `P133-ICLUSTER-SYNCINIT` prints only for the first 20 carves per module lifetime. Fixed in `tests/bootstrap_full_restart.sh` and `tests/d0512_sf_to_block_replay.sh`. [[trap-mxfs-slice-holds-only-last-txns-destage-kick-crash-tests-need-target-txn-last]]
- **A raw PR OUT REGISTER must set APTPL.** SCST does `dev->pr_aptpl = aptpl` on every register, including nexus-local probes and unregisters, so one REGISTER with byte 20 = 0 turns persistence off for the whole LU; MXFS then refuses every mount (`P303-FENCECAP-NOPERSIST`, `TCP mount REFUSED (-1)`) and `run.sh` reports only `PREP FAIL (form test1):`. Hand-built REGISTER (SA 0x00) and REGISTER AND IGNORE (SA 0x06) set `data[20] = 0x01`; PREEMPT / PREEMPT AND ABORT pass 0. On an empty-reason prep failure after touching PR code, read node dmesg for `P303-FENCECAP` first. [[trap-a-raw-pr-out-register-without-aptpl-turns-persistence-off-for-the-whole-lu]]

## Evidence integrity

- **Vacuous PASS is the dominant evidence failure.** Six independent instances: an unprepped fleet scored as failures after `run.sh` rc=3; a remote grep with `$vslot` in single quotes that could never match; `grep -qv '^0$'` as a numeric gate (true for any unexpected line, false for empty); three fault-injection matrices (`tmpfile_churn_kill.sh`) that injected nothing yet printed `VERDICT PASS` (`iclus_marked=0 P282=0`); `./showstat.sh` run unconditionally after a refused `run.sh`, rendering the previous day's board as this build's result (log annotated `RETRACTED — VOID, DO NOT CITE`); and `ls -dt <glob> | head -1` scoring the previous lap's directory. Confirm the step ran before reading any verdict. Vacuity gate: assert the injection counter is non-zero and FAIL loudly otherwise (pattern at `tmpfile_churn_kill.sh:450`, `VACUOUS ARM`). Freshness gate: pin the artifact identity (`run_id` in `.last_run.json`, evidence directory) before the step and require it to change after; print no table otherwise. Audit old evidence for `installed=1 got=0`, `P282=0`, `iclus_marked=0`, `entries=0 statted=0`, `order=unknown`, `relog_holders=[]`, `got=0 want=N` beside `VERDICT PASS`, and a `DONE` seconds after `START`. Closures resting on a chain log need that re-read; the closed:found ratio has been under 1.0 every month. [[vacuous-pass-the-dominant-evidence-failure-in-this-project]]
- **Never write a second parser for a format the producer already parses.** `tests/create_scale_curve.sh` emits `OP <index> <duration ms>` and parses it with `len(f) == 3 and f[0] == 'OP'` then `f[2]`. A "tolerant" re-parse taking the first numeric field read the op index and reported 5 ms p50 against a measured 193 ms; it was caught only because `max=8` equalled F=8. Copy the producer's parse verbatim, prefer strict over tolerant (fails loudly on format change), sanity-check a new parser against a number already in the ledger, and treat output equal to an experiment parameter (`max=8` at F=8, `n=32` at 32 nodes) as a counter read instead of a measurement. [[trap-never-write-a-second-parser-for-a-format-the-producer-already-parses]]

## Recurring pattern

Almost every entry is a harness reporting on state it did not control: a load or heartbeat still running from the previous lap, a log or board from the previous run, a tree changed under a live chain, or an injection that never fired. Before reading a result, establish what was running, what was fresh, and whether the fault actually landed.
