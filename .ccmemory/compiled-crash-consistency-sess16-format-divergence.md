## Root-cause evolution (each proven, RULE 4)
1. **xfsaild stale-flush onto a reused daddr** (P35E-DIRWR names, BFFA37B1): lost `node2_f46..f50.md5`; daddr 8372976 got a ~130ms burst of ~30 writes ALL `comm=xfsaild/sda` on TEST1 with a sliding/SHRINKING name window (nent 15→1) = test1's `rm -rf` of a PRIOR iter (removename relogs+each shrink pushed by xfsaild). Current iter REUSES daddr 8372976; test1's lingering AIL backlog of stale shrinking images flushed OVER the fresh current dir → durable loss. LOCAL (single-node test1) bug exposed by daddr reuse. Proposed fix: `xfs_trans_binval`/`xfs_buf_stale` the dir data+leaf blocks on free/realloc so xfsaild can't flush stale content (upstream XFS_BLI_STALE cancel). [[sess16-ROOT-xfsaild-stale-flush-reused-daddr]]
2. **FORMAT DIVERGENCE sf-vs-block** (P16-RELEASE, 03A6D084): the two nodes DISAGREE on ino 131's on-disk format. test1 P16-RELEASE-DUMP `fmt=1` (LOCAL/shortform, dirents inline in dinode, dir_gen=2,3 fresh) while test2 `fmt=2` (EXTENTS/block, dir_gen=225,241 recycled, data block daddr 2093304 undest=0). Mechanism: test2 converted dir sf→block; test1's in-core dinode is STALE shortform, never re-read the conversion; test1 adds an entry → RMW on stale inline dinode → writes a SHORTFORM dinode over test2's block dinode → entries durably lost. This is INODE/dinode coherency on EX acquire, NOT the dir-data-block drain. The earlier xfsaild trace was a coincidental prior-iter rm drain. Existing machinery `i_dlm_dir_loaded_gen` (xfs_inode.h:136, sess94) and `i_dlm_dir_evicted_incarn` (sess104) NOT firing for this reuse case. [[sess16-FORMAT-DIVERGENCE-shortform-vs-block]]
3. **GPT-5.5 consult (RULE 5) confirmed** (demote-drain by lock ownership): the sess97 release fence discovers blocks to drain by WALKING THE CURRENT DIR FORMAT (`mxfs_dir_data_durable`/`mxfs_dir_flush_data_blocks` for_each_xfs_iext over i_df) — fundamentally INCOMPLETE: misses shortform-inline dinode (walk lands nothing, returns true vacuously), mid-conversion blocks, block→sf freed-but-cached blocks, reused/freed daddrs. A committed-unwritten block (in_ail=1,dirty=0,pin=0,undestaged [logged_seq!=written_seq],buf_incarn==cur_gen) SURVIVES EX handoff → peer modifies → this node's stale copy is RMW base → durable lost update. **INVARIANT to codify**: no metadata buffer protected by a DLM resource may remain dirty/pinned/delwri/in-AIL-undestaged capable of later home writeback when that resource is released/demoted. MXFS has NO peer-visible CIL/AIL replay → home-write-before-unlock is MANDATORY. [[sess16-gpt-architecture-demote-drain-by-lock-ownership]]
4. **Release fence is EXONERATED** (P16-RELEASE-UNDESTAGED, 895603D7): dumps EVERY dir data-fork buffer at the EX release fence just before unlock — on BOTH nodes for ino 131, EVERY block undest=0, in_ail=0, lseq==wseq (daddr=472 lseq=wseq=467; daddr=1888 223/223; daddr=2093320 191/191). The on-disk dir IS consistent at release. wseq=0 appears only MID-TENURE at the modify-path evict (P-EVICT-SKIP, `mxfs_dir_evict_data_blocks`): the acquirer's OWN current-incarnation committed-unwritten fresh block (wseq resets to 0 on buffer realloc); evict correctly KEEPS it. So loss is a MID-TENURE concurrent-create issue, NOT a release-handoff durability gap → REFUTES the release-drain-gap framing. Pivots focus to ACQUIRE-side reread coherency (does acquirer FUA-reread the durable block, or serve stale cached buffer?). [[sess16-REFUTES-release-drain-gap-blocks-durable-at-release]]
5. **DECISIVE gen-differs-by-one = inode-reuse ABA** (enriched P62, 171D846C): losing node test2 P62-RELOAD-FORK-SHRINK `ino=131 incore_fmt=2 incore_nx=3 incore_size=8192 disk_fmt=1 disk_nx=0 disk_size=22 shrink=1 incore_gen=2276945648 disk_gen=2276945649 post_release=1`. incore_gen vs disk_gen differ by EXACTLY 1 (XFS bumps di_gen +1 per reallocation): in-core = PREV incarnation (gen 648, block, prior iter's grown dir); on-disk = NEW incarnation (gen 649, empty shortform). This particular P62 (post_release=1) ADOPTING gen 649 is CORRECT (the incarnation switch, a RED HERRING for the loss). The 5 lost entries belong to the NEW incarnation (gen 649==649) = a SAME-incarnation concurrent-create clobber AFTER the switch. So BOTH mechanisms exist: cross-incarnation cache lingering (648 vs 649) AND same-incarnation concurrent-create races; reuse supplies fresh-shortform-restart timing each iter. [[sess16-DECISIVE-gen-differs-by-one-reuse-aba]]

## Final refined HEAD root
crash_consistency durable loss = **dir DATA/leaf-block concurrent-RMW lost-update on the SAME inode incarnation** (P36-DINO-WR: both nodes' FINAL dinode writes for ino 131 are block fmt=2 nx=3 size=8192 — dinode resolves CORRECTLY to block; the 5 lost md5 entries live in a dir data/leaf block dropped by a concurrent RMW from a stale base). `mxfs_dir_evict_data_blocks` (~2043) SKIPS an in-AIL undestaged data block (keep-guard) → RMW reads a stale base missing the peer's entries → durable drop; the acquirer's OWN block is in-AIL undestaged from its prior tenure (drain/BLI-lifecycle gap). [[sess16-HEAD-status]]

## THE FIX (the only sound path — GPT demote-drain)
On dir EX RELEASE, drain by LOCK OWNERSHIP (not current-format walk): per-dir-DLM-lock registry of every buffer dirtied under that EX tenure (hook `xfs_trans_log_buf` for dir data/leaf/free/node + `xfs_trans_log_inode` for the dir inode's shortform dirents + dir-block init + stale/free paths). On BAST/demote WHILE STILL HOLDING EX: (1) quiesce new dir txns + wait active==0; (2) `xfs_log_force` SYNC + wait unpin; (3) synchronously `xfs_bwrite` EVERY protected buffer where logged_seq!=written_seq (NOT just XFS_LI_DIRTY — the bad state is dirty=0,in_ail=1,undestaged=true); (4) wait I/O + `blkdev_issue_flush`/FUA so home block is visible on LUN before unlock COMPLETES; (5) invalidate/drop buffers; (6) THEN dlm_unlock. ASSERT before unlock: logged_seq==written_seq && !dirty && !delwri && !pin && !(in_ail&&undestaged) else withdraw/shutdown. Write data/leaf BEFORE the dinode. On EX ACQUIRE (gen advanced/peer modified): invalidate old-gen cached dir blocks + reread from LUN; an old-gen in_ail+undestaged buffer at acquire = FATAL coherency violation. Strengthen the existing sess97 fence (`xfs_mxfs_dlm.c` ~3758/~3868) to cover ALL dir blocks (data+leaf+free+node+sf-inline dinode) by lock ownership. [[sess16-gpt-architecture-demote-drain-by-lock-ownership]] [[sess16-HEAD-status]]

## Secondary fix leads (subordinate to demote-drain)
- **Format-blind self-skip gate** — `mxfs_dlm_reload_inode` (`xfs/xfs_mxfs_dlm.c`:5042) self-skip block ~5213 `if (!mxfs_dir_disk_superset && (in_ail||dirty||ili_fields||pin)) { i_dlm_stale=false; return; }` is FORMAT-BLIND: `dip` (decl 5049) is not assigned until AFTER the gate (post-5284 buffer read). Decision is purely gen-based; under reuse `peer_modified_since_load` (~5189, `i_dlm_dir_gen > i_dlm_dir_loaded_gen`) is a FALSE NEGATIVE → test1 keeps its stale SHORTFORM while test2 grew the dir to BLOCK on disk → test1 writes shortform dinode → downgrade → loss; test2 then adopts shortform (P62 shrink=1) → oscillation. Fix: make self-skip DISK-FORMAT-AWARE + FORMAT MONOTONICITY (adopt disk upgrade sf→block as strict superset, re-apply in-flight adds via extended `merge_ours` ~5935; refuse non-post_release downgrades; preserve sess8 resurrection guard for committed-not-durable deletes). [[sess16-NEXT-FIX-format-blind-selfskip-gate]]
- **Self-skip needs a FRESH read, not a peek** — a disk di_format peek before the self-skip won't work: `xfs_imap_to_bp` returns the CACHED cluster buffer (XBF_DONE) which IS the stale shortform. Real disk image only at ~5328 (dip 5337), AFTER buffer invalidation ~5284 (clear XBF_DONE), both AFTER the self-skip return ~5273. TCP/SCST has NO FUA (plain-read fallback) so a fresh read REQUIRES invalidating first. Correct fix = RESTRUCTURE `mxfs_dlm_reload_inode` so invalidate+fresh-read happen BEFORE the self-skip decision, preserving the P91-RELOAD-PROTECT `mxfs_buf_has_uncheckpointed_mods` guard (~5302). Most regression-prone function (sess8/36/49/58/59/87/91 fixes layered here). [[sess16-NEXT-FIX-refinement-selfskip-needs-fresh-read]]
- **sf→block upgrade-adoption (partial, reverted)** — build 3BE73553 added `disk_dir_block_upgrade` (fresh plain-bdev dinode read; adopt peer's block if in-core LOCAL but fresh-disk EXTENTS/BTREE — gen-independent peer-modified signal). Result: clean iters 1–12 (baseline failed iter2), loss 4–100→2 entries, onset iter2→13 — so sf↔block oscillation IS real and adopting helps. BUT introduced `xfs_dir3_block_read` metadata corruption at 0x1f0 (daddr 496). KEY INSIGHT: adopting a block-format dinode is UNSAFE when the converted DATA BLOCK is not yet durable on the LUN. Both defects must be fixed together AND conversion's data block + dinode must be durable together before any handoff/adoption. Reverted (rare corruption worse than one test fail). [[sess16-PARTIAL-sfblk-upgrade-adoption-needs-datablock-durable]] [[sess16-FORMAT-DIVERGENCE-shortform-vs-block]]
- **Chokepoint dir-block skip lead** — an EXISTING guard `mxfs_buf_xfsaild_skip_bmbt_write` (sess61 P61-CHOKEPOINT-SKIP-BMBT, `pal/linux/xfs_buf.c`:1715) already suppresses a stale prior-tenure BMBT-LEAF xfsaild write at the bio-submit chokepoint when the dir's per-inode DLM grant went EX→NL. Scoped to BMBT-leaf ONLY, not dir DATA/leaf-DIRENT blocks (b_ops = xfs_dir3_{data,block,leaf1,leafn}_buf_ops). Lead: extend it (or sibling `mxfs_buf_xfsaild_skip_dir_write`) to suppress an xfsaild dir data/leaf write when the owning dir inode's i_dlm_mode is NL-released (owner ino from dir3 block header, `mxfs_dir_data_buf_owner_mismatch` already extracts it). Instrument P16-DIRBLK-STALE-SUBMIT first. [[sess16-FIX-LEAD-extend-chokepoint-skip-to-dir-dirent-blocks]]
- **Lingering-BLI xfsaild reflush hypothesis** — dir blocks recur as `li_empty=1 (list_empty b_li_list) AND in_ail=1 AND bip!=NULL`: transitional/lingering state where buffer-write removed the item from the buffer list but AIL removal didn't happen (or relog re-added). Such a buffer can be re-pushed by xfsaild, writing stale-vs-peer content. Proposed detector P16-REFLUSH-CLOBBER (per-daddr max name-set; a write dropping a previously-durable name → clobber, if comm=xfsaild CONFIRMED). Fix = on release fence write-completion, properly RETIRE the BLI from the AIL (xfs_buf_item lifecycle) — NOT a blunt XBF_DONE clear (proven to corrupt). [[sess16-NEXT-xfsaild-reflush-lingering-bli-hypothesis]]

Keep-guard MUST keep them. [[sess16-ROOT-xfsaild-stale-flush-reused-daddr]] [[sess16-HEAD-status]] [[sess16-stale-tenure-keepguard-fix]]
