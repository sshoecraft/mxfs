## Compiled: sess54–58 — coresident cluster-flush dirent resurrection + create/remove AG↔dir ABBA deadlock

Ship criterion: **`2 node dlm=tcp` suite 17/17, reliably (≥6–8 consecutive clean-reboot runs)**. The failing test throughout was `tcp_dlm_scaling` (== `dlm_fairness` == the `repro_rename_drain` workload): each of 2 nodes does create→mv→rm of `n${R}_r${i}` in ONE shared dir, 150 rounds within 60s, then node1 asserts the dir drained to 0. **MET in sess58 at build `60EFBE5E23421FC56645074` — 17/17 across 8 consecutive fresh-reboot runs (100%).** Two independent root causes had to be fixed: (A) a durable **dirent resurrection** and (B) a create↔remove **AG↔dir ABBA deadlock**.

### The central bug (A): 4KB-cluster write granularity vs per-inode DLM authority
PROVEN sess54 ([[sess54-ROOT-coresident-cluster-flush-stale-buffer-resurrection]]), re-confirmed every session after. DLM write authority is **per-inode** (NL/PR/EX), but the physical write is the **whole 4KB inode cluster**. A shortform dir's dirents are inline in its dinode, which co-resides in a 4KB cluster with 7 other churned inodes. Flushing inode X's cluster rewrites co-resident dir Y's on-disk dinode even when Y is held PR/NL — writing back **stale cached bytes** (the pre-removal image) → durable RESURRECTION of a removed dirent, seen by both nodes, survives drop_caches. Always one node's OWN removal (rm or mv-source) is lost, on the last hot-dir test. NOT the 3-way shortform merge (P-SFMERGE=0, P-SFM-READD=0 with sfm_dbg=1 — sess53's EX-gate+clean-adopt already suppressed merges).

GPT-5.5 (RULE-5 consult, [[sess54-gpt-coresident-cluster-flush-design]]) diagnosed authority-granularity ≠ write-granularity as the architectural root and ranked fixes: (1) **ICLUSTER DLM lock** — a per-4KB-cluster EX resource `ICLUSTER:<uuid>:<agno>:<cluster_start_agino>`; for every full-cluster write acquire EX → destage+read FRESH 4KB → overlay ONLY authoritative inodes (EX / RELFLUSH-current-tenure) → write → release; (2) target-only durable flush (no co-flush of arbitrary co-residents); (3) systematic EX `dirty_holders` pin not tied to ILOCK lifetime; (4) classified P119 handling (never silent-discard a LIVE inode); (5) DLM `dirty_epoch` for ownership, not di_gen (di_gen equality is only a same-incarnation test).

### The three interlocking reconciliation faces (why piecemeal `in_ail` guards can't converge)
A committed shortform-dir removal must survive THREE in-core-vs-disk reconciliation points, all of which prefer stale disk for a non-EX inode ([[sess55-CONCLUSION-icluster-lock-is-the-only-convergent-fix]], re-verified [[sess57-durable-verify-flawed-resurrection-is-deep-interlock-need-icluster]]):
1. **P119 (`xfs_iflush`, xfs_inode.c:4710/~4636)** — discards a non-EX dirty inode (`error=0; goto flush_out` marks clean w/o copying in-core; removed from AIL on iodone = LOSS).
2. **`mxfs_iflush_cluster_merge_dirs` (xfs_inode.c ~5508/5510)** — `memcpy(dbuf, ddisk)` overlays disk onto a co-resident dir slot = RESURRECTION.
3. **EX-reacquire RELOAD (`xfs_inode_from_disk`, xfs_mxfs_dlm.c:7813)** — adopts FUA-fresh disk unconditionally (does NOT check in_ail) = REVERT.

"Buffer behind disk" is AMBIGUOUS: either our committed removal (keep buffer) OR a peer's add we're stale on (adopt disk) — count/in_ail alone can't disambiguate, so no single guard closes it. Fixing P119 just moves the loss to face (2) or (3). GPT's convergent answer was the ICLUSTER lock (makes disk always coherent → adopt-disk always correct → all faces close). **Ultimately the ICLUSTER lock was NOT implemented** — sess56/58 found cheaper root fixes.

### The two sess58 root fixes that MET the criterion (build `60EFBE5E`) — both in xfs/xfs_inode.c
The ICLUSTER lock was NEVER needed. sess58 found the two actual roots ([[sess58-CRITERION-MET-2tcp-17of17-8consecutive]]):

**(B) create↔remove AG↔dir ABBA deadlock** ([[sess58-FIX-create-remove-AG-dir-ABBA-deadlock]], build `456774D1`) — this was the tcp_dlm_scaling within-60s-window + shutdown failure (a LIVELOCK: poll/retry, interruptible sleep, threads NOT D-state, sysrq-w/-t show nothing). Captured cycle: test1 `P36-RETRY ino=0 type=3` (blocked on AG-0 EX, holds dir-132 EX); test2 `P36-RETRY ino=132 type=1` (blocked on dir-132 EX, holds AG-0 via a create's `xfs_dialloc`, `P58-AGSTATE ag=0 holders=1`). ~60s P36 storm → -ETIMEDOUT → dirty `xfs_trans_cancel:1061` "Corruption of in-memory data (0x8)" SHUTDOWN. Lock orders: xfs_create = `xfs_dialloc`(1421) before dp ILOCK(1430) = **AG→dir** (v0.3.148 drop-ILOCK-across-dialloc); xfs_rename = `mxfs_trans_preacquire_inode_ags`(4104) before `xfs_lock_inodes`(4116) = **AG→dir** (sess77); xfs_remove = `xfs_trans_alloc_dir` takes dp ILOCK(3676) before iunlink AG in `xfs_dir_remove_child`(3727) = **dir→AG — THE LONE OUTLIER**. FIX: xfs_remove pre-acquires the child inode's AG DLM grant via standalone `mxfs_ag_dlm_lock(mp, child_ag)` BEFORE `xfs_trans_alloc_dir`; release via standalone `mxfs_ag_dlm_unlock` on success (after commit + dir-durable flush) and at `out_parent` (all error paths). Mirrors the `xfs_inactive_ifree` standalone-AG pattern (~2507/2666). Now all three ops are AG→dir → serialize on the AG, no ABBA. Verified `repro_rename_drain 150 8` → 4/4 drained clean, P36=0, shutdown=0, P58-DIRPIN-NONEX=0 (was ~50% deadlock). Also proved P58-DIRPIN-NONEX at NL was a deadlock-TEARDOWN artifact, not a separate resurrection bug.

**(A) resurrection root = `xfs_ilock_nowait` skips the DLM grant for ILOCK** ([[sess58-FIX-resurrection-lock-two-inodes-nowait-skips-dlm]], build `1686FC03`). PROVEN by P58-DIRPIN-NONEX (added at `xfs_inode_item_pin`, xfs_inode_item.c) + dump_stack: `xfs_inode_item_pin ← xfs_trans_commit ← xfs_remove` — a dir pinned/committed at dlm_mode=NL(0)/PR(3), ex_h=0. `xfs_lock_two_inodes` (remove/link, xfs_inode.c:619) and `xfs_lock_inodes` (rename) lock the AIL-contended inode via `xfs_ilock_nowait`, which for ILOCK acquires ONLY the rwsem, NOT the DLM grant (the DLM acquire is gated on `XFS_IOLOCK_*` only — the atomic xfsaild/reclaim carve-out, xfs_inode.c:296-302). So when the parent DIR is the higher-ino inode (common under rapid create/rm inode reuse) and the lower-ino child is in the AIL, the dir gets modified+committed at its STALE cached DLM mode with NO exclusive authority → flush-skipped (P119-NONEX in_ail=1) → overlaid (P-CLMERGE) → peer reads stale → dirent resurrects (TDS-LEFTOVER). Intermittent because it depends on dir-vs-child ino ordering + ip0-in-AIL. FIX: in BOTH `xfs_lock_two_inodes` (~650) and `xfs_lock_inodes` (~585), when the nowait-locked inode is a DIRECTORY (`S_ISDIR`), acquire its DLM grant via `mxfs_dlm_ilock_begin` before the nowait rwsem lock (released on the drop-and-retry path; balanced by the caller's `xfs_iunlock` → `mxfs_dlm_ilock_end`). Safe: process context always, ascending ino (no DLM ABBA), inode-DLM release drains only ip1 (no v0.3.148 AG-drain wedge). **DIR-ONLY is essential** — acquiring for files too (build `F06293AE`) went 12/17 (broad slowness + a pre-existing inobt-stale create double-alloc shutdown cascade). The remove fix alone got 2/3 (rename still leaked, comm=mv); adding the rename/lock_inodes fix → 8/8.
