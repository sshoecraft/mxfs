# sess22 — dir_reuse_coherency clean-slate blocker: torn shortform flush, daddr-0x78 double-alloc, stale in-core inode/bmap

Central topic: the sess22 (ccloop 8ddb16a2) investigation of why the `dir_reuse_coherency` test shuts the FS down on a **clean-slate 2-node dlm=tcp** run. The test churns dir ino 131 (`.dir_reuse_coherency`, parent=root 128) via round-1 rm-rf teardown → round-2 mkdir REUSE, plus `dd if=/dev/urandom of=node*_f*` file writes. dir_reuse_coherency is a **deterministic proxy** for the real ship criterion — "2 node dlm=tcp 100% successful" = the full `./run.sh 2 tcp` suite (16 tests); best result was 13 PASS / 3 FAIL (build AFC07F4D, ~2d prior) but VARIABLE (a re-run gave 9/16), and the variance itself is the blocker. See [[sess22-CONSOLIDATED-criteria-is-full-suite-root-is-stale-inode-bmap]].

## The corruption chain on ino-131 reuse (round-1 teardown / round-2 mkdir)
Round 1 PASSES; FS shuts down in the reuse window. During rm-rf, dir ino 131 down-converts leaf→block→shortform. Three corruptions share the window ([[sess22-progress-two-fixes-and-reuse-corruption-chain]]):
1. **Torn in-core shortform fork** — xfsaild flushes count=1 but the single entry has namelen=0 (`01 00 00 00 00 80 00 ...`, hdr count=1 i8count=0 parent=128, entry[0].namelen=0 INVALID). `xfs_ifork_verify_local_data`→`xfs_dir2_sf_verify` fails (xfs_inode.c:4355) → `xfs_force_shutdown(SHUTDOWN_CORRUPT_INCORE)` at `xfs_iflush_cluster` (xfs_inode.c:5209), dmesg `P9-ICD-FAIL ino=131 last_rerr=-117` (-EFSCORRUPTED). The in-core if_format FLIPS between EXTENTS (P78-FMT-TORN-FIX storm, nx=3, ili_fields=0x1 CORE-only) and LOCAL (sf_verify fail) across flushes = reuse race.
2. **Bad-CRC on-disk dir DATA block at daddr 0x78** (ino 131 data block 0) — `Metadata CRC error (error 74 EFSBADCRC) at xfs_dir3_data_read_verify`. PRE-EXISTING; FIX1 unmasked it by letting the FS limp past the torn-SF shutdown.
3. **Leaf-hash hole** — deterministic missing entry (node2_f50.md5, the LAST entry, every round); FIX2 targets it.

Reload path in the reuse window: rm wants EX on ino 131 → `DLM inode lock failed: ino=131 mode=5 rc=-35` (-EDEADLK, P109 conversion-deadlock prevention) → ilock hook (xfs_mxfs_dlm.c ~8435) releases via BAST drain + reacquires from NL → reacquire RELOADs ino 131 (`mxfs_dlm_reload_inode`: P62-RELOAD-FORK-SHRINK post_release=1, P34D-RELOAD-FRESHSRC src=plain, P91-RELOAD-PROTECT) adopting a mid-reuse-inconsistent disk image → torn SF and/or bad data block.

## The two competing root theories (chronological within sess22)

### Theory A — daddr 0x78 is AG free-space DOUBLE-ALLOCATION ([[sess22-DECISIVE-daddr-doublealloc-dirblock-vs-filedata]])
The `First 128 bytes of corrupted metadata buffer` for daddr 0x78 is HIGH-ENTROPY RANDOM (`d2 d8 0e 56 54 45 89 7c 4c 31 ...`) = `/dev/urandom` FILE DATA, NOT a dir data block (no XDD3 magic), NOT an inode cluster, NOT zeros. => daddr 0x78 was handed to BOTH ino 131's dir data block 0 AND a regular file's data block; the file's urandom write clobbered the dir block → CRC verifier fail → shutdown. Mechanism: under concurrent 2-node rm-rf (frees) + create (allocs), AG free-space metadata (bnobt/cntbt/AGF) is not coherent at allocation time, so a stale AG view lets a node hand out an already-allocated/just-freed-elsewhere block despite AG-DLM serialization + drain. This is the long-standing AG free-space double-alloc family (sess24/39/42/43/44/46/47). Where to look: xfs/libxfs/xfs_alloc.c, xfs/xfs_mxfs_dlm.c AG-DLM acquire/release + AG-meta drain (bast_work_fn, drain_alloc_buflist, pag_mxfs_alloc_buflist, b_mxfs_ag_gen, pag_dlm_meta_gen), xfs/xfs_buf.c AGF/bnobt FUA read. Watch for regression of proven fixes: sess42 `C6970FF9` (only advance b_mxfs_ag_gen when genuinely fresh), sess43 `BB54A138` (in-AIL AG-meta must not be discarded), sess47 `29977E5D` (stale cached inode inactivation FUA-check).

### Theory B — CONSOLIDATED: root is cross-node stale in-core INODE / stale in-core BMAP, NOT allocator double-alloc ([[sess22-CONSOLIDATED-criteria-is-full-suite-root-is-stale-inode-bmap]])
Later consolidation supersedes Theory A's allocator framing with live RULE-4 detectors on the 4F45F442 run:
- `P81-DEXT ... disk_claims_freed=0 verdict=DISK-INODE-DIFFERS=>incore-extent-stale` → in-core BMAP is stale, bnobt is CORRECT (no real on-disk double-free).
- `P47-INACT ino=18876321 incore_gen=4258309808 disk_di_gen=4258309809 disk_di_mode=00 verdict=DISK-FREE=>B-stale/double-free` → in-core inode is ONE generation behind disk (freed+reincarnated on disk), held stale-live in-core with a stale extent map.
Corroborated by sess111 (Gemini #2 DEBUNKED the bnobt/AG-meta path as a red herring — async-writeback/SCST-destage lag mis-read as corruption) and sess55 (P55 alloc-over-inode detectors fired 0× — allocator never double-hands a block). Conclusion: **NOT allocator/bnobt double-alloc, NOT AG-data-block partitioning, NOT a dir-format bug** — it is inode-recycle / cross-node inode-cache coherency (sess40/48/108/111 lineage). The daddr-0x78 symptom is a node reading dir ino 131's data block via a STALE bmap entry that resolves to a reused daddr now holding file data.

Residual hole: existing guards catch the destructive INACTIVATION free (xfs_inode.c:2208-2289 nlink==0 takes per-inode DLM EX, FUA-reads disk di_mode/di_gen, skips B1 disk-free / B2 gen-mismatch → INACT-SKIP-STALE fires, e.g. ino 1959), but the stale in-core BMAP is still USED for block resolution/read, OR a non-inactivation free (truncate/bmap_del), OR a DISK-LIVE-same-gen A-lost-removal. The reused/reloaded inode's extent map is not invalidated when its disk incarnation advanced.

### Theory B refined — the strongest concrete fix hypothesis ([[sess22-HYP-p91-keeps-stale-inode-buffer-via-crude-bli-heuristic]])
`mxfs_buf_has_uncheckpointed_mods(bp)` (xfs/xfs_mxfs_dlm.c, the P91-RELOAD-PROTECT gate, at xfs_mxfs_dlm.c:5878 in mxfs_dlm_reload_inode AND xfs_icache.c:427/1239) returns **true** whenever pinned, OR `!list_empty(&bp->b_li_list)`, OR a BLI is attached AT ALL, OR `_XBF_DELWRI_Q`. This is the exact contradiction sess120 documented for AG-meta buffers, now hitting the INODE cluster buffer: the BLI-attached flag cannot distinguish (A) drained pre-yield, content ON disk, BLI merely lingering in the AIL until next checkpoint (safe to adopt disk) from (B) un-destaged, content NOT on disk (must keep in-core). It conservatively returns true for BOTH → reload KEEPS the in-core cluster buffer (kept_protected=true; no xfs_buf_stale, no XBF_DONE clear), never adopts the coherent on-disk dinode. If the kept in-core inode is a stale incarnation (prior life's bmap, lingering BLI), the reload no-ops, the stale bmap survives → block-resolve reads reused daddr 0x78 → file data → EFSBADCRC. Matches P47/P81 (in-core gen one behind disk).

Fix direction (subtle, HIGH-RISK — verify before shipping): sess120 already built the correct AG-meta discriminator (li_lsn vs write-verifier-stamped payload_lsn: pinned→un-destaged keep; in-AIL && li_lsn>payload_lsn→modified-since-write keep; else drained→adopt). The INODE path needs the analogous discriminator: when the in-core cluster buffer only has a LINGERING BLI (drained, on disk) AND a coherent PLAIN-bio read of the on-disk dinode shows an advanced di_gen vs in-core i_generation, ADOPT disk (in-core is a stale ghost). MUST NOT regress a genuinely un-destaged same-EX-tenure dirty inode (real uncommitted work) — that must still be KEPT or lost-update returns. RULE-4 instrument first: at the P91-keep site for a DIR, plain-bio read on-disk di_gen and log when it differs from in-core i_generation while P91 keeps → proves the hole. (A workflow wf_4035945c-2a0 / wdur6o86j was adversarially analyzing this reload-reset path + 3 others; cross-check its candidate against this hypothesis.)

## Fixes landed in tree (build 4F45F442) — DEFENSIVE, symptom-level, KEEP unless they complicate root work
- **FIX1 torn-shortform flush skip** — xfs/xfs_inode.c `xfs_iflush`, the `xfs_ifork_verify_local_data` fail branch (~4355): for a multi-node DIR, on shortform verify-fail do NOT `xfs_force_shutdown(CORRUPT_INCORE)` — set error=0, mark XFS_ISTALE_CAW, `goto flush_out` (skip cleanly + cold-reload), like the P119/P17B skips at xfs_inode.c:4426/4470. Detector `P22-SFTORN-SKIP`. PROVEN to fire: caught a torn SF flush (`comm=rm dlm_mode=EX dirty_seq==ex_grant_seq if_bytes=22 hdr=[01 01 00 ...]` = count=1 i8count=1 garbage) and prevented the shutdown. Never writes a known-invalid shortform to the shared LUN; authoritative image is re-read. Verify flush_out releases the AIL item (no xfsaild storm).
- **FIX2 authoritative data-scan lookup fallback** — xfs/libxfs/xfs_dir2_leaf.c: new `mxfs_dir2_datascan_lookup()` hooked in `xfs_dir2_leaf_lookup`; on hash-lookup ENOENT for a multi-node dir, linearly scan the AUTHORITATIVE coherent data blocks (returns xfs_dir_cilookup_result => -EEXIST→0). Detector `P22-DATASCAN-HIT`. Targets the deterministic leaf-hash hole (node2_f50.md5, last entry). Only runs on ENOENT (no hot-path cost). NOTE: because it reads data blocks on lookup-miss it reaches the bad-CRC daddr-0x78 block FAST — it EXPOSES the real corruption, does not cause or mask it. Could be reverted if it complicates root work.

## Recurring failure modes / gotchas
- **Warm vs cold cluster diverge.** force_reset (rmmod) hides the real bug; ALWAYS full virsh reboot: `bash tests/reboot_cluster.sh 2` then `MXFS_TEST_ENV="DRC_ROUNDS=15" timeout 460 ./run.sh 2 tcp dir_reuse_coherency` (round 2 shuts down). run.sh prep does mkfs; needs device unmounted (tests/force_reset.sh handles a leftover mount).
- **run.sh "PASS" summary can disagree with per-node `RESULT: FAIL`.** Trust per-node RESULT lines + dmesg, not the run.sh summary.
- **LIO target = no SCSI PR, rejects CAW, drops FUA** → FS often EIO-wedged at suite end; reboot to recover.
- FUA reads the stale platter; the coherent copy is the SCST write-back cache via plain bio.
