Topic: death, fence and authority-lease laps (and the recovery/wait code under them) that pass or fail without measuring the thing they were written for. Mostly harness-measurement traps, plus two code traps and two techniques. Group is a topic cluster, not assorted.

## A lap that needs a declared death must not let the victim withdraw itself

- `tests/multi_victim_containment.sh` with `VICTIM_EVICT=1` pins each victim's log tail (`dbg_ail_pin_ino`). About 23 s after cluster formation the victim cannot finish a no-inode release (`P-NOINO-DRAIN-STUCK`), shuts its own filesystem down, survivors see `P163-WITHDRAW-SEEN` and recover it at once. The later power cut kills an already-recovered node: `dead_lines=0`, no prover, no lease race. Laps meant to exercise a refused replay (queue r34c) measured nothing. Rule: a lap needing a node DECLARED DEAD (62 s silent window, fence prover, replayer lease request) runs plain load on its victims; use the exerciser only when the subject is the victim's unreplayed log window. Check `withdraw_stamp=` on the victim line and `dead_lines=` on survivors before reading a lap; withdraw_stamp=1 with dead_lines=0 means no death. Same laps: the harness computed load end as `LOAD_S + VICTIM_GAP * NV + 30` but unmounted at `last kill + LOAD_S + 25`, so a long gap left load running at unmount (`umount rc=32`) and read its error count early; it now stops the load, waits, then judges. [[trap-the-eviction-exerciser-victims-withdraw-themselves-so-a-lap-that-needs-a-declared-death-measures-nothing]]
- Generalisation: when the stimulus that makes the victim's clock observable is also an input to the peer's detector, the lap measures the cooperative path. `tests/authority_handoff_phase.sh` ran a 2 Hz writer so the gate would be called; the closure withdrew the mount (`P290-AUTH-WITHDRAW`), stamped the slot WITHDRAWN, and the peer fired on `P163-WITHDRAW-SEEN` one monitor pass later. Measured margins of 0.9-1.6 s against an expected 30 s were causally non-negative, and "heartbeat expired after 14 checks" was an equal-sample count, not a threshold (`dead_threshold` was 31). A session wasted a step suspecting a wrong constant. Removing the writer did not help: the PR worker tick asks the gate every 250 ms, so an idle live node closes on time and withdraws. A live node always takes the cooperative path; only a node that cannot run its own tick presents the silent path. To produce silence hold the CONVERSION, not the closure: `dbg_auth_withdraw_pause_ms` (0.89.66) keeps the lease evaluated and withholds the withdrawal pump; `dbg_auth_pump_pause_ms` holds both and nothing closes. Print the detector's window fields on the death line (`threshold= last_stamp_ms= last_seen_ms= now_ms=`) and classify `path=withdrawn|certificate|epoch|silent`. A margin on a causal chain proves nothing about the boundary. [[trap-a-stimulus-that-provokes-the-victims-own-withdrawal-measures-the-cooperative-handoff-not-the-silent-window]]
- The earlier s126 belief (idle mount keeps ADMITTED past the deadline because only `mxfs_authority_ok` converts expiry and nothing periodic calls it) is superseded: the periodic tick now closes an idle lease (`dlm/v5_mount.c`). Still true: `MXFS_AUTH_NOT_ADMITTED` returns true (no beat landed yet admits writes). Constants: lease 30000 ms, heartbeat interval 2000 ms, dead threshold 31. [[trap-an-idle-mounts-authority-lease-does-not-expire-until-something-calls-the-gate]]

## Harness assertions and evidence capture

- A fix that adds an expected signal breaks "nothing happened" assertions (`tests/fence_late_detection.sh`: "B noticed nothing", "zero shutdown/BUG/Oops"). The local authority lease makes the victim notice and withdraw, failing both on a healthy lap. Do not relax them; split by cause. `DETECT` keeps every LUN-dependent detector and excludes the new one by reason string, not line name (it reuses `P131-SELF-FENCE`, so `grep -v` on the name hides the old detectors); add a positive assertion that the local one fired with the expected reason. Shutdown count excludes exactly one call site, the cluster-withdrawal entry point. Add a control: run the identical write probe on a healthy node first, before injection, and require success. [[trap-a-fix-that-adds-an-expected-signal-breaks-the-harnesss-nothing-happened-assertions-and-they-must-be-split-by-cause-not-relaxed]]
- A chatty transport's journal rotates out the death window (0.90.25, 8/cawd, `tests/multi_victim_containment.sh`). `RuntimeMaxUse=400M` with ~1,200 lines/s of probes left only T0+267..+364 s (116,184 lines); death/fence/replay at +60-90 s were gone, harness counted `P163-RECOVERY-COMPLETE` as 0 of 2. TCP kept the whole window. Before trusting any journal count, print the first line's time for the requested window. Start a filtered follower per node at T0 (`journalctl -kf | grep --line-buffered -E ... >> file`) and save node logs into the evidence dir at collection. A zero from a rotated journal is a capture failure, never "did not happen". [[trap-a-chatty-transports-journal-rotates-out-the-death-window-before-a-harness-reads-it-at-the-end]]
- `mountpoint -q` on a withdrawn MXFS mount stats the path, gets EIO and reports "not a mountpoint"; prep skips the unmount and `mkdir -p` fails (two freeze-test laps died in setup, looking like a node that could not rejoin). Detect with `grep -q " $MNT mxfs " /proc/mounts`, unmount with `timeout 30 umount`, and kill any writer by recorded PID first (it holds the withdrawn mount busy). `tests/tcp_peer_freeze_death.sh` does this. [[trap-mountpoint-calls-a-withdrawn-mxfs-mount-unmounted-because-stat-returns-eio]]
- Banked lap evidence expires when a change withdraws the mechanism the laps depended on. `D-FENCE-CRASH-MATRIX-UNTESTED` carried "12/12 laps PASS" measured on 0.89.10; 0.89.16 withdrew the deployment clause that supplied a RETIREMENT basis for an absent victim registration, and cut 1 fails on 0.89.19 (`P238-BOOTSUCC-NO-RETIRE-BASIS`, `P238-GATE-NO-RETIRE-BASIS`, `obs=no-mxfs-successor-observed`; mounts return 32). A version string does not say what the lap depended on. When a change withdraws or revokes a mechanism, sweep the ledger for entries whose banked evidence ran through it and mark them for re-measurement in the same version. Ask "could any banked lap only have passed because the withdrawn path existed?". Also check whether a record's whole queue sits behind a record classified non-blocking before planning its next step; here every cut destroys the prover and purges its registration, making the remaining matrix unrunnable until a retirement route exists. [[trap-banked-lap-evidence-stops-describing-the-build-when-an-intervening-change-withdraws-the-mechanism-the-lap-depended-on]]

## Death-lap design: in-flight state, tail pin, timing anchors

- Death laps must kill with core changes IN FLIGHT and end with a cold structural check (`chk_mxfs`). Earlier laps created files long before the kill, so replayed inode items read `disk_cc >= log_cc` and were skipped; only nextents/size growth or a create exposes the defect (D-0976, 2/tcp, `tests/recov_bmbt_reuse.sh`).
- Technique: to put a cleanly released tenure's image in a live replayer's window, pin the victim's log tail with `mxfs.dbg_ail_pin_ino=<ino>` (`xfs/xfs_inode_item.c`; push answers XFS_ITEM_LOCKED, `xfs_iflush_cluster` skips it so a sibling cannot flush the cluster buffer). Prints `P-AILPIN-HOLD`. Without it, invariant 1 plus the coalesced destage kick always move the tail past a released image (REDUNDANT_CLEAN=0 in s593g/h, s594a). Harness handshake in `tests/tcp_death_replay.sh` TDR_FALSE_APPLY=3: writer creates the pin file, prints PIN_INO, waits for `/root/tdr_pin.go`; harness sets the knob over ssh and touches go; writer re-dirties and fsyncs. Read `P-AILPIN-HOLD` on the victim before the kill (its dmesg dies with it). Vacuity check is the arm's REDUNDANT_CLEAN>=1, not `P-RMAN-EVAL hits` (a released resource is absent from the fence-time manifest). Never pin a node meant to survive (log exhaustion). Editing a running harness is safe only after the byte offset bash has reached. [[technique-pin-the-victims-log-tail-to-put-a-released-tenure-image-in-front-of-the-replayer]]
- Timeline anchoring: dmesg monotonic stamps do not compare with harness wall clock; fit `realns=` fields against monotonic stamps (427 lines, zero spread) and anchor the kill on the mtime of the file written at that moment (`virsh_destroy.txt`). Survivor TCP-disconnect detection of a power-cut peer took 25.28 s, which is `icsk_user_timeout=25000` in `pal/linux/kern.c`, set so TCP aborts before the 30 s DLM lock wait. It was chosen for DLM waiter wakeup, not SCSI-PR, and eats 25 of the ~32 s before the target purges the victim's registration; MXFS declares death at 63.24 s so the fence always arrives late and the proved-exclusion path (needs the victim key PRESENT at the classifying read) never fires. A constant chosen against one deadline becomes an implicit budget downstream; grep for the constant by value as well as name. [[trap-the-peer-death-detection-latency-is-our-own-socket-constant-not-tcp-behaviour-and-it-spends-the-whole-fencing-window]]

## Code traps found by those laps

- Write-authority mask with no notion of recovery (D-0976, 0.87.8, builds ABD7370F/9C04D519). A survivor's foreign replay applied 7 dinode images (`P77-FRINODE verdict=APPLY`) into its cached cluster; `mxfs_submit_partial_inode_write` saw a slot with no in-core inode and no inode log item (`P218-CLUSTER-PASSENGER nocore=1 skipped=1`), masked it, refused the write with no I/O (`P218-WRITE-REFUSED`) and completed the buffer as success (`P226-FR-HOMEFLUSH flushed home` still printed). Bmbt leaves landed, the dinode stayed at the pre-death flush, giving `P-BMBT-OVERCOUNT` and shutdown at the victim's `rm`; also the mechanism behind D-0517's 32-node `P-ALLOC-FREE-CORE`. Lessons: a publication filter keyed on live-tenure state needs an explicit recovery-ownership input (`b_mxfs_recov_slots`) tested BEFORE the free/NL/PR/no-core exclusions; a refuse-with-no-I/O branch must fail the write (`P218-RECOV-REFUSED`) when a recovery obligation is nonzero, since success completion hides the loss from home flush, IMAGES_REPLAYED and P163; a replayed image patches only logged fields, so give the slot a platter baseline once per recovery before its first patch (not after the recovery owns it, not for a slot in core); an icreate replay initialises a whole cluster, so record all initialised slots as owed or a later inode item drops the other 31. [[trap-a-write-authority-mask-with-no-notion-of-recovery-drops-every-replayed-dinode-and-a-no-io-completion-reads-as-landed]]
- `dlm_lock_impl()` tests `ctx->shutting_down`, assigned only in `mxfs_v5_dlm_shutdown_defer_release()` at unmount. The fence/lease-closure path `mxfs_v5_dlm_shutdown_withdraw()` does not set it, so a waiter blocked on a dropped request rode its 60 s budget: closed=1 shut=1 at +85 s, task gone at +157 s (72 s against a 10 s bound; `tests/evidence/20260920T175325Z_lockreqbh_s88f`). Grep for the setters of a guard flag before believing its name; a subsystem has several terminal states (going away, withdrawn, authority closed) and a loop must test the one matching its event. "Did it eventually end" proves nothing; assert on the interval from the signal that should have ended it. Ruling: `docs/rulings/terminal-authority-cancellation-in-the-acquire-machinery.md`. [[trap-a-loop-guarded-by-a-shutdown-flag-that-only-unmount-sets-ignores-a-withdrawal-and-a-forced-shutdown-alike]]

## Technique: a self-deadlocked wait is cured in the call graph

The post-reset convergence barrier waits for a heartbeat issued after a LOGICAL UNIT RESET; that establishes the stranded beat was resolved and the lease is still renewed. It deadlocked because peer death is declared from the MONITOR stage of the heartbeat loop and the whole fence ran inside that dispatch (`P278-HB-STALL stage=MONITOR`, 30241 ms vs 30000 ms lease, authority closed, survivor shut down). 0.89.34 made the wait beat for itself (`mxfs_disklock_beat_now`); that removed the proof, since the wait's value was that the heartbeat SERVICE was alive. A parked heartbeat thread could then mint a retirement certificate and replay past its lease; the injector arm flipped REFUSE to CERTIFY (8 assertions). Correct fix: move the caller, handing the death from the monitor stage to a worker (`v5_death_fence_handoff` / `v5_death_fence_drain`, `atomic_xchg` full barrier, SPSC), wait unchanged with no self-satisfying fallback so a dead heartbeat fails closed. Before self-satisfying a proof-carrying wait, state what it establishes and whether the self-issued event still does. A comment justifying a change by what it removes ("one fewer dependency on another thread's schedule") describes what the mechanism was for. [[technique-cure-a-self-deadlocked-wait-in-the-call-graph-not-in-the-wait]]
