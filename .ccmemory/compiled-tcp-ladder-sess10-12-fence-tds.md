# Compiled: TCP ladder sess10-12 — fence AG→dir ABBA, bpend-refire storm, tds SF-MHT, pin-aware release, iget-miss reload

Central thread: driving the full **4-node TCP** suite (`tests/suite_iter.sh`, ~14-17 min/iter, recycles VMs first) toward a sustained PASS streak (≥4-5 consecutive 17/17) before opening the 8/2/1-node columns. Three interlocking blocker families surfaced across sess10→11→12: (1) **durable dirent loss at EX handoff** (SF-dir + block0-conversion), (2) a **bast_pending refire storm** that throttled `dlm_scaling` and was accidentally load-bearing for `tcp_dlm_scaling` pacing, and (3) the **fence/netpartition/tds triple-FAIL** rooted in an AG-0↔dir ABBA in the remove path. All three fed each other; fence/netpartition/tds FAILs after any fence shutdown are ONE root (dead FSes cascade).

## sess10 — durable loss at EX-handoff (transport exonerated, cluster-clobber + SF/block0 provenance)

**Unified failure model** (evidence-backed across faces): **EX handoff outruns durable-to-PLATTER** (SCST write-cache vs SCSI-FUA-read asymmetry) → next holder RMWs a stale base → last-writer-wins erases peers' entries. FUA-read is treated as platter authority throughout.

- **Transport EXONERATED** ([[sess10run2-PROVEN-transport-clean-lastrel1-cluster-clobber-suspect]]): plain-write+SYNC_CACHE+same-node FUA ×100 idle = 0 miss; ×120 under 3GB cross-node storm = 0 miss; t2 writes 1500 ascending patterns +sync, t1 FUA-reads ×6000 = **0 backward**. The async SCST export (`/etc/scst.conf`: v5 LUN = vdisk_fileio disk1, `async 1 + o_direct 1`) honors flush-vs-FUA ordering. Infra is sound; the regression is a LATER WRITE carrying older bytes.
- **Cluster-clobber prime suspect**: co-resident inode-cluster clobber — parent dir + subdir/file dinodes share a 4KB cluster; a node whose buffer holds stale parent bytes writes the mosaic (xfs_iflush_cluster only re-copies owned/dirty inodes; P119 discards non-EX co-residents). Detector **P10-CLREGRESS** added (pal/linux/xfs_buf.c, gated `mxfs_dir_relverify`): on every multinode cluster write submit, FUA-read the on-disk cluster; flag DIR slots where disk di_size>buf or equal-size+disk SF-count>buf. `owned=0` hits = clobbering an unowned peer slot = the mechanism.
- **P10-CLREGRESS is a FALSE-POSITIVE detector under rm-heavy load** ([[sess10run2-BREAKTHROUGH-clregress-owned-stale-dirty-ili-livelock]]): the 1630× t1 hits (artifact `run_dlm_scaling_20260703T210920Z`, build 89321B9D) were ino 132 = node1's OWN `.dlm_scaling` dir held EX, oscillating create fN (size 18)→rm fN (size 6); buf_size=6 is the NEWER post-rm image. The size-only compare can't tell newer-smaller from stale-smaller. Do NOT chase P10-CLREGRESS without a version/seq discriminator. This corrects the initial "stale-dirty-ili livelock" read.
- **SF-dir durability lead** ([[sess10run2-iter-results-dlm-scaling-sf-durability-lead]]): dlm_scaling iter5 (artifact `run_dlm_scaling_20260703T191250Z`) — node4 mkdir ok then first `node4/f1` create = ENOENT → quota 0/2000. Parent `.dlm_scaling` ino=12583063 SHORTFORM. **P-SFDIR-REVERT** fired 21-30×/node: incore_cnt=N, disk_cnt=N-1, **fua_cnt==disk_cnt** → platter genuinely lacked the last committed entry at reload, in_ail=0 pin=0. No P13-SFPARENT-DURABLE-FAIL / P68-DIRINODE-DURABLE-FAIL → release-side `__mxfs_dlm_dir_inode_durable` (xfs_mxfs_dlm.c ~10769) either ran+succeeded (flush landed only in SCST write-cache; blkdev_issue_flush→platter step unreliable) or a bypass path skipped the drain. `mxfs_inode_cluster_durable` (~3870) = the release-side 1500×2ms wait + iflush_cluster + delwri_submit + blkdev_issue_flush.
- **lastrel ledger** ([[sess10run2-HEAD-state-and-next-steps]], build 35DAB8EB = D4C22548 + ledger): `i_mxfs_lastrel_ns/size/flag` (flag 1=durable ran, 2=skipped by pr_release_fast clean gate) stamped in `mxfs_dlm_bast_process` sd stage. P-SFDIR-REVERT prints it. **Proven** ([[sess10run2-PROVEN-transport-clean-lastrel1-cluster-clobber-suspect]]): at every SF revert `lastrel_flag=1, age_ms=5..256, size=full` → the durable call RAN and completed yet the platter regressed to N-1 within ms ⇒ flush→platter gap OR a co-resident clobber write.
- **block0-conversion loss (NOT an SF-phase loss)** ([[sess10run2-CORRECTION-no-sf-phase-forceblock-birth-block0-fork]]): storm dir converts SF→block **at MKDIR** (empty, force_block; P42-SFCONV sf_count=0 comm=mkdir, rank1/t1 only) so block0 exists from birth. dir_reuse round-3 victims (readdir 395/400, missing peers' first 1-2 adds) are BLOCK-format adds erased from block0's birth-era lineage. Round 1-2 clean, **round 3** (second reuse of the dir's ino+daddr set) loses — stale-lineage block0 image wins over peers' earliest adds. P-SFDIR-REVERT = 0 here (detector needs fmt==LOCAL; dir is never LOCAL post-mkdir).
- **r8 round-13 forensics** ([[sess10run2-r8-forensics-t3-stale-serve-conversion-fork]], build 48BCA7DF): 59 dirents durably lost from block0 daddr=**7872**. Storm dir = ino **2529 (>256)** → the entire ino≤256-scoped storm probe family was scope-blind in-suite (why nothing fired). **P5D-STALE-SERVED**: t3 served a stale block0 base (honor-wait 25×2ms expired while buffer busy in write storm; P34-TRYLOCK-STALE rc=-11) to a modifying RMW; t3 converted block→leaf at 343.066, last block0 write t3@343.810 durably erased the coherent lineage. P5D sites: xfs_da_btree.c ~3262 (LOCKED) & ~3320 (busy) — comment admits "serve stale as before" on exhaustion. Forensics survived only via test's own `/root/drc_fail_r13_rank*.dmesg` snapshots (virsh destroy skips journal flush → journald pre-reboot LOST).
- Instrumentation landed sess10 (all in-tree): `mxfs_ino_watched()` / `mxfs.watch_ino` ullong modparam rescoping the storm probes (P9-LFREE, P13-LADD, P11-DATALOG, P2-EPOCHPLACE, P13-COLLIDE+P49-STALEBASE, P10-RDBLK, P-DIRWR); `mxfs_dirdump()` + `.mxfs_dirdump*` magic-lookup trigger at top of xfs_lookup (returns ENOENT, no side effects); P10-RDBLK in xfs_dir2_leaf_getdents; run.sh FAIL→kernlog capture; `scripts/suite_cycle_run.sh` (cycle+suite+kernlog archive+MXFS_WATCH_ARM env+test filter). **QUIRK**: kernlog_test1 twice empty-of-markers while 11MB+ present — clock/journal window, don't trust t1 absence-of-evidence blindly.

## sess11 — bpend-refire storm (ROOT), tds SF-MHT retune, fence ABBA fix

Order the three fixes: **E7EB3081 (FIX-storm) → 2BB9A4D3 (FIX2 tds) → D0151E9A (FIX3 fence)**; all KEEP.

- **ROOT: bast_pending refire storm** ([[sess11run-ROOT-FIX-bpend-refire-storm-E7EB3081]], build **E7EB3081**, KEEP). dlm_scaling rate-face = ino 131 (`.dlm_scaling` parent, block-dir daddr=72) PR revoke storm: FAIL run had 22,587 P4L-ALLOC (all PR, 2 owners), 11,445 P6U-UNLOCK, 2,554 P3D-RELINVAL, rel_gen ~10,000 — with **ZERO real BASTs**. ~20ms/op → <50 ops/s floor FAIL (peers 212). Engine PROVEN via new qsrc/bpend forensics: **all qsrc=1 (ilock_end refire) bpend=1** (5,991 entries on t2). Lifecycle bug: `i_dlm_bast_pending` set by 4 sites but the sess9-v3 `mxfs_dlm_ilock_end` `CACHED && bast_pending` arm released on it and **NEVER cleared it** → every subsequent use refired a full DLM release+reacquire forever. **Fix**: ilock_end clears `i_dlm_bast_pending=false` when committing state=DEMOTING (obligation discharged by the release; abort paths re-SET it). Verified: relinval 0-3/node (was 4000+), qsrc1/bpend1=0, bp_entries 4-10, wall 73s (was ~110s). P10-CLREGRESS misread corrected here (see sess10). New always-on instrumentation: `i_dlm_stale_src` (u8, last stale setter), `i_dlm_bastq_src` (u8, who queued bast work), P11-ACQSTALE-SELFBAST, modparam `mxfs.acq_stale_selfbast` (default 1; A/B lever, not yet flipped).
- **FIX2: tds SF-MHT retune** ([[sess11run-FIX2-tds-sf-mht-retune-2BB9A4D3]], build **2BB9A4D3**, KEEP). Post-storm-fix, `tcp_dlm_scaling` regressed 71-75s (window 60) uniformly clean-boot = structural. The eternal-refire bug had been **accidentally load-bearing**: stuck bast_pending released the hot dir at every idle instant, defeating MHT batching → per-op handoffs at raw latency = historical 39-44s. P70-BP held_ms histogram: 144 qsrc=9 coasts at 50-150ms = `dir_sf_mht_ms=100` enforcing a minimum hold on an IDLE holder while 3 peers wait. **Fix**: `dir_sf_mht_ms` 100→**2** (xfs_mxfs_dlm.c ~8912) → tds **19.6-19.9s PASS** (2.2× historical best); block dirs keep inode_mht_ms=300 (preserves dir_reuse create-storm batching). sess20's "40 broke cache_coherency" sensitivity retested: cache_coherency PASS ×2 with sf=2. Also `mxfs_inode_unpin` (pinned_resource.c) got a `CACHED && bast_pending` arm mirroring ilock_end (create/mv/rm tenures no longer coast to MHT expiry).
- **FIX3: fence/defer_finish ABBA** ([[sess11run-FIX3-create-dir-before-ag-ordering-D0151E9A]], build **D0151E9A**, KEEP). fence double-shutdown = cross-node ABBA: `rm` holds dir ino=166 EX (Approach-A defers its BAST to trans_free) and needs AG-0 EX inside xfs_defer_finish; peer `create` holds AG-0 EX until commit (t_mxfs_ag_unlocks) and waits ino-166 EX. Both DIRTY → sess5 clean-trans breaker can't fire → unbreakable 60s cycle → P36-RETRY 60×1s → `DLM AG lock failed ag=0 rc=-110` → "Corruption of in-memory data (0x8) at xfs_defer_finish_noroll" shutdown; dead FS then fails fault_netpartition + tcp_dlm_scaling = one root, 3 FAILs. Root asymmetry: xfs_create (xfs_inode.c ~1465, v0.3.148) took first dp lock only AFTER xfs_dialloc → create=AG→dir; rm/unlink=dir→AG. **Fix**: take `xfs_ilock(dp, EXCL|PARENT)` + `mxfs_inode_pin(dp)` + `xfs_iunlock` BEFORE xfs_dialloc (dir DLM EX first, GRANT pinned across alloc; BASTs defer on i_dlm_pin_count; v0.3.148 RWSEM drop preserved so peer xfsaild iop_push trylock still works — sess33 AIL wedge cannot return). Unpin at re-lock success or gated on `!unlock_dp_on_error`. Verified fresh-cycle: fence ×3 PASS, tds 20.4s. **Not-yet-covered siblings**: xfs_symlink dialloc, xfs_rename whiteout dialloc, dead-incarnation GRANTED entries after lazy-umount. CAW caveat: pin-across-dialloc keeps dir BASTs deferred up to the 120s CAW poll (latency, revalidate on CAW ladder).

- **FIX-A: pin-aware release abort** ([[sess12run-FIXA-pin-aware-release-abort-99136941]], build **99136941**, KEEP — proven hole). - **FIX-B: iget-miss cluster reload** ([[sess12run-FIXB-igetmiss-cluster-reload-and-ladder-state]], build **5BE16AA5**, KEEP — dlm_scaling face gone since). Discriminator gap: if the face recurs WITHOUT the P12 print, the buffer wasn't incore → read was already fresh → CREATOR-side destage bug instead. Frequency rose post-FIX-A (FIX-A's longer pinned tenures shift inum-reuse/cluster timing); FIX-B is the consumer-side guard regardless.
- **END: fence root stack CAPTURED** ([[sess12run-END-fence-root-stack-trans-alloc-dir-AG-before-entry-locks]], build 5BE16AA5, ladder iter2=r16, artifact `run_fence_during_write_20260704T032716Z`): P12-HOLDERTASK ag=0 pid=13873 comm=rm on test1 stack: `xfs_vn_unlink → xfs_remove → xfs_trans_alloc_dir → xfs_lock_two_inodes → xfs_ilock → mxfs_dlm_ilock_begin → mxfs_v5_dlm_inode_lock → mxfs_dlm_lock_retries (waiting ino=540053 EX)`. So the rm **ACQUIRED AG-0 EX before/at xfs_trans_alloc_dir, THEN blocks acquiring the two entry inode locks** → AG→dir hold-and-wait; peer rm (dir→AG in defer_finish) completes the 60s cycle. ino 540053 = fence hot dir. Upstream order says rm takes dp EX before any AG, so this AG→dir edge comes from an mxfs hook. **Fix target for next session**: read `xfs_trans_alloc_dir`, find where AG-0 EX is taken before xfs_lock_two_inodes in the remove path (candidates: mxfs hook in trans reservation, sync inodegc/xfs_inactive of the previous unlink leaving a grant on the task, trans_dup migration), apply FIX3-style ordering (entry locks BEFORE AG acquire, preserving RWSEM). This remove-path AG→dir edge is the ONLY remaining 4/tcp blocker.

## Recurring gotchas
- **Any defer_finish shutdown wedges rmmod** → `NODE_PREP_FAIL` on the next run (silent no-op). ALWAYS virsh-recycle all 4 VMs after any shutdown before trusting subsequent results. suite_iter recycles every iter anyway.
- **Do NOT edit tests/suite_iter.sh while an instance runs** (bash re-reads → corrupts that instance). Edit only between iterations.
- FAIL artifacts persist only for FAILed tests; forensics that must survive virsh-destroy reboots go to test's own `/root/*.dmesg` snapshots (journald pre-reboot is lost).
- Storm probe family is ino≤256-scoped by default; hot dirs are AG-affine (large inums) → use watch_ino arming to see them.
- P10-CLREGRESS = false-positive under rm-heavy workloads (no version/seq discriminator).
- Check `pgrep -f suite_ladder` before starting new runs; kill leftovers + recycle VMs after shutdowns.
