This is a `kind: assorted` compilation: twelve trap notes the clusterer could not fit to one topic. Two are kernel-side (bmbt cache eviction, io_uring nowait). The rest are about measurement integrity: what a harness, a sweep or a log line is allowed to claim.

## Kernel-side traps

- **Owner-keyed bmbt eviction misses reused blocks.** A reload at re-acquire evicts cached bmbt buffers whose `bb_owner` is the acquired inode. A block that a peer freed from inode Y and reallocated into X's tree still carries owner Y in this node's cache. X's first lookup is an XBF_DONE hit on Y's old leaf. Measured as `P975-BMBT-LOOKUP-BAD` (`cached_owner=131 disk_owner=132`), refused by the btree owner check with one EFSCORRUPTED write. The same image under a matching owner would have been served silently, so an owner check at the consumption point is a detector, not the mechanism. The rule is that no reusable XBF_DONE bmbt image survives the release of the tenure that read it. This is implemented as `mxfs_bmbt_tenure_end_evict` before the wire unlock and in `mxfs_dlm_evict`, and it is fail-closed. Reproduction is two back-to-back 20000-extent laps with no re-prep, and the harness removes the file only on PASS, so a failed first lap destroys the precondition. Still open: buffers left by log recovery of a dead peer were read under no tenure. [[trap-an-owner-keyed-cache-eviction-cannot-see-a-block-another-inode-freed-and-reused-evict-at-tenure-end]]

- **io_uring reaches IOCB_NOWAIT on any O_NONBLOCK file.** MXFS sets no FMODE_NOWAIT, so `RWF_NOWAIT` returns EOPNOTSUPP. io_uring still marks the file nowait-capable when it is `O_NONBLOCK` and issues the first attempt with IOCB_NOWAIT, so the IOMAP_NOWAIT branches are live. `xfs_ilock_for_iomap`'s nowait arm took the ILOCK without a DLM begin, and 184 of 200 reads produced `P71-UNDERFLOW`. The control without O_NONBLOCK produced 0. Exercise nowait from userspace with io_uring on an `O_NONBLOCK` fd. Userspace success proves nothing, because io_uring retries from a worker, so read a kernel counter. `p71_underflows` is exact and the printk is budgeted at 300. On the 6.8 nodes only the O_DIRECT arms are reachable. The lock-pairing audit now fails caller-released helpers that lack an explicit contract. [[trap-io-uring-reaches-iocb-nowait-on-any-o-nonblock-file-even-without-fmode-nowait]]

## Harness verdicts that measured nothing

- **A verdict on absence of failure passes a zero-write writer.** In the two-writer DIO lap, the preamble `cat` ran inside the writer's timed window, so test1 wrote `ok=0 failed=0` and the lap PASSed on test2's writes alone. A lap with N writers has measured its claim only if every writer wrote. Any per-node counter the verdict relies on must be checked non-zero on every node that should produce it. The slow preamble is itself a pace observation. [[trap-a-two-writer-lap-passes-with-one-writer-at-zero-writes-when-a-preamble-shares-its-window]]

- **The log window must open at the incarnation under test.** A window opened at the lap marker counted the previous lap's takeover pass. That gave about 7000 old activations, a quoted summary line from the old incarnation, and a mixed on-demand count. Scope each count to a marker written at the boundary of the thing measured (the incarnation, the pass, the mount), not the lap start. [[trap-a-lap-window-opened-before-the-incarnation-under-test-counts-the-previous-laps-pass]]

- **A symptom that depends on a retry's luck must be asserted at the mechanism.** The poisoned-shell harness reproduced the whole kernel chain (`P34H-INCARN-POISON`, `P240-QUAR-NSOP-REFUSE rc=-116`), yet mkdir returned 0 because `P34H-POISON-EVICT try=1` retired the shell and the retry succeeded. Scoring only rc would have read the control as clean and the fix as vacuous. The verdict counts the mechanism lines alongside rc, and a round in which the reader never read the free image is VACUOUS, not OK. [[trap-a-poisoned-shell-that-retires-on-the-first-try-hides-the-estale-behind-the-kernels-own-retry]]

- **A control arm's expected behaviour must be measured, not derived.** The `drop_grant` control asserted from code reading that H's write would block for 40 s. Measured, it blocked 10 s, because the existing phantom-reconcile path (`P-PHANTOM-RECONCILE`) is a second defence that retires the orphan. Widening or dropping the control's checks would have hidden that the pre-fix system was bounded, and the CHANGELOG would have claimed a hang that never existed. A control arm's checks must name the old mechanism and report the wall, so run the control once and write the checks from what it printed. The treatment arm must also assert the second defence did NOT fire. [[trap-a-control-arms-expected-behaviour-written-from-reasoning-hides-the-second-defence]]

- **Everything that changes the outcome goes behind the A/B knob.** A second-cause fix added outside the `poison_retire_wait` knob turned the control into a second treatment arm: unretired went from tracking `poison_n` 1:1 to 0 on the control. An A/B whose control contains the treatment cannot fail. The knob defaults to on, so gating costs nothing. A control that goes clean after a code change is the first thing to distrust, so diff what moved between builds before believing any arm. [[trap-a-fix-outside-the-ab-knob-turns-the-control-arm-into-a-second-treatment-arm]]

## Log and evidence reading

- **"DEBUG:" contains "BUG:".** A probe line (`P238-FENCE-TAKEOVER-DECLINED`) saying "DEBUG:" scored 71 splats in a `grep 'BUG:\|Oops'` sweep, and `dlm/dlm.c:2245` carries the same substring. Never put "DEBUG:" in a printk. The convention for test-only lines is "TEST ONLY:". Separately, `ls -la <mount> | md5sum` differs across nodes because `..` is each node's local parent. Compare `ls -A -l --time-style=+%s`, or entries by name and size. Neither was an MXFS defect. [[trap-a-kernel-message-containing-debug-colon-is-counted-by-every-bug-colon-sweep-and-ls-la-digests-differ-on-the-local-parent]]

- **Run-dir kernlogs carry the whole boot journal.** `run_*/kernlog_test*.gz` are `journalctl -k` captures reaching back to boot. The "Corruption of in-memory data at mxfs_ailpin_work_fn ... Shutting down filesystem" hits in 10 run dirs were the deliberate `P487-INJECT-UNDER-LOCK` fail-stop legs, whose shutdown is the leg's PASS criterion. Check a marker's timestamp against the run's own window and look 15 lines above for an INJECT marker. Byte-identical context blocks in different run dirs were the tell. [[trap-run-dir-kernlogs-carry-the-whole-boot-journal-shutdowns-in-a-cc-run-dir-may-be-an-earlier-injection-leg]]

- **SCSI PR evidence.** READ KEYS proves a key is registered somewhere, not on which I_T nexus, so use READ FULL STATUS for "whose registration". `P305-RESV-SELF-GONE-INSPECT` on a live node has four explanations: a legitimate fence of the active incarnation, a stale or wrongly authorised fence, an unregister on another path, or genuine PR-state loss. Telling them apart needs the completed PR OUT correlated (issuer, action, RK, SARK, type, status, sense) against the incarnation active at that instant. Three lines read stronger than they are:
  - `P302-PR-KEY-RETAINED-FENCE-TARGET` only says the unregister was skipped.
  - `umount` rc=0 together with `log_shutdown=1` is not cleanliness.
  - `holder_key=0x0` under WE-AR is expected.
  Keep the selected key, an observed registration, one proven on our own nexus, a completed fence and a durable certificate of it distinct. [[trap-read-keys-does-not-say-which-nexus-holds-a-key-and-lost-registration-has-four-causes]]

- **Sweeps that succeed silently.** Memory triage missed files in two ways, both caught only by an independent verifier. First, the filename and frontmatter `name:` disagreed on 27 of 2,801 files, so keyed plans and deletes missed them; reconcile rows-without-files and files-without-rows. Second, `path.lstrip("./")` strips the dot of a dot-directory, so 116 citations in awareness docs were skipped with no error. Use `path[2:] if path.startswith("./")` and print every skipped path. Collapsing `.md.md` is not idempotent, so replace `(?:\.md){2,}` in one substitution. [[trap-a-sweep-keyed-on-one-name-and-a-path-scan-that-eats-dot-directories]]

## Harness safety

- **XFS_IOC_GOINGDOWN (0x8004587d) equals EXT4_IOC_SHUTDOWN.** `vergate.sh` ran it unconditionally on `/mnt/vgate` after a failed loop mount. That left the path a plain dir on the ext4 root, shutting down the node's root filesystem and forcing a power-cycle, which is why post-mortem dmesg captures were empty. The mount had failed because, since 0.15.0, a device with no SCSI PR needs `mxfs.fence_capability_override=1` (`single_node_exclusive=1` does not waive it). Never issue a shutdown ioctl before `/proc/mounts` shows the path is the mxfs mount intended. With the setup fixed, the arm exposed a real finding, `Allocated a known in-use inode 0x83!`, instrumented as `P-DIALLOC-VERIFY`. [[trap-the-goingdown-ioctl-shut-down-the-node-root-filesystem]]
