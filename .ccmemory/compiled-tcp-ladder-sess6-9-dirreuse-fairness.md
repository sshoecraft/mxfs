# TCP ladder sess6-9 (ccloop a9a03929): dir_reuse + dlm_fairness, FIX-11..28

Central thread: bringing the MXFS **TCP transport** clean across the ship criteria at 8/4/2/1 nodes. Two dominant criteria drove nearly every fix — `dir_reuse_coherency` (rm-rf/recreate ABA on shared dirs → durable name loss) and `dlm_fairness` / `tcp_dlm_scaling` (cross-AG convoy + phantom-EX ghosts). The chain runs FIX-11 through FIX-28 across builds `6D52DE30` → `2493D345`. End state at the sess9 relay boundary: **4/tcp full suite = 17/17 twice** (r5, r7), one residual dir_reuse flake. Ladder criteria = 17/17 at each of 1/2/4/8 nodes. Marker NOT written.

## Governing invariant (Inv-1)
An **undestaged buffer** (`lseq != wseq` i.e. logged-but-not-written, or pinned) may NEVER be staled/invalidated, and no DLM unlock may proceed past one — under Inv-1 the on-disk platter can never legitimately be ahead of it. Almost every dir_reuse root below is an Inv-1 hole: some path invalidated, evicted, reclaimed, or unlocked-past an mxfs-seq dir buffer that had committed-but-unlanded adds. The mxfs-seq dir-block class (`lseq>0 wseq=0`, `in_ail=0`, clean flags, no BLI/AIL hold) has **no upstream reclaim/writeback guard at all** — MXFS must supply every one.

## Cross-cutting lessons
- **Uncoordinated xfsaild writeback** is the deepest structural hazard: all N nodes flush the same dinode/dir-block daddr concurrently with divergent images, out of sync with DLM tenure. MXFS fixes attack the harmful *consumers* (FIX-14 evict, FIX-19 shrinker, FIX-22 union, FIX-16 noino land-scan) — the disorder itself is untouched; every new consumer is a fresh loss vector.
- **Phantom-EX** (in-core mode ≠ DLM table) is a recurring family: noino-release non-demote (FIX-13), late-grant/6s-retry race (FIX-20b), mid-drain upgrade release (FIX-26), deferred-publish (FIX-28). The **DLM table is always the source of truth**; local-mirror reads lie. On TCP a mirror read is cheap; on CAW `grant_gen` returns 0 so gen-based fixes are TCP-only by construction.
- **"Corruption of in-memory data (0x8) at xfs_defer_finish_noroll (xfs_defer.c:721)"** is the shutdown POLICY signature after an AG/inode lock rc=-110, NOT real corruption. A fs-shutdown node **retains its DLM grants and zombie-wedges the cluster** — the grant-surrender-on-shutdown liveness gap remains OPEN across all four sessions.
- **Timing/pace is a first-class failure:** a single node's 22-45s stall blows the 120s COORD barrier and the 480s in-suite budget, producing false cross-round misses. Round-pace technique: mxfs-DRCph per-node timestamps isolate the one late node.
- **Do not widen timeouts to pass.** Every reverted "aggressive release" fix (FIX-20 v1, FIX-23) killed LIVE grants; the receiver-side unsolicited-grant reject already handles no-mirror discard, so blanket sender-side releases only cause double-EX.
- **Repro infra:** `MXFS_EXTRA_MODARGS='dir_relverify=1 leafprobe=1' ./run.sh 4 tcp dir_reuse_coherency`; clean VM cycle = `virsh destroy+start` all nodes + delete `drc_*` per node (never rm-glob) + re-mount `/src` NFS per node; read `testN-serial.log` before cycling; `dmesg` not `/dev/kmsg` (blocks); harvest per-run dmesg before cycling. Instrumentation caps exhaust mid-run (`P70-BP` ~170s, `P9-LFREE` 60000, `P44` 2000) — only reliable standalone/fresh-boot.
