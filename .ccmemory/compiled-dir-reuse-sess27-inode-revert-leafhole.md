## dir_reuse_coherency 2/tcp — sess27 (ccloop 8ddb16a2): two durable lost-updates in tension, plus the LIO/FUA infra correction

Single ship-blocking criterion this session: `dir_reuse_coherency` on a 2-node TCP cluster (test1+test2). All other 2/tcp criteria pass. The criterion exposes TWO durable on-disk lost-updates of the same architectural class (invariant #1: no metadata destaged after DLM release), held in TENSION by the `partial_iwrite` module param — each setting fixes one bug and exposes the other. Both bugs survive `echo 3 > drop_caches` on BOTH nodes = genuinely on-disk, not in-core.

### CRITICAL INFRA CORRECTION — FUA IS DEAD ON THIS TARGET (fix this framing first)
Per [[sess27-target-is-LIO-rejects-FUA-reads-handoff-plan-dead]]: test2 boot dmesg (build C99F988B) shows the target is **LIO-ORG** (`Direct-Access LIO-ORG mxfs 4.0`), NOT SCST. It **rejects SCSI READ(16)+FUA** with `ILLEGAL REQUEST asc=0x24` (INVALID FIELD IN CDB). `mxfs_pal_scsi_read_fua_bdev` falls back to **plain bio reads** for ALL metadata. Consequences:
- The project memory `project_test_cluster_scst` ("SCST — CAW works") is WRONG for this cluster; trust the boot log.
- The ENTIRE sess21–26 fix corpus is FUA-based (`mxfs_buf_read_fua` / `_XBF_FUA_FRESH`) and is INERT here. Read-side refresh CANNOT fix a durably-wrong disk.
- The sess26 handoff ("detach BLI + xfs_buf_stale + run fua_disable=0 to pierce SCST") is DEAD: FUA does nothing on LIO. Any prior "raw FUA read returned fresh inum" worked because it forced an actual device read bypassing the in-core `xfs_buf` cache — the LIO backstore is write-through/coherent — NOT because of FUA. Default `fua_disable=1` is correct; NEVER chase `fua_disable=0`.
- Coherency on this cluster works because plain-bio reads hit the coherent write-through LIO backstore (15+ other 2/tcp tests pass on this). So the fix must be **write-side / in-core invalidation**, never FUA.
- Infra gotcha: test1/test2 AUTO-MOUNT mxfs ~20s into boot (LIO LUN appears → module loads → mounts /mnt/shared); source of the auto-mount unknown (no fstab/systemd/cron/rc.local). It races manual prep and can split-brain. `umount -l` leaves refcnt=1 (won't rmmod = wedged). Use `run.sh`'s `prep_cluster` (parallel `fuser -k` + umount + rmmod retries before mkfs) or virsh-reboot then re-prep. Always reboot the cluster before runs (`tests/reboot_cluster.sh 2`).

### PROVEN ROOT of BUG1 — durable on-disk inode-allocation REVERT (RULE 4, fully instrumented)
Per [[sess27-PROVEN-root-durable-inode-alloc-revert-not-leafhole-not-fua]] (build F156B768 = C99F988B + un-capped detectors). This supersedes ALL prior framings (leaf-hash-hole, ABA-BLI-FUA, iget-stale-cache):
- Symptom: `readdir=200` (all names present), `lookup_fail=57–95` (mostly node2's files). `P26-IGET-FAIL dp=1960 name="node2_f10" inum=2101385 err=-2 ftype=1`: the leaf lookup SUCCEEDS (finds name→inum) but `xfs_iget(inum)` returns -ENOENT — the dirent points to a **FREED inode**. Not a leaf hole, not a datascan gap.
- Durable + consistent: after drop_caches, BOTH nodes show identical `d_ino` — node2_f1→2101376 VALID, node2_f2→2101377 FREED, … node2_f10→2101385 FREED. Consecutive inodes in ONE 64-inode chunk aligned at 2101376. First ~9 durably allocated, rest reverted to free. `.md5` files got a separate chunk (2097783+), also partially reverted.
- NOT double-alloc: 0 duplicate d_inos among 200 entries; 57 dirents point at genuinely-free inodes; no freed inode reused by a node1 file. Pure REVERT (alloc lost).
- Mechanism: dirent (dir data block) + inode allocation (cluster di_mode + inobt) are written in the SAME XFS txn = atomic in the log. A durable split (dirent present, inode free) means the inode-cluster/inobt **AIL writeback was overwritten by a STALE buffer write** after node2's destage. The dir is rm-rf'd+recreated every round (test1=rank1 owns lifecycle) → INODE REUSE: round N-1 rm-rf frees inode X (node1 writes di_mode=0); round N node2 reallocs X. If node1's round-(N-1) free writeback is only log-committed/in-AIL (not destaged) at its DLM release, it lands AFTER node2's round-N alloc → reverts X to free. Observed at the cold read before this round's rm-rf → it's the PRIOR round's free landing late. This is invariant #1 applied to INODE-CLUSTER buffers — a likely GAP: release drains AG-meta (bnobt/agf/agi) + dir DATA, but NOT inode clusters.

### The partial_iwrite TENSION (the core structural finding)
Per [[sess27-UNIFIED-bug1-bug2-tension-fix-skip-NL-inodes]] and [[sess27-partial-iwrite-0-viable-only-leafhole-remains]]:
- `partial_iwrite=1` (default; write only b_li_list-logged inodes): REVERTS node2's FILE inodes (BUG1) because it skips node2's own freshly-allocated-but-checkpointed inodes. BUT protects the shared DIR inode (node1's stale di_size=1 dir inode isn't logged at write time → skipped → no dir revert).
- `partial_iwrite=0` (whole-buffer inode writes): FIXES BUG1 (all node2 file inodes written) BUT REVERTS the shared DIR inode (BUG2) — node1 whole-writes its cluster containing the dir inode it cached with stale di_size=1 from a PRIOR tenure → overwrites node2's durable di_size=2.
- The dir inode (e.g. ino 131) is REUSED+SHARED: rank1 creates it + adds files; rank2 adds files + grows it. So each setting fixes one bug and exposes the other. NEITHER passes as-is.
- KEY viability result (build 2C3150CB): `partial_iwrite=0` PASSES `cache_coherency` 2/2, `strong_consistency` 2/2, `posix_multi` 2/2 — the sess115 partial-inode-write (added for "cross_write_read xfs_inode_buf_verify corruption") does NOT regress with whole writes, because current AG-affinity keeps inode clusters single-owner in practice. So whole-writes are a viable base; only BUG2 remains under it.

### BUG2 investigation arc (under partial_iwrite=0) — di_size revert vs leaf-hole vs pure lookup miss
Chronological narrowing:
1. First cracked as a stale-di_size / 1-block extent-map problem — [[sess27-BUG2-CRACKED-lookup-reload-stale-1block-extent-map]] (build 0548BE0A): added a `scanned` counter to `mxfs_dir2_datascan_lookup`. At the failing cold-read lookup: `P26-DSCAN-MISS ino=131 ndb=1 scanned=100 name="node2_f10"`. Datascan computes ndb=1 from the in-core data-fork EXTENT MAP → only ONE data block (node1's ~100 dirents). But readdir (same round) lists 200 names across 2 data blocks and node2_f10 durably lives in block 1. Root theorized: `xfs_lookup` → `mxfs_dlm_dir_consumer_refresh` → `mxfs_dlm_reload_inode` rebuilds the data fork from the ON-DISK dir inode whose di_size/di_nextents reflect only 1 block (the grow to 2 blocks was not durably committed, OR reload reads stale di_size) → reload SHRINKS the reader's extent map from 2 blocks to 1. Proposed fixes: durable di_size/extent grow on the writer, OR reload must never shrink the in-core extent map below current max.
2. Refuted the di_size-stale theory — [[sess27-bug2-leafhole-not-datascan-underscan-deeper]] and [[sess27-FINAL-bug2-is-lookup-bug-datascan-misses-present-dirent]] (build 9753480F): changed the datascan to compute ndb from the extent map instead of di_size/blksize → **ndb=2 either way** (di_size=8192 was NOT stale). dir_reuse STILL fails: readdir=200/200, lookup_fail=97–98, P26-DSCAN=20, P26-DSCAN-MISS=20, P22-DATASCAN-HIT=0, P26-IGET-FAIL=0. So the datascan scans BOTH data blocks correctly but MISSES node2_f10, which readdir (same round, same blocks) LISTS. `ls | grep node2_f10` → PRESENT and survives TWO drop_caches (durable on disk); `stat node2_f10` → ENOENT. Under whole-writes this is a **read/lookup-path bug, NOT a write-side durable lost-update** (contrast the di_size framing above). The extent-map ndb change is harmless/more-correct robustness — keep or revert, no behavior change.
3. The paradox to crack next: readdir and the lookup datascan both read the same dir DATA blocks by daddr through the same buffer cache, yet readdir finds node2_f10 and datascan doesn't. Candidate causes: (a) readdir vs `xfs_dir3_data_read` see different in-core data-block states (different refresh path — `xfs_lookup` calls `mxfs_dlm_dir_consumer_refresh` at top; readdir may do more/less); (b) durable DATA-block revert where readdir lists from a staler cached block that still has the dirent while datascan re-reads a fresher block without it — note under partial_iwrite=0 the missing set GREW (now includes node2_f1, valid under =1), consistent with whole writes worsening a separate dir-data revert; (c) `xfs_dir2_compname` hash/ci mismatch (unlikely).
4. PRIME lookup-bug suspect (from [[sess27-FINAL-bug2-is-lookup-bug-datascan-misses-present-dirent]]): `args->cmpresult` interaction in `mxfs_dir2_datascan_lookup` (xfs/libxfs/xfs_dir2_leaf.c). The scan does `if (cmp != XFS_CMP_DIFFERENT && cmp != args->cmpresult) {...}`. The FAILED prior leaf lookup (`xfs_dir2_leaf_lookup_int`) may have already set `args->cmpresult = XFS_CMP_EXACT`, making `cmp != args->cmpresult` FALSE for an exact match → present dirent SKIPPED. FIX CANDIDATE: reset `args->cmpresult = XFS_CMP_DIFFERENT` at the top of the datascan. Decisive probe: in the inner while-loop, when `args->name` matches "node2_f10", log `P-DSCAN-SEES name=X cmp=%d cmpresult=%d db=%d` to distinguish SEES-but-skips (cmpresult bug) from never-sees (wrong block/read); also log the daddr readdir reads vs datascan reads for the same dir.

### GPT-5.5 design consult (RULE 5) — unified root = incomplete release-side destage
Per [[sess27-gpt-design-release-drain-is-foundation-unified-root]]. Both corruptions are ONE class: a node writes a STALE cached metadata buffer over the peer's durable newer version because dirty metadata OUTLIVES its DLM lock tenure (released with buffers still in-AIL/pinned, not destaged home). GPT verdict:
- **RMW (read-modify-merge-write) is the WRONG general model**: not atomic vs peer writes, breaks structured blocks (CRC/LSN/hdr/hash), and `b_li_list` ("currently-attached log items") is the WRONG durability predicate.
- **FOUNDATION = strict per-resource DLM release/demotion drain** (per-inode, per-AG, per-dir-inode): 1) quiesce new txns; 2) wait active txns; 3) `xfs_log_force_lsn(max_commit_lsn)`; 4) push AIL + submit ALL home-dirty buffers for the lock; 5) **WAIT for write I/O completion**; 6) ASSERT no home-dirty remains; 7) invalidate (`xfs_buf_stale`) CLEAN cached buffers for the tenure; 8) THEN `dlm_unlock`. No buffer with local home-dirty state may survive demotion.
- **Submit-time guard (backstop)**: at buffer write, if not holding the owning lock epoch — CLEAN stale buffer → skip+stale; DIRTY stale buffer → `xfs_force_shutdown(CORRUPT_INCORE)` (release-before-checkpoint invariant violation). Extend existing dir/agmeta/bmbt skip-guards to INODE CLUSTERS (none exists today).
- **partial_inode_write predicate must be a PERSISTENT per-sector `local_home_dirty` mask** (set on modify under EX, cleared only on successful home I/O completion), NOT b_li_list — so a freshly-allocated inode whose log item detached before its sector was written stays home-dirty and won't be skipped. Alternative: a physical INODE-CLUSTER DLM lock (`ICLUSTER:<agno>:<cluster_ino>`), whole-write only under it, lock order AG→icluster→inode.
- **Round N-1 free vs round N realloc hazard is REAL** (matches the proven BUG1): free writeback (di_mode=0) lands after realloc. Fix = free path must logforce+checkpoint+WAIT+invalidate the inode cluster + inobt + AGI before releasing AG/inode locks. Add inode generation/incarnation guard at write submit to reject stale prior-incarnation writes. GFS2/OCFS2 do exactly this (glock demotion checkpoints journal + invalidates). Add explicit lock EPOCH/tenure (b_tenure_id exists) + born-under-lock tag to avoid sess17-class false positives on freshly-created blocks.
- GPT recommended: fix release-drain FIRST (addresses BOTH inode + leaf), re-run with DEFAULT args (partial_iwrite=1), verify P26-IGET-FAIL=0 AND lookup_fail=0. Do NOT ship partial_iwrite=0 (per GPT's false-sharing caution — but note the measured passes above weaken that concern).

### The UNIFIED FIX design (skip prior-tenure NL inodes) — chosen implementation direction
Per [[sess27-UNIFIED-bug1-bug2-tension-fix-skip-NL-inodes]] and [[sess27-unified-fix-compile-fixes-for-next-session]]. Rewrite `mxfs_submit_partial_inode_write` (pal/linux/xfs_buf.c) to write EVERY inode sector in the cluster EXCEPT sectors of inodes IN-CORE on this node with `i_dlm_mode == MXFS_LOCK_NL` (this node released it = prior tenure; a peer may own/have-superseded it). This simultaneously: writes node2's OWN held (EX) file inodes even after their log item detaches → fixes BUG1; skips node1's RELEASED (NL) dir inode → node1 can't revert node2's di_size=2 → fixes BUG2; preserves sess115 cross-node false-sharing. If no NL inode in the cluster → return false → normal whole-buffer write. REPLACES the b_li_list "write-only-logged" predicate.
- Enumerate cluster inodes by NUMBER (NL ones are NOT on b_li_list): look up `(base_agino+s)` in `pag->pag_ici_root` under `pag_ici_lock`.
- RISK (sess17 false-positive): a freshly-created inode can transiently read `i_dlm_mode==0/NL`; skipping it DROPS a legit write (corruption, sess23 suppression-was-corruptor class). Start STRICT: only skip NL inodes whose VFS inode is a DIR (`S_ISDIR`) — the proven BUG2 victim — then broaden. Never skip an inode NOT in-core (no NL signal; owning-cluster assumption).
- **Compile gotchas** (this kernel = 6.8 headers, fork of 6.19-rc0 XFS) — in pal/linux/xfs_buf.c these are NOT available and caused 3 build errors (reverted to keep tree building at 0548BE0A): `XFS_DADDR_TO_AGBNO` (does not exist); `XFS_DADDR_TO_FSB` (expands to undeclared `xfs_mask32lo`); `pag->pag_agno` (field renamed under the xfs_group abstraction — compiler suggests `pagl_pagino`; DO NOT use pag_agno). CORRECT computation (no agno needed, since fsb = agno*agblocks + agbno):
```c
struct xfs_perag *pag = bp->b_pag;      /* inode-cluster bufs have b_pag */
xfs_fsblock_t fsb   = (xfs_fsblock_t)(bp->b_maps[0].bm_bn >> mp->m_blkbb_log);
xfs_agblock_t agbno = (xfs_agblock_t)(fsb % mp->m_sb.sb_agblocks);
xfs_agino_t base_agino = (xfs_agino_t)agbno << mp->m_sb.sb_inopblog;
/* spin_lock(&pag->pag_ici_lock); for s in 0..ni-1:
   ip = radix_tree_lookup(&pag->pag_ici_root, base_agino + s);
   if (ip && ip->i_dlm_mode==MXFS_LOCK_NL && S_ISDIR(VFS_I(ip)->i_mode)) skip its spi sectors;
   spin_unlock. if nskip==0 return false; dirty = all & ~skip. */
```
`all = (total_sects>=64) ? ~0ULL : ((1ULL<<total_sects)-1)`. Downstream run-finder + submit reuse `dirty`+`nslots` unchanged. `(void)lip;` after removing the b_li_list loop.
