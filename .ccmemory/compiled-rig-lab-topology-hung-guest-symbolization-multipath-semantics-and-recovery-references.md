## Debugging a hung rig VM

[[technique-symbolize-a-hung-kvm-guests-cpu-from-the-qemu-monitor-with-the-kaslr-slide-from-idt-gate-0]] -- guest stopped answering, no netconsole, sysrq too restricted for dumps:
1. `virsh domstats <dom> --vcpu --interface` twice. A vCPU whose time advances 1 s/s is spinning; frozen rx pkts means network dead.
2. `virsh qemu-monitor-command <dom> --hmp 'info registers'` several times: RIP, RSP, RFL (IF bit), IDT base.
3. `--hmp 'x /2gx <IDT base>'`: gate 0 handler = low16 | (bits 48-63 << 16) | (high qword low32 << 32). KASLR slide = handler minus `asm_exc_divide_error` in System.map (take System.map from a healthy host on the same kernel).
4. `--hmp 'x /200gx <RSP>'`; symbolize every word in kernel text (subtract slide, bisect System.map). `0xffffffffc0..` words are modules.
5. For a module return address: get the same build's .ko (DKMS on a sibling host, pulled as base64 over ssh), `objdump -d --disassemble=<fn>`, match low bits to the call's return offset in .text (mxfs .text was 0xffffffffc0c00000; return c0e6b085 = .text+0x26b085, after mxfs_ioq_end_io's last call).
Then confirm with netconsole (`tools/pve_netconsole.sh`, PVE_PAIR_ALL listing the physical hosts first so nested ones get ports 6669/6670, PVE_NETCONSOLE_TO=192.168.120.1, PVE_NETCONSOLE_IF=br0, `dmesg -n 8`). Case: pve9-2 spun in delay_tsc under vpanic after a BUG in bio_chain_endio.

## Lab addressing and reachability

- [[env-test1-needs-a-static-dhcp-reservation]]: test1/test2 on 192.168.120.x get DYNAMIC leases from a system dnsmasq (br0:67, not libvirt's virbr0); ".186" was only lease affinity. After a reboot test1 took .114 and the harness (hardcoded .186) could not reach it. Fix: `dhcp-host=` reservations in `/etc/dnsmasq.d/lab.conf` (test1 52:54:00:80:b0:04 -> .186, test2 52:54:00:f5:f5:3a -> .182), restart dnsmasq. Never leave a `.bak` in `/etc/dnsmasq.d/` -- dnsmasq loads every file there and fails with "illegal repeated keyword"; keep backups elsewhere. Unreachable-node recovery: `scripts/vm_console_type.py` types into the VGA console via `virsh send-key`; the serial console is silent on these VMs, so use `virsh screenshot` and Read the PNG. `UseDNS no` in sshd if ssh is slow.
- [[reference-pve9-vms-use-static-ips-find-them-in-the-br0-neighbour-table]]: pve9-1/pve9-2 have installer-set static IPs (.120.194 / .120.138), no dnsmasq lease, no guest agent; `getent` and `virsh domifaddr` find nothing (a 240 s boot-wait lap burned its budget on that). Look up by MAC in `ip neigh show dev br0` (52:54:00:cc:8e:c1, 52:54:00:17:d1:9b). Their old `/dev/mxfs-shared` disk was detached from both definitions; they reach the shared LUN by in-guest iSCSI (`scripts/pve_iscsi_login.sh`).
- [[reference-vsphere-lab-esxi-hosts-are-nested-in-vmware-workstation-on-clyde]]: esxhost1/esxhost2 are ESXi VMs nested in VMware Workstation (`~/vms/vmware/`), vstest guests two hypervisors deep. When clyde is loaded, guests soft-lock on every CPU including idle tasks ("CPU#1 stuck for 23s! [swapper/1:0]") -- hosting layer, not guest code. Before reading any vSphere guest's timing (lease expiry, scan windows, "hung" mounts) as an MXFS result, check the guest's dmesg for idle-CPU soft lockups and clyde's load over the same interval. A post-stall clock jump expires every MXFS deadline at once and mimics a renewal bug.

## Shared storage

- [[reference-the-shared-lun-is-clyde-scst-since-the-qnap-was-retired]]: QNAP retired 2026-09-26; anything naming 192.168.1.4 or WWID 6e843b is dead. `/src` is a clyde bind mount exported at `192.168.120.1:/src`. LUN layout in that note was superseded 2026-10-01: every LUN is now borrowed from `tools/lun_pool.sh`. Still true: do not use scst.service; SCST objects are runtime-only (recreate with `tools/lun_pool.sh up` after a clyde reboot); no `allowed_initiator` attribute, so isolation is by ini_groups; run.sh's iSCSI restore must log a node into its own target only (bare discovery+login records every target, and RHEL logs into all at boot). SCST keeps a dead initiator's PR registration (QNAP purged it ~34 s after power cut), so absent-key fence routes exercised on the QNAP are not reached by a power cut alone.
- [[reference-2node-caw-runs-on-the-qnap-lun-via-mxfs-dev-and-cawd]]: superseded stub. 2-node CAW now runs on clyde's SCST target with no MXFS_DEV: `MXFS_FORCE_PREP=1 ./run.sh 2 cawd prep_cluster`.
- [[reference-sixteen-node-boards-run-on-g16-g16b-with-80g-pool-luns]]: since 0.90.42 the release matrix includes 16/net/mesh/direct and 16/disk/caw/direct. Groups g16 (test1-16) and g16b (test17-32) overlap the g2/g4/g8 groups, so they cannot run side by side with smaller boards; chain is `CLAIM=16 SIDE_BY_SIDE=0 POWER=1 tests/release_verify_chain.sh V`. Each needs an 80G pool LUN (lun12, lun13; pool is 11x20G + 2x80G; no room for a third under the preflight's 88% gate). test29-32 are normally off; `scripts/lab_power.sh up group:g16b` (~26 s). Both boards ~22 min wall. ag_strand_repair needs 32 rounds at 16 nodes (16 rounds fails `strands=0` -- harness coverage, not FS). A filtered `./run.sh <cfg> --group g <row>` after a full board is refused as "cluster is prepped for ..."; use `tests/board_4node_chain.sh <label> <cfg>:<row>@<group>`.

## dm-multipath

[[reference-on-dm-multipath-mxfs-sends-caw-to-one-path-itself-and-pr-registration-fans-out-to-every-path]] (0.90.44). Ask separately about (a) bio I/O through dm, (b) passthrough commands, (c) PR commands.
- CAW and FUA passthrough bypass dm: `mxfs_bdev_to_sdev` (pal/linux/kern.c) resolves to ONE path's scsi_device (by LBA-0 content, cached per dev_t). A dead path returns a transport error and nothing resends it except `caw_slot_ex`'s own retry loop (dlm/dlm_caw.c, 5 retries, 10..200 ms). A CAW applied with its answer lost is re-sent with the same compare image and miscompares against its own write; `hb_cas_own_slot` already treated I/O error as indeterminate, `caw_slot_ex` did not until 0.90.44 (P-CAW-ANSWER-LOST-LANDED).
- PR REGISTER goes through dm `dm_pr_register`, on every path, unregistering all if any fails: 2N registrations for N nodes on two paths; mount with a path down is refused (DID_NO_CONNECT, rc 32); a path's registration survives down/up, only a path absent at REGISTER lacks one; an unregistered path answers RESERVATION CONFLICT, which dm-multipath does not treat as a path error.
- To inject "applied, answer lost": drop only host-to-guest frames on the path's tap (`scripts/san_net.sh mute`).

## Protocol readings

- [[reference-a-tcp-mounts-node-id-is-random-per-mount-so-no-remount-renews-its-old-lease-entry]] (0.89.69): TCP node id comes from 16 random bytes each mount (`dlm/v5_mount.c`). Only the bootstrap RESUME arm (`P-BOOT-RESUME-IDENTITY`) reuses one; `node_id_override` is the debug way to force it. Clean unmount's GOODBYE unregisters the lease entry and retires the id; a crashed node's entry stays until recovery completes (~72 s = 62 s stale window + replay; rebooted guest answers ssh at ~120-150 s). So "rebooted node renews old entry with new incarnation" cannot happen on TCP; do not build a lap for `P-LEASE-INCARNATION-MISMATCH`.
- [[reference-a-two-node-total-outage-is-recovered-by-the-bootstrap-owner-which-adopts-one-victims-slot-as-its-own-log]]: with both nodes down, the next mount sees a frozen disklock table (`P-BOOT-SCAN-FROZEN` TOTAL OUTAGE), becomes provisional bootstrap owner (`P-BOOT-CLAIMED`), fences/certifies victims, then ADOPTS one victim's slot as its own log (`P-BOOT-ADOPT`, full authority-evaluated replay by ordinary log recovery, `P-BOOT-ESCROW-K-REPLAY-OK`) while other victims are foreign-replayed. The adopted victim gets NO `P163-RECOVERY-COMPLETE`. Harness trap: asserting that line fails a recovery that ran (`tests/fence_crash_cuts.sh` at s118a -- every cut is a total outage). Grade adoption on `P-BOOT-ADOPT` + `P-BOOT-ESCROW-K-REPLAY-OK` + `P-BOOT-RECOVERY-COMPLETE` together. The bootstrap once had a CAW-only call site and reaches TCP now, so banked pre-TCP evidence grades differently.
- [[ruling-tauth-ledger-recovery-scan-cost-sparse-summary-first]] (design consult, D-TAUTH-RECOVERY-SCANS-SCALE-WITH-LUN-SIZE-NOT-LEDGER-USE; 1 TB takeover scan 14.5 s, live_pages=1 of 541,201): ship a crash-ordered sharded occupancy summary first. Set the bit durably BEFORE a page's first non-empty commit, clear only AFTER a canonical empty page is durable; false positives harmless, a false zero is corruption. Summary blocks need shadow copies + crc + seq and one serialized writer per shard (aligned with page ownership; two masters doing RMW lose bits). Invalid shard falls back to scanning that shard's range. Clear bits incrementally or scans return to O(npages). Sizing npages from nodes x records is unsafe until per-node record count is an enforced admission bound and page-full (-EDQUOT, requester waits, no forcing mechanism) has a bounded answer; seeded FNV is not collision resistant. The fixed second orphan sweep is not a correctness boundary: drop only after instrumenting changes between passes and proving quiescence, or replace with a barrier / dirty-page worklist. Measure first: per-page occupancy high-water (reclaimable vs not), 0->1/1->0 rates, page-full events with holder identities, hash histogram.
